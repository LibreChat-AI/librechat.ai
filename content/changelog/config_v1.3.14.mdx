- Updated Agents endpoint capabilities
  - Added `memory` and `ask_user_question` to the default capability list
  - Added highly experimental, opt-in `stateful_code_sessions` for reusable Code Interpreter workspaces; behavior and configuration may change substantially during experimentation
  - Added opt-in `run_in_background`; Code Interpreter tools are background-eligible by default while eligible MCP, Plugin, and Action tools remain explicit opt-ins
  - Action-level background selection covers every eligible operation; OAuth Actions and operations that already define `run_in_background` are excluded
  - Added opt-in `tool_intents` for live model-written labels on native and selected MCP tool calls
  - Programmatic MCP tools now require Code Interpreter on the Agent; the builder disables or clears incompatible selections and the server strips stale caller options
  - Programmatic Tool Calling now exposes a compact live trace of inner tool calls and intersects each run's caller-authorized tools with LibreChat's trusted execution registry

- Added `endpoints.agents.maxSubagents`
  - Configures the maximum explicit subagents accepted in flat Agent lists and Agent team graph definitions
  - Defaults to `10`, accepts values from `1` to `50`, and is enforced process-wide from the base YAML

- Added Agent activity-group settings
  - `activityLabel` enables generated one-line headers for contiguous reasoning and tool-call blocks
  - `activityModel`, `activityEndpoint`, and `activityPrompt` select and configure the header model call
  - `activityMaxPerRun` and `activityCharLimit` bound additional calls and prompt input
  - Fields can be set under `endpoints.all`, `endpoints.agents`, or the backing provider/custom endpoint and resolve independently by precedence

- Added parent Agent activity-phase settings
  - `activityPhaseLabel` generates a collapsed summary for run phases containing at least two logical activities
  - `activityPhaseModel`, `activityPhaseEndpoint`, and `activityPhasePrompt` configure the summary model call
  - `activityPhaseMaxPerRun` defaults to `5`; `activityCharLimit` also bounds phase-summary evidence
  - Phase settings fall back through activity-label, title-model, and current-run settings and use the same endpoint configuration precedence
  - Two or more completed labeled tool groups fold into the phase-card surface before an optional phase summary arrives; the newest completed child label acts as the interim header while live work remains outside
  - Files produced inside a phase remain visible beneath the collapsed card, and resolvable bare, `/mnt/data/`, or `sandbox:` Markdown image references render the matching attachment inline without duplication
  - Short progress remains grouped, substantial answer text closes the active phase before the result, and later activity blocks can create another phase in the same run
  - Persisted phase boundaries are rebased after content compaction so they remain aligned after reload

- Added live Agent reasoning-label settings
  - `reasoningLabel` replaces the generic top-level reasoning heading with a generated orientation as a response develops
  - `reasoningLabelModel`, `reasoningLabelEndpoint`, and `reasoningLabelPrompt` configure the separate label call
  - `reasoningLabelMinChars`, `reasoningLabelUpdateChars`, and `reasoningLabelUpdateIntervalMs` control when streaming revisions run
  - `reasoningLabelMaxPerRun` defaults to `8`; each attempted revision is a separate model call with its own usage and cost
  - Each call receives at most 4,000 characters of visible reasoning, and Langfuse records that input unless active redaction suppresses the label call
  - The current live reasoning label and response timer shimmer only while generation is active; settled or non-latest reasoning remains static

- Added `endpoints.agents.toolApproval`
  - Enables human approval for matching Agent tool calls
  - Supports `default`, `dontAsk`, and `bypass` modes plus glob-based `allow`, `deny`, and `ask` rules
  - Evaluates static rules in `deny`, `ask`, then `allow` order before applying the configured mode fallback
  - Matches MCP runtime names and model-facing aliases across top-level and nested Subagent tools
  - Supports trusted programmatic hooks for context-aware approval policy; hooks can only make the static policy stricter

- Added `endpoints.agents.checkpointer`
  - Persists paused Ask User and tool-approval runs so they can resume later
  - Uses MongoDB by default with a 24-hour TTL
  - Supports configurable collection names and a process-local `memory` mode for development

- Added `summarization.retainRecent`
  - `turns` preserves a configurable number of recent complete conversation turns outside the summary
  - `tokens` sets a recent token-retention budget

- Updated automatic memory extraction
  - `memory.agent.enabled: true` is now required to run the automatic memory agent
  - Manual memories and Agent memory tools remain available when automatic extraction is off

- Added model spec controls
  - `showInMenu` can hide a spec from the selector while retaining trusted explicit `spec` access
  - `memory` equips an ephemeral Agent with memory tools
  - `askUserQuestion` enables durable question-and-resume flows
  - `runInBackground` now accepts a boolean or resolved tool-ID list; `false` or `[]` opts out of background-native code tools
  - `describeIntent` accepts a boolean or resolved tool-ID list for live tool intent labels

- Added `customParams.paramDefinitions[].range.positiveMin`
  - Supports numeric controls whose `range.min` is a sentinel while ordinary values begin at a higher floor
  - Validation and UI clamping accept only the sentinel or values from `positiveMin` through `max`

- Added OpenAI reasoning controls
  - `reasoning_mode` supports `standard` and `pro`
  - `reasoning_context` supports `auto`, `current_turn`, and `all_turns`
  - `reasoning_effort` now supports `max` on compatible models
  - GPT-5.6 reasoning requests default to the Responses API unless `useResponsesApi: false` is set explicitly

- Updated Agent model runtime behavior
  - Saved `model_parameters.imageDetail` values now control native vision image encoding for Agent requests and are stripped from provider model options
  - `{{current_date}}`, `{{current_datetime}}`, and `{{iso_datetime}}` are anchored to the logical turn start and remain stable across provider loops, Subagent initialization, and human-in-the-loop resume
  - Recognized model-not-found and provider rate-limit failures use localized guidance; other provider text is persisted without appended LangChain troubleshooting URLs unless content protection requires the generic message

- Added top-level `langfuse` tenant configuration
  - Stores enabled state, public key, encrypted secret key, verified project ID, masked `secretKeyPreview`, and an approved destination key
  - Added an admin-only **Settings → Langfuse** connection flow with server-side credential verification
  - Complete environment credentials take precedence in single-tenant deployments; fanout availability remains deployment-controlled
  - Removed the legacy `displaySecretKey` and nested `fanout.enabled` fields
  - Added opt-in Compose and Helm fanout deployment settings for central and tenant-scoped trace export
  - Added `LANGFUSE_FANOUT_LISTEN_ADDR` to override the gateway's default `:4318` listen address
  - Added `LANGFUSE_PROJECT_ID`, `LANGFUSE_TRACING_ENABLED`, and deterministic `LANGFUSE_SAMPLE_RATE`
  - Authorized administrators can open a sampled conversation's Langfuse session from Context Usage and from authenticated same-tenant shared conversations
  - Added YAML-only `langfuse.headers` for authenticating one self-hosted Langfuse origin or gateway across traces, media, feedback, project lookup, and credential verification
  - Header values support `${ENV_VAR}` references, are masked in config output, and fail closed when configuration resolves multiple Langfuse origins
  - Added `librechat.tenant.id`, `librechat.langfuse.export_plan`, and `librechat.langfuse.export_reason` trace attributes plus secret-free `librechat.langfuse.connection.changed` events for export troubleshooting

- Expanded admin config secret handling
  - Registered OCR, speech, web-search, Assistants, Azure Assistants, and Langfuse keys are encrypted and redacted on admin writes and reads
  - `endpoints.custom[].apiKey` literals are encrypted; environment references and `user_provided` remain passthrough values
  - Registered secret fields expose server-generated `<field>Preview` companions

- Added Node.js HTTP server timeout settings
  - `HTTP_KEEP_ALIVE_TIMEOUT_MS` and `HTTP_KEEP_ALIVE_TIMEOUT_BUFFER_MS`
  - `HTTP_HEADERS_TIMEOUT_MS` and `HTTP_REQUEST_TIMEOUT_MS`
  - Values are non-negative milliseconds; `0` disables the corresponding timeout

- Added configurable baseline HTTP security headers
  - HSTS, X-Frame-Options, X-Content-Type-Options, Cross-Origin-Opener-Policy, Cross-Origin-Resource-Policy, and Referrer-Policy are sent by default
  - `SECURITY_HEADERS=false` disables the baseline and acts as the global Content Security Policy kill switch
  - HSTS lifetime, subdomain and preload behavior, framing, opener, resource, and referrer policies can be configured independently

- Added opt-in nonce-based Content Security Policy
  - `CSP_ENABLED=true` enables the policy, with `CSP_REPORT_ONLY=true` by default for staged rollout
  - Each SPA response receives a fresh script and module-preload nonce and is forced to `Cache-Control: no-store`
  - Source-specific `CSP_*_EXTRA` variables append deployment origins; `CSP_FRAME_ANCESTORS` replaces the default frame policy
  - `CSP_ALLOW_WASM` and `CSP_ALLOW_DATA_WORKERS` default on for HEIC conversion and Monaco workers

- Added Code Interpreter runtime settings
  - `CODEAPI_AUTH_PROVIDER=librechat-jwt` and `CODEAPI_JWT_ENABLED=true` enable per-user bearer-token authentication for self-hosted Code Interpreter services
  - LibreChat supports EdDSA and RS256 private keys supplied as PEM, base64-encoded PEM, or private JWK, with configurable key ID, issuer, audience, token lifetime, and mint cache
  - `CODEAPI_JWT_SINGLE_TENANT_ID` provides the matching non-strict tenant fallback; strict tenant isolation rejects missing tenant context, including ambient system contexts, instead of minting an invalid tenant claim
  - `CODE_SANDBOX_PREWARM` controls stateful sandbox prewarming
  - `CODE_SANDBOX_COLD_AFTER_MS` controls when tracked sandboxes are treated as cold
  - `LIBRECHAT_CODE_SANDBOX_OUTPUT_MAX_SIZE` defaults to `65536` and derives safe sandbox-image windows; match it to the worker's `SANDBOX_OUTPUT_MAX_SIZE`
  - `LIBRECHAT_CODE_IMAGE_CHUNK_BYTES` is now an optional exact image-window override rather than a fixed `32768`-byte default
  - `CODE_ENVIRONMENT_PAIRING_USER_MAX` and `CODE_ENVIRONMENT_PAIRING_USER_WINDOW` control per-user self-service worker pairing limits
  - When `endpoints.agents.statefulCodeSessions` is present, `allowedEnvironments` is required and restricts selectable workspace scopes; omitting the entire block allows `user`, `agent-user`, and `conversation`
  - `endpoints.agents.statefulCodeSessions.environments` defines named managed or attached stateful backends, requires exactly one default when executable entries exist, and fails closed when an Agent's selected environment is unavailable
  - Deployment-owned attached environments can route through top-level `workerId`, enroll an operator worker with `pairing.workerId`, or permit owner-bound workers with `pairing.allowPrincipalWorkers`; `pairing.tokenEnv` names the secret-bearing environment variable
  - A principal-worker control plane with neither worker ID is pairing-only, cannot be the default, and is omitted from execution selectors
  - Authorized users can pair, list, select, and revoke personal workers under **Settings > Code environments**; credentials and registry records are reconciled during environment or account deletion
  - Attached environments use an outbound Code Interpreter worker and are excluded from sandbox prewarming; the entire attached-environment and pairing contract remains highly experimental
  - Stateful `create_file` and `edit_file` outputs now appear in a per-message **Workspace changes** list with authenticated downloads; the workspace itself remains highly experimental and non-durable

- Added experimental Agent Plugin runtime settings
  - `DEPLOYMENT_PLUGINS_DIR` selects the startup-loaded plugin package directory and defaults to `./plugin`
  - `DEPLOYMENT_PLUGIN_DATA_DIR` selects the persistent per-plugin data root and defaults to `./data/plugins`
  - Agent Plugins `1.0.0` can bundle deployment Skills and MCP servers
  - `DEPLOYMENT_PLUGIN_HOOKS=true` opts trusted plugins into `command` hook execution on the API host; hooks are ignored with a warning by default
  - Command hooks receive bounded lifecycle payloads over standard input, run with a minimal environment plus explicit `allowedEnvVars`, and can return event-appropriate decisions

- Updated GitHub Skill Sync isolation
  - Valid Skills can publish when another Skill in the source is invalid or conflicts
  - Partially successful runs report `partial` with bounded skipped-Skill counts and details
  - Skipped Skills preserve last-known-good mirrors; source authentication, rate-limit, lock-loss, and rollback failures remain fatal

- Updated model-visible Skill descriptions
  - Descriptions longer than 250 characters remain valid for import but are truncated in the Agent catalog
  - LibreChat logs a warning for each affected Skill, so trigger phrases should appear early

- Updated Agent Skill scoping and runtime authoring
  - **Enable skills** controls both Skill use and authoring, while **Use all skills** independently exposes the complete accessible catalog
  - An Agent with no selected Skills can remain authoring-only, creating Skills without receiving the existing catalog; creation and edits still enforce the user's Skill permissions

- Updated Agent step-limit handling
  - Reaching `recursionLimit` now preserves the partial response and tool history instead of replacing the turn with `GraphRecursionError`
  - The saved unfinished turn offers **Keep going** with a fresh step budget or **Answer now** without further tool use

- Updated bundled Skill file handling
  - Code and programmatic execution verify every mounted file reference against the current Skill version
  - Editing `SKILL.md` causes the complete bundle to be re-uploaded when any stored Code Interpreter reference is stale

- Updated `speech.speechTab` engine defaults
  - `engineSTT` accepts `browser` and `external`; legacy `openai` and `azureOpenAI` values normalize to `external`
  - `engineTTS` accepts `browser` and `external`; legacy provider values normalize to `external`
  - Saved legacy values are migrated before speech settings initialize, and unavailable external engines fall back to `browser`

- Added file upload runtime settings
  - `FILE_UPLOAD_SSE_ENABLED` keeps long-running uploads alive with SSE heartbeats
  - `REMOTE_FILE_FETCH_TIMEOUT_MS` limits server-side remote file download time
  - `REMOTE_FILE_FETCH_MAX_BYTES` limits server-side remote file download size
  - `FILE_USAGE_USER_MAX` and `FILE_USAGE_USER_WINDOW` limit queued-attachment TTL renewal requests separately from upload limits
  - Shell MIME variants `application/x-shellscript` and `text/x-shellscript` normalize to the canonical `application/x-sh` before endpoint allowlist checks
  - Rejected uploads now return their specific unsupported-file message and HTTP status instead of a generic server error
  - Multi-file selections skip individual duplicates and files over the per-file size limit while continuing with valid files; whole-batch count and total-size limits still reject the surviving batch together

- Expanded PowerPoint template handling
  - `.potx` files are recognized by their standard MIME type across uploads and SharePoint imports
  - PowerPoint templates can use file search, Code Interpreter, OCR, and inline presentation previews

- Added separate authentication token-submission rate limits
  - `RESET_PASSWORD_SUBMISSION_MAX` and `RESET_PASSWORD_SUBMISSION_WINDOW` limit password-reset token validation independently from reset-email requests
  - `VERIFY_EMAIL_SUBMISSION_MAX` and `VERIFY_EMAIL_SUBMISSION_WINDOW` limit verification-token validation independently from email resends
  - Added separate violation-score controls for both submission limiters

- Added Agent conversation control `STEER_MAX_LENGTH`
  - Caps the length of one mid-run steering message

- Moved ordinary Agent queued follow-ups to a server-owned lifecycle
  - Saved-Agent queues persist text, attachments, quoted excerpts, selected Skills, FIFO order, claims, and terminal failures in MongoDB across disconnects, app restarts, and replica handoffs
  - Queue delivery waits for the preceding response to settle; an aborted or failed predecessor leaves the affected turn actionable instead of admitting it silently
  - Each tenant, user, and conversation can hold up to 100 active queued turns; each turn accepts up to 16,000 characters and 10 files
  - Cancellation remains available until provider admission begins, while ambiguous admission is quarantined instead of replayed
  - A database-enforced admission boundary serializes each queue lane; ambiguous predecessor or mixed-version ownership remains **Awaiting reconciliation** instead of starting out of order
  - Current workers select the queued-turn capability automatically; older servers and startup windows without a generation epoch retain the client-side compatibility queue
  - **Interrupt & steer** remains on the live steering path and does not insert at the front of the durable FIFO queue

- Updated Agent event and background delivery configuration
  - Bound child continuations are automatic; detached Subagent and supported background-tool completions resume saved parent Agents by default
  - Added `endpoints.agents.backgroundTasks.completionWakeups`, which defaults to `true`; set it to `false` for poll-only background tools and Subagents
  - Removed `endpoints.agents.eventDriven.childTurns`, `completionWakeups`, `coalescing`, `actorMailbox`, `checkpointForks`, and `durableReceipts`; `eventDriven` now contains only optional `selfUrl`
  - Removed the legacy `ENABLE_AGENT_EVENT_CHILD_TURNS` and `ENABLE_SUBAGENT_COMPLETION_WAKEUPS` environment fallbacks
  - `endpoints.agents.eventDriven.selfUrl` overrides the bound listener only when trusted internal admission must traverse another HTTP origin; `AGENT_TRIGGERS_SELF_URL` remains its compatibility fallback
  - Added durable handling receipts, per-binding actor mailboxes, compatible checkpoint continuation with history fallback, and optional bounded coalescing for observational bound events
  - Added `expectedAction` verification: only host-observed matching tool evidence can produce an `applied` outcome
  - Bound Event Actors can durably pause for Ask User or tool approval; the exact signed suspension blocks the actor mailbox until it resumes or settles
  - Pause-capable Event Actors select compatible checkpoint continuation or durable-history reconstruction automatically; existing protocol-v1 work remains on history until it drains
  - Amazon DocumentDB maintenance uses a pure-inclusion projection for the legacy actor-receipt sweep; independent maintenance failures no longer suppress unrelated work, while lane reclamation still waits for successful batch-receipt recovery
  - Event Actor detached Action completion is automatic for built-in generation stores; in-memory execution is process-local, while Redis adds durable restart recovery and replica handoff
  - Ordinary background tools remain process-local while running; once a content-only result is persisted, completion delivery can continue on another replica, while live artifacts remain poll-only on the owning run
  - Open conversations attach to server-started automatic continuations after the preceding foreground submission settles, so harvested output and the resumed generation appear without a reload
  - Background invocations that ignore cancellation stop renewing their producer lease after a one-minute post-abort grace period; automatic delivery retires without falsely converting uncertain external work into a timeout
  - Event-child activity panels retain the current thread while a new delivery loads, render external triggers as normal user rows, and apply the shared per-item limits within a 64 KB activity budget so shortening notices reflect real omissions
  - The Subagent panel keeps one main-chat-shaped composer mounted across task deliveries, preserving focus and draft text while the new task's control state resolves
  - Submitting guidance steers by default; queue and interrupt remain available from the send control or touch-friendly icon controls, while an empty composer exposes task cancellation
  - After an eligible child settles, the same composer and draft can continue it in a new writable chat
  - The panel aligns its composer with main chat and lets child history scroll beneath a compact floating header
  - Removed the pre-release `AGENT_TRIGGERS_DETACHED_ACTIONS_PRODUCER_ENABLED` fence; operators no longer enable detached completion with an environment flag
  - A detached expected Action resumes the original actor only from durable terminal evidence; ambiguous launches are quarantined instead of replayed
  - `rateLimits.agentEvents.userMax` and `userWindowInMinutes` configure a separate API-key-principal ingress bucket, defaulting to 40 requests per minute
  - The Remote Agents API now exposes authenticated event admission, binding registration, and delivery-status endpoints; it does not expose an unauthenticated webhook

- Added experimental Scheduled Chats
  - `interface.schedules` is absent by default and must be added explicitly before the panel or engine is enabled
  - `use` and `create` seed the `SCHEDULES` role permissions; `maxPerUser`, `minIntervalMinutes`, `autoDisableAfterFailures`, and `fireConcurrency` configure runtime limits
  - `schedules: false` and `{ use: false }` are authoritative deployment-wide stops that configuration overrides cannot re-enable
  - `SCHEDULES_DISABLED=true` immediately blocks automatic and manual runs without deleting definitions
  - Multi-replica deployments require Redis-backed resumable streams; `SCHEDULES_SINGLE_PROCESS=true` is only for a truly single-process deployment without Redis
  - Pause-capable scheduled Agents always require Redis streams for shared action state and a durable shared checkpointer; MongoDB is the built-in default
  - Saved Agents can run hourly, daily, on weekdays, or weekly in the user's recorded timezone, with durable trigger delivery, overlap prevention, and failure-based auto-disable
  - `requireProject` requires each schedule to target a user-owned Chat Project; `projectId` pins the destination and implies that requirement
  - Project access is checked when a schedule is saved and fired; deleted or unavailable projects disable affected schedules
  - `maxPerUser` counts all existing definitions, including legacy records, and scheduled prompts are stored literally without composer-variable insertion

- Generation protocol v2 is selected automatically by current clients and built-in generation stores
  - Removed the pre-release `GENERATION_PROTOCOL_VERSION` setting; explicit and stored protocol-v1 jobs remain compatible until they drain
  - Rolling upgrades require every API and worker image to run `v0.8.8-rc1` or newer; Helm chart `2.0.8` selects a compatible default image, but custom overrides must meet the same floor
  - Older deployments must stop every old API and worker replica before starting the new image

  - Redundant server-name prefixes are stripped from model-facing MCP tool keys while server routing remains unchanged

- Updated OpenID credential placeholders for MCP headers

  - ID-token placeholders require a current ID token

  - Missing or expired credentials return an actionable `401` re-authentication error; credential headers are omitted when the request has no OpenID identity

  - `OPENID_REFRESH_BRIDGE_GRACE_MS` controls the short rotated-token recovery bridge and defaults to `60000` ms

- Hardened SAML and OpenID identity flows

  - `SAML_IDP_ISSUER` optionally pins the expected IdP entity ID and rejects missing or mismatched issuers

  - Exact trusted private host:port entries bypass the block without restricting public destinations
  - Literal private destinations remain blocked through a proxy unless exempted; proxied hostname egress remains the proxy's responsibility

- Added `webSearch.allowedAddresses`
  - Web search, scrape, and rerank connections now block private, loopback, link-local, and cloud-metadata destinations at connect time
  - The field exempts exact trusted private host:port services without becoming a public-host allowlist
  - Self-hosted SearXNG, Firecrawl, Jina, or compatible provider endpoints on private networks must be exempted

- Added `webSearch.searxngSearchOptions`
  - `engines` accepts a comma-separated string or list and defaults to `google,bing,duckduckgo`
  - `language`, `timeRange`, and `timeout` configure SearXNG query language, date range, and request timeout

- Added Keenable as a web-search provider and scraper
  - Search and page fetch work against public endpoints without an API key; `KEENABLE_API_KEY` raises rate limits
  - `KEENABLE_API_URL` overrides search and environment-only `KEENABLE_FETCH_URL` overrides page fetch
  - `keenableSearchOptions` configures result count, domain restriction, attribution title, and timeout
  - `keenableScraperOptions` configures attribution title and timeout
  - Pair Keenable search and scraping with `rerankerType: none` for a fully keyless stack

- Added `interface.feedback`
  - Defaults to `true`; setting it to `false` hides response feedback controls and rejects feedback writes

- Updated provider stream smoothing
  - OpenAI, custom, Anthropic, Google, Bedrock, and Agents SDK-backed streams use adaptive smoothing with a 25 ms target by default
  - Endpoint `streamRate` remains in effect when `endpoints.all` omits it, and an explicit `0` disables adaptive smoothing

- Removed published credential and search defaults
  - Blank `CREDS_KEY`, `CREDS_IV`, `JWT_SECRET`, and `JWT_REFRESH_SECRET` values generate temporary credentials, reusing `LIBRECHAT_TEMP_CREDENTIALS_PATH` when available
  - Startup now rejects the retired published `JWT_SECRET` and `JWT_REFRESH_SECRET` values from either the environment or temporary credentials file
  - Bundled Compose files persist `/app/data/.env.temp`; production and multi-replica deployments must still provide permanent shared values
  - `SEARCH` now defaults to `false` and `MEILI_MASTER_KEY` is blank so operators must opt in with a unique key

- Changed `secureImageLinks` to default to `true`
  - Local conversation images require an authenticated owner, while Agent, Assistant, and stored-user avatars follow their tenant and sharing policies
  - Authorization and effective-config lookup failures fail closed
  - Set `secureImageLinks: false` only as a compatibility opt-out for intentionally public local image URLs

- Added built-in API observability for Agent Events and shared-link publication
  - `agent_event_actor_receipt_operations_total` counts bounded receipt reads, settlements, replays, conflicts, and legacy backfills
  - Agent Event gauges report retained and expiry-eligible receipts, pending reconciliation count and age, and retry/dead deliveries
  - `share_link_rejections_total` counts create/update failures for an unpersisted branch tail or an empty persisted conversation

- Added `CONSOLE_LOG_LEVEL`
  - Accepts `error`, `warn`, `info`, `http`, `verbose`, `debug`, `activity`, `silly`, or `silent`; an explicit value overrides the `DEBUG_CONSOLE` fallback
  - Defaults to `info`, or `debug` when `DEBUG_CONSOLE=true`; invalid values fall back with a warning and `silent` disables console output
