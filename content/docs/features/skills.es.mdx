Las Skills son paquetes de instrucciones reutilizables para los agentes de LibreChat. Una skill se centra en un archivo `SKILL.md`: el frontmatter describe cuándo debe utilizarse la skill, y el cuerpo en markdown proporciona al agente el procedimiento, las reglas, los ejemplos o las referencias a seguir.

Las Skills son útiles para trabajos repetibles tales como:

- Aplicación de directrices de marca o escritura
- Siguiendo las listas de verificación de revisión interna
- Ejecución de un flujo de trabajo de investigación estándar
- Preparación de un flujo de trabajo de herramientas especializado
- Empaquetado de scripts, referencias y activos reutilizables con un archivo de instrucciones

LibreChat no incluye una biblioteca de habilidades. Cada habilidad proviene de su propia instancia: [escrita o cargada en la interfaz de usuario](#create-a-skill), [creada por un agente durante un chat](#runtime-skill-authoring), [montada desde el sistema de archivos](#deployment-skills) o [reflejada desde un repositorio de GitHub](#github-skill-sync).

## Habilitar Skills [#enable-skills]

La capacidad de agente `skills` está habilitada de forma predeterminada. Los administradores pueden eliminarla de la lista de capacidades del endpoint de agentes para ocultar Skills a los usuarios.

```yaml filename="librechat.yaml"
endpoints:
  agents:
    capabilities:
      - 'deferred_tools'
      - 'execute_code'
      - 'file_search'
      - 'web_search'
      - 'artifacts'
      - 'subagents'
      - 'actions'
      - 'context'
      - 'skills'
      - 'memory'
      - 'ask_user_question'
      - 'tools'
      - 'chain'
      - 'ocr'
```

Los permisos de rol controlan quién puede usar, crear, compartir y compartir públicamente skills. El uso y la creación de skills están permitidos de forma predeterminada; compartir y compartir públicamente están desactivados por defecto para los roles que no son de administrador. Los administradores pueden cambiar esto desde la configuración de administrador en el panel de Skills.

Si la funcionalidad está desactivada, o si tu rol carece del permiso de uso, Skills no aparecerá en absoluto en el panel lateral.

## Usar una Skill [#use-a-skill]

<Steps>
<Step>

**Open Skills** desde el panel lateral. El panel enumera las habilidades que posees y las habilidades compartidas contigo, con un cuadro de filtro para listas largas. Al seleccionar una habilidad se abre su página, donde puedes leer las instrucciones y explorar sus archivos incluidos.

</Step>
<Step>

**Comprueba que la skill esté disponible.** Cada skill tiene un interruptor de **Available to agent**. Las skills que posees y las skills de despliegue están disponibles de forma predeterminada; las skills compartidas siguen el valor predeterminado configurado por el administrador hasta que lo anules.

</Step>
<Step>

**Dale acceso al agente.** En el generador de agentes, activa **Enable skills**, luego decide si el agente ve el catálogo completo o solo las habilidades que tú elijas. Consulta [Agent Scope](#agent-scope).

</Step>
<Step>

**Invocar la skill.** Escriba `$` en el cuadro de mensaje y seleccione una skill por su nombre. No se inserta nada en el texto de su mensaje: la skill se pone en cola para ese turno y se muestra como una etiqueta (chip) sobre el compositor. El modelo también puede elegir una skill por sí mismo, y las skills con `always-apply` no requieren ninguna acción.

</Step>
</Steps>

## Crear una Skill [#create-a-skill]

Abre **Skills** desde el panel lateral y utiliza el botón **+**, el cual ofrece dos rutas:

- **Escribir instrucciones de skill** — un diálogo con un nombre, una descripción y el cuerpo de la instrucción.
- **Cargar una skill** — un archivo `.md`, `.zip` o `.skill` que contenga un `SKILL.md`.

Un agente también puede crear una skill para ti mientras trabaja, sin tener que pasar por este panel. Consulta [Runtime Skill Authoring](#runtime-skill-authoring).

`SKILL.md` mínimo:

```md filename="SKILL.md"
---
name: brand-guidelines
description: Use when writing public-facing content that must follow the company voice and terminology.
---

# Brand Guidelines

Write in a concise, practical tone.
Prefer active voice.
Use product terminology consistently.
```

Las claves se comparan sin distinguir entre mayúsculas y minúsculas, y los campos booleanos solo aceptan `true` o `false`. Eliminar una clave booleana en un guardado posterior la borra, por lo que eliminar `disable-model-invocation` restaura la invocación del modelo.

Los campos de frontmatter reconocidos son validados por tipo. Los campos no reconocidos se conservan como metadatos delimitados y seguros para JSON en lugar de invalidar el Skill; los valores de extensión excesivamente grandes o profundamente anidados siguen siendo rechazados.

Mantenga la `description` de una Skill invocada por un modelo en 250 caracteres o menos y coloque sus frases de activación más importantes al principio. Las descripciones más largas aún pueden importarse, pero LibreChat las trunca en el catálogo visible para el modelo y registra una advertencia nombrando cada Skill afectada.

### Límites de nombres y tamaño [#naming-and-size-limits]

- `name` es obligatorio, debe coincidir con `^[a-z0-9][a-z0-9-]*$` y está limitado a 64 caracteres. Debe ser único entre tus propias habilidades; volver a subir un nombre existente fallará con un error de conflicto en lugar de sobrescribirlo.
- Los nombres no pueden comenzar con `anthropic-` o `claude-`, y no pueden ser exactamente `help`, `clear`, `compact`, `model`, `exit`, `quit`, `settings`, `anthropic` o `claude`. Esos nombres ocultarían comandos reales.
- `description` es obligatorio y está limitado a 1024 caracteres. Las descripciones de menos de 20 caracteres se aceptan con una advertencia, ya que rara vez se activan de forma fiable.
- El cuerpo de la instrucción está limitado a 100,000 caracteres.

### Cargar un Bundle [#upload-a-bundle]

Un archivo `.zip` o `.skill` debe contener `SKILL.md` en la raíz del archivo o exactamente en una carpeta de profundidad. Una única carpeta contenedora se elimina al importar; las estructuras más profundas no son detectadas.

    <FileTree.File name="SKILL.md" />
    <FileTree.Folder name="references" defaultOpen>
      <FileTree.File name="tone-examples.md" />
    </FileTree.Folder>
    <FileTree.Folder name="scripts">
      <FileTree.File name="lint-copy.py" />
    </FileTree.Folder>
  </FileTree.Folder>
</FileTree>

Límites de importación:

- Extensiones aceptadas: `.md`, `.zip`, `.skill`.
- 50 MB por carga de forma predeterminada. Los administradores pueden cambiar esto con [`fileConfig.skills.fileSizeLimit`](/docs/configuration/librechat_yaml/object_structure/file_config#skills) en `librechat.yaml`.
- Hasta 500 entradas por archivo, y 10 MB por archivo empaquetado.
- Una carga de `.md` sin `name` en el frontmatter deriva el nombre de la habilidad a partir del nombre del archivo.
- Las entradas con rutas no seguras, como las de recorrido o rutas absolutas, se notifican como errores y se omiten; el resto de la skill se sigue importando.

Las habilidades que provienen de `DEPLOYMENT_SKILLS_DIR` o de la sincronización de habilidades de GitHub son de solo lectura. Solo las habilidades creadas dentro de LibreChat pueden editarse en la interfaz de usuario.

## Modos de invocación [#invocation-modes]

Las Skills pueden llegar a un agente de tres maneras:

- **Manual**: el usuario escribe `$` en el chat y selecciona una habilidad desde el menú emergente.
- **Model-invoked**: el modelo elige una habilidad del catálogo de habilidades inyectado y llama a la herramienta de habilidad.
- **Always apply**: la habilidad se prepara en cada turno cuando está activa.

Lo que realmente entra en el contexto difiere según la ruta:

- El catálogo invocado por el modelo solo contiene nombres y descripciones, hasta 100 habilidades, con cada entrada recortada a aproximadamente 250 caracteres. Los cuerpos de las instrucciones no forman parte del catálogo.
- La invocación manual y la de aplicación siempre preparan el cuerpo completo de `SKILL.md` para ese turno, hasta 10 habilidades manuales y 20 de aplicación siempre, y 30 combinadas. Cuando se supera el límite combinado, las habilidades de aplicación siempre se eliminan primero para que la intención explícita del usuario prevalezca.

La invocación manual es una intención explícita del usuario. Puede utilizar habilidades que están ocultas para la invocación del modelo con `disable-model-invocation: true`, siempre y cuando `user-invocable` no sea false.

## Alcance del Agente [#agent-scope]

Los Agents deben tener **Enable skills** activado antes de que puedan usar o crear Skills. El interruptor independiente **Use all skills** controla la exposición en el catálogo.

- **All:** active **Use all skills** para exponer el catálogo completo y activo visible para el usuario, incluyendo los Skills añadidos posteriormente.
- **Seleccionado:** deje **Use all skills** desactivado y añada Skills individuales para exponer solo esas entradas.
- **Solo para la creación:** deje **Use all skills** desactivado sin Skills seleccionadas. Las entradas de catálogo existentes no se exponen, pero el agente puede crear una Skill durante una conversación cuando el usuario tiene permiso para crear Skills.
- **Deshabilitado:** desactive **Enable skills** para deshabilitar tanto el uso del catálogo como la creación en tiempo de ejecución.

Esto permite a los administradores exponer la función Skills globalmente mientras mantienen enfocado el conjunto de habilidades utilizables de cada agente.

Desactivar **Use all skills** restaura la selección que estaba activa antes de que se habilitara el interruptor. Los agentes existentes conservan el comportamiento heredado donde las Skills habilitadas sin un alcance explícito significan el catálogo completo.

## Creación de habilidades en tiempo de ejecución [#runtime-skill-authoring]

Un agente con Skills habilitadas puede crear o editar archivos de Skill reutilizables mientras trabaja. Los archivos en tiempo de ejecución utilizan el mismo espacio de nombres `skills/{skillName}/...` que los paquetes cargados, por lo que el agente puede crear `SKILL.md` y referencias, scripts o activos de soporte como parte de un flujo de trabajo exitoso.

La creación sigue el modelo de permisos de Skills normal:

- Crear una nueva Skill requiere el permiso de **Creación** de Skill del usuario.
- Editar una Skill existente requiere tanto acceso de edición como su inclusión en el alcance del catálogo activo del agente; las Skills desplegadas y sincronizadas con GitHub permanecen como de solo lectura.
- Un agente de solo creación puede crear una nueva Skill sin recibir el catálogo existente del usuario.

La creación en tiempo de ejecución (runtime authoring) no omite la capacidad de despliegue ni los permisos de usuario. Eliminar `skills` de las capacidades del endpoint de Agents oculta la función, y desactivar **Enable skills** en el agente deshabilita sus herramientas de creación.

## Habilidades activas y compartidas [#active-and-shared-skills]

Los usuarios pueden activar o desactivar las habilidades con el interruptor **Available to agent**. Las habilidades propias y de despliegue están activas de forma predeterminada. Las habilidades compartidas utilizan el valor predeterminado configurado por el administrador hasta que el usuario las anule.

Las habilidades inactivas se excluyen de:

- El popover `$`
- El catálogo de habilidades invocadas por el modelo
- Aplicar siempre el priming

Compartir una skill otorga acceso de visor, editor o propietario a usuarios, grupos o roles específicos a través del diálogo de compartir estándar, y requiere el permiso de compartir en su rol. Consulte [Access Control](/docs/features/access_control) para ver el modelo completo.

## Archivos incluidos [#bundled-files]

Los paquetes de habilidades cargados pueden incluir archivos junto con `SKILL.md`, tales como:

- `references/...`
- `scripts/...`
- `assets/...`

El backend almacena esos archivos con la skill. El agente puede resolver los archivos de la skill cuando esta está activa y dentro del alcance. Los archivos anidados mantienen sus rutas relativas y se direccionan a través del espacio de nombres `skills/{skillName}/...` orientado al modelo. En el visor de Skills, los enlaces Markdown relativos se resuelven desde el archivo actual y abren el archivo referenciado dentro de la misma Skill. Cuando Code Interpreter está habilitado, los mismos archivos se montan en `/mnt/data/skills/{skillName}/...` para que las operaciones de shell y código puedan utilizarlos directamente. Editar `SKILL.md` hace avanzar la versión de la Skill; antes de la ejecución de código o la ejecución programática, LibreChat verifica que cada referencia de archivo montado coincida con esa versión y vuelve a cargar el paquete completo cuando alguna referencia está desactualizada.

La página de una skill también tiene un árbol de archivos con acciones para **New File**, **New Folder** y **Upload File**, con un límite de hasta 10 MB por archivo añadido. `SKILL.md` está reservado allí: edite el cuerpo de la skill en su lugar.

<Callout type="note" title="Consejo de autoría">
  Mantén la `description` específica. Es la señal más fuerte para las habilidades invocadas por el modelo. Una descripción corta o vaga provocará una activación insuficiente.
</Callout>

## Habilidades de despliegue [#deployment-skills]

Los administradores pueden implementar Skills de solo lectura desde el sistema de archivos con `DEPLOYMENT_SKILLS_DIR`.

```bash filename=".env"
DEPLOYMENT_SKILLS_DIR=./skill
```

El directorio predeterminado es `./skill` en la raíz del proyecto. Cada skill reside en su propio subdirectorio que contiene un `SKILL.md`, junto con cualquier archivo incluido. LibreChat carga las Skills de despliegue al inicio y las expone a los usuarios que tienen habilitada la capacidad de Skills.

Habilidades de despliegue:

- Son de solo lectura en la interfaz de usuario
- Utilice `deployment` como su fuente
- Tienen prioridad sobre las Skills persistentes con el mismo nombre
- Requiere un reinicio de LibreChat después de que los archivos sean añadidos, eliminados o modificados

Los [Agent Plugins](/docs/features/agent_plugins) experimentales también pueden agrupar Skills de despliegue de solo lectura junto con servidores MCP relacionados. Una Skill en el directorio de despliegue independiente tiene prioridad sobre una Skill de plugin con el mismo nombre.

## Sincronización de habilidades de GitHub [#github-skill-sync]

Los administradores pueden replicar Skills desde repositorios de GitHub con `skillSync.github` en `librechat.yaml`. Esta es la forma práctica de compartir un conjunto seleccionado de skills en todo un equipo.

```yaml filename="librechat.yaml"
skillSync:
  github:
    enabled: true
    intervalMinutes: 60
    runOnStartup: true
    sources:
      - id: librechat-skills
        owner: your-org
        repo: your-skills-repo
        ref: main
        paths:
          - skills
        skillDiscoveryDepth: 2
        token: '${GITHUB_SKILLS_TOKEN}'
```

Sincronización de habilidades de GitHub:

- Escanea las rutas del repositorio configuradas en busca de `SKILL.md`
- Trata el directorio que contiene cada `SKILL.md` como una raíz de habilidad, dentro de los niveles `skillDiscoveryDepth` de la ruta configurada
- Importa archivos incluidos junto a cada skill
- Almacena Skills reflejadas con `source: "github"`
- Actualiza las Skills reflejadas cuando el repositorio upstream cambia
- Elimina las Skills reflejadas que ya no existen en la fuente configurada
- Publica Skills válidas incluso cuando otra Skill en la fuente no es válida o entra en conflicto
- Informa a los administradores sobre ejecuciones parcialmente exitosas y detalles de las Skill omitidas delimitadas
- Admite ejecuciones programadas, al inicio y activadas manualmente por el administrador

Una Skill omitida mantiene su última réplica conocida como válida cuando existe una. Los fallos a nivel de fuente, tales como la autenticación, la limitación de tasa (rate limiting), la pérdida de propiedad de sincronización o una reversión fallida, siguen provocando el fallo de la ejecución completa de la fuente.

Utilice un personal access token de GitHub de grano fino con permisos de solo lectura para Contents y Metadata para el repositorio seleccionado. Consulte [Skill Sync Object Structure](/docs/configuration/librechat_yaml/object_structure/skill_sync) para ver todos los campos, opciones de credenciales, alcance de inquilino (tenant scoping) y endpoints de sincronización de administrador.
