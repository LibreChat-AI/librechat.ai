Las Skills son paquetes de instrucciones reutilizables para los agentes de LibreChat. Una skill se centra en un archivo `SKILL.md`: el frontmatter describe cuándo debe utilizarse la skill, y el cuerpo en markdown proporciona al agente el procedimiento, las reglas, los ejemplos o las referencias a seguir.

Las Skills son útiles para trabajos repetibles tales como:

- Aplicación de directrices de marca o escritura
- Siguiendo las listas de verificación de revisión interna
- Ejecución de un flujo de trabajo de investigación estándar
- Preparación de un flujo de trabajo de herramientas especializado
- Empaquetado de scripts, referencias y activos reutilizables con un archivo de instrucciones

## Habilitar Skills [#enable-skills]

La capacidad de agente `skills` está habilitada de forma predeterminada. Los administradores pueden eliminarla de la lista de capacidades del endpoint de agentes para ocultar Skills a los usuarios.

```yaml filename="librechat.yaml"
endpoints:
  agents:
    capabilities:
      - 'deferred_tools'
      - 'execute_code'
      - 'file_search'
      - 'web_search'
      - 'artifacts'
      - 'subagents'
      - 'actions'
      - 'context'
      - 'skills'
      - 'memory'
      - 'ask_user_question'
      - 'tools'
      - 'chain'
      - 'ocr'
```

Los permisos de rol también controlan quién puede usar, crear, compartir y compartir públicamente habilidades.

## Habilidades de despliegue [#deployment-skills]

Los administradores pueden implementar Skills de solo lectura desde el sistema de archivos con `DEPLOYMENT_SKILLS_DIR`.

```bash filename=".env"
DEPLOYMENT_SKILLS_DIR=./skill
```

El directorio predeterminado es `./skill` en la raíz del proyecto. LibreChat carga los Skills de despliegue al inicio y los expone a los usuarios que tienen habilitada la capacidad de Skills.

Habilidades de despliegue:

- Son de solo lectura en la interfaz de usuario
- Utilice `deployment` como su fuente
- Tienen prioridad sobre las Skills persistentes con el mismo nombre
- Requiere un reinicio de LibreChat después de que los archivos sean añadidos, eliminados o modificados

Los [Agent Plugins](/docs/features/agent_plugins) experimentales también pueden agrupar Skills de despliegue de solo lectura junto con servidores MCP relacionados. Una Skill en el directorio de despliegue independiente tiene prioridad sobre una Skill de plugin con el mismo nombre.

## Sincronización de habilidades de GitHub [#github-skill-sync]

Los administradores pueden replicar Skills desde repositorios de GitHub con `skillSync.github` en `librechat.yaml`.

```yaml filename="librechat.yaml"
skillSync:
  github:
    enabled: true
    intervalMinutes: 60
    runOnStartup: true
    sources:
      - id: librechat-skills
        owner: your-org
        repo: your-skills-repo
        ref: main
        paths:
          - skills
        skillDiscoveryDepth: 2
        token: '${GITHUB_SKILLS_TOKEN}'
```

Sincronización de habilidades de GitHub:

- Escanea las rutas del repositorio configuradas en busca de `SKILL.md`
- Importa archivos incluidos junto a cada skill
- Almacena Skills reflejadas con `source: "github"`
- Actualiza las Skills reflejadas cuando el repositorio upstream cambia
- Elimina las Skills reflejadas que ya no existen en la fuente configurada
- Publica Skills válidas incluso cuando otra Skill en la fuente no es válida o entra en conflicto
- Informa a los administradores sobre ejecuciones parcialmente exitosas y detalles de las Skill omitidas delimitadas
- Admite ejecuciones programadas, al inicio y activadas manualmente por el administrador

Una Skill omitida mantiene su última réplica conocida como válida cuando existe una. Los fallos a nivel de fuente, tales como la autenticación, la limitación de tasa (rate limiting), la pérdida de propiedad de sincronización o una reversión fallida, siguen provocando el fallo de la ejecución completa de la fuente.

Utilice un personal access token de GitHub de grano fino con permisos de solo lectura para Contents y Metadata para el repositorio seleccionado. Consulte [Skill Sync Object Structure](/docs/configuration/librechat_yaml/object_structure/skill_sync) para ver todos los campos, opciones de credenciales, alcance de inquilino (tenant scoping) y endpoints de sincronización de administrador.

## Crear una Skill [#create-a-skill]

Abre **Skills** desde el panel lateral. Puedes escribir una skill directamente en LibreChat o subir un archivo `.md`, `.zip` o `.skill` que contenga `SKILL.md`.

`SKILL.md` mínimo:

```md filename="SKILL.md"
---
name: brand-guidelines
description: Use when writing public-facing content that must follow the company voice and terminology.
---

# Brand Guidelines

Write in a concise, practical tone.
Prefer active voice.
Use product terminology consistently.
```

Mantenga la `description` de una Skill invocada por un modelo en 250 caracteres o menos y coloque sus frases de activación más importantes al principio. ## Modos de invocación [#invocation-modes]

Las Skills pueden llegar a un agente de tres maneras:

- **Manual**: el usuario escribe `$` en el chat y selecciona una habilidad desde el menú emergente.
- **Model-invoked**: el modelo elige una habilidad del catálogo de habilidades inyectado y llama a la herramienta de habilidad.
- **Always apply**: la habilidad se prepara en cada turno cuando está activa.

La invocación manual es una intención explícita del usuario. Puede utilizar habilidades que están ocultas para la invocación del modelo con `disable-model-invocation: true`, siempre y cuando `user-invocable` no sea false.

## Alcance del Agente [#agent-scope]

Los Agents deben tener **Enable skills** activado antes de que puedan usar o crear Skills. El interruptor independiente **Use all skills** controla la exposición en el catálogo.

- **All:** active **Use all skills** para exponer el catálogo completo y activo visible para el usuario, incluyendo los Skills añadidos posteriormente.
- **Seleccionado:** deje **Use all skills** desactivado y añada Skills individuales para exponer solo esas entradas.
- **Solo para la creación:** deje **Use all skills** desactivado sin Skills seleccionadas. Las entradas de catálogo existentes no se exponen, pero el agente puede crear una Skill durante una conversación cuando el usuario tiene permiso para crear Skills.
- **Deshabilitado:** desactive **Enable skills** para deshabilitar tanto el uso del catálogo como la creación en tiempo de ejecución.

Esto permite a los administradores exponer la función Skills globalmente mientras mantienen enfocado el conjunto de habilidades utilizables de cada agente.

Desactivar **Use all skills** restaura la selección que estaba activa antes de que se habilitara el interruptor. Los agentes existentes conservan el comportamiento heredado donde las Skills habilitadas sin un alcance explícito significan el catálogo completo.

## Creación de habilidades en tiempo de ejecución [#runtime-skill-authoring]

Un agente con Skills habilitadas puede crear o editar archivos de Skill reutilizables mientras trabaja. Los archivos en tiempo de ejecución utilizan el mismo espacio de nombres `skills/{skillName}/...` que los paquetes cargados, por lo que el agente puede crear `SKILL.md` y referencias, scripts o activos de soporte como parte de un flujo de trabajo exitoso.

La creación sigue el modelo de permisos de Skills normal:

- Crear una nueva Skill requiere el permiso de **Creación** de Skill del usuario.
- Editar una Skill existente requiere tanto acceso de edición como su inclusión en el alcance del catálogo activo del agente; las Skills desplegadas y sincronizadas con GitHub permanecen como de solo lectura.
- Un agente de solo creación puede crear una nueva Skill sin recibir el catálogo existente del usuario.

La creación en tiempo de ejecución (runtime authoring) no omite la capacidad de despliegue ni los permisos de usuario. Eliminar `skills` de las capacidades del endpoint de Agents oculta la función, y desactivar **Enable skills** en el agente deshabilita sus herramientas de creación.

## Habilidades activas y compartidas [#active-and-shared-skills]

Los usuarios pueden activar o desactivar las habilidades. Las habilidades propias y de despliegue están activas de forma predeterminada. Las habilidades compartidas utilizan el valor predeterminado configurado por el administrador hasta que el usuario las anula.

Las habilidades inactivas se excluyen de:

- El popover `$`
- El catálogo de habilidades invocadas por el modelo
- Aplicar siempre el priming

## Archivos incluidos [#bundled-files]

Los paquetes de habilidades cargados pueden incluir archivos junto con `SKILL.md`, tales como:

- `references/...`
- `scripts/...`
- `assets/...`

El backend almacena esos archivos con la skill. El agente puede resolver los archivos de la skill cuando esta está activa y dentro del alcance. Los archivos anidados mantienen sus rutas relativas y se direccionan a través del espacio de nombres `skills/{skillName}/...` orientado al modelo. En el visor de Skills, los enlaces Markdown relativos se resuelven desde el archivo actual y abren el archivo referenciado dentro de la misma Skill. Cuando Code Interpreter está habilitado, los mismos archivos se montan en `/mnt/data/skills/{skillName}/...` para que las operaciones de shell y código puedan utilizarlos directamente. Editar `SKILL.md` hace avanzar la versión de la Skill; antes de la ejecución de código o la ejecución programática, LibreChat verifica que cada referencia de archivo montado coincida con esa versión y vuelve a cargar el paquete completo cuando alguna referencia está desactualizada.

<Callout type="note" title="Consejo de autoría">
  Mantén la `description` específica. Es la señal más fuerte para las habilidades invocadas por el modelo. Una descripción corta o vaga provocará una activación insuficiente.
</Callout>
