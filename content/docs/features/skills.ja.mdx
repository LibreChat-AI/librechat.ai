---

Skillsは、LibreChatのAgent向けの再利用可能な命令バンドルです。Skillは`SKILL.md`ファイルを中心に構成されます。フロントマターにはそのSkillをいつ使用すべきかが記述され、Markdown本文にはAgentが従うべき手順、ルール、例、または参照情報が記載されます。

Skillsは、以下のような反復的な作業に役立ちます：

- ブランドやライティングガイドラインの適用
- 内部レビューチェックリストに従う
- 標準的なリサーチワークフローの実行
- 専門的なツールワークフローの準備
- 再利用可能なスクリプト、リファレンス、およびアセットを指示ファイルと共にパッケージ化する

LibreChatにはスキルライブラリは付属していません。すべてのスキルは、ご自身のインスタンスから提供されます：[UI上で作成またはアップロード](#create-a-skill)、[チャット中にエージェントによって作成](#runtime-skill-authoring)、[ファイルシステムからマウント](#deployment-skills)、または[GitHubリポジトリからミラーリング](#github-skill-sync)のいずれかとなります。

## スキルを有効にする [#enable-skills]

`skills` エージェント機能はデフォルトで有効になっています。管理者は、ユーザーからSkillsを非表示にするために、agents エンドポイントの機能リストからそれを削除することができます。

```yaml filename="librechat.yaml"
endpoints:
  agents:
    capabilities:
      - 'deferred_tools'
      - 'execute_code'
      - 'file_search'
      - 'web_search'
      - 'artifacts'
      - 'subagents'
      - 'actions'
      - 'context'
      - 'skills'
      - 'memory'
      - 'ask_user_question'
      - 'tools'
      - 'chain'
      - 'ocr'
```

ロール権限は、誰がスキルを使用、作成、共有、および公開共有できるかを制御します。スキルの使用と作成はデフォルトで許可されていますが、共有と公開共有は管理者以外のロールではデフォルトでオフになっています。管理者は、Skillsパネルの管理者設定からこれらを変更できます。

機能が無効になっている場合、またはあなたのロールに使用権限がない場合、サイドパネルにSkillsは一切表示されません。

## スキルを使用する [#use-a-skill]

<Steps>
<Step>

サイドパネルから **Open Skills** を選択します。パネルには、自身が所有するスキルと共有されたスキルが一覧表示され、長いリスト用にフィルターボックスも用意されています。スキルを選択するとそのページが開き、指示を読んだり、バンドルされているファイルを閲覧したりできます。

</Step>
<Step>

**スキルが利用可能であることを確認してください。** 各スキルには **Available to agent** スイッチがあります。自身が所有するスキルおよびデプロイされたスキルはデフォルトで利用可能に設定されています。共有スキルは、オーバーライドしない限り、管理者が設定したデフォルトに従います。

</Step>
<Step>

**エージェントにアクセス権を付与します。** エージェントビルダーで **Enable skills** をオンにし、エージェントがカタログ全体を参照するか、選択したスキルのみを参照するかを決定します。 [Agent Scope](#agent-scope) を参照してください。

</Step>
<Step>

**スキルの呼び出し。** メッセージボックスに `$` と入力し、名前でスキルを選択します。メッセージテキストには何も挿入されません。スキルはそのターン用にキューに入れられ、コンポーザーの上にチップとして表示されます。モデルが独自にスキルを選択することも可能で、`always-apply` スキルの場合は操作は一切不要です。

</Step>
</Steps>

## スキルを作成する [#create-a-skill]

サイドパネルから **Skills** を開き、**+** ボタンを使用します。これには2つの方法があります：

- **スキル指示の作成** — 名前、説明、指示本文を含むダイアログです。
- **スキルのアップロード** — `SKILL.md` を含む `.md`、`.zip`、または `.skill` ファイル。

エージェントは、このパネルを経由することなく、作業中にスキルを作成することもできます。[Runtime Skill Authoring](#runtime-skill-authoring) を参照してください。

最小限の `SKILL.md`:

```md filename="SKILL.md"
---
name: brand-guidelines
description: Use when writing public-facing content that must follow the company voice and terminology.
---

# Brand Guidelines

Write in a concise, practical tone.
Prefer active voice.
Use product terminology consistently.
```

キーは大小文字を区別せずに照合され、ブール値フィールドは `true` または `false` のみを受け付けます。後の保存でブール値キーを削除するとその設定はクリアされるため、`disable-model-invocation` を削除するとモデルの呼び出しが復元されます。

認識されたfrontmatterフィールドは型チェックされます。認識されないフィールドは、Skillを無効にするのではなく、境界のあるJSONセーフなメタデータとして保持されます。ただし、深くネストされた値や過度に大きな拡張値は引き続き拒否されます。

モデルが呼び出すスキルの `description` は250文字以内に抑え、最も重要なトリガーフレーズを先頭に配置してください。これより長い説明文もインポート自体は可能ですが、LibreChatはモデルから見えるカタログ内でそれらを切り詰め、影響を受ける各スキル名をログに警告として出力します。

### 名前とサイズ制限 [#naming-and-size-limits]

- `name` は必須であり、`^[a-z0-9][a-z0-9-]*$` に一致する必要があり、64文字までに制限されています。これは自身のスキル内で一意である必要があります。既存の名前を再アップロードすると、上書きされるのではなく、競合エラーが発生します。
- 名前は `anthropic-` または `claude-` で始めることはできず、`help`、`clear`、`compact`、`model`、`exit`、`quit`、`settings`、`anthropic`、または `claude` と完全に一致することもできません。これらの名前は実際のコマンドと競合（シャドウイング）するためです。
- `description` は必須であり、1024文字までに制限されています。20文字未満の記述も警告付きで受け入れられますが、その場合、確実にトリガーされることは稀です。
- 指示本文は100,000文字までに制限されています。

### バンドルをアップロードする [#upload-a-bundle]

`.zip` または `.skill` アーカイブには、アーカイブのルート、またはルートから1階層下のフォルダ内に `SKILL.md` が含まれている必要があります。単一のラップ用フォルダはインポート時に削除されますが、それより深い階層のレイアウトは検出されません。

<FileTree>
  <FileTree.Folder name="brand-guidelines" defaultOpen>
    <FileTree.File name="SKILL.md" />
    <FileTree.Folder name="references" defaultOpen>
      <FileTree.File name="tone-examples.md" />
    </FileTree.Folder>
    <FileTree.Folder name="scripts">
      <FileTree.File name="lint-copy.py" />
    </FileTree.Folder>
  </FileTree.Folder>
</FileTree>

インポート制限:

- 許可されている拡張子: `.md`, `.zip`, `.skill`。
- デフォルトではアップロードごとに 50 MB です。管理者は `librechat.yaml` 内の [`fileConfig.skills.fileSizeLimit`](/docs/configuration/librechat_yaml/object_structure/file_config#skills) でこれを変更できます。
- アーカイブごとに最大500エントリー、バンドルされたファイルごとに最大10 MBまで。
- フロントマターに `name` が含まれていない `.md` アップロードは、ファイル名からスキル名を導出します。
- トラバーサルパスや絶対パスなどの安全でないパスを含むエントリはエラーとして報告されスキップされますが、残りのスキルは引き続きインポートされます。

`DEPLOYMENT_SKILLS_DIR` または GitHub Skill Sync から読み込まれたスキルは読み取り専用です。LibreChat 内で作成されたスキルのみが、UI 上で編集可能です。

## 呼び出しモード (Invocation Modes) [#invocation-modes]

Skillsは、以下の3つの方法でエージェントに到達できます：

- **Manual**: ユーザーがチャットで `$` を入力し、ポップオーバーからスキルを選択します。
- **Model-invoked**: モデルが注入されたスキルカタログからスキルを選択し、スキルツールを呼び出します。
- **Always apply**: 有効な場合、そのスキルはすべてのターンでプライミング（準備）されます。

実際にコンテキストに入る内容はパスによって異なります：

- モデルが呼び出すカタログには名前と説明のみが含まれ、最大100個のスキルを保持し、各エントリは約250文字にトリミングされます。指示本文はカタログの一部ではありません。
- 手動および常に適用（always-apply）の呼び出しは、そのターンのために完全な `SKILL.md` 本文を準備します。手動スキルは最大10個、常に適用スキルは最大20個まで、合計で最大30個までとなります。合計の上限を超えた場合、ユーザーの明示的な意図が優先されるよう、常に適用スキルから先に除外されます。

手動呼び出しは、明示的なユーザーの意図によるものです。`user-invocable` が false でない限り、`disable-model-invocation: true` でモデル呼び出しから隠されているスキルを使用することができます。

## Agent Scope [#agent-scope]

AgentsがSkillsを使用または作成するには、事前に **Enable skills** をオンにする必要があります。個別の **Use all skills** スイッチは、カタログへの公開を制御します。

- **すべて:** **すべてのスキルを使用**をオンにすると、後から追加されたスキルを含む、ユーザーが利用可能なすべてのアクティブなカタログが公開されます。
- **選択済み:** **Use all skills** をオフにし、個別の Skills を追加して、それらのエントリのみを公開します。
- **作成のみ:** **すべてのスキルを使用 (Use all skills)** をオフにし、スキルを選択しない状態にします。既存のカタログエントリは公開されませんが、ユーザーがスキル作成権限を持っている場合、エージェントは会話中にスキルを作成できます。
- **無効:** **Enable skills** をオフにすると、カタログの使用とランタイムオーサリングの両方が無効になります。

これにより、管理者はSkills機能をグローバルに公開しつつ、各エージェントが使用可能なスキルセットを絞り込むことができます。

**Use all skills** をオフにすると、スイッチが有効になる前にアクティブだった選択状態が復元されます。既存のエージェントは、明示的なスコープなしで有効化されたスキルがカタログ全体を意味するという従来の動作を保持します。

## Runtime Skill Authoring [#runtime-skill-authoring]

Skillsが有効なエージェントは、作業中に再利用可能なSkillファイルを新規作成または編集できます。ランタイムファイルはアップロードされたバンドルと同じ `skills/{skillName}/...` 名前空間を使用するため、エージェントはワークフローを成功させる過程で `SKILL.md` や、それをサポートする参照、スクリプト、アセットを作成できます。

Authoringは、通常のSkills権限モデルに従います。

- 新しいSkillを作成するには、ユーザーのSkill **Create** 権限が必要です。
- 既存のSkillを編集するには、編集権限とエージェントのアクティブなカタログスコープへの含まれていることの両方が必要です。デプロイ済みおよびGitHub同期済みのSkillは読み取り専用のままとなります。
- 作成専用（authoring-only）のエージェントは、ユーザーの既存のカタログを受け取ることなく、新しいSkillを作成できます。

ランタイムでのオーサリングは、デプロイ機能やユーザー権限をバイパスするものではありません。Agents エンドポイントの機能から `skills` を削除するとこの機能は非表示になり、エージェントの **Enable skills** をオフにすると、そのオーサリングツールが無効になります。

## アクティブおよび共有スキル [#active-and-shared-skills]

ユーザーは **Available to agent** スイッチを使用して、スキルを有効または無効に切り替えることができます。所有スキルおよびデプロイ済みスキルはデフォルトで有効になっています。共有スキルは、ユーザーが上書きするまで、管理者が設定したデフォルト値が使用されます。

非アクティブなスキルは以下から除外されます：

- `$` ポップオーバー
- モデルが呼び出すスキルカタログ
- 常に適用されるプライミング

スキルを共有すると、標準の共有ダイアログを通じて特定のユーザー、グループ、またはロールに対して閲覧者、編集者、または所有者のアクセス権を付与できます。これには、ご自身のロールに共有権限が必要です。詳細なモデルについては、[Access Control](/docs/features/access_control) を参照してください。

## Bundled Files [#bundled-files]

アップロードされたスキルバンドルには、`SKILL.md` に加えて以下のようなファイルを含めることができます。

- `references/...`
- `scripts/...`
- `assets/...`

バックエンドはそれらのファイルをスキルと共に保存します。エージェントは、スキルがアクティブでスコープ内にある場合にスキルファイルを解決できます。ネストされたファイルは相対パスを保持し、モデル向けの `skills/{skillName}/...` 名前空間を通じてアドレス指定されます。スキルビューアでは、相対的なMarkdownリンクは現在のファイルから解決され、参照されたファイルが同じスキル内で開かれます。Code Interpreterが有効な場合、同じファイルが `/mnt/data/skills/{skillName}/...` にマウントされるため、シェルやコード操作で直接使用できます。`SKILL.md` を編集するとスキルバージョンが進みます。コードやプログラムによる実行の前に、LibreChatはマウントされたすべてのファイル参照がそのバージョンと一致していることを検証し、参照が古い場合は完全なバンドルを再アップロードします。

スキルのページには、**New File**、**New Folder**、**Upload File**のアクションを備えたファイルツリーもあり、1ファイルあたり最大10 MBまで追加可能です。`SKILL.md`自体は予約されているため、スキルの本文を編集してください。

<Callout type="note" title="作成のヒント">
  `description` は具体的に記述してください。これはモデルがスキルを呼び出すための最も強力なシグナルとなります。説明が短すぎたり曖昧だったりすると、トリガーがうまく機能しません。
</Callout>

## デプロイのスキル [#deployment-skills]

管理者は `DEPLOYMENT_SKILLS_DIR` を使用して、ファイルシステムから読み取り専用の Skills を配布できます。

```bash filename=".env"
DEPLOYMENT_SKILLS_DIR=./skill
```

ディレクトリのデフォルトはプロジェクトルートの `./skill` です。各Skillは、`SKILL.md` を含む独自のサブディレクトリに配置され、関連するファイルもその横に格納されます。LibreChatは起動時にデプロイされたSkillを読み込み、Skills機能が有効になっているユーザーに対してそれらを提供します。

デプロイスキル:

- UI上で読み取り専用です
- `deployment` をソースとして使用します
- 同じ名前の永続化されたSkillsよりも優先されます
- ファイルが追加、削除、または変更された後は、LibreChatの再起動が必要です。

実験的な [Agent Plugins](/docs/features/agent_plugins) は、読み取り専用のデプロイメント Skill を関連する MCP サーバーとまとめてバンドルすることもできます。スタンドアロンのデプロイメントディレクトリにある Skill は、同じ名前を持つプラグイン Skill よりも優先されます。

## GitHub Skill Sync [#github-skill-sync]

管理者は `librechat.yaml` の `skillSync.github` を使用して、GitHubリポジトリからSkillsをミラーリングできます。これは、厳選されたSkillsのセットをチーム全体で共有するための実用的な方法です。

```yaml filename="librechat.yaml"
skillSync:
  github:
    enabled: true
    intervalMinutes: 60
    runOnStartup: true
    sources:
      - id: librechat-skills
        owner: your-org
        repo: your-skills-repo
        ref: main
        paths:
          - skills
        skillDiscoveryDepth: 2
        token: '${GITHUB_SKILLS_TOKEN}'
```

GitHub Skill Sync:

- 設定されたリポジトリパスをスキャンして `SKILL.md` を探します
- 各 `SKILL.md` を含むディレクトリをスキルルートとして扱い、設定されたパスから `skillDiscoveryDepth` レベルの範囲内で探索します。
- 各スキルの横にバンドルされたファイルをインポートします
- `source: "github"` を持つミラーリングされたスキルを保存します
- アップストリームのリポジトリが変更された際に、ミラーリングされたSkillsを更新します
- 設定されたソース内に存在しなくなったミラーリングされたSkillsを削除します
- ソース内の他のSkillが無効であったり競合していたりする場合でも、有効なSkillを公開します
- 管理者に対して、部分的に成功した実行結果およびスキップされたスキルの詳細を報告します。
- スケジュール実行、起動時実行、および管理者による手動実行をサポートしています

スキップされたSkillは、存在する場合、最後に確認された正常なミラーを保持します。認証、レート制限、同期所有権の喪失、またはロールバックの失敗といったソース全体に関わる障害が発生した場合は、ソース全体の実行が失敗します。

選択したリポジトリに対して、読み取り専用のContentsおよびMetadata権限を持つGitHubのファイングレイン個人アクセストークンを使用してください。すべてのフィールド、認証情報のオプション、テナントのスコープ設定、および管理同期エンドポイントについては、[Skill Sync Object Structure](/docs/configuration/librechat_yaml/object_structure/skill_sync) を参照してください。
