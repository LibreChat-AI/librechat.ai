Skillsは、LibreChatのAgent向けの再利用可能な命令バンドルです。Skillは`SKILL.md`ファイルを中心に構成されます。フロントマターにはそのSkillをいつ使用すべきかが記述され、Markdown本文にはAgentが従うべき手順、ルール、例、または参照情報が記載されます。

Skillsは、以下のような反復的な作業に役立ちます：

- ブランドやライティングガイドラインの適用
- 内部レビューチェックリストに従う
- 標準的なリサーチワークフローの実行
- 専門的なツールワークフローの準備
- 再利用可能なスクリプト、リファレンス、およびアセットを指示ファイルと共にパッケージ化する

## スキルを有効にする [#enable-skills]

`skills` エージェント機能はデフォルトで有効になっています。管理者は、ユーザーからSkillsを非表示にするために、agents エンドポイントの機能リストからそれを削除することができます。

```yaml filename="librechat.yaml"
endpoints:
  agents:
    capabilities:
      - 'deferred_tools'
      - 'execute_code'
      - 'file_search'
      - 'web_search'
      - 'artifacts'
      - 'subagents'
      - 'actions'
      - 'context'
      - 'skills'
      - 'memory'
      - 'ask_user_question'
      - 'tools'
      - 'chain'
      - 'ocr'
```

ロール権限は、スキルを使用、作成、共有、および公開共有できるユーザーを制御します。

## デプロイのスキル [#deployment-skills]

管理者は `DEPLOYMENT_SKILLS_DIR` を使用して、ファイルシステムから読み取り専用の Skills を配布できます。

```bash filename=".env"
DEPLOYMENT_SKILLS_DIR=./skill
```

ディレクトリのデフォルトはプロジェクトルートの `./skill` です。LibreChatは起動時にデプロイされたSkillsを読み込み、Skills機能が有効になっているユーザーに対してそれらを公開します。

デプロイスキル:

- UI上で読み取り専用です
- `deployment` をソースとして使用します
- 同じ名前の永続化されたSkillsよりも優先されます
- ファイルが追加、削除、または変更された後は、LibreChatの再起動が必要です。

実験的な [Agent Plugins](/docs/features/agent_plugins) は、読み取り専用のデプロイメント Skill を関連する MCP サーバーとまとめてバンドルすることもできます。スタンドアロンのデプロイメントディレクトリにある Skill は、同じ名前を持つプラグイン Skill よりも優先されます。

## GitHub Skill Sync [#github-skill-sync]

管理者は `librechat.yaml` の `skillSync.github` を使用して、GitHub リポジトリから Skills をミラーリングできます。

```yaml filename="librechat.yaml"
skillSync:
  github:
    enabled: true
    intervalMinutes: 60
    runOnStartup: true
    sources:
      - id: librechat-skills
        owner: your-org
        repo: your-skills-repo
        ref: main
        paths:
          - skills
        skillDiscoveryDepth: 2
        token: '${GITHUB_SKILLS_TOKEN}'
```

GitHub Skill Sync:

- 設定されたリポジトリパスをスキャンして `SKILL.md` を探します
- 各スキルの横にバンドルされたファイルをインポートします
- `source: "github"` を持つミラーリングされたスキルを保存します
- アップストリームのリポジトリが変更された際に、ミラーリングされたSkillsを更新します
- 設定されたソース内に存在しなくなったミラーリングされたSkillsを削除します
- ソース内の他のSkillが無効であったり競合していたりする場合でも、有効なSkillを公開します
- 管理者に対して、部分的に成功した実行結果およびスキップされたスキルの詳細を報告します。
- スケジュール実行、起動時実行、および管理者による手動実行をサポートしています

スキップされたSkillは、存在する場合、最後に確認された正常なミラーを保持します。認証、レート制限、同期所有権の喪失、またはロールバックの失敗といったソース全体に関わる障害が発生した場合は、ソース全体の実行が失敗します。

選択したリポジトリに対して、読み取り専用のContentsおよびMetadata権限を持つGitHubのファイングレイン個人アクセストークンを使用してください。すべてのフィールド、認証情報のオプション、テナントのスコープ設定、および管理同期エンドポイントについては、[Skill Sync Object Structure](/docs/configuration/librechat_yaml/object_structure/skill_sync) を参照してください。

## スキルを作成する [#create-a-skill]

サイドパネルから **Skills** を開きます。LibreChat 内で直接スキルを作成するか、`SKILL.md` を含む `.md`、`.zip`、または `.skill` ファイルをアップロードできます。

最小限の `SKILL.md`:

```md filename="SKILL.md"
---
name: brand-guidelines
description: Use when writing public-facing content that must follow the company voice and terminology.
---

# Brand Guidelines

Write in a concise, practical tone.
Prefer active voice.
Use product terminology consistently.
```

## 呼び出しモード (Invocation Modes) [#invocation-modes]

Skillsは、以下の3つの方法でエージェントに到達できます：

- **Manual**: ユーザーがチャットで `$` を入力し、ポップオーバーからスキルを選択します。
- **Model-invoked**: モデルが注入されたスキルカタログからスキルを選択し、スキルツールを呼び出します。
- **Always apply**: 有効な場合、そのスキルはすべてのターンでプライミング（準備）されます。

手動呼び出しは、明示的なユーザーの意図によるものです。`user-invocable` が false でない限り、`disable-model-invocation: true` でモデル呼び出しから隠されているスキルを使用することができます。

## Agent Scope [#agent-scope]

AgentsがSkillsを使用または作成するには、事前に **Enable skills** をオンにする必要があります。個別の **Use all skills** スイッチは、カタログへの公開を制御します。

- **すべて:** **すべてのスキルを使用**をオンにすると、後から追加されたスキルを含む、ユーザーが利用可能なすべてのアクティブなカタログが公開されます。
- **選択済み:** **Use all skills** をオフにし、個別の Skills を追加して、それらのエントリのみを公開します。
- **作成のみ:** **すべてのスキルを使用 (Use all skills)** をオフにし、スキルを選択しない状態にします。既存のカタログエントリは公開されませんが、ユーザーがスキル作成権限を持っている場合、エージェントは会話中にスキルを作成できます。
- **無効:** **Enable skills** をオフにすると、カタログの使用とランタイムオーサリングの両方が無効になります。

これにより、管理者はSkills機能をグローバルに公開しつつ、各エージェントが使用可能なスキルセットを絞り込むことができます。

**Use all skills** をオフにすると、スイッチが有効になる前にアクティブだった選択状態が復元されます。既存のエージェントは、明示的なスコープなしで有効化されたスキルがカタログ全体を意味するという従来の動作を保持します。

## Runtime Skill Authoring [#runtime-skill-authoring]

Skillsが有効なエージェントは、作業中に再利用可能なSkillファイルを新規作成または編集できます。ランタイムファイルはアップロードされたバンドルと同じ `skills/{skillName}/...` 名前空間を使用するため、エージェントはワークフローを成功させる過程で `SKILL.md` や、それをサポートする参照、スクリプト、アセットを作成できます。

Authoringは、通常のSkills権限モデルに従います。

- 新しいSkillを作成するには、ユーザーのSkill **Create** 権限が必要です。
- 既存のSkillを編集するには、編集権限とエージェントのアクティブなカタログスコープへの含まれていることの両方が必要です。デプロイ済みおよびGitHub同期済みのSkillは読み取り専用のままとなります。
- 作成専用（authoring-only）のエージェントは、ユーザーの既存のカタログを受け取ることなく、新しいSkillを作成できます。

ランタイムでのオーサリングは、デプロイ機能やユーザー権限をバイパスするものではありません。Agents エンドポイントの機能から `skills` を削除するとこの機能は非表示になり、エージェントの **Enable skills** をオフにすると、そのオーサリングツールが無効になります。

## アクティブおよび共有スキル [#active-and-shared-skills]

ユーザーはスキルを有効または無効に切り替えることができます。所有スキルおよびデプロイ済みスキルはデフォルトで有効になります。共有スキルは、ユーザーが上書きするまで、管理者が設定したデフォルト値が使用されます。

非アクティブなスキルは以下から除外されます：

- `$` ポップオーバー
- モデルが呼び出すスキルカタログ
- 常に適用されるプライミング

## Bundled Files [#bundled-files]

アップロードされたスキルバンドルには、`SKILL.md` に加えて以下のようなファイルを含めることができます。

- `references/...`
- `scripts/...`
- `assets/...`

バックエンドはそれらのファイルをスキルと共に保存します。エージェントは、スキルがアクティブでスコープ内にある場合にスキルファイルを解決できます。ネストされたファイルは相対パスを保持し、モデル向けの `skills/{skillName}/...` 名前空間を通じてアドレス指定されます。スキルビューアでは、相対的なMarkdownリンクは現在のファイルから解決され、参照されたファイルが同じスキル内で開かれます。Code Interpreterが有効な場合、同じファイルが `/mnt/data/skills/{skillName}/...` にマウントされるため、シェルやコード操作で直接使用できます。`SKILL.md` を編集するとスキルバージョンが進みます。コードやプログラムによる実行の前に、LibreChatはマウントされたすべてのファイル参照がそのバージョンと一致していることを検証し、参照が古い場合は完全なバンドルを再アップロードします。

<Callout type="note" title="作成のヒント">
  `description` は具体的に記述してください。これはモデルがスキルを呼び出すための最も強力なシグナルとなります。説明が短すぎたり曖昧だったりすると、トリガーがうまく機能しません。
</Callout>
