Les Skills sont des ensembles d'instructions réutilisables pour les Agents LibreChat. Un skill est centré sur un fichier `SKILL.md` : le frontmatter décrit quand le skill doit être utilisé, et le corps en markdown fournit à l'agent la procédure, les règles, les exemples ou les références à suivre.

Les Skills sont utiles pour les tâches répétitives telles que :

- Application des directives de marque ou de rédaction
- Suivi des listes de contrôle d'examen interne
- Exécution d'un flux de travail de recherche standard
- Préparation d'un flux de travail d'outil spécialisé
- Empaqueter des scripts, références et ressources réutilisables avec un fichier d'instructions

## Activer les Skills [#enable-skills]

La fonctionnalité d'agent `skills` est activée par défaut. Les administrateurs peuvent la supprimer de la liste des fonctionnalités de l'endpoint agents pour masquer les Skills aux utilisateurs.

```yaml filename="librechat.yaml"
endpoints:
  agents:
    capabilities:
      - 'deferred_tools'
      - 'execute_code'
      - 'file_search'
      - 'web_search'
      - 'artifacts'
      - 'subagents'
      - 'actions'
      - 'context'
      - 'skills'
      - 'memory'
      - 'ask_user_question'
      - 'tools'
      - 'chain'
      - 'ocr'
```

Les autorisations de rôle contrôlent également qui peut utiliser, créer, partager et partager publiquement des skills.

## Compétences de déploiement [#deployment-skills]

Les administrateurs peuvent déployer des Skills en lecture seule depuis le système de fichiers avec `DEPLOYMENT_SKILLS_DIR`.

```bash filename=".env"
DEPLOYMENT_SKILLS_DIR=./skill
```

Le répertoire par défaut est `./skill` à la racine du projet. LibreChat charge les Skills de déploiement au démarrage et les expose aux utilisateurs ayant la fonctionnalité Skills activée.

Compétences de déploiement :

- Sont en lecture seule dans l'interface utilisateur
- Utilisez `deployment` comme source
- Ont la priorité sur les Skills persistés portant le même nom
- Nécessite un redémarrage de LibreChat après l'ajout, la suppression ou la modification de fichiers

Les [Agent Plugins](/docs/features/agent_plugins) expérimentaux peuvent également regrouper des Skills de déploiement en lecture seule avec des serveurs MCP associés. Un Skill situé dans le répertoire de déploiement autonome est prioritaire sur un Skill de plugin portant le même nom.

## Synchronisation des compétences GitHub [#github-skill-sync]

Les administrateurs peuvent répliquer des Skills à partir de dépôts GitHub avec `skillSync.github` dans `librechat.yaml`.

```yaml filename="librechat.yaml"
skillSync:
  github:
    enabled: true
    intervalMinutes: 60
    runOnStartup: true
    sources:
      - id: librechat-skills
        owner: your-org
        repo: your-skills-repo
        ref: main
        paths:
          - skills
        skillDiscoveryDepth: 2
        token: '${GITHUB_SKILLS_TOKEN}'
```

Synchronisation des compétences GitHub :

- Analyse les chemins de dépôt configurés à la recherche de `SKILL.md`
- Importe les fichiers groupés à côté de chaque compétence
- Stocke les Skills en miroir avec `source: "github"`
- Met à jour les Skills en miroir lorsque le dépôt amont change
- Supprime les Skills en miroir qui n'existent plus dans la source configurée
- Publie des Skills valides même lorsqu'un autre Skill dans la source est invalide ou en conflit
- Signale aux administrateurs les exécutions partiellement réussies et les détails des compétences ignorées (skipped-Skill) limitées.
- Prend en charge les exécutions planifiées, au démarrage et déclenchées manuellement par l'administrateur

Une Skill ignorée conserve son dernier miroir connu comme fonctionnel lorsqu'il en existe un. Les échecs à l'échelle de la source, tels que l'authentification, la limitation de débit, la perte de propriété de synchronisation ou une restauration infructueuse, entraînent toujours l'échec de l'exécution complète de la source.

Utilisez un jeton d'accès personnel GitHub à grain fin avec des autorisations de lecture seule pour Contents et Metadata pour le dépôt sélectionné. Voir [Skill Sync Object Structure](/docs/configuration/librechat_yaml/object_structure/skill_sync) pour tous les champs, les options d'identification, le scoping de tenant et les endpoints de synchronisation d'administration.

## Créer une compétence [#create-a-skill]

Ouvrez **Skills** depuis le panneau latéral. Vous pouvez écrire une skill directement dans LibreChat ou télécharger un fichier `.md`, `.zip` ou `.skill` qui contient `SKILL.md`.

`SKILL.md` minimal :

```md filename="SKILL.md"
---
name: brand-guidelines
description: Use when writing public-facing content that must follow the company voice and terminology.
---

# Brand Guidelines

Write in a concise, practical tone.
Prefer active voice.
Use product terminology consistently.
```

Les champs de frontmatter reconnus sont soumis à une vérification de type. Les champs non reconnus sont conservés sous forme de métadonnées limitées et compatibles JSON au lieu de rendre le Skill invalide ; les valeurs d'extension trop volumineuses ou profondément imbriquées sont toujours rejetées.

Gardez la `description` d'une Skill invoquée par un modèle à 250 caractères ou moins et placez ses expressions déclencheuses les plus importantes en premier. Des descriptions plus longues peuvent toujours être importées, mais LibreChat les tronque dans le catalogue visible par le modèle et enregistre un avertissement nommant chaque Skill concernée.

## Modes d'invocation [#invocation-modes]

Les Skills peuvent atteindre un agent de trois manières :

- **Manuel** : l'utilisateur tape `$` dans le chat et sélectionne une compétence dans la fenêtre contextuelle.
- **Model-invoked** : le modèle choisit une compétence dans le catalogue de compétences injecté et appelle l'outil de compétence.
- **Toujours appliquer** : la compétence est amorcée à chaque tour lorsqu'elle est active.

L'invocation manuelle est une intention explicite de l'utilisateur. Elle peut utiliser des compétences qui sont masquées de l'invocation par le modèle avec `disable-model-invocation: true`, tant que `user-invocable` n'est pas défini sur false.

## Portée de l'agent [#agent-scope]

Les Agents doivent avoir l'option **Enable skills** activée avant de pouvoir utiliser ou créer des Skills. Le commutateur séparé **Use all skills** contrôle l'exposition dans le catalogue.

- **Tous :** activez **Utiliser toutes les compétences** pour exposer le catalogue actif complet visible par l'utilisateur, y compris les compétences ajoutées ultérieurement.
- **Sélectionné :** laissez **Use all skills** désactivé et ajoutez des Skills individuelles pour n'exposer que ces entrées.
- **Authoring only :** laissez **Use all skills** désactivé sans aucune Skill sélectionnée. Les entrées de catalogue existantes ne sont pas exposées, mais l'agent peut créer une Skill au cours d'une conversation lorsque l'utilisateur dispose de l'autorisation de création de Skill.
- **Désactivé :** désactivez **Enable skills** pour désactiver à la fois l'utilisation du catalogue et la création au moment de l'exécution.

Cela permet aux administrateurs d'exposer la fonctionnalité Skills globalement tout en gardant l'ensemble des compétences utilisables de chaque agent ciblé.

Désactiver **Use all skills** restaure la sélection qui était active avant que l'option ne soit activée. Les agents existants conservent le comportement hérité où les Skills activées sans portée explicite signifient le catalogue complet.

## Création de compétences à l'exécution [#runtime-skill-authoring]

Un agent avec les Skills activés peut créer ou modifier des fichiers de Skill réutilisables pendant son exécution. Les fichiers d'exécution utilisent le même espace de nom `skills/{skillName}/...` que les bundles téléchargés, de sorte que l'agent peut créer un `SKILL.md` ainsi que les références, scripts ou ressources associés dans le cadre d'un flux de travail réussi.

La création suit le modèle de permission normal des Skills :

- La création d'une nouvelle Skill nécessite l'autorisation **Create** (Créer) de la Skill de l'utilisateur.
- La modification d'une Skill existante nécessite à la fois un accès en modification et son inclusion dans le périmètre du catalogue actif de l'agent ; les Skills déployées et synchronisées avec GitHub restent en lecture seule.
- Un agent en mode création uniquement peut créer une nouvelle Skill sans recevoir le catalogue existant de l'utilisateur.

La création au moment de l'exécution (runtime authoring) ne contourne pas la capacité de déploiement ni les autorisations des utilisateurs. La suppression de `skills` des capacités de l'endpoint Agents masque la fonctionnalité, et la désactivation de **Enable skills** sur l'agent désactive ses outils de création.

## Compétences actives et partagées [#active-and-shared-skills]

Les utilisateurs peuvent activer ou désactiver les compétences. Les compétences possédées et celles déployées sont actives par défaut. Les compétences partagées utilisent la valeur par défaut configurée par l'administrateur jusqu'à ce que l'utilisateur les remplace.

Les compétences inactives sont exclues de :

- Le popover `$`
- Le catalogue de compétences invoquées par le modèle
- Amorçage toujours appliqué

## Fichiers groupés [#bundled-files]

Les bundles de compétences téléchargés peuvent inclure des fichiers aux côtés de `SKILL.md`, tels que :

- `references/...`
- `scripts/...`
- `assets/...`

Le backend stocke ces fichiers avec la skill. L'agent peut résoudre les fichiers de skill lorsque la skill est active et dans le périmètre. Les fichiers imbriqués conservent leurs chemins relatifs et sont adressés via l'espace de nommage `skills/{skillName}/...` exposé au modèle. Dans la visionneuse de Skill, les liens Markdown relatifs se résolvent à partir du fichier actuel et ouvrent le fichier référencé au sein de la même Skill. Lorsque Code Interpreter est activé, les mêmes fichiers sont montés sur `/mnt/data/skills/{skillName}/...` afin que les opérations shell et de code puissent les utiliser directement. La modification de `SKILL.md` fait progresser la version de la Skill ; avant toute exécution de code ou programmatique, LibreChat vérifie que chaque référence de fichier monté correspond à cette version et retéléverse le bundle complet si une référence est obsolète.

<Callout type="note" title="Conseil de rédaction">
  Gardez la `description` spécifique. C'est le signal le plus fort pour les compétences invoquées par le modèle. Une description courte ou vague entraînera un sous-déclenchement.
</Callout>
