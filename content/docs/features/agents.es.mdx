# Agentes: Construye asistentes de IA personalizados [#agents-build-custom-ai-assistants]

La función de AI Agents de LibreChat proporciona un marco flexible para crear asistentes de IA personalizados impulsados por varios proveedores de modelos.

Esta función es similar a la Assistants API de OpenAI y a los GPTs de ChatGPT, pero con un soporte de modelos más amplio y una implementación sin código (no-code), lo que le permite crear asistentes sofisticados con capacidades especializadas.

## Primeros pasos [#getting-started]

Para crear un nuevo agente, seleccione "Agents" en el menú de endpoint y abra el panel Agent Builder que se encuentra en el Side Panel.

![Agentes - Menú de endpoints](/images/agents/endpoints_menu.png)

El formulario de creación incluye:

- **Avatar**: Sube un avatar personalizado para personalizar tu agente
- **Name**: Elija un nombre distintivo para su agente
- **Descripción**: Detalles opcionales sobre el propósito de tu agente
- **Instructions**: Instrucciones del sistema que definen el comportamiento de tu agente
- **Model**: Seleccione entre los proveedores y modelos disponibles

Los controles de **Tools** y **Skills** abren bibliotecas con capacidad de búsqueda para funciones integradas, herramientas, servidores MCP, Actions y Skills. Seleccione un elemento para configurarlo y, a continuación, guarde el agente.

**Los agentes existentes pueden seleccionarse desde el menú desplegable superior del Panel Lateral.**

- **También mediante mención con "@" en la entrada del chat.**

![Agents - Mention](/images/agents/mention.png)

### Biblioteca de herramientas [#tool-library]

El Agent Builder mantiene los elementos habilitados en secciones separadas de **Tools** y **Skills**. Abra **Add tools** para buscar en el catálogo completo o filtrarlo por **Official**, **Tools**, **MCP** o **Actions**. **Made by you** recopila los servidores MCP y las Actions que usted creó, mientras que **Favorites** mantiene los elementos marcados como favoritos disponibles en todos los agentes. Cada usuario puede guardar hasta 100 favoritos en la biblioteca de herramientas.

Seleccione un elemento para configurarlo sin salir del generador. El menú **Create new** solo aparece cuando el usuario tiene permiso para crear servidores MCP o Actions. Eliminar una capacidad basada en archivos, como File Search, File Context o Code Interpreter, abre su administrador de archivos cuando todavía hay archivos adjuntos que deben revisarse.

Las Skills utilizan su propio selector y pueden seleccionarse individualmente o habilitarse como el catálogo completo accesible. Consulta [Skills](/docs/features/skills#agent-scope).

Los operadores también pueden usar [Agent Plugins](/docs/features/agent_plugins) experimentales para agrupar Skills de despliegue y servidores MCP en paquetes cargados al inicio.

### Configuración del modelo [#model-configuration]

La interfaz de parámetros del modelo permite ajustar con precisión las respuestas de su agente:

- Temperatura (escala de 0 a 1 para la creatividad de la respuesta)
- Tokens de contexto máximo
- Máximo de tokens de salida
- Configuraciones adicionales específicas del proveedor

### Historial de versiones [#version-history]

Los usuarios con acceso de edición pueden abrir el **Version History** desde el Agent Builder para inspeccionar las configuraciones guardadas en una línea de tiempo. Cada entrada muestra cuándo se guardó y resume sus herramientas y capacidades. Restaurar una entrada anterior requiere confirmación y reemplaza la configuración actual del agente con ese estado guardado. Guardar siempre aplica los cambios actuales del agente, incluso cuando la configuración resultante coincide con la entrada del historial más reciente y LibreChat no añade una entrada duplicada.

## Capacidades de los agentes [#agent-capabilities]

> **Nota:** Todas las capacidades pueden activarse o desactivarse a través del archivo de configuración `librechat.yaml`. Consulta [docs/configuration/librechat_yaml/object_structure/agents#capabilities](/docs/configuration/librechat_yaml/object_structure/agents#capabilities) para obtener más información.

### Intérprete de código [#code-interpreter]

Cuando está habilitada, la capacidad de Code Interpreter permite a su agente:

- Ejecute código en múltiples lenguajes, incluyendo:
  - Python, JavaScript, TypeScript, Go, C, C++, Java, PHP, Rust y Fortran
- Procese archivos de forma segura a través de la API de Code Interpreter de LibreChat
- Ejecute código sin necesidad de configuración local, ajustes o despliegue de sandbox
- Gestiona la carga y descarga de archivos sin problemas
- [Más información sobre la API de Code Interpreter](/docs/features/code_interpreter)
  - **Con tecnología del servicio [code-interpreter](https://github.com/ClickHouse/code-interpreter) de código abierto (autoalojado)**

Cuando todos los archivos de Code Interpreter requeridos de una conversación no logran restaurarse en el sandbox actual, LibreChat detiene al Agent antes de invocar al modelo y le pide al usuario que vuelva a adjuntar los archivos. Esto evita que la ejecución continúe con referencias a archivos obsoletos o inaccesibles.

#### Sesiones de código con estado [#stateful-code-sessions]

Las sesiones de código con estado (stateful) permiten que un agente reutilice un espacio de trabajo de sandbox por conversación. Los archivos, los paquetes instalados y el estado de trabajo generalmente se mantienen entre ejecuciones de código, lo cual es útil para el análisis iterativo y el trabajo con archivos en varios pasos.

<Callout type="warning" title="Altamente experimental">
  Las Stateful Code Sessions se encuentran en una fase de experimentación temprana. Su comportamiento, configuración, características de persistencia e integración subyacente pueden cambiar sustancialmente. No trate la implementación actual como un contrato de producción estable.
</Callout>

Esta función es opcional. Un administrador debe añadir `stateful_code_sessions` a las [capacidades del agente](/docs/configuration/librechat_yaml/object_structure/agents#capabilities), el Intérprete de código debe estar habilitado en el agente y **Stateful code sessions** debe estar activado en la configuración avanzada del agente. El espacio de trabajo puede reiniciarse en cualquier momento. Guarde los resultados importantes en `/mnt/data` y no confíe en el estado de la sesión como almacenamiento duradero.

### Búsqueda de archivos [#file-search]

La capacidad de File Search permite:

- Funcionalidad RAG (Retrieval-Augmented Generation)
- Búsqueda semántica en documentos subidos
- Respuestas con reconocimiento de contexto basadas en el contenido de los archivos
- Soporte para archivos adjuntos tanto a nivel de agente como de hilo de chat

### Contexto de archivo [#file-context]

La funcionalidad de File Context permite que su agente almacene texto extraído de archivos como parte de sus instrucciones del sistema:

- Extraer texto manteniendo la estructura y el formato del documento
- Procesar diseños complejos, incluyendo texto en varias columnas y contenido mixto
- Manejar tablas, ecuaciones y otro contenido especializado
- Trabajar con contenido multilingüe
- El texto se almacena en las instrucciones del agente en la base de datos
- **No se requiere servicio de OCR** - Utiliza análisis de texto de forma predeterminada con métodos de respaldo
- **Mejorado por OCR** - Si OCR está configurado, la calidad de extracción mejora para imágenes y documentos escaneados
- Utiliza la misma lógica de procesamiento que "Upload as Text": **OCR > STT > text parsing**
- [Más información sobre la configuración de OCR](/docs/features/ocr)

**Nota:** El contexto de archivo incluye texto extraído en las instrucciones del sistema del agente. Para preguntas sobre documentos temporales en conversaciones individuales, utilice [Cargar como texto](/docs/features/upload_as_text) desde el chat.

### Model Context Protocol (MCP) [#model-context-protocol-mcp]

MCP es un protocolo abierto que estandariza cómo las aplicaciones proporcionan contexto a los Large Language Models (LLMs), actuando como un adaptador universal para herramientas de IA y fuentes de datos.

Para más información, consulta la documentación sobre [MCP](/docs/features/mcp).

#### Agentes con herramientas MCP [#agents-with-mcp-tools]

1. Configure los servidores MCP en su archivo `librechat.yaml`
2. Reinicia LibreChat para inicializar las conexiones
3. Crear o editar un agente
4. Abre **Add tools** en el Agent Builder y selecciona **MCP**
5. Seleccione el/los servidor(es) MCP que desea añadir; cada servidor aparece como una única entrada
6. Guarda tus cambios en el agente

En este ejemplo, hemos añadido el **[servidor MCP de Spotify](https://github.com/LibreChat-AI/spotify-mcp)** a un agente.

![Agentes - MCP](/images/agents/mcp_tools_v2.png)

#### Gestión de herramientas MCP [#managing-mcp-tools]

Una vez que se añade un servidor MCP a un agente, puede ajustar con precisión qué herramientas específicas están disponibles:

- Después de agregar un servidor MCP, expándalo para ver todas las herramientas disponibles
- Marque/desmarque las herramientas individuales según sea necesario
- Por ejemplo, el servidor MCP de Spotify proporciona ~20 herramientas (búsqueda, control de reproducción, gestión de listas de reproducción, etc.)
- Este control granular le permite limitar a los agentes solo a las herramientas que necesitan

Los servidores con ámbito de solicitud que utilizan `{{LIBRECHAT_BODY_*}}` no pueden enumerar herramientas hasta que una ejecución de chat proporcione esos valores. Por lo tanto, el Agent Builder muestra una selección de herramientas en tiempo de ejecución para todo el servidor en lugar de interruptores por herramienta; borrar esa selección desconecta el servidor. Después de OAuth, LibreChat mantiene la autorización y espera hasta la primera ejecución elegible para conectarse.

Si un Agent selecciona explícitamente herramientas MCP pero ninguna puede ser resuelta al iniciar una ejecución, LibreChat detiene la ejecución con una guía de conexión y acceso en lugar de continuar silenciosamente sin ellas. Vuelva a conectar o autenticar el servidor, verifique el acceso a la herramienta y reintente la ejecución.

![Agentes - Herramientas MCP](/images/agents/mcp_agent_tools.png)

Más información:

- [Configuración de servidores MCP](/docs/features/mcp)
- [Introducción al Model Context Protocol](https://modelcontextprotocol.io/introduction)

### Herramientas diferidas [#deferred-tools]

Las herramientas diferidas (deferred tools) permiten que los agentes tengan acceso a muchas herramientas MCP sin cargarlas todas en el contexto del LLM por adelantado. En su lugar, las herramientas diferidas se pueden descubrir en tiempo de ejecución mediante un mecanismo de **Búsqueda de herramientas** (Tool Search).

Esto es especialmente útil cuando un agente tiene acceso a muchos servidores MCP con docenas de herramientas; cargarlas todas consumiría una gran parte de la ventana de contexto y degradaría la calidad de la respuesta.

**Cómo funciona:**

- Las herramientas marcadas como "deferred" se excluyen del contexto inicial del LLM
- Una herramienta `ToolSearch` se añade automáticamente, permitiendo al LLM descubrir y cargar herramientas diferidas bajo demanda.
- Una vez descubierta, la herramienta estará disponible para el resto de la conversación

**Configuración de herramientas diferidas:**

1. Abre el Agent Builder y añade herramientas MCP
2. Haz clic en el menú desplegable de cualquier herramienta MCP
3. Alternar "Defer Loading" (Diferir carga) — las herramientas diferidas muestran un icono de reloj

**Nota:** La capacidad `deferred_tools` está habilitada de forma predeterminada. Puede activarse o desactivarse a través de la configuración de agentes en [`librechat.yaml`](/docs/configuration/librechat_yaml/object_structure/agents#capabilities).

### Grupos de actividad [#activity-groups]

Los grupos de actividad contraen cada bloque contiguo de razonamiento del Agente y llamadas a herramientas bajo un encabezado generado de una sola línea, lo que facilita el escaneo de ejecuciones largas. Los administradores los habilitan con `activityLabel` y pueden usar un modelo más rápido, otro endpoint configurado, un prompt personalizado y límites por ejecución. La generación del encabezado es una llamada de modelo independiente cuyos tokens y costo se registran. Consulta [Agent Activity Groups](/docs/configuration/librechat_yaml/object_structure/shared_endpoint_settings#agent-activity-groups).

Los administradores pueden habilitar de forma independiente `activityPhaseLabel` para agrupar dos o más actividades lógicas en un resumen principal contraído antes de la respuesta final. Esto proporciona a las ejecuciones largas un esquema de alto nivel mientras se conserva cada actividad secundaria. Los resúmenes de fase utilizan su propio modelo, endpoint, prompt y límite por ejecución, con respaldo a la configuración de la etiqueta de actividad y de ejecución.

El texto de progreso breve permanece dentro de su fase principal. Cuando el Agent comienza una respuesta sustancial, LibreChat cierra la fase antes de ese texto para que el resultado visible para el usuario permanezca fuera del resumen contraído. Una ejecución puede crear múltiples fases principales cuando razonamientos posteriores o herramientas inician otro bloque de actividad lógica. Los límites de fase persistidos se reajustan cuando las partes de contenido mal formadas u omitidas se compactan, de modo que la agrupación permanezca alineada después de recargar.

### Etiquetas de intención de herramientas [#tool-intent-labels]

Las etiquetas de intención de herramienta reemplazan los estados genéricos de herramientas en vivo con una breve descripción escrita por el modelo para esa llamada específica. Los administradores deben añadir la capacidad de agente `tool_intents` [agent capability](/docs/configuration/librechat_yaml/object_structure/agents#capabilities). Las herramientas nativas utilizan etiquetas automáticamente; en el Agent Builder, expanda un servidor MCP y active **Intent label** para herramientas individuales o para el servidor completo.

Para Model Specs, [`describeIntent`](/docs/configuration/librechat_yaml/object_structure/model_specs#describeintent) puede habilitar cada herramienta elegible o seleccionar IDs de herramientas resueltos. Los campos de intención se añaden al esquema de herramientas enviado al modelo, por lo que la habilitación selectiva puede reducir la sobrecarga de tokens del esquema.

Las etiquetas de intención (intent labels) no se aplican a las herramientas MCP programáticas, ya que las llamadas realizadas dentro del código en sandbox no renderizan tarjetas de herramientas individuales.

### Programmatic Tool Calling [#programmatic-tool-calling]

Programmatic Tool Calling (PTC) permite a los agentes ejecutar herramientas MCP seleccionadas desde dentro del sandbox de [Code Interpreter](/docs/features/code_interpreter) en lugar de llamar a cada herramienta directamente desde el modelo. El modelo recibe una herramienta de orquestación respaldada por Code Interpreter, escribe código en el sandbox que llama a las funciones de herramientas generadas, y puede utilizar bucles, condicionales, reintentos y procesamiento de resultados antes de devolver una respuesta.

Esto es útil para flujos de trabajo de herramientas de varios pasos, como consultar varios recursos, paginar resultados, comparar salidas o transformar las respuestas de las herramientas antes de que el agente las explique.

**Configuración de herramientas programáticas:**

1. Enable both `programmatic_tools` and `execute_code` in the [`librechat.yaml` agents capabilities](/docs/configuration/librechat_yaml/object_structure/agents#capabilities).
2. Habilita el Code Interpreter en el agente.
3. Agregue herramientas MCP, expanda un servidor MCP y alterne **Programmatic** para herramientas individuales o para el servidor completo. Las herramientas Programmatic muestran un icono de código.

**Nota:** `programmatic_tools` es opcional y no está incluido en la lista de capacidades predeterminadas de los agentes. PTC también requiere un despliegue de Code Interpreter con el componente Tool Call Server. Solo las herramientas registradas para el agente pueden ser llamadas desde el sandbox; las llamadas a herramientas no registradas son rechazadas.

### Llamadas a herramientas en segundo plano [#background-tool-calls]

Las llamadas a herramientas en segundo plano permiten que un agente inicie una herramienta MCP o de Code Interpreter elegible de larga duración, continúe trabajando y consulte el resultado más tarde. La llamada inicial devuelve inmediatamente una referencia de tarea; el agente recupera el estado y los resultados a través de `check_background_task`.

Para utilizar esta función, un administrador debe añadir la capacidad de agente `run_in_background` [agent capability](/docs/configuration/librechat_yaml/object_structure/agents#capabilities). Luego, configure las herramientas elegibles en el Agent Builder:

- **Code Interpreter:** Habilite Code Interpreter en el agente. La ejecución de código y los comandos de shell se vuelven elegibles para ejecutarse en segundo plano de forma predeterminada; desactive **Background execution** en la configuración de sus herramientas para optar por no participar.
- **MCP:** Abra un servidor MCP y marque herramientas individuales, o el servidor completo, como **Background**.

Estos ajustes permiten la ejecución en segundo plano, pero no la fuerzan. El modelo decide en cada llamada si ejecutar una herramienta elegible en segundo plano.

En el chat de LibreChat, cuando el código en segundo plano termina, su stdout y los archivos generados aparecen en la llamada de código original en lugar de en la consulta posterior. Los archivos generados también se conservan para los turnos subsiguientes.

El estado de las tareas en segundo plano es actualmente local al proceso. Los resultados pueden recopilarse en un turno posterior en el mismo proceso del servidor, pero no sobreviven a un reinicio y no se comparten entre réplicas.

### Solicitar al usuario y aprobación de herramientas [#ask-user-and-tool-approval]

La herramienta **Ask User** permite que un agente pause una ejecución para solicitar información faltante, presentar opciones o confirmar cómo proceder. Una sola llamada puede agrupar hasta cuatro preguntas relacionadas en un único formulario. Cada pregunta acepta una respuesta de formato libre o las opciones de selección única o múltiple del agente; el usuario responde a cada pregunta y envía el formulario una vez, o puede omitirlo. Mientras el modelo prepara la llamada, LibreChat transmite las preguntas a una tarjeta de progreso; el formulario interactivo la reemplaza cuando está listo. Tras el envío, la misma ejecución se reanuda con las respuestas. Añada **Ask User** desde el mercado de Tools; los administradores pueden eliminar la capacidad predeterminada `ask_user_question` para ocultarla.

Las respuestas enviadas se persisten con la acción de reanudar, por lo que detenerse mientras se inicializa la ejecución reanudada no descarta las respuestas aceptadas.

Cada pregunta acepta un encabezado opcional de hasta 80 caracteres, un texto de pregunta de hasta 2,000 caracteres, un contexto de apoyo opcional de hasta 4,000 caracteres y hasta 12 opciones. Las etiquetas de las opciones están limitadas a 280 caracteres, los valores de las opciones a 500 caracteres y cada respuesta enviada a 16,000 caracteres.

Los administradores también pueden requerir una revisión antes de que se ejecuten las llamadas a herramientas coincidentes. Dependiendo de la herramienta, los usuarios pueden aprobar, rechazar, editar argumentos o responder directamente. Las ejecuciones pausadas se guardan en puntos de control para que puedan reanudarse después de la decisión, incluso en otra réplica cuando se utiliza el punto de control de MongoDB predeterminado. La aprobación de herramientas está desactivada de forma predeterminada; consulte [`toolApproval` y `checkpointer`](/docs/configuration/librechat_yaml/object_structure/agents#toolapproval).

### Habilidades [#skills]

Las Skills permiten a los agentes cargar instrucciones reutilizables desde definiciones en `SKILL.md`. Pueden seleccionarse manualmente desde el chat con `$`, ser descubiertas automáticamente por el modelo a través del catálogo de skills, o aplicarse siempre en cada turno.

Para obtener detalles sobre la creación, invocación y control de acceso, consulta [Skills](/docs/features/skills).

### Memoria [#memory]

La herramienta **Memory** permite que un agente guarde, actualice o elimine recuerdos estructurados del usuario cuando este solicita explícitamente recordar u olvidar algo. Memory debe estar configurada para el despliegue, permitida por el rol y la configuración de personalización del usuario, y habilitada en el agente.

De forma predeterminada, un agente utiliza el grupo de memoria personal compartido del usuario. Activa **Keep memories separate for this agent** para darle una partición privada por usuario y por agente. El agente aislado no verá las memorias compartidas existentes ni las memorias creadas por otros agentes aislados. Los usuarios pueden filtrar el panel de Memory por memorias personales o específicas del agente. Consulta [User Memory](/docs/features/memory#agent-memory).

### Artifacts [#artifacts]

La funcionalidad Artifacts permite que tu agente genere y muestre contenido interactivo:

- Crear componentes de React, código HTML y diagramas de Mermaid
- Mostrar contenido en una ventana de interfaz de usuario separada para mayor claridad e interacción
- Configurar instrucciones específicas para artefactos a nivel de agente
- [Más información sobre Artifacts](/docs/features/artifacts)

Cuando esté habilitado, elija uno de los tres modos de instrucción:

- **Normal**: Añade las instrucciones de artefactos estándar para React, HTML, SVG, Markdown y Mermaid.
- **shadcn/ui**: Añade las instrucciones estándar además de orientación para construir interfaces con la biblioteca de componentes shadcn/ui.
- **Custom**: Mantiene el renderizado de artefactos habilitado pero no inyecta instrucciones de artefactos integradas, lo que otorga control total a las propias instrucciones del agente.

Configurar artifacts a nivel de agente es el enfoque preferido, ya que permite un control más granular en comparación con la configuración heredada de toda la aplicación.

Si seleccionas **Custom**, incluye como mínimo el formato básico de artefacto en tus instrucciones.

Aquí tienes un ejemplo sencillo de las instrucciones mínimas necesarias:

````md
When creating content that should be displayed as an artifact, use the following format:

:::artifact{identifier="unique-identifier" type="mime-type" title="Artifact Title"}

```
Your artifact content here
```

:::

For the type attribute, use one of:

- "text/html" for HTML content
- "application/vnd.mermaid" for Mermaid diagrams
- "application/vnd.react" for React components
- "image/svg+xml" for SVG images
````

- **[Stable Diffusion](/docs/features/image_gen#stable-diffusion-local)** / **[Flux](/docs/features/image_gen#flux)**: Generación de texto a imagen
- **[Wolfram](/docs/configuration/tools/wolfram)**: Capacidades computacionales y matemáticas
- **[OpenWeather](/docs/configuration/tools/openweather)**: Recuperación de datos meteorológicos
- **[Google Search](/docs/configuration/tools/google_search)**: Acceso a la funcionalidad de búsqueda web
- **[Calculator](/docs/configuration/tools/calculator)**: Cálculos matemáticos
- **[Tavily Search](/docs/configuration/tools/tavily)**: API de búsqueda avanzada con integración de diversas fuentes de datos
- **[Azure AI Search](/docs/configuration/tools/azure_ai_search)**: Recuperación de información desde índices de Azure AI Search
- **[Traversaal](/docs/configuration/tools/traversaal)**: Una API de búsqueda robusta para agentes LLM

#### Crear un agente con herramientas de imagen [#create-an-agent-with-image-tools]

1. Agregue las credenciales de la herramienta de imagen a `.env`, como `IMAGE_GEN_OAI_API_KEY` para las herramientas de imagen de OpenAI.
2. Reinicie LibreChat para que las nuevas variables de entorno se carguen.
3. Selecciona **Agents** en el menú de endpoint.
4. Abre el Agent Builder desde el panel lateral y crea o edita un agente.
5. Abra la lista de **Tools** del agente, seleccione **OpenAI Image Tools**, **Gemini Image Tools**, **DALL-E-3**, **Stable Diffusion** o **Flux**, y luego guarde el agente.
6. Inicia un chat con ese agente y pídele que genere o edite una imagen.

Para obtener la guía completa de configuración de imágenes, incluidas las variables de modelo como `IMAGE_GEN_OAI_MODEL`, consulte [Image Generation & Editing](/docs/features/image_gen).

- Las herramientas pueden desactivarse utilizando el archivo de configuración [`librechat.yaml`](/docs/configuration/librechat_yaml):
  - [Más información](/docs/configuration/librechat_yaml/object_structure/agents#capabilities)

  - [Más información](/docs/configuration/librechat_yaml/object_structure/agents#capabilities)
- Se pueden incluir dominios individuales en la lista blanca para las acciones de los agentes:

  Si utiliza un modelo de OpenAI que lo admita, esto generará automáticamente llamadas a funciones con el modo 'strict' habilitado.
  - El modo estricto solo admite un subconjunto parcial de json. Lea https://platform.openai.com/docs/guides/structured-outputs para obtener más detalles.

### Handoffs [#handoffs]

Las transferencias (handoffs) permiten que un agente principal transfiera una conversación a un agente especialista con el contexto relevante. En **Advanced settings**, abre la sección de orquestación y añade hasta 10 agentes de transferencia. Cada transferencia configurada crea una herramienta de transferencia que el modelo puede elegir dinámicamente cuando se necesite la experiencia del especialista.

Para cada transferencia, puede añadir una descripción que ayude al modelo a elegir al especialista adecuado. También puede proporcionar instrucciones de paso (passthrough instructions) que describan qué contenido debe generar el agente principal para el especialista y, opcionalmente, renombrar el parámetro de contenido desde su valor predeterminado, `instructions`. Las transferencias están siempre disponibles en el Agent Builder; a diferencia de Agent Chain y Subagents, no requieren que se habilite una capacidad de endpoint.

### Cadena de agentes [#agent-chain]

La funcionalidad Agent Chain permite un enfoque de Mixture-of-Agents (MoA), lo que le permite crear una secuencia de agentes que trabajan juntos:

- Crea cadenas de agentes especializados para tareas complejas
- Cada agente en la cadena puede acceder a las salidas de los agentes anteriores
- Configurar el número máximo de pasos para la cadena del agente
- **Nota:** Acceda a esta función desde el panel de Advanced Settings en el Agent Builder
- **Nota:** Esta función se encuentra actualmente en fase beta y puede estar sujeta a cambios
  - El máximo actual de agentes que se pueden encadenar es 10, pero esto podría ser configurable en el futuro.

Esta funcionalidad introduce una arquitectura de Mixture-of-Agents por capas en LibreChat, donde cada agente toma todas las salidas de los agentes de la capa anterior como información auxiliar para generar su respuesta, tal como se describe en [el artículo homónimo "Mixture-of-Agents"](https://arxiv.org/abs/2406.04692).

### Subagentes [#subagents]

Los Subagents permiten que un agente delegue una tarea específica a una ejecución secundaria aislada. El proceso secundario obtiene su propia ventana de contexto y flujo de ejecución de herramientas, y luego devuelve un resultado compacto al proceso principal en lugar de llenar el contexto del padre con cada paso intermedio.

Los subagentes son diferentes a la cadena de agentes (Agent Chain): las cadenas ejecutan múltiples agentes coordinados como participantes de un grafo, mientras que los subagentes son generados por un agente como una llamada de herramienta para una delegación de alcance limitado. Para la configuración y los límites, consulta [Subagents](/docs/features/subagents).

### Configuración avanzada [#advanced-settings]

Configuración avanzada para su agente (que se encuentra en la vista Advanced del formulario de Agente) fuera de "capabilities".

#### Pasos máximos del agente [#max-agent-steps]

Esta configuración le permite limitar el número de pasos que un agente puede realizar en una "ejecución" (run), lo cual se refiere al bucle del agente antes de que se proporcione una respuesta final.

Si se deja sin configurar, el valor predeterminado es 25 pasos, pero puede ajustarlo según sus necesidades. Para los administradores, es posible establecer un valor predeterminado global, así como un máximo global, en el archivo [`librechat.yaml`](/docs/configuration/librechat_yaml/object_structure/agents#recursionlimit).

Los administradores también pueden limitar los argumentos de llamadas a herramientas transmitidos y los eventos delta del modelo con [Agent stream circuit breakers](/docs/configuration/librechat_yaml/object_structure/agents#stream-circuit-breakers).

Un "paso" (step) se refiere ya sea a una solicitud de API de IA o a una ronda de uso de herramientas (1 o varias herramientas, dependiendo de cuántas llamadas a herramientas proporcione el LLM a partir de una sola solicitud).

Una respuesta única, sin herramientas, es 1 paso. Una ronda singular de uso de herramientas suele ser de 3 pasos:

1. Solicitud de API -> 2. Uso de herramientas (1 o muchas herramientas) -> 3. Solicitud de API de seguimiento

## Gestión de archivos [#file-management]

Los Agents admiten múltiples formas de trabajar con archivos:

### En la interfaz de chat [#in-chat-interface]

Al chatear con un agente, tienes cuatro opciones de carga:

1. **Subir imágenes**
   - Sube imágenes para soporte nativo de modelos de visión
   - Envía imágenes directamente al proveedor del modelo

2. **Subir como texto** (requiere la capacidad `context`)
   - Extrae e incluye el contenido completo del documento en la conversación
   - Utiliza análisis de texto de forma predeterminada; mejorado mediante OCR si está configurado
   - El contenido solo existe en la conversación actual
   - Consulta [Upload as Text](/docs/features/upload_as_text)

3. **Carga para búsqueda de archivos** (requiere la capacidad `file_search`, activada)
   - Utiliza búsqueda semántica (RAG) con almacenes vectoriales
   - Devuelve fragmentos relevantes mediante el uso de herramientas
   - Óptimo para documentos grandes/múltiples archivos
   - Subóptimo para datos estructurados (CSV, Excel, JSON, etc.)

4. **Carga para Code Interpreter** (requiere la capacidad `execute_code`, activada)
   - Añade archivos al entorno del intérprete de código
   - Óptimo para datos estructurados (CSV, Excel, JSON, etc.)
   - Más información sobre [Code Interpreter](/docs/features/code_interpreter)

### En Agent Builder [#in-agent-builder]

Al configurar un agente, puede adjuntar archivos en diferentes categorías:

1. **Carga de imágenes**: Para contenido visual que el agente puede referenciar
2. **Carga de búsqueda de archivos**: Documentos para capacidades de RAG
3. **Carga de Code Interpreter**: Archivos para procesamiento de código
4. **Contexto de archivo**: Documentos con texto extraído para complementar las instrucciones del agente

**File Context** utiliza la capacidad `context` y funciona exactamente igual que ["Upload as Text"](/docs/features/upload_as_text): utiliza el análisis de texto de forma predeterminada y se mejora mediante OCR cuando está configurado. El texto se extrae en el momento de la carga y se almacena en las instrucciones del agente. Esto es ideal para proporcionar a los agentes conocimiento persistente a partir de documentos, archivos PDF, archivos de código o imágenes con texto.

**Prioridad de procesamiento:** OCR > STT > análisis de texto (igual que Cargar como texto)

**Nota:** El texto extraído se incluye como parte de las instrucciones del sistema del agente.

## Compartir y permisos [#sharing-and-permissions]

Los agentes utilizan el sistema de [control de acceso](/docs/features/access_control) granular de LibreChat. Cada agente tiene su propia Lista de Control de Acceso (ACL) y puede compartirse con **usuarios**, **grupos**, **roles** específicos o **públicamente**, cada uno con un nivel de permiso elegido.

### Roles de acceso [#access-roles]

Al compartir un agente, al beneficiario se le asigna uno de tres roles:

| Rol | Qué puede hacer el beneficiario |
| ---------- | ----------------------------------------------------------------------------------------------------- |
| **Viewer** | Usar el agente en conversaciones; no puede abrir el constructor ni ver instrucciones, herramientas o archivos adjuntos |
| **Editor** | Ver + modificar las instrucciones, el modelo, las herramientas y los archivos del agente |
| **Owner**  | Control total: ver, editar, eliminar y volver a compartir el agente |

El autor original y los administradores siempre conservan el control total independientemente de la ACL.

### Compartir un Agent [#sharing-an-agent]

1. Abre el agente en el Agent Builder
2. Haz clic en el botón **Share** en el pie de página (visible cuando eres el autor, un administrador o se te ha concedido el permiso `SHARE` en ese agente específico)
3. Busque usuarios, grupos o roles en el selector de personas y asígnele un rol a cada uno
4. Opcionalmente, activa **Public** para hacer que el agente sea visible para todos en la instancia (requiere el permiso de función `SHARE_PUBLIC`).

Las tarjetas de agente y las vistas de inicio muestran el contacto de soporte configurado. Cuando no se ha establecido ninguno, LibreChat puede recurrir al nombre para mostrar del primer propietario resoluble, pero no expone la dirección de correo electrónico del propietario a menos que se haya configurado explícitamente como el contacto de soporte.

Para obtener detalles completos sobre los principales, los bits de permiso y cómo las ACL se combinan con los permisos de funciones basados en roles, consulte [Access Control](/docs/features/access_control).

### Controles de administrador [#administrator-controls]

Los administradores tienen acceso a la configuración de permisos globales dentro de la interfaz de usuario del generador de agentes:

- Habilitar/deshabilitar el uso compartido de agentes para todos los usuarios
- Controlar los permisos de uso de agentes
- Gestionar los derechos de creación de agentes
- Configurar los ajustes de toda la plataforma

La primera cuenta creada para su instancia es un administrador. Si necesita agregar un administrador adicional, puede [access MongoDB](/docs/configuration/mongodb/mongodb_auth) y actualizar el perfil del usuario:

```
db.users.updateOne(
  { email: 'USER_EMAIL_ADDRESS' },
  { $set: { role: 'ADMIN' } }
)
```

El uso de agentes para todos los usuarios también se puede deshabilitar a través de la configuración, [más información](/docs/configuration/librechat_yaml/object_structure/interface).

Los permisos a nivel de función (quién puede _usar_, _crear_, _compartir_ o _compartir públicamente_ agentes) se gestionan desde el [**LibreChat Admin Panel**](/docs/features/admin_panel) en cada rol, incluyendo cualquier rol personalizado. El bloque [`interface.agents`](/docs/configuration/librechat_yaml/object_structure/interface#agents) en `librechat.yaml` todavía puede establecer valores predeterminados para el rol `USER` integrado al inicio, pero el panel de administración es la forma recomendada para editarlos de ahora en adelante.

### Uso compartido a nivel de usuario [#user-level-sharing]

Los usuarios individuales pueden:

- Compartir sus agentes con usuarios, grupos o roles específicos (si `SHARE` está habilitado para su rol)
- Hacer que los agentes sean visibles para todos en la instancia (si `SHARE_PUBLIC` está habilitado)
- Otorgue a cada destinatario un nivel de acceso diferente (Viewer / Editor / Owner)
- Vuelva a compartir o revoque el acceso en cualquier momento desde el diálogo de compartir

## Steering y mensajes en cola [#steering-and-queued-messages]

Mientras un Agent está respondiendo, puedes enviar otro mensaje de dos maneras:

- **Steer** inserta el mensaje en la ejecución actual en su siguiente paso de herramienta o agente, para que el agente pueda ajustar su trabajo antes de finalizar.
- **Queue** retiene el mensaje y lo envía como un turno de seguimiento normal una vez que se completa la respuesta actual.

**Interrupt & steer** detiene la generación en el siguiente límite seguro del proveedor, conserva la respuesta parcial, inserta el mensaje y reanuda la misma respuesta del asistente. Utilice el control dedicado en el compositor, selecciónelo desde el menú del botón de envío o presione `Command/Ctrl + Shift + .`. La acción recurre a la dirección ordinaria cuando el despliegue no puede interrumpir el flujo activo del proveedor.

En **Settings → Chat**, **While generating, Enter will** elige la acción predeterminada. El menú del botón de envío puede anular esa elección para un mensaje individual, y **Steering interrupts generation** controla si la dirección (steering) ordinaria también solicita una interrupción.

Los steers pendientes aparecen sobre el compositor hasta que el servidor los inserta en la ejecución. Una vez reconocidos, su menú puede recuperar el mensaje para editarlo, convertirlo en un seguimiento en cola o cancelarlo y restaurar su texto y archivos adjuntos en el compositor. LibreChat evita sobrescribir un borrador más reciente; si el compositor ya no está disponible, conserva el mensaje recuperado en la cola. Un steer fallido permanece disponible para reintentar, editar, poner en cola o eliminar.

Los seguimientos en cola pueden enviarse inmediatamente, convertirse en una dirección (steer) mientras la ejecución sigue activa, escalarse a **Interrupt & steer now**, editarse o eliminarse. Las direcciones en curso ofrecen el mismo escalamiento cuando aún están esperando un límite de herramienta. Eliminar un mensaje en cola lo restaura a un compositor vacío cuando es posible. Una ejecución activa acepta hasta 10 direcciones pendientes; cada dirección puede incluir hasta 10 archivos y está limitada por [`STEER_MAX_LENGTH`](/docs/configuration/dotenv#agent-conversation-controls).

Las implementaciones de múltiples réplicas respaldadas por Redis deben completar el [despliegue del protocolo de generación v2](/docs/configuration/redis#generation-protocol-rollout) antes de depender del comportamiento de interrupción y recuperación entre réplicas.

### Notas [#notes]

- Las instrucciones, los parámetros del modelo, los archivos adjuntos y las herramientas solo se muestran al usuario si tiene permisos de edición.
  - Un agente puede filtrar cualquier dato adjunto, ya sean instrucciones o archivos, a través de la conversación, así que asegúrese de que sus instrucciones sean robustas contra esto antes de otorgar acceso de Editor/Propietario o hacer que el agente sea público.
- Solo los autores originales, los administradores y los usuarios con permiso de Propietario pueden eliminar agentes compartidos
- Los Agents son privados para sus autores a menos que se compartan

1. Selecciona "Agents" en el menú desplegable de endpoint
2. Abre el panel de Agent Builder
3. Complete los detalles requeridos del agente

## Migración requerida (v0.8.0-rc3+) [#migration-required-v080-rc3]

<Callout type="warning" title="Importante: Se requiere la migración de permisos de agente">
  A partir de la versión v0.8.0-rc3, LibreChat utiliza un nuevo sistema de permisos basado en listas de control de acceso (ACL) para los agentes. Si está actualizando desde una versión anterior, debe ejecutar la migración de permisos de agentes para que los agentes existentes sigan siendo accesibles.
</Callout>

### Qué hace la migración [#what-the-migration-does]

La migración de permisos de agentes transiciona a sus agentes de un modelo de propiedad simple a un sistema sofisticado basado en ACL con múltiples niveles de permisos:

- **OWNER**: Control total sobre el agente
- **EDITOR**: Puede ver y modificar el agente
- **VIEWER**: Acceso de solo lectura al agente

Sin ejecutar esta migración, los agentes existentes no serán accesibles a través de los nuevos endpoint de la API con reconocimiento de permisos.

### Ejecución de la migración [#running-the-migration]

Elija el comando apropiado según su método de despliegue:

#### 1. Para el `docker-compose.yml` predeterminado (si utiliza `docker compose up` para iniciar la aplicación): [#1-for-the-default-docker-composeyml-if-you-use-docker-compose-up-to-start-the-app]

**Vista previa de cambios (simulacro):**

```bash
docker compose exec api npm run migrate:agent-permissions:dry-run
```

**Ejecutar migración:**

```bash
docker compose exec api npm run migrate:agent-permissions
```

**Tamaño de lote personalizado (para conjuntos de datos grandes):**

```bash
docker compose exec api npm run migrate:agent-permissions:batch
```

#### 2. Para el `deploy-compose.yml` [#2-for-the-deploy-composeyml]

Si seguiste la [Guía de Docker para Ubuntu](/docs/remote/docker_linux):

**Vista previa de cambios (simulacro):**

```bash
docker exec -it LibreChat-API /bin/sh -c "cd .. && npm run migrate:agent-permissions:dry-run"
```

**Ejecutar migración:**

```bash
docker exec -it LibreChat-API /bin/sh -c "cd .. && npm run migrate:agent-permissions"
```

**Tamaño de lote personalizado (para conjuntos de datos grandes):**

```bash
docker exec -it LibreChat-API /bin/sh -c "cd .. && npm run migrate:agent-permissions:batch"
```

#### 3. Para desarrollo local (desde la raíz del proyecto): [#3-for-local-development-from-project-root]

**Vista previa de cambios (simulacro):**

```bash
npm run migrate:agent-permissions:dry-run
```

**Ejecutar migración:**

```bash
npm run migrate:agent-permissions
```

**Tamaño de lote personalizado (para conjuntos de datos grandes):**

```bash
npm run migrate:agent-permissions:batch
```

### Qué sucede durante la migración [#what-happens-during-migration]

- **Agentes Privados**: Permanecen accesibles solo para sus creadores (reciben permiso de OWNER)
- **Agentes compartidos**: Si un agente fue compartido previamente, recibirá las entradas de ACL correspondientes como un Agente Público (compartido con todos los usuarios)
- **Detección del sistema**: LibreChat detecta automáticamente los agentes no migrados al iniciarse y muestra una advertencia

Puedes ajustar los permisos del agente resultante a través de la interfaz de usuario del Agent Builder.

<Callout type="info" title="Nota">
  El mismo proceso de migración se aplica a los prompts. Si también tienes prompts existentes, ejecuta la migración de permisos de prompts usando los mismos comandos, pero reemplaza `agent` con `prompt` en los nombres de los comandos.
</Callout>

## ¿Qué sigue? [#whats-next]

Los Agents de LibreChat marcan el comienzo de una nueva era para la aplicación, donde los futuros pipelines podrán optimizarse mediante Agents para tareas y flujos de trabajo específicos a lo largo de su experiencia en LibreChat.

Las futuras actualizaciones incluirán:

- Mejoras generales a la experiencia actual de los Agentes
- Orquestación multi-agente para flujos de trabajo complejos
- Capacidad para personalizar agentes para diversas funciones: titulación (nombramiento de hilos de chat), gestión de memoria (contexto/historial del usuario) y mejora de prompts (asistencia/predicciones de entrada)
- Más herramientas, parámetros de herramientas configurables, creación dinámica de herramientas.

Además, la actualización introduce un nuevo paradigma para LibreChat, ya que su arquitectura subyacente proporciona una renovación muy necesaria para la aplicación, optimizando tanto la experiencia del usuario como el rendimiento general de la misma.

Para destacar una optimización notable, una generación de IA de aproximadamente 1000 tokens transferirá cerca de 1 MB de datos utilizando endpoints tradicionales (al momento de escribir esto, cualquier opción de endpoint además de Agents y AWS Bedrock).

Al usar un agente, la misma generación transferirá alrededor de 52 kb de datos, una reducción del 95% en la transferencia de datos, lo que supone una carga mucho menor tanto para el servidor como para el dispositivo del usuario.

Los AI Agents en LibreChat ofrecen una forma potente de crear asistentes especializados sin necesidad de conocimientos de programación, manteniendo al mismo tiempo la flexibilidad para trabajar con sus modelos y proveedores de IA preferidos.
