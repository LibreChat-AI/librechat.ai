# Agen: Membangun Asisten AI Kustom [#agents-build-custom-ai-assistants]

Fitur AI Agents pada LibreChat menyediakan kerangka kerja yang fleksibel untuk membuat asisten AI kustom yang ditenagai oleh berbagai penyedia model.

Fitur ini mirip dengan Assistants API dari OpenAI dan GPTs dari ChatGPT, namun dengan dukungan model yang lebih luas dan implementasi tanpa kode (no-code), memungkinkan Anda membangun asisten canggih dengan kemampuan khusus.

## Memulai [#getting-started]

Untuk membuat agen baru, pilih "Agents" dari menu endpoint dan buka panel Agent Builder yang terdapat di Side Panel.

![Agents - Endpoints Menu](/images/agents/endpoints_menu.png)

Formulir pembuatan mencakup:

- **Avatar**: Unggah avatar kustom untuk mempersonalisasi agen Anda
- **Name**: Pilih nama yang unik untuk agen Anda
- **Description**: Detail opsional mengenai tujuan agen Anda
- **Instruksi**: Instruksi sistem yang menentukan perilaku agen Anda
- **Model**: Pilih dari penyedia dan model yang tersedia

Kontrol **Tools** dan **Skills** membuka pustaka yang dapat dicari untuk kapabilitas bawaan, tools, server MCP, Actions, dan Skills. Pilih item untuk mengonfigurasinya, lalu simpan agen tersebut.

**Agen yang sudah ada dapat dipilih dari menu tarik-turun di bagian atas Panel Samping.**

- **Juga dengan menyebut "@" di input obrolan.**

![Agents - Mention](/images/agents/mention.png)

### Pustaka Alat [#tool-library]

Agent Builder menyimpan item yang diaktifkan dalam bagian **Tools** dan **Skills** yang terpisah. Buka **Add tools** untuk mencari di seluruh katalog atau memfilternya berdasarkan **Official**, **Tools**, **MCP**, atau **Actions**. **Made by you** mengumpulkan server MCP dan Actions yang Anda buat, sementara **Favorites** menyimpan item yang ditandai bintang agar tersedia di seluruh agen. Setiap pengguna dapat menyimpan hingga 100 favorit pustaka alat.

Pilih item untuk mengonfigurasinya tanpa meninggalkan builder. Menu **Create new** hanya muncul ketika pengguna memiliki izin untuk membuat server MCP atau Actions. Menghapus kapabilitas berbasis file seperti File Search, File Context, atau Code Interpreter akan membuka pengelola filenya jika masih ada file terlampir yang perlu ditinjau.

Skills menggunakan pemilihnya sendiri dan dapat dipilih secara individu atau diaktifkan sebagai katalog lengkap yang dapat diakses. Lihat [Skills](/docs/features/skills#agent-scope).

Operator juga dapat menggunakan [Agent Plugins](/docs/features/agent_plugins) eksperimental untuk menggabungkan Skills deployment dan server MCP ke dalam paket yang dimuat saat startup.

### Konfigurasi Model [#model-configuration]

Antarmuka parameter model memungkinkan penyesuaian respons agen Anda:

- Temperature (skala 0-1 untuk kreativitas respons)
- Token konteks maksimal
- Token output maksimum
- Pengaturan tambahan khusus penyedia

### Riwayat Versi [#version-history]

Pengguna dengan akses edit dapat membuka **Version History** dari Agent Builder untuk memeriksa konfigurasi yang tersimpan dalam linimasa. Setiap entri menunjukkan kapan konfigurasi tersebut disimpan dan merangkum alat serta kapabilitasnya. Memulihkan entri sebelumnya memerlukan konfirmasi dan akan mengganti konfigurasi agen saat ini dengan status yang tersimpan tersebut. Menyimpan akan selalu menerapkan perubahan agen saat ini, bahkan ketika konfigurasi yang dihasilkan cocok dengan entri riwayat terbaru dan LibreChat tidak akan menambahkan entri duplikat.

## Kemampuan Agen [#agent-capabilities]

> **Catatan:** Semua kapabilitas dapat diaktifkan atau dinonaktifkan melalui file konfigurasi `librechat.yaml`. Lihat [docs/configuration/librechat_yaml/object_structure/agents#capabilities](/docs/configuration/librechat_yaml/object_structure/agents#capabilities) untuk informasi lebih lanjut.

### Code Interpreter [#code-interpreter]

Saat diaktifkan, kemampuan Code Interpreter memungkinkan agen Anda untuk:

- Jalankan kode dalam berbagai bahasa, termasuk:
  - Python, JavaScript, TypeScript, Go, C, C++, Java, PHP, Rust, dan Fortran
- Memproses file secara aman melalui API Code Interpreter LibreChat
- Jalankan kode tanpa pengaturan lokal, konfigurasi, atau penerapan sandbox
- Tangani unggahan dan unduhan file dengan lancar
- [Info lebih lanjut tentang API Code Interpreter](/docs/features/code_interpreter)
  - **Diberdayakan oleh layanan [code-interpreter](https://github.com/ClickHouse/code-interpreter) sumber terbuka (di-host sendiri)**

Ketika setiap file Code Interpreter yang diperlukan dari sebuah percakapan gagal dipulihkan ke dalam sandbox saat ini, LibreChat akan menghentikan Agent sebelum memanggil model dan meminta pengguna untuk melampirkan kembali file tersebut. Hal ini mencegah eksekusi berlanjut dengan referensi file yang sudah kedaluwarsa atau tidak dapat diakses.

#### Sesi Kode Stateful [#stateful-code-sessions]

Sesi kode stateful memungkinkan agen untuk menggunakan kembali satu ruang kerja sandbox per percakapan. File, paket yang diinstal, dan status kerja biasanya terbawa di antara eksekusi kode, yang berguna untuk analisis iteratif dan pekerjaan file multi-langkah.

<Callout type="warning" title="Sangat eksperimental">
  Stateful Code Sessions saat ini berada dalam tahap eksperimen awal. Perilaku, konfigurasi, karakteristik persistensi, dan integrasi dasarnya dapat berubah secara substansial. Jangan menganggap implementasi saat ini sebagai kontrak produksi yang stabil.
</Callout>

Fitur ini bersifat opt-in. Administrator harus menambahkan `stateful_code_sessions` ke [agent capabilities](/docs/configuration/librechat_yaml/object_structure/agents#capabilities), Code Interpreter harus diaktifkan pada agen, dan **Stateful code sessions** harus dinyalakan di bawah pengaturan Advanced agen. Workspace dapat diatur ulang kapan saja. Simpan output penting di bawah `/mnt/data`, dan jangan mengandalkan status sesi sebagai penyimpanan permanen.

### Pencarian File [#file-search]

Kemampuan File Search memungkinkan:

- Fungsionalitas RAG (Retrieval-Augmented Generation)
- Pencarian semantik di seluruh dokumen yang diunggah
- Respons yang sadar konteks berdasarkan isi file
- Dukungan lampiran file baik di tingkat agen maupun utas obrolan

### Konteks File [#file-context]

Kemampuan File Context memungkinkan agen Anda untuk menyimpan teks yang diekstrak dari file sebagai bagian dari instruksi sistemnya:

- Ekstrak teks sambil mempertahankan struktur dan pemformatan dokumen
- Memproses tata letak kompleks termasuk teks multi-kolom dan konten campuran
- Menangani tabel, persamaan, dan konten khusus lainnya
- Bekerja dengan konten multibahasa
- Teks disimpan dalam instruksi agent di dalam database
- **Tidak memerlukan layanan OCR** - Menggunakan penguraian teks secara default dengan metode cadangan
- **Ditingkatkan dengan OCR** - Jika OCR dikonfigurasi, kualitas ekstraksi akan meningkat untuk gambar dan dokumen yang dipindai
- Menggunakan logika pemrosesan yang sama seperti "Upload as Text": **OCR > STT > text parsing**
- [Info lebih lanjut tentang konfigurasi OCR](/docs/features/ocr)

**Catatan:** File Context menyertakan teks yang diekstrak ke dalam instruksi sistem agen. Untuk pertanyaan dokumen sementara dalam percakapan individu, gunakan [Upload as Text](/docs/features/upload_as_text) dari obrolan sebagai gantinya.

### Model Context Protocol (MCP) [#model-context-protocol-mcp]

MCP adalah protokol terbuka yang menstandarisasi cara aplikasi menyediakan konteks ke Large Language Models (LLMs), yang bertindak seperti adaptor universal untuk alat AI dan sumber data.

Untuk informasi lebih lanjut, lihat dokumentasi tentang [MCP](/docs/features/mcp).

#### Agen dengan MCP Tools [#agents-with-mcp-tools]

1. Konfigurasikan server MCP di dalam file `librechat.yaml` Anda
2. Mulai ulang LibreChat untuk menginisialisasi koneksi
3. Buat atau edit agen
4. Buka **Add tools** di Agent Builder dan pilih **MCP**
5. Pilih server MCP yang ingin Anda tambahkan; setiap server akan muncul sebagai satu entri
6. Simpan perubahan Anda ke agen

Dalam contoh ini, kami telah menambahkan **[Spotify MCP server](https://github.com/LibreChat-AI/spotify-mcp)** ke sebuah agen.

![Agents - MCP](/images/agents/mcp_tools_v2.png)

#### Mengelola MCP Tools [#managing-mcp-tools]

Setelah server MCP ditambahkan ke agen, Anda dapat menyempurnakan alat spesifik mana yang tersedia:

- Setelah menambahkan server MCP, perluas server tersebut untuk melihat semua alat yang tersedia
- Centang/hapus centang alat individual sesuai kebutuhan
- Sebagai contoh, server MCP Spotify menyediakan ~20 alat (pencarian, kontrol pemutaran, manajemen daftar putar, dll.)
- Kontrol terperinci ini memungkinkan Anda membatasi agen hanya pada alat yang mereka perlukan

Server dengan cakupan permintaan (request-scoped) yang menggunakan `{{LIBRECHAT_BODY_*}}` tidak dapat melakukan enumerasi alat (tools) hingga sebuah chat run menyediakan nilai-nilai tersebut. Oleh karena itu, Agent Builder menampilkan satu pilihan runtime-tools untuk keseluruhan server, alih-alih tombol toggle per-alat; menghapus pilihan tersebut akan melepaskan server. Setelah OAuth, LibreChat menyimpan otorisasi tersebut dan menunggu hingga run pertama yang memenuhi syarat untuk melakukan koneksi.

Jika sebuah Agent secara eksplisit memilih alat MCP tetapi tidak ada yang dapat diselesaikan saat proses berjalan dimulai, LibreChat akan menghentikan proses tersebut dengan panduan koneksi dan akses alih-alih melanjutkannya secara diam-diam tanpa alat tersebut. Sambungkan kembali atau autentikasi server, verifikasi akses alat, dan coba jalankan kembali prosesnya.

![Agents - MCP Tools](/images/agents/mcp_agent_tools.png)

Pelajari Lebih Lanjut:

- [Mengonfigurasi Server MCP](/docs/features/mcp)
- [Pengantar Model Context Protocol](https://modelcontextprotocol.io/introduction)

### Deferred Tools [#deferred-tools]

Deferred tools memungkinkan agen untuk memiliki akses ke banyak MCP tools tanpa harus memuat semuanya ke dalam konteks LLM di awal. Sebagai gantinya, deferred tools dapat ditemukan saat runtime melalui mekanisme **Tool Search**.

Ini sangat berguna ketika agen memiliki akses ke banyak server MCP dengan puluhan alat—memuat semuanya akan menghabiskan sebagian besar jendela konteks dan menurunkan kualitas respons.

**Cara kerjanya:**

- Tools yang ditandai sebagai "deferred" dikecualikan dari konteks awal LLM
- Sebuah tool `ToolSearch` ditambahkan secara otomatis, yang memungkinkan LLM untuk menemukan dan memuat tool yang ditangguhkan (deferred tools) sesuai permintaan.
- Setelah ditemukan, alat tersebut tersedia untuk sisa percakapan.

**Mengonfigurasi deferred tools:**

1. Buka Agent Builder dan tambahkan alat MCP
2. Klik menu dropdown pada alat MCP mana pun
3. Alihkan "Defer Loading" — alat yang ditangguhkan akan menampilkan ikon jam

**Catatan:** Kemampuan `deferred_tools` diaktifkan secara default. Fitur ini dapat diaktifkan atau dinonaktifkan melalui konfigurasi agen [`librechat.yaml`](/docs/configuration/librechat_yaml/object_structure/agents#capabilities).

### Grup Aktivitas [#activity-groups]

Grup aktivitas melipat setiap blok penalaran Agen dan pemanggilan alat yang berurutan di bawah satu header satu baris yang dibuat secara otomatis, sehingga memudahkan pemindaian pada proses yang panjang. Administrator mengaktifkannya dengan `activityLabel` dan dapat menggunakan model yang lebih cepat, endpoint lain yang dikonfigurasi, prompt kustom, dan batas per-eksekusi. Pembuatan header adalah panggilan model terpisah yang token dan biayanya dicatat. Lihat [Agent Activity Groups](/docs/configuration/librechat_yaml/object_structure/shared_endpoint_settings#agent-activity-groups).

Administrator dapat mengaktifkan `activityPhaseLabel` secara mandiri untuk membungkus dua atau lebih aktivitas logis ke dalam ringkasan induk yang diciutkan sebelum jawaban akhir. Hal ini memberikan kerangka tingkat tinggi untuk proses yang panjang sekaligus tetap mempertahankan setiap aktivitas anak. Ringkasan fase menggunakan model, endpoint, prompt, dan batas per-run miliknya sendiri, dengan fallback ke label aktivitas dan pengaturan run.

Teks progres singkat tetap berada di dalam fase induknya. Saat Agen memulai jawaban yang substansial, LibreChat menutup fase sebelum teks tersebut agar hasil yang dilihat pengguna tetap berada di luar ringkasan yang diciutkan. Satu kali proses dapat membuat beberapa fase induk ketika penalaran atau alat (tools) selanjutnya memulai blok aktivitas logis lainnya. Batas fase yang dipertahankan akan diatur ulang (rebased) ketika bagian konten yang cacat atau dihilangkan dipadatkan, sehingga pengelompokan tetap selaras setelah dimuat ulang.

### Label Intent Alat [#tool-intent-labels]

Label intent tool menggantikan status alat langsung yang umum dengan deskripsi singkat yang ditulis oleh model untuk panggilan spesifik tersebut. Administrator harus menambahkan `tool_intents` [agent capability](/docs/configuration/librechat_yaml/object_structure/agents#capabilities) sebagai opsi. Alat bawaan menggunakan label secara otomatis; di Agent Builder, perluas server MCP dan aktifkan **Intent label** untuk alat individu atau seluruh server.

Untuk Model Specs, [`describeIntent`](/docs/configuration/librechat_yaml/object_structure/model_specs#describeintent) dapat mengaktifkan setiap tool yang memenuhi syarat atau memilih ID tool yang telah ditentukan. Bidang intent ditambahkan ke skema tool yang dikirim ke model, sehingga pengaktifan selektif dapat mengurangi overhead token skema.

Label intent tidak berlaku untuk alat MCP yang hanya bersifat programatis karena panggilan yang dilakukan di dalam kode sandbox tidak merender kartu alat secara individual.

### Pemanggilan Alat Secara Programatis [#programmatic-tool-calling]

Programmatic Tool Calling (PTC) memungkinkan agen untuk mengeksekusi alat MCP yang dipilih dari dalam sandbox [Code Interpreter](/docs/features/code_interpreter) alih-alih memanggil setiap alat secara langsung dari model. Model menerima alat orkestrasi yang didukung oleh Code Interpreter, menulis kode dalam sandbox yang memanggil fungsi alat yang dihasilkan, serta dapat menggunakan perulangan, kondisional, percobaan ulang, dan pemrosesan hasil sebelum memberikan jawaban.

Ini berguna untuk alur kerja alat multi-langkah seperti melakukan kueri ke beberapa sumber daya, melakukan penomoran halaman melalui hasil, membandingkan output, atau mengubah respons alat sebelum agen menjelaskannya.

**Mengonfigurasi alat terprogram:**

1. Aktifkan `programmatic_tools` dan `execute_code` di dalam [`librechat.yaml` agents capabilities](/docs/configuration/librechat_yaml/object_structure/agents#capabilities).
2. Aktifkan Code Interpreter pada agen.
3. Tambahkan alat MCP, perluas server MCP, dan aktifkan **Programmatic** untuk alat individu atau untuk seluruh server. Alat Programmatic menampilkan ikon kode.

**Catatan:** `programmatic_tools` bersifat opsional dan tidak disertakan dalam daftar kapabilitas agen default. PTC juga memerlukan deployment Code Interpreter dengan komponen Tool Call Server. Hanya alat yang terdaftar untuk agen yang dapat dipanggil dari sandbox; panggilan alat yang tidak terdaftar akan ditolak.

### Panggilan Alat Latar Belakang [#background-tool-calls]

Pemanggilan alat latar belakang (background tool calls) memungkinkan agen untuk memulai alat MCP atau Code Interpreter yang memenuhi syarat dan berjalan dalam durasi lama, tetap bekerja, dan melakukan polling untuk mendapatkan hasilnya nanti. Pemanggilan awal akan segera mengembalikan referensi tugas; agen kemudian mengambil status dan hasil melalui `check_background_task`.

Untuk menggunakan fitur ini, administrator harus menambahkan kemampuan agen `run_in_background` [agent capability](/docs/configuration/librechat_yaml/object_structure/agents#capabilities) yang bersifat opt-in. Kemudian, konfigurasikan alat yang memenuhi syarat di Agent Builder:

- **Code Interpreter:** Aktifkan Code Interpreter pada agen. Eksekusi kode dan perintah shell secara default memenuhi syarat untuk berjalan di latar belakang; nonaktifkan **Background execution** di pengaturan alatnya untuk memilih keluar.
- **MCP:** Buka server MCP dan tandai alat individual, atau seluruh server, sebagai **Background**.

Pengaturan ini memungkinkan eksekusi latar belakang tetapi tidak memaksakannya. Model memutuskan per panggilan apakah akan menjalankan alat yang memenuhi syarat di latar belakang.

Di obrolan LibreChat, saat kode latar belakang selesai dijalankan, stdout dan file yang dihasilkan akan muncul pada panggilan kode asli, bukan pada polling berikutnya. File yang dihasilkan juga disimpan untuk giliran (turn) berikutnya.

Status tugas latar belakang saat ini bersifat process-local. Hasil dapat dikumpulkan pada giliran berikutnya di proses server yang sama, tetapi tidak akan bertahan setelah dimulai ulang (restart) dan tidak dibagikan di seluruh replika.

### Minta Persetujuan Pengguna dan Tool [#ask-user-and-tool-approval]

Alat **Ask User** memungkinkan agen untuk menjeda proses eksekusi guna meminta informasi yang kurang, menyajikan pilihan, atau mengonfirmasi langkah selanjutnya. Satu panggilan dapat mengelompokkan hingga empat pertanyaan terkait dalam satu formulir. Setiap pertanyaan menerima jawaban bebas atau pilihan tunggal maupun ganda dari agen; pengguna menjawab setiap pertanyaan dan mengirimkannya sekaligus, atau melewati formulir tersebut. Saat model menyiapkan panggilan, LibreChat melakukan streaming pertanyaan ke dalam kartu progres; formulir interaktif akan menggantikannya saat sudah siap. Setelah dikirim, proses eksekusi yang sama akan dilanjutkan dengan jawaban yang diberikan. Tambahkan **Ask User** dari marketplace Tools; administrator dapat menghapus kapabilitas default `ask_user_question` untuk menyembunyikannya.

Jawaban yang dikirimkan akan disimpan bersama tindakan resume, sehingga berhenti saat proses resume berjalan tidak akan membuang jawaban yang telah diterima.

Setiap pertanyaan menerima judul opsional hingga 80 karakter, teks pertanyaan hingga 2.000 karakter, konteks pendukung opsional hingga 4.000 karakter, dan hingga 12 pilihan. Label pilihan dibatasi hingga 280 karakter, nilai pilihan hingga 500 karakter, dan setiap jawaban yang dikirimkan hingga 16.000 karakter.

Administrator juga dapat mewajibkan peninjauan sebelum pemanggilan tool yang cocok dijalankan. Bergantung pada tool-nya, pengguna dapat menyetujui, menolak, mengedit argumen, atau merespons secara langsung. Eksekusi yang dijeda akan disimpan di checkpoint sehingga dapat dilanjutkan setelah keputusan dibuat, termasuk pada replika lain saat checkpointer MongoDB default digunakan. Persetujuan tool dinonaktifkan secara default; lihat [`toolApproval` dan `checkpointer`](/docs/configuration/librechat_yaml/object_structure/agents#toolapproval).

### Skills [#skills]

Skills memungkinkan agen untuk memuat instruksi yang dapat digunakan kembali dari definisi `SKILL.md`. Skill tersebut dapat dipilih secara manual dari obrolan dengan `$`, ditemukan secara otomatis oleh model melalui katalog skill, atau selalu diterapkan pada setiap giliran.

Untuk detail mengenai penulisan, pemanggilan, dan kontrol akses, lihat [Skills](/docs/features/skills).

### Memory [#memory]

Alat **Memory** memungkinkan agen untuk menyimpan, memperbarui, atau menghapus memori pengguna yang terstruktur ketika pengguna secara eksplisit memintanya untuk mengingat atau melupakan sesuatu. Memory harus dikonfigurasi untuk deployment, diizinkan oleh peran pengguna dan pengaturan personalisasi, serta diaktifkan pada agen tersebut.

Secara default, agen menggunakan kumpulan memori pribadi bersama milik pengguna. Aktifkan **Keep memories separate for this agent** untuk memberikan partisi pribadi per-pengguna, per-agen. Agen yang terisolasi tidak akan melihat memori bersama yang sudah ada atau memori yang dibuat oleh agen terisolasi lainnya. Pengguna dapat memfilter panel Memory berdasarkan memori pribadi atau memori khusus agen. Lihat [User Memory](/docs/features/memory#agent-memory).

### Artifacts [#artifacts]

Kemampuan Artifacts memungkinkan agen Anda untuk membuat dan menampilkan konten interaktif:

- Buat komponen React, kode HTML, dan diagram Mermaid
- Tampilkan konten di jendela UI terpisah untuk kejelasan dan interaksi
- Konfigurasikan instruksi khusus artefak di tingkat agen
- [Info lebih lanjut tentang Artifacts](/docs/features/artifacts)

Saat diaktifkan, pilih salah satu dari tiga mode instruksi:

- **Normal**: Menambahkan instruksi artefak standar untuk React, HTML, SVG, Markdown, dan Mermaid.
- **shadcn/ui**: Menambahkan instruksi standar serta panduan untuk membangun antarmuka dengan pustaka komponen shadcn/ui.
- **Custom**: Membiarkan rendering artefak tetap aktif tetapi tidak menyuntikkan instruksi artefak bawaan, sehingga memberikan kendali penuh kepada instruksi agen itu sendiri.

Mengonfigurasi artifacts di tingkat agen adalah pendekatan yang lebih disarankan, karena memungkinkan kontrol yang lebih terperinci dibandingkan dengan konfigurasi warisan di seluruh aplikasi.

Jika Anda memilih **Custom**, sertakan setidaknya format artefak dasar dalam instruksi Anda.

Berikut adalah contoh sederhana dari instruksi minimum yang diperlukan:

````md
When creating content that should be displayed as an artifact, use the following format:

:::artifact{identifier="unique-identifier" type="mime-type" title="Artifact Title"}

```
Your artifact content here
```

:::

For the type attribute, use one of:

- "text/html" for HTML content
- "application/vnd.mermaid" for Mermaid diagrams
- "application/vnd.react" for React components
- "image/svg+xml" for SVG images
````

#### Membuat Agen dengan Alat Gambar [#create-an-agent-with-image-tools]

1. Tambahkan kredensial alat gambar ke `.env`, seperti `IMAGE_GEN_OAI_API_KEY` untuk OpenAI Image Tools.
2. Mulai ulang LibreChat agar variabel lingkungan yang baru dimuat.
3. Pilih **Agents** dari menu endpoint.
4. Buka Agent Builder dari panel samping dan buat atau edit agen.
5. Buka daftar **Tools** agen, pilih **OpenAI Image Tools**, **Gemini Image Tools**, **DALL-E-3**, **Stable Diffusion**, atau **Flux**, kemudian simpan agen tersebut.
6. Mulai obrolan dengan agen tersebut dan minta ia untuk membuat atau mengedit gambar.

Untuk panduan pengaturan gambar lengkap, termasuk variabel model seperti `IMAGE_GEN_OAI_MODEL`, lihat [Image Generation & Editing](/docs/features/image_gen).

- Tools dapat dinonaktifkan menggunakan file konfigurasi [`librechat.yaml`](/docs/configuration/librechat_yaml):
  - [Info lebih lanjut](/docs/configuration/librechat_yaml/object_structure/agents#capabilities)

**Mengklik tombol di atas akan membuka formulir tempat Anda dapat memasukkan URL spesifikasi OpenAPI dan membuat sebuah action:**

- Actions dapat dinonaktifkan menggunakan file konfigurasi [`librechat.yaml`](/docs/configuration/librechat_yaml):
  - [Info lebih lanjut](/docs/configuration/librechat_yaml/object_structure/agents#capabilities)
- Domain individu dapat dimasukkan ke dalam daftar putih (whitelist) untuk tindakan agen:
  - [Info lebih lanjut](/docs/configuration/librechat_yaml/object_structure/actions#alloweddomains)

  - Strict mode hanya mendukung subset parsial dari json. Baca https://platform.openai.com/docs/guides/structured-outputs untuk detailnya.

### Handoffs [#handoffs]

Handoff memungkinkan agen utama untuk mengalihkan percakapan ke agen spesialis dengan konteks yang relevan. Di **Advanced settings**, buka bagian orchestration dan tambahkan hingga 10 agen handoff. Setiap handoff yang dikonfigurasi akan membuat alat transfer yang dapat dipilih oleh model secara dinamis saat keahlian spesialis diperlukan.

Untuk setiap handoff, Anda dapat menambahkan deskripsi yang membantu model memilih spesialis yang tepat. Anda juga dapat memberikan instruksi passthrough yang menjelaskan konten apa yang harus dihasilkan oleh agen utama untuk spesialis tersebut dan secara opsional mengganti nama parameter konten dari default-nya, `instructions`. Handoff selalu tersedia di Agent Builder; tidak seperti Agent Chain dan Subagents, fitur ini tidak memerlukan kemampuan endpoint untuk diaktifkan.

### Rantai Agen [#agent-chain]

Kemampuan Agent Chain memungkinkan pendekatan Mixture-of-Agents (MoA), yang memungkinkan Anda membuat urutan agen yang bekerja bersama:

- Buat rantai agen khusus untuk tugas-tugas kompleks
- Setiap agen dalam rantai dapat mengakses output dari agen sebelumnya
- Konfigurasikan jumlah langkah maksimum untuk rantai agen
- **Catatan:** Akses fitur ini dari panel Advanced Settings di Agent Builder
- **Catatan:** Fitur ini saat ini dalam tahap beta dan dapat berubah sewaktu-waktu
  - Batas maksimum agen yang dapat dirantai saat ini adalah 10, namun hal ini mungkin dapat dikonfigurasi di masa mendatang

### Subagents [#subagents]

Subagents memungkinkan agen untuk mendelegasikan tugas terfokus ke proses anak yang terisolasi. Proses anak tersebut mendapatkan jendela konteks dan alur eksekusi alatnya sendiri, kemudian mengembalikan hasil yang ringkas kepada induknya alih-alih memenuhi konteks induk dengan setiap langkah perantara.

Subagent berbeda dari Agent Chain: chain menjalankan koordinasi beberapa agen sebagai partisipan graf, sementara subagent dipicu oleh agen sebagai panggilan alat untuk delegasi lingkup tertentu. Untuk pengaturan dan batasan, lihat [Subagents](/docs/features/subagents).

### Pengaturan Lanjutan [#advanced-settings]

Pengaturan lanjutan untuk agen Anda (ditemukan di tampilan Advanced pada formulir Agent) di luar "capabilities."

#### Langkah Agen Maksimum [#max-agent-steps]

Pengaturan ini memungkinkan Anda untuk membatasi jumlah langkah yang dapat diambil oleh agen dalam sebuah "run," yang merujuk pada loop agen sebelum respons akhir diberikan.

Jika dibiarkan tanpa konfigurasi, nilai defaultnya adalah 25 langkah, tetapi Anda dapat menyesuaikannya dengan kebutuhan Anda. Untuk admin, Anda dapat menetapkan nilai default global serta nilai maksimum global di dalam file [`librechat.yaml`](/docs/configuration/librechat_yaml/object_structure/agents#recursionlimit).

Administrator juga dapat membatasi argumen *tool-call* yang di-*stream* dan *event* delta model dengan [Agent stream circuit breakers](/docs/configuration/librechat_yaml/object_structure/agents#stream-circuit-breakers).

"Step" (langkah) merujuk pada permintaan API AI atau satu putaran penggunaan alat (1 atau banyak alat, tergantung pada berapa banyak panggilan alat yang disediakan LLM dari satu permintaan).

Satu respons non-alat adalah 1 langkah. Satu putaran penggunaan alat biasanya terdiri dari 3 langkah:

1. Permintaan API -> 2. Penggunaan Tool (1 atau banyak tool) -> 3. Permintaan API Lanjutan

## Manajemen File [#file-management]

Agents mendukung berbagai cara untuk bekerja dengan file:

### Di Antarmuka Obrolan [#in-chat-interface]

Saat mengobrol dengan agen, Anda memiliki empat opsi unggahan:

1. **Unggah Gambar**
   - Mengunggah gambar untuk dukungan model vision native
   - Mengirim gambar secara langsung ke penyedia model

2. **Unggah sebagai Teks** (memerlukan kapabilitas `context`)
   - Mengekstrak dan menyertakan konten dokumen lengkap dalam percakapan
   - Menggunakan penguraian teks secara default; ditingkatkan dengan OCR jika dikonfigurasi
   - Konten hanya ada dalam percakapan saat ini
   - Lihat [Upload as Text](/docs/features/upload_as_text)

3. **Unggah untuk Pencarian File** (memerlukan kapabilitas `file_search`, diaktifkan ke posisi ON)
   - Menggunakan pencarian semantik (RAG) dengan penyimpanan vektor
   - Mengembalikan potongan yang relevan melalui penggunaan tool
   - Optimal untuk dokumen besar/banyak file
   - Kurang optimal untuk data terstruktur (CSV, Excel, JSON, dll.)

4. **Unggah untuk Code Interpreter** (memerlukan kapabilitas `execute_code`, diaktifkan ke posisi ON)
   - Menambahkan file ke lingkungan code interpreter
   - Optimal untuk data terstruktur (CSV, Excel, JSON, dll.)
   - Info lebih lanjut tentang [Code Interpreter](/docs/features/code_interpreter)

### Di Agent Builder [#in-agent-builder]

Saat mengonfigurasi agen, Anda dapat melampirkan file dalam kategori yang berbeda:

1. **Unggah Gambar**: Untuk konten visual yang dapat dirujuk oleh agen
2. **Unggahan Pencarian File**: Dokumen untuk kapabilitas RAG
3. **Code Interpreter Upload**: File untuk pemrosesan kode
4. **Konteks Berkas**: Dokumen dengan teks yang diekstrak untuk melengkapi instruksi agen

**File Context** menggunakan kapabilitas `context` dan bekerja persis seperti ["Upload as Text"](/docs/features/upload_as_text) - fitur ini menggunakan penguraian teks secara default dan ditingkatkan dengan OCR saat dikonfigurasi. Teks diekstraksi pada saat pengunggahan dan disimpan dalam instruksi agen. Ini sangat ideal untuk memberikan pengetahuan persisten kepada agen dari dokumen, PDF, file kode, atau gambar yang berisi teks.

**Prioritas pemrosesan:** OCR > STT > penguraian teks (sama dengan Unggah sebagai Teks)

**Catatan:** Teks yang diekstraksi disertakan sebagai bagian dari instruksi sistem agen.

## Berbagi dan Izin [#sharing-and-permissions]

Agen menggunakan sistem [access control](/docs/features/access_control) yang terperinci dari LibreChat. Setiap agen memiliki Access Control List (ACL)-nya sendiri, dan dapat dibagikan kepada **pengguna**, **grup**, **peran**, atau **secara publik**, masing-masing dengan tingkat izin yang dipilih.

### Peran Akses [#access-roles]

Saat membagikan agen, penerima akan diberikan salah satu dari tiga peran berikut:

| Peran | Apa yang dapat dilakukan penerima hak |
| ---------- | ----------------------------------------------------------------------------------------------------- |
| **Viewer** | Menggunakan agen dalam percakapan; tidak dapat membuka builder atau melihat instruksi, tools, atau file yang dilampirkan |
| **Editor** | Melihat + mengubah instruksi, model, tools, dan file agen |
| **Owner**  | Kontrol penuh: melihat, mengedit, menghapus, dan membagikan ulang agen |

Penulis asli dan administrator selalu memegang kendali penuh terlepas dari ACL.

### Berbagi Agen [#sharing-an-agent]

1. Buka agen di Agent Builder
2. Klik tombol **Share** di footer (terlihat saat Anda adalah penulis, admin, atau telah diberikan izin `SHARE` pada agen spesifik tersebut)
3. Cari pengguna, grup, atau peran di pemilih orang (people picker) dan tetapkan peran untuk masing-masing.
4. Secara opsional, aktifkan **Public** untuk membuat agen terlihat oleh semua orang di instance tersebut (memerlukan izin fitur `SHARE_PUBLIC`)

Kartu agen dan tampilan landas menampilkan kontak dukungan yang telah dikonfigurasi. Jika tidak ada yang ditetapkan, LibreChat dapat menggunakan nama tampilan pemilik pertama yang dapat diselesaikan sebagai cadangan, namun tidak akan menampilkan alamat email pemilik kecuali jika dikonfigurasi secara eksplisit sebagai kontak dukungan.

Untuk detail lengkap mengenai prinsipal, bit izin, dan bagaimana ACL disusun dengan izin fitur berbasis peran, lihat [Access Control](/docs/features/access_control).

### Kontrol Administrator [#administrator-controls]

Administrator memiliki akses ke pengaturan izin global di dalam UI pembuat agen:

- Aktifkan/nonaktifkan berbagi agen untuk semua pengguna
- Kontrol izin penggunaan agen
- Kelola hak pembuatan agen
- Konfigurasikan pengaturan seluruh platform

Akun pertama yang dibuat untuk instance Anda adalah administrator. Jika Anda perlu menambahkan administrator tambahan, Anda dapat [mengakses MongoDB](/docs/configuration/mongodb/mongodb_auth) dan memperbarui profil pengguna tersebut:

```
db.users.updateOne(
  { email: 'USER_EMAIL_ADDRESS' },
  { $set: { role: 'ADMIN' } }
)
```

Penggunaan agen untuk semua pengguna juga dapat dinonaktifkan melalui konfigurasi, [informasi lebih lanjut](/docs/configuration/librechat_yaml/object_structure/interface).

Izin tingkat fitur (siapa yang dapat _menggunakan_, _membuat_, _membagikan_, atau _membagikan secara publik_ agen) dikelola dari [**LibreChat Admin Panel**](/docs/features/admin_panel) pada setiap peran, termasuk peran kustom apa pun. Blok [`interface.agents`](/docs/configuration/librechat_yaml/object_structure/interface#agents) di dalam `librechat.yaml` masih dapat menetapkan nilai default untuk peran `USER` bawaan saat startup, namun panel admin adalah cara yang direkomendasikan untuk mengeditnya di masa mendatang.

### Berbagi Tingkat Pengguna [#user-level-sharing]

Pengguna individu dapat:

- Bagikan agen mereka kepada pengguna, grup, atau peran tertentu (jika `SHARE` diaktifkan untuk peran mereka)
- Membuat agen terlihat oleh semua orang di instance (jika `SHARE_PUBLIC` diaktifkan)
- Berikan setiap penerima tingkat akses yang berbeda (Viewer / Editor / Owner)
- Bagikan ulang atau cabut akses kapan saja dari dialog berbagi

## Steering dan Pesan yang Diantrekan [#steering-and-queued-messages]

Saat Agent sedang merespons, Anda dapat mengirim pesan lain dengan salah satu dari dua cara berikut:

- **Steer** menyisipkan pesan ke dalam proses yang sedang berjalan pada langkah alat atau agen berikutnya, sehingga agen dapat menyesuaikan pekerjaannya sebelum selesai.
- **Queue** menampung pesan dan mengirimkannya sebagai giliran tindak lanjut normal setelah respons saat ini selesai.

**Interrupt & steer** menghentikan pembuatan pada batas aman penyedia berikutnya, menyimpan respons parsial, menyisipkan pesan, dan melanjutkan respons asisten yang sama. Gunakan kontrol komposer khusus, pilih dari menu tombol kirim, atau tekan `Command/Ctrl + Shift + .`. Tindakan ini akan kembali ke pengarahan biasa (ordinary steering) jika deployment tidak dapat menginterupsi aliran penyedia yang aktif.

Di bawah **Settings → Chat**, **While generating, Enter will** memilih tindakan default. Menu tombol kirim dapat menggantikan pilihan tersebut untuk pesan individu, dan **Steering interrupts generation** mengontrol apakah steering biasa juga meminta interupsi.

Steer yang tertunda muncul di atas komposer hingga server memasukkannya ke dalam run. Setelah diakui, menu mereka dapat mengambil kembali pesan untuk diedit, mengubahnya menjadi tindak lanjut dalam antrean, atau membatalkannya dan mengembalikan teks serta lampirannya ke komposer. LibreChat menghindari penimpaan draf yang lebih baru; jika komposer tidak lagi tersedia, LibreChat akan menyimpan pesan yang diambil kembali tersebut di dalam antrean. Steer yang gagal tetap tersedia untuk dicoba kembali, diedit, diantrekan, atau dihapus.

Tindak lanjut yang mengantre dapat dikirim segera, diubah menjadi steer saat proses masih aktif, ditingkatkan ke **Interrupt & steer now**, diedit, atau dihapus. Steer yang sedang berlangsung menawarkan peningkatan yang sama saat masih menunggu batas alat. Menghapus pesan yang mengantre akan mengembalikannya ke komposer kosong jika memungkinkan. Satu proses aktif menerima hingga 10 steer tertunda; setiap steer dapat menyertakan hingga 10 file dan dibatasi oleh [`STEER_MAX_LENGTH`](/docs/configuration/dotenv#agent-conversation-controls).

Penyebaran multi-replika yang didukung Redis harus menyelesaikan [peluncuran protokol generasi v2](/docs/configuration/redis#generation-protocol-rollout) sebelum mengandalkan perilaku interupsi dan pemulihan di seluruh replika.

### Catatan [#notes]

- Instruksi, parameter model, file yang dilampirkan, dan alat hanya akan ditampilkan kepada pengguna jika mereka memiliki izin penyuntingan.
  - Agen dapat membocorkan data apa pun yang dilampirkan, baik instruksi maupun file, melalui percakapan, jadi pastikan instruksi Anda cukup kuat untuk menghadapi hal ini sebelum memberikan akses Editor/Owner atau membuat agen tersebut menjadi publik.
- Hanya penulis asli, administrator, dan penerima dengan izin Owner yang dapat menghapus agen yang dibagikan.
- Agen bersifat pribadi bagi penulis kecuali jika dibagikan

## Praktik Terbaik [#best-practices]

- Atur file dengan tepat di seluruh empat kategori unggahan

- Uji agen Anda secara menyeluruh sebelum menyebarkannya ke pengguna lain

## Migrasi Diperlukan (v0.8.0-rc3+) [#migration-required-v080-rc3]

<Callout type="warning" title="Penting: Migrasi Izin Agen Diperlukan">
  Mulai dari versi v0.8.0-rc3, LibreChat menggunakan sistem izin berbasis Access Control List (ACL) yang baru untuk agen. Jika Anda melakukan peningkatan dari versi sebelumnya, Anda harus menjalankan migrasi izin agen agar agen yang sudah ada tetap dapat diakses.
</Callout>

### Apa yang Dilakukan Migrasi Ini [#what-the-migration-does]

Migrasi izin agen mengalihkan agen Anda dari model kepemilikan sederhana ke sistem berbasis ACL yang canggih dengan berbagai tingkat izin:

- **OWNER**: Kontrol penuh atas agen
- **EDITOR**: Dapat melihat dan mengubah agen
- **VIEWER**: Akses baca-saja ke agen

Tanpa menjalankan migrasi ini, agen yang sudah ada tidak akan dapat diakses melalui endpoint API baru yang mendukung izin (permission-aware).

### Menjalankan Migrasi [#running-the-migration]

Pilih perintah yang sesuai berdasarkan metode deployment Anda:

#### 1. Untuk `docker-compose.yml` default (jika Anda menggunakan `docker compose up` untuk memulai aplikasi): [#1-for-the-default-docker-composeyml-if-you-use-docker-compose-up-to-start-the-app]

**Pratinjau perubahan (dry run):**

```bash
docker compose exec api npm run migrate:agent-permissions:dry-run
```

**Jalankan migrasi:**

```bash
docker compose exec api npm run migrate:agent-permissions
```

**Ukuran batch kustom (untuk dataset besar):**

```bash
docker compose exec api npm run migrate:agent-permissions:batch
```

#### 2. Untuk `deploy-compose.yml` [#2-for-the-deploy-composeyml]

Jika Anda mengikuti [Panduan Docker Ubuntu](/docs/remote/docker_linux):

**Pratinjau perubahan (dry run):**

```bash
docker exec -it LibreChat-API /bin/sh -c "cd .. && npm run migrate:agent-permissions:dry-run"
```

**Jalankan migrasi:**

```bash
docker exec -it LibreChat-API /bin/sh -c "cd .. && npm run migrate:agent-permissions"
```

**Ukuran batch kustom (untuk dataset besar):**

```bash
docker exec -it LibreChat-API /bin/sh -c "cd .. && npm run migrate:agent-permissions:batch"
```

#### 3. Untuk pengembangan lokal (dari root proyek): [#3-for-local-development-from-project-root]

**Pratinjau perubahan (dry run):**

```bash
npm run migrate:agent-permissions:dry-run
```

**Jalankan migrasi:**

```bash
npm run migrate:agent-permissions
```

**Ukuran batch kustom (untuk dataset besar):**

```bash
npm run migrate:agent-permissions:batch
```

### Apa yang Terjadi Selama Migrasi [#what-happens-during-migration]

- **Private Agents**: Tetap hanya dapat diakses oleh pembuatnya (menerima izin OWNER)
- **Shared Agents**: Jika agen sebelumnya telah dibagikan, agen tersebut akan menerima entri ACL yang sesuai sebagai Public Agent (dibagikan kepada semua pengguna)
- **Deteksi Sistem**: LibreChat secara otomatis mendeteksi agen yang belum dimigrasi saat startup dan menampilkan peringatan

Anda dapat menyesuaikan izin agen yang dihasilkan melalui UI Agent Builder.

<Callout type="info" title="Catatan">
  Proses migrasi yang sama berlaku untuk prompt. Jika Anda juga memiliki prompt yang sudah ada, jalankan migrasi izin prompt menggunakan perintah yang sama, tetapi ganti `agent` dengan `prompt` pada nama perintah tersebut.
</Callout>

## Apa selanjutnya? [#whats-next]

Agen LibreChat mengantarkan era baru bagi aplikasi ini di mana alur kerja di masa depan dapat disederhanakan melalui Agen untuk tugas dan alur kerja tertentu di seluruh pengalaman Anda di LibreChat.

Pembaruan di masa mendatang akan mencakup:

- Peningkatan umum pada pengalaman Agent saat ini
- Orkestrasi multi-agen untuk alur kerja yang kompleks
- Kemampuan untuk menyesuaikan agen untuk berbagai fungsi: penjudulan (penamaan utas obrolan), manajemen memori (konteks/riwayat pengguna), dan peningkatan prompt (bantuan/prediksi input)
- Lebih banyak alat, parameter alat yang dapat dikonfigurasi, pembuatan alat secara dinamis.

Selain itu, pembaruan ini memperkenalkan paradigma baru bagi LibreChat, karena arsitektur dasarnya memberikan penyegaran yang sangat dibutuhkan untuk aplikasi ini, mengoptimalkan pengalaman pengguna dan kinerja aplikasi secara keseluruhan.

Sebagai sorotan atas satu optimalisasi penting, pembuatan AI sekitar 1000 token akan mentransfer data sebesar kurang lebih 1 MB menggunakan endpoint tradisional (pada saat penulisan ini, opsi endpoint apa pun selain Agents dan AWS Bedrock).

Menggunakan agen, generasi yang sama akan mentransfer sekitar 52 kb data, pengurangan sebesar 95% dalam transfer data, yang berarti beban yang jauh lebih ringan pada server dan perangkat pengguna.
