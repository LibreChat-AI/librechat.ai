Le Skills sono pacchetti di istruzioni riutilizzabili per gli Agent di LibreChat. Una skill è incentrata su un file `SKILL.md`: il frontmatter descrive quando la skill deve essere utilizzata e il corpo in markdown fornisce all'agent la procedura, le regole, gli esempi o i riferimenti da seguire.

Le Skills sono utili per lavori ripetibili come:

- Applicazione delle linee guida del brand o di scrittura
- Seguendo le checklist di revisione interna
- Esecuzione di un flusso di lavoro di ricerca standard
- Preparazione di un flusso di lavoro con strumenti specializzati
- Packaging di script, riferimenti e risorse riutilizzabili con un file di istruzioni

LibreChat non viene fornito con una libreria di skill. Ogni skill proviene dalla tua istanza: [scritta o caricata nell'interfaccia utente](#create-a-skill), [creata da un agente durante una chat](#runtime-skill-authoring), [montata dal file system](#deployment-skills) o [sincronizzata da un repository GitHub](#github-skill-sync).

## Abilita le Skills [#enable-skills]

La funzionalità dell'agente `skills` è abilitata per impostazione predefinita. Gli amministratori possono rimuoverla dall'elenco delle funzionalità dell'endpoint degli agenti per nascondere le Skills agli utenti.

```yaml filename="librechat.yaml"
endpoints:
  agents:
    capabilities:
      - 'deferred_tools'
      - 'execute_code'
      - 'file_search'
      - 'web_search'
      - 'artifacts'
      - 'subagents'
      - 'actions'
      - 'context'
      - 'skills'
      - 'memory'
      - 'ask_user_question'
      - 'tools'
      - 'chain'
      - 'ocr'
```

Le autorizzazioni dei ruoli controllano chi può utilizzare, creare, condividere e condividere pubblicamente le skill. L'utilizzo e la creazione di skill sono consentiti per impostazione predefinita; la condivisione e la condivisione pubblica sono disattivate per impostazione predefinita per i ruoli non amministratore. Gli amministratori possono modificare queste impostazioni dal pannello Skills nelle impostazioni di amministrazione.

Se la funzionalità è disabilitata, o se il tuo ruolo non dispone dell'autorizzazione di utilizzo, Skills non apparirà affatto nel pannello laterale.

## Usa una Skill [#use-a-skill]

<Steps>
<Step>

**Open Skills** dal pannello laterale. Il pannello elenca le skill che possiedi e quelle condivise con te, con una casella di filtro per gli elenchi lunghi. Selezionando una skill si apre la sua pagina, dove puoi leggere le istruzioni e sfogliare i file in essa contenuti.

</Step>
<Step>

**Verifica che la skill sia disponibile.** Ogni skill ha un interruttore **Available to agent**. Le skill di tua proprietà e le skill di distribuzione sono disponibili per impostazione predefinita; le skill condivise seguono l'impostazione predefinita configurata dall'amministratore finché non le sovrascrivi.

</Step>
<Step>

**Dai accesso all'agente.** Nel generatore di agenti, attiva **Enable skills**, quindi decidi se l'agente deve vedere l'intero catalogo o solo le skill che hai selezionato. Vedi [Agent Scope](#agent-scope).

</Step>
<Step>

**Richiama la skill.** Digita `$` nella casella di testo e seleziona una skill per nome. Nulla viene inserito nel testo del tuo messaggio: la skill viene messa in coda per quel turno e mostrata come un chip sopra il compositore. Il modello può anche scegliere una skill autonomamente, e le skill `always-apply` non richiedono alcuna azione.

</Step>
</Steps>

## Crea una Skill [#create-a-skill]

Apri **Skills** dal pannello laterale e usa il pulsante **+**, che offre due percorsi:

- **Scrivi le istruzioni per le skill** — una finestra di dialogo con un nome, una descrizione e il corpo dell'istruzione.
- **Carica una skill** — un file `.md`, `.zip` o `.skill` che contiene un `SKILL.md`.

Un agente può anche creare una skill per te mentre lavora, senza passare attraverso questo pannello. Vedi [Runtime Skill Authoring](#runtime-skill-authoring).

`SKILL.md` minimo:

```md filename="SKILL.md"
---
name: brand-guidelines
description: Use when writing public-facing content that must follow the company voice and terminology.
---

# Brand Guidelines

Write in a concise, practical tone.
Prefer active voice.
Use product terminology consistently.
```

Le chiavi vengono confrontate senza distinzione tra maiuscole e minuscole e i campi booleani accettano solo `true` o `false`. La rimozione di una chiave booleana in un salvataggio successivo la cancella, quindi eliminare `disable-model-invocation` ripristina l'invocazione del modello.

I campi del frontmatter riconosciuti vengono sottoposti a controllo del tipo. I campi non riconosciuti vengono preservati come metadati delimitati e sicuri per JSON invece di rendere lo Skill non valido; i valori di estensione eccessivamente grandi o profondamente annidati vengono comunque rifiutati.

Mantieni la `description` di una Skill invocata dal modello entro i 250 caratteri e posiziona le sue frasi di attivazione più importanti all'inizio. Descrizioni più lunghe possono comunque essere importate, ma LibreChat le tronca nel catalogo visibile al modello e registra un avviso indicando ogni Skill interessata.

### Limiti di denominazione e dimensione [#naming-and-size-limits]

- `name` è obbligatorio, deve corrispondere a `^[a-z0-9][a-z0-9-]*$` ed è limitato a 64 caratteri. Deve essere univoco tra le tue competenze; il caricamento di un nome già esistente fallirà con un errore di conflitto invece di sovrascriverlo.
- I nomi non possono iniziare con `anthropic-` o `claude-` e non possono essere esattamente `help`, `clear`, `compact`, `model`, `exit`, `quit`, `settings`, `anthropic` o `claude`. Tali nomi oscurerebbero i comandi reali.
- `description` è obbligatorio e limitato a 1024 caratteri. Le descrizioni inferiori a 20 caratteri sono accettate con un avviso, poiché raramente si attivano in modo affidabile.
- Il corpo dell'istruzione è limitato a 100.000 caratteri.

### Carica un Bundle [#upload-a-bundle]

Un archivio `.zip` o `.skill` deve contenere `SKILL.md` nella root dell'archivio o esattamente all'interno di una singola cartella. Una singola cartella di avvolgimento viene rimossa durante l'importazione; layout più profondi non vengono rilevati.

<FileTree>
  <FileTree.Folder name="brand-guidelines" defaultOpen>
    <FileTree.File name="SKILL.md" />
    <FileTree.Folder name="references" defaultOpen>
      <FileTree.File name="tone-examples.md" />
    </FileTree.Folder>
    <FileTree.Folder name="scripts">
      <FileTree.File name="lint-copy.py" />
    </FileTree.Folder>
  </FileTree.Folder>
</FileTree>

Limiti di importazione:

- Estensioni accettate: `.md`, `.zip`, `.skill`.
- 50 MB per caricamento come impostazione predefinita. Gli amministratori possono modificarlo con [`fileConfig.skills.fileSizeLimit`](/docs/configuration/librechat_yaml/object_structure/file_config#skills) in `librechat.yaml`.
- Fino a 500 voci per archivio e 10 MB per file raggruppato.
- Un caricamento `.md` senza `name` nel frontmatter deriva il nome della skill dal nome del file.
- Le voci con percorsi non sicuri, come i percorsi di attraversamento o assoluti, vengono segnalate come errori e ignorate; il resto della skill viene comunque importato.

Le Skills che provengono da `DEPLOYMENT_SKILLS_DIR` o da GitHub Skill Sync sono di sola lettura. Solo le Skills create all'interno di LibreChat possono essere modificate nell'interfaccia utente.

## Modalità di invocazione [#invocation-modes]

Le Skills possono raggiungere un agente in tre modi:

- **Manuale**: l'utente digita `$` nella chat e seleziona una skill dal popover.
- **Model-invoked**: il modello sceglie una skill dal catalogo delle skill iniettato e richiama lo strumento della skill.
- **Always apply**: l'abilità viene preparata in ogni turno quando attiva.

Ciò che entra effettivamente nel contesto differisce in base al percorso:

- Il catalogo richiamato dal modello contiene solo nomi e descrizioni, fino a 100 competenze, con ogni voce ridotta a circa 250 caratteri. I corpi delle istruzioni non fanno parte del catalogo.
- L'invocazione manuale e quella "always-apply" preparano l'intero corpo di `SKILL.md` per quel turno, fino a un massimo di 10 skill manuali e 20 "always-apply", con un limite combinato di 30. Quando il limite combinato viene superato, le skill "always-apply" vengono rimosse per prime, in modo che l'intento esplicito dell'utente venga preservato.

L'invocazione manuale è un'intenzione esplicita dell'utente. Può utilizzare skill che sono nascoste dall'invocazione del modello con `disable-model-invocation: true`, a condizione che `user-invocable` non sia false.

## Ambito dell'agente [#agent-scope]

Gli Agents devono avere **Enable skills** attivato prima di poter utilizzare o creare Skills. L'interruttore separato **Use all skills** controlla l'esposizione nel catalogo.

- **Tutti:** attiva **Use all skills** per esporre l'intero catalogo attivo visibile all'utente, incluse le Skills aggiunte in seguito.
- **Selezionato:** lascia **Use all skills** disattivato e aggiungi le singole Skills per esporre solo quelle voci.
- **Solo per la creazione:** lascia disattivato **Use all skills** senza selezionare alcuna Skill. Le voci di catalogo esistenti non vengono esposte, ma l'agente può creare una Skill durante una conversazione quando l'utente dispone dell'autorizzazione per creare Skill.
- **Disabilitato:** disattiva **Enable skills** per disabilitare sia l'uso del catalogo che la creazione in runtime.

Ciò consente agli amministratori di esporre la funzionalità Skills a livello globale, mantenendo al contempo focalizzato l'insieme di skill utilizzabili da ciascun agente.

Disattivando **Use all skills** viene ripristinata la selezione che era attiva prima dell'attivazione dell'interruttore. Gli agenti esistenti mantengono il comportamento legacy in cui le Skills abilitate senza un ambito esplicito indicano l'intero catalogo.

## Creazione di Skill in Runtime [#runtime-skill-authoring]

Un agente con le Skills abilitate può creare o modificare file di Skill riutilizzabili mentre è in funzione. I file di runtime utilizzano lo stesso namespace `skills/{skillName}/...` dei bundle caricati, quindi l'agente può creare `SKILL.md` e riferimenti, script o risorse di supporto come parte di un flusso di lavoro riuscito.

La creazione segue il normale modello di autorizzazione delle Skills:

- La creazione di una nuova Skill richiede il permesso **Create** (Crea) della Skill dell'utente.
- La modifica di una Skill esistente richiede sia l'accesso in modifica che l'inclusione nell'ambito del catalogo attivo dell'agente; le Skill distribuite e sincronizzate con GitHub rimangono in sola lettura.
- Un agente di sola creazione (authoring-only) può creare una nuova Skill senza ricevere il catalogo esistente dell'utente.

La creazione in fase di runtime non aggira la funzionalità di distribuzione o le autorizzazioni utente. La rimozione di `skills` dalle funzionalità dell'endpoint Agents nasconde la funzione e la disattivazione di **Enable skills** sull'agente disabilita i suoi strumenti di creazione.

## Skill attive e condivise [#active-and-shared-skills]

Gli utenti possono attivare o disattivare le competenze con l'interruttore **Available to agent**. Le competenze possedute e quelle distribuite sono attive per impostazione predefinita. Le competenze condivise utilizzano l'impostazione predefinita configurata dall'amministratore finché l'utente non le sovrascrive.

Le competenze inattive sono escluse da:

- Il popover `$`
- Il catalogo delle abilità richiamate dal modello
- Priming sempre applicato

Condividere una skill garantisce l'accesso come visualizzatore, editor o proprietario a utenti, gruppi o ruoli specifici tramite la finestra di dialogo di condivisione standard e richiede il permesso di condivisione nel proprio ruolo. Consulta [Access Control](/docs/features/access_control) per il modello completo.

## File in bundle [#bundled-files]

I bundle di skill caricati possono includere file insieme a `SKILL.md`, come ad esempio:

- `references/...`
- `scripts/...`
- `assets/...`

Il backend archivia quei file insieme alla skill. L'agente può risolvere i file della skill quando la skill è attiva e nel contesto. I file nidificati mantengono i loro percorsi relativi e vengono indirizzati tramite lo spazio dei nomi `skills/{skillName}/...` rivolto al modello. Nel visualizzatore di Skill, i link Markdown relativi vengono risolti a partire dal file corrente e aprono il file di riferimento all'interno della stessa Skill. Quando Code Interpreter è abilitato, gli stessi file vengono montati in `/mnt/data/skills/{skillName}/...` in modo che le operazioni di shell e di codice possano utilizzarli direttamente. La modifica di `SKILL.md` fa avanzare la versione della Skill; prima dell'esecuzione del codice o dell'esecuzione programmatica, LibreChat verifica che ogni riferimento al file montato corrisponda a quella versione e ricarica l'intero pacchetto quando un riferimento risulta non aggiornato.

La pagina di una skill dispone anche di un albero dei file con le azioni **Nuovo file**, **Nuova cartella** e **Carica file**, fino a 10 MB per file aggiunto. `SKILL.md` stesso è riservato in quella posizione: modifica invece il corpo della skill.

<Callout type="note" title="Suggerimento per la creazione">
  Mantieni la `description` specifica. È il segnale più forte per le competenze richiamate dal modello. Una descrizione breve o vaga porterà a un sotto-utilizzo.
</Callout>

## Competenze di Deployment [#deployment-skills]

Gli amministratori possono distribuire Skills in sola lettura dal filesystem con `DEPLOYMENT_SKILLS_DIR`.

```bash filename=".env"
DEPLOYMENT_SKILLS_DIR=./skill
```

La directory predefinita è `./skill` nella root del progetto. Ogni skill risiede nella propria sottodirectory contenente un `SKILL.md`, con eventuali file in bundle accanto ad esso. LibreChat carica le Skill di deployment all'avvio e le espone agli utenti con la funzionalità Skills abilitata.

Competenze di distribuzione:

- Sono di sola lettura nell'interfaccia utente
- Usa `deployment` come loro origine
- Hanno la precedenza sulle Skills persistenti con lo stesso nome
- È necessario riavviare LibreChat dopo che i file sono stati aggiunti, rimossi o modificati

I [Agent Plugins](/docs/features/agent_plugins) sperimentali possono anche raggruppare Skill di distribuzione in sola lettura insieme ai server MCP correlati. Una Skill nella directory di distribuzione standalone ha la precedenza su una Skill di un plugin con lo stesso nome.

## Sincronizzazione delle Skill di GitHub [#github-skill-sync]

Gli amministratori possono replicare le Skills dai repository GitHub con `skillSync.github` in `librechat.yaml`. Questo è il metodo pratico per condividere un set curato di skills all'interno di un team.

```yaml filename="librechat.yaml"
skillSync:
  github:
    enabled: true
    intervalMinutes: 60
    runOnStartup: true
    sources:
      - id: librechat-skills
        owner: your-org
        repo: your-skills-repo
        ref: main
        paths:
          - skills
        skillDiscoveryDepth: 2
        token: '${GITHUB_SKILLS_TOKEN}'
```

Sincronizzazione competenze GitHub:

- Scansiona i percorsi del repository configurati alla ricerca di `SKILL.md`
- Tratta la directory contenente ogni `SKILL.md` come una root di skill, entro i livelli `skillDiscoveryDepth` del percorso configurato
- Importa i file in bundle accanto a ogni skill
- Memorizza le Skills replicate con `source: "github"`
- Aggiorna le Skills replicate quando il repository upstream cambia
- Rimuove le Skill specchiate che non esistono più nella sorgente configurata
- Pubblica le Skill valide anche quando un'altra Skill nella sorgente non è valida o è in conflitto
- Segnala agli amministratori le esecuzioni parzialmente riuscite e i dettagli delle Skill ignorate limitate
- Supporta esecuzioni pianificate, all'avvio e attivate manualmente dall'amministratore

Una Skill ignorata mantiene il suo ultimo mirror funzionante noto, quando ne esiste uno. Errori a livello di origine, come autenticazione, limitazione della frequenza (rate limiting), perdita della proprietà di sincronizzazione o un rollback non riuscito, causano comunque il fallimento dell'intera esecuzione dell'origine.

Utilizza un personal access token fine-grained di GitHub con permessi di sola lettura (read-only) per Contents e Metadata per il repository selezionato. Consulta [Skill Sync Object Structure](/docs/configuration/librechat_yaml/object_structure/skill_sync) per tutti i campi, le opzioni di credenziali, l'ambito del tenant e gli endpoint di sincronizzazione dell'amministratore.
