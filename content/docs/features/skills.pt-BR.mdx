Skills são pacotes de instruções reutilizáveis para Agentes do LibreChat. Uma skill é centrada em um arquivo `SKILL.md`: o frontmatter descreve quando a skill deve ser usada, e o corpo em markdown fornece ao agente o procedimento, regras, exemplos ou referências a serem seguidos.

Skills são úteis para trabalhos repetíveis, tais como:

- Aplicando diretrizes de marca ou escrita
- Seguindo checklists de revisão interna
- Executando um fluxo de trabalho de pesquisa padrão
- Preparando um fluxo de trabalho de ferramenta especializada
- Empacotando scripts, referências e ativos reutilizáveis com um arquivo de instrução

O LibreChat não vem com uma biblioteca de habilidades. Cada habilidade vem da sua própria instância: [escrita ou carregada na UI](#create-a-skill), [criada por um agente durante um chat](#runtime-skill-authoring), [montada a partir do sistema de arquivos](#deployment-skills) ou [espelhada de um repositório do GitHub](#github-skill-sync).

## Habilitar Skills [#enable-skills]

A capacidade de agente `skills` está habilitada por padrão. Administradores podem removê-la da lista de capacidades do endpoint de agentes para ocultar as Skills dos usuários.

```yaml filename="librechat.yaml"
endpoints:
  agents:
    capabilities:
      - 'deferred_tools'
      - 'execute_code'
      - 'file_search'
      - 'web_search'
      - 'artifacts'
      - 'subagents'
      - 'actions'
      - 'context'
      - 'skills'
      - 'memory'
      - 'ask_user_question'
      - 'tools'
      - 'chain'
      - 'ocr'
```

As permissões de função controlam quem pode usar, criar, compartilhar e compartilhar publicamente skills. O uso e a criação de skills são permitidos por padrão; o compartilhamento e o compartilhamento público estão desativados por padrão para funções que não sejam de administrador. Os administradores alteram essas configurações nas configurações de administrador no painel de Skills.

Se a funcionalidade estiver desativada, ou se sua função não tiver a permissão de uso, Skills não aparecerá no painel lateral.

## Usar uma Skill [#use-a-skill]

<Steps>
<Step>

**Open Skills** no painel lateral. O painel lista as skills que você possui e as skills compartilhadas com você, com uma caixa de filtro para listas longas. Selecionar uma skill abre sua página, onde você pode ler as instruções e navegar pelos arquivos agrupados.

</Step>
<Step>

**Verifique se a skill está disponível.** Cada skill possui uma chave **Available to agent**. Skills que você possui e skills de implantação são definidas como disponíveis por padrão; skills compartilhadas seguem o padrão configurado pelo administrador até que você as substitua.

</Step>
<Step>

**Dê acesso ao agente.** No construtor de agentes, ative **Enable skills**, então decida se o agente verá o catálogo completo ou apenas as skills que você escolher. Veja [Agent Scope](#agent-scope).

</Step>
<Step>

**Invoque a skill.** Digite `$` na caixa de mensagem e selecione uma skill pelo nome. Nada é inserido no texto da sua mensagem: a skill é colocada na fila para aquele turno e exibida como um chip acima do compositor. O modelo também pode escolher uma skill por conta própria, e skills com `always-apply` não precisam de nenhuma ação.

</Step>
</Steps>

## Criar uma Skill [#create-a-skill]

Abra **Skills** no painel lateral e use o botão **+**, que oferece dois caminhos:

- **Escrever instruções de habilidade** — uma caixa de diálogo com um nome, uma descrição e o corpo da instrução.
- **Upload a skill** — um arquivo `.md`, `.zip` ou `.skill` que contenha um `SKILL.md`.

Um agente também pode criar uma skill para você enquanto trabalha, sem precisar passar por este painel. Veja [Runtime Skill Authoring](#runtime-skill-authoring).

`SKILL.md` mínimo:

```md filename="SKILL.md"
---
name: brand-guidelines
description: Use when writing public-facing content that must follow the company voice and terminology.
---

# Brand Guidelines

Write in a concise, practical tone.
Prefer active voice.
Use product terminology consistently.
```

As chaves são comparadas sem diferenciar maiúsculas de minúsculas, e os campos booleanos aceitam apenas `true` ou `false`. Remover uma chave booleana em um salvamento posterior a limpa, portanto, excluir `disable-model-invocation` restaura a invocação de modelo.

Campos de frontmatter reconhecidos são verificados quanto ao tipo. Campos não reconhecidos são preservados como metadados limitados e seguros para JSON, em vez de tornar a Skill inválida; valores de extensão excessivamente grandes ou profundamente aninhados ainda são rejeitados.

Mantenha a `description` de uma Skill invocada por modelo com 250 caracteres ou menos e coloque suas frases de gatilho mais importantes primeiro. Descrições mais longas ainda podem ser importadas, mas o LibreChat as truncará no catálogo visível ao modelo e registrará um aviso nomeando cada Skill afetada.

### Limites de Nome e Tamanho [#naming-and-size-limits]

- `name` é obrigatório, deve corresponder a `^[a-z0-9][a-z0-9-]*$` e é limitado a 64 caracteres. Ele deve ser único entre suas próprias skills; reenviar um nome existente falhará com um erro de conflito em vez de sobrescrever.
- Nomes não podem começar com `anthropic-` ou `claude-`, e não podem ser exatamente `help`, `clear`, `compact`, `model`, `exit`, `quit`, `settings`, `anthropic` ou `claude`. Esses nomes ocultariam comandos reais.
- `description` é obrigatório e limitado a 1024 caracteres. Descrições com menos de 20 caracteres são aceitas com um aviso, pois raramente são acionadas de forma confiável.
- O corpo da instrução é limitado a 100.000 caracteres.

### Fazer upload de um Bundle [#upload-a-bundle]

Um arquivo `.zip` ou `.skill` deve conter um `SKILL.md` na raiz do arquivo ou exatamente em uma subpasta. Uma única pasta de encapsulamento é removida na importação; layouts mais profundos não são detectados.

    <FileTree.Folder name="references" defaultOpen>
      <FileTree.File name="tone-examples.md" />

    </FileTree.Folder>
  </FileTree.Folder>

Limites de importação:

- Extensões aceitas: `.md`, `.zip`, `.skill`.
- 50 MB por upload por padrão. Administradores podem alterar isso com [`fileConfig.skills.fileSizeLimit`](/docs/configuration/librechat_yaml/object_structure/file_config#skills) no `librechat.yaml`.
- Até 500 entradas por arquivo, e 10 MB por arquivo agrupado.
- Um upload `.md` sem `name` no frontmatter deriva o nome da skill a partir do nome do arquivo.
- Entradas com caminhos inseguros, como travessia de diretório ou caminhos absolutos, são relatadas como erros e ignoradas; o restante da skill ainda é importado.

Habilidades provenientes de `DEPLOYMENT_SKILLS_DIR` ou do GitHub Skill Sync são somente leitura. Apenas habilidades criadas dentro do LibreChat podem ser editadas na interface.

## Modos de Invocação [#invocation-modes]

As Skills podem chegar a um agente de três maneiras:

- **Manual**: o usuário digita `$` no chat e seleciona uma skill a partir do popover.
- **Model-invoked**: o modelo escolhe uma skill do catálogo de skills injetado e chama a ferramenta da skill.
- **Sempre aplicar**: a skill é preparada em cada turno quando ativa.

O que realmente entra no contexto difere por caminho:

- O catálogo invocado pelo modelo contém apenas nomes e descrições, com até 100 habilidades, sendo cada entrada limitada a aproximadamente 250 caracteres. Os corpos das instruções não fazem parte do catálogo.
- A invocação manual e a de aplicação sempre preparam o corpo completo do `SKILL.md` para aquele turno, até 10 habilidades manuais e 20 de aplicação sempre, e 30 combinadas. Quando o limite combinado é excedido, as habilidades de aplicação sempre são descartadas primeiro para que a intenção explícita do usuário seja preservada.

A invocação manual é uma intenção explícita do usuário. Ela pode usar skills que estão ocultas da invocação do modelo com `disable-model-invocation: true`, desde que `user-invocable` não seja false.

## Escopo do Agente [#agent-scope]

Agentes devem estar com **Enable skills** ativado antes que possam usar ou criar Skills. A chave separada **Use all skills** controla a exposição no catálogo.

- **All:** ative **Use all skills** para expor o catálogo ativo completo visível ao usuário, incluindo Skills adicionadas posteriormente.
- **Selecionado:** deixe **Use all skills** desativado e adicione Skills individuais para expor apenas essas entradas.
- **Apenas para autoria:** deixe **Use all skills** desativado sem nenhuma Skill selecionada. As entradas de catálogo existentes não são expostas, mas o agente pode criar uma Skill durante uma conversa quando o usuário tiver permissão de criação de Skill.
- **Desativado:** desative **Enable skills** para desabilitar tanto o uso do catálogo quanto a criação em tempo de execução.

Isso permite que administradores exponham o recurso de Skills globalmente, mantendo o conjunto de habilidades utilizáveis de cada agente focado.

Desativar **Use all skills** restaura a seleção que estava ativa antes de o botão ser ativado. Agentes existentes mantêm o comportamento legado, onde Skills ativadas sem um escopo explícito significam o catálogo completo.

## Criação de Habilidades em Tempo de Execução [#runtime-skill-authoring]

Um agente com Skills habilitadas pode criar ou editar arquivos de Skill reutilizáveis enquanto trabalha. Os arquivos de tempo de execução usam o mesmo namespace `skills/{skillName}/...` que os pacotes enviados, portanto, o agente pode criar o `SKILL.md` e referências, scripts ou ativos de suporte como parte de um fluxo de trabalho bem-sucedido.

A autoria segue o modelo de permissão de Skills normal:

- Criar uma nova Skill requer a permissão de **Create** (Criar) de Skill do usuário.
- Editar uma Skill existente requer tanto acesso de edição quanto inclusão no escopo do catálogo ativo do agente; Skills implantadas e sincronizadas com o GitHub permanecem somente leitura.
- Um agente apenas de autoria pode criar uma nova Skill sem receber o catálogo existente do usuário.

A criação em tempo de execução (runtime authoring) não ignora a capacidade de implantação ou as permissões do usuário. Remover `skills` das capacidades do endpoint Agents oculta o recurso, e desativar **Enable skills** no agente desabilita suas ferramentas de criação.

## Habilidades Ativas e Compartilhadas [#active-and-shared-skills]

Os usuários podem alternar as skills entre ativas ou inativas com a chave **Available to agent**. Skills próprias e de implantação são ativas por padrão. Skills compartilhadas usam o padrão configurado pelo administrador até que o usuário as substitua.

Habilidades inativas são excluídas de:

- O popover `$`
- O catálogo de habilidades invocadas pelo modelo
- Sempre aplicar priming

Compartilhar uma skill concede acesso de visualizador, editor ou proprietário a usuários, grupos ou funções específicos por meio da caixa de diálogo de compartilhamento padrão, e requer a permissão de compartilhamento em sua função. Consulte [Access Control](/docs/features/access_control) para o modelo completo.

## Arquivos Agrupados [#bundled-files]

Os pacotes de habilidades (skill bundles) enviados podem incluir arquivos juntamente com o `SKILL.md`, tais como:

- `references/...`
- `scripts/...`
- `assets/...`

O backend armazena esses arquivos com a skill. O agente pode resolver arquivos de skill quando a skill está ativa e no escopo. Arquivos aninhados mantêm seus caminhos relativos e são endereçados através do namespace `skills/{skillName}/...` voltado para o modelo. No visualizador de Skill, links Markdown relativos são resolvidos a partir do arquivo atual e abrem o arquivo referenciado dentro da mesma Skill. Quando o Code Interpreter está habilitado, os mesmos arquivos são montados em `/mnt/data/skills/{skillName}/...` para que operações de shell e código possam utilizá-los diretamente. Editar o `SKILL.md` avança a versão da Skill; antes da execução de código ou programática, o LibreChat verifica se cada referência de arquivo montado corresponde a essa versão e faz o re-upload do pacote completo quando qualquer referência está desatualizada.

A página de uma skill também possui uma árvore de arquivos com ações para **New File**, **New Folder** e **Upload File**, com até 10 MB por arquivo adicionado. O próprio `SKILL.md` está reservado lá: edite o corpo da skill em vez disso.

<Callout type="note" title="Dica de autoria">
  Mantenha a `description` específica. É o sinal mais forte para habilidades invocadas pelo modelo. Uma descrição curta ou vaga causará subativação.
</Callout>

## Habilidades de Implantação [#deployment-skills]

Admins podem disponibilizar Skills somente leitura a partir do sistema de arquivos com `DEPLOYMENT_SKILLS_DIR`.

```bash filename=".env"
DEPLOYMENT_SKILLS_DIR=./skill
```

O diretório padrão é `./skill` na raiz do projeto. Cada skill reside em seu próprio subdiretório contendo um `SKILL.md`, com quaisquer arquivos agrupados ao lado dele. O LibreChat carrega as Skills de implantação na inicialização e as expõe aos usuários com a funcionalidade Skills habilitada.

Habilidades de Implantação:

- São somente leitura na UI
- Use `deployment` como sua fonte
- Têm precedência sobre Skills persistidas com o mesmo nome
- Requer uma reinicialização do LibreChat após arquivos serem adicionados, removidos ou alterados

[Agent Plugins](/docs/features/agent_plugins) experimentais também podem agrupar Skills de implantação somente leitura com servidores MCP relacionados. Uma Skill no diretório de implantação autônomo tem precedência sobre uma Skill de plugin com o mesmo nome.

## GitHub Skill Sync [#github-skill-sync]

Admins podem espelhar Skills de repositórios do GitHub com `skillSync.github` no `librechat.yaml`. Esta é a maneira prática de compartilhar um conjunto curado de skills com toda a equipe.

```yaml filename="librechat.yaml"
skillSync:
  github:
    enabled: true
    intervalMinutes: 60
    runOnStartup: true
    sources:
      - id: librechat-skills
        owner: your-org
        repo: your-skills-repo
        ref: main
        paths:
          - skills
        skillDiscoveryDepth: 2
        token: '${GITHUB_SKILLS_TOKEN}'
```

Sincronização de Habilidades do GitHub:

- Verifica caminhos de repositório configurados em busca de `SKILL.md`
- Trata o diretório que contém cada `SKILL.md` como uma raiz de skill, dentro dos níveis de `skillDiscoveryDepth` do caminho configurado
- Importa arquivos agrupados ao lado de cada skill
- Armazena Skills espelhadas com `source: "github"`
- Atualiza as Skills espelhadas quando o repositório upstream é alterado
- Remove Skills espelhadas que não existem mais na fonte configurada
- Publica Skills válidas mesmo quando outra Skill na fonte é inválida ou entra em conflito
- Relata execuções parcialmente bem-sucedidas e detalhes de Skill ignoradas limitadas aos administradores
- Suporta execuções agendadas, na inicialização e acionadas manualmente pelo administrador

Uma Skill ignorada mantém seu último espelho conhecido como bom quando um existe. Falhas em toda a fonte, como autenticação, limitação de taxa, perda de propriedade de sincronização ou uma reversão malsucedida, ainda causam a falha da execução completa da fonte.

Use um personal access token do tipo fine-grained do GitHub com permissões de leitura (read-only) para Contents e Metadata no repositório selecionado. Consulte [Skill Sync Object Structure](/docs/configuration/librechat_yaml/object_structure/skill_sync) para todos os campos, opções de credenciais, escopo de tenant e endpoints de sincronização de administrador.
