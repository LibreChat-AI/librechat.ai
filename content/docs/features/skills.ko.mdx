Skills는 LibreChat 에이전트를 위한 재사용 가능한 명령어 번들입니다. Skill은 `SKILL.md` 파일을 중심으로 구성됩니다. 프런트매터(frontmatter)는 해당 Skill을 언제 사용해야 하는지 설명하며, 마크다운 본문은 에이전트가 따라야 할 절차, 규칙, 예시 또는 참조 정보를 제공합니다.

Skills는 다음과 같은 반복 가능한 작업에 유용합니다:

- 브랜드 또는 작성 가이드라인 적용하기
- 내부 검토 체크리스트 따르기
- 표준 연구 워크플로우 실행하기
- 특화된 도구 워크플로우 준비하기
- 재사용 가능한 스크립트, 참조 자료 및 에셋을 지침 파일과 함께 패키징하기

LibreChat은 기본적으로 제공되는 스킬 라이브러리가 없습니다. 모든 스킬은 사용자의 인스턴스에서 직접 생성됩니다: [UI에서 작성 또는 업로드](#create-a-skill), [채팅 중 에이전트가 작성](#runtime-skill-authoring), [파일 시스템에서 마운트](#deployment-skills), 또는 [GitHub 저장소에서 미러링](#github-skill-sync).

## 스킬 활성화 [#enable-skills]

`skills` 에이전트 기능은 기본적으로 활성화되어 있습니다. 관리자는 에이전트 엔드포인트 기능 목록에서 이를 제거하여 사용자에게서 Skills를 숨길 수 있습니다.

```yaml filename="librechat.yaml"
endpoints:
  agents:
    capabilities:
      - 'deferred_tools'
      - 'execute_code'
      - 'file_search'
      - 'web_search'
      - 'artifacts'
      - 'subagents'
      - 'actions'
      - 'context'
      - 'skills'
      - 'memory'
      - 'ask_user_question'
      - 'tools'
      - 'chain'
      - 'ocr'
```

역할 권한은 누가 스킬을 사용, 생성, 공유 및 공개 공유할 수 있는지 제어합니다. 스킬 사용 및 생성은 기본적으로 허용되지만, 공유 및 공개 공유는 관리자가 아닌 역할의 경우 기본적으로 꺼져 있습니다. 관리자는 스킬 패널의 관리자 설정에서 이를 변경할 수 있습니다.

기능이 비활성화되어 있거나 사용자의 역할에 사용 권한이 없는 경우, 사이드 패널에 Skills가 전혀 표시되지 않습니다.

## 스킬 사용하기 [#use-a-skill]

<Steps>
<Step>

사이드 패널에서 **Open Skills**를 선택하세요. 패널에는 사용자가 소유한 스킬과 공유받은 스킬이 나열되며, 목록이 길 경우를 대비한 필터 상자가 제공됩니다. 스킬을 선택하면 해당 페이지가 열리며, 여기서 지침을 읽고 포함된 파일을 탐색할 수 있습니다.

</Step>
<Step>

**스킬이 사용 가능한지 확인하세요.** 각 스킬에는 **Available to agent** 스위치가 있습니다. 본인이 소유한 스킬과 배포 스킬은 기본적으로 사용 가능으로 설정됩니다. 공유 스킬은 사용자가 재정의하기 전까지 관리자가 구성한 기본값을 따릅니다.

</Step>
<Step>

**에이전트에게 액세스 권한을 부여하세요.** 에이전트 빌더에서 **Enable skills**를 켜고, 에이전트가 전체 카탈로그를 볼지 아니면 선택한 스킬만 볼지 결정하세요. [Agent Scope](#agent-scope)를 참조하세요.

</Step>
<Step>

**스킬 호출.** 메시지 입력창에 `$`를 입력하고 이름으로 스킬을 선택하세요. 메시지 텍스트에는 아무것도 삽입되지 않으며, 해당 턴을 위해 스킬이 대기열에 추가되고 입력창 위에 칩 형태로 표시됩니다. 모델이 스스로 스킬을 선택할 수도 있으며, `always-apply` 스킬은 별도의 작업이 필요하지 않습니다.

</Step>
</Steps>

## 스킬 생성하기 [#create-a-skill]

사이드 패널에서 **Skills**를 열고 **+** 버튼을 사용하세요. 이 버튼은 두 가지 경로를 제공합니다:

- **스킬 지침 작성** — 이름, 설명, 지침 본문이 포함된 대화 상자입니다.
- **스킬 업로드** — `SKILL.md`를 포함하는 `.md`, `.zip` 또는 `.skill` 파일입니다.

에이전트는 이 패널을 거치지 않고 작업하는 동안 직접 스킬을 생성할 수도 있습니다. [Runtime Skill Authoring](#runtime-skill-authoring)을 참조하세요.

최소 `SKILL.md`:

```md filename="SKILL.md"
---
name: brand-guidelines
description: Use when writing public-facing content that must follow the company voice and terminology.
---

# Brand Guidelines

Write in a concise, practical tone.
Prefer active voice.
Use product terminology consistently.
```

키는 대소문자를 구분하지 않으며, 불리언 필드는 `true` 또는 `false`만 허용합니다. 이후 저장 시 불리언 키를 제거하면 해당 설정이 초기화되므로, `disable-model-invocation`을 삭제하면 모델 호출이 다시 활성화됩니다.

인식된 frontmatter 필드는 타입 검사를 거칩니다. 인식되지 않은 필드는 Skill을 무효화하는 대신 제한된 JSON 안전 메타데이터로 보존됩니다. 단, 깊게 중첩되거나 크기가 너무 큰 확장 값은 여전히 거부됩니다.

모델이 호출하는 Skill의 `description`은 250자 이하로 유지하고 가장 중요한 트리거 문구를 앞부분에 배치하세요. 더 긴 설명도 가져올 수는 있지만, LibreChat은 모델이 볼 수 있는 카탈로그에서 이를 잘라내며 영향을 받는 각 Skill의 이름을 로그에 경고로 기록합니다.

### 명명 및 크기 제한 [#naming-and-size-limits]

- `name`은 필수 항목이며, `^[a-z0-9][a-z0-9-]*$` 정규식을 만족해야 하고, 64자 이내여야 합니다. 이는 사용자의 스킬들 사이에서 고유해야 하며, 기존 이름을 다시 업로드하면 덮어쓰기 대신 충돌 오류가 발생합니다.
- 이름은 `anthropic-` 또는 `claude-`로 시작할 수 없으며, `help`, `clear`, `compact`, `model`, `exit`, `quit`, `settings`, `anthropic`, `claude`와 정확히 일치할 수 없습니다. 이러한 이름은 실제 명령어를 가릴 수 있기 때문입니다.
- `description`은 필수 항목이며 1024자로 제한됩니다. 20자 미만의 설명은 거의 안정적으로 트리거되지 않기 때문에 경고와 함께 허용됩니다.
- 지침 본문은 100,000자로 제한됩니다.

### 번들 업로드 [#upload-a-bundle]

`.zip` 또는 `.skill` 아카이브는 아카이브 루트 또는 루트에서 정확히 한 단계 아래 폴더에 `SKILL.md`를 포함해야 합니다. 단일 래핑 폴더는 가져올 때 제거되지만, 더 깊은 구조는 검색되지 않습니다.

가져오기 제한:

- 허용되는 확장자: `.md`, `.zip`, `.skill`.
- 기본적으로 업로드당 50 MB로 제한됩니다. 관리자는 `librechat.yaml`의 [`fileConfig.skills.fileSizeLimit`](/docs/configuration/librechat_yaml/object_structure/file_config#skills)을 통해 이를 변경할 수 있습니다.
- 아카이브당 최대 500개의 항목, 번들 파일당 최대 10 MB까지 가능합니다.
- frontmatter `name`이 없는 `.md` 업로드는 파일 이름에서 스킬 이름을 가져옵니다.
- 트래버스(traversal) 또는 절대 경로와 같이 안전하지 않은 경로가 포함된 항목은 오류로 보고되고 건너뛰어지며, 나머지 스킬은 계속해서 가져오기가 진행됩니다.

`DEPLOYMENT_SKILLS_DIR` 또는 GitHub Skill Sync에서 가져온 스킬은 읽기 전용입니다. LibreChat 내부에서 작성된 스킬만 UI에서 편집할 수 있습니다.

## 호출 모드 (Invocation Modes) [#invocation-modes]

Skills는 다음 세 가지 방식으로 에이전트에 도달할 수 있습니다:

- **Manual**: 사용자가 채팅창에 `$`를 입력하고 팝오버에서 스킬을 선택합니다.
- **Model-invoked**: 모델이 주입된 스킬 카탈로그에서 스킬을 선택하고 해당 스킬 도구를 호출합니다.
- **Always apply**: 활성화 시 모든 턴에 해당 스킬이 적용됩니다.

실제로 컨텍스트에 포함되는 내용은 경로에 따라 다릅니다:

- 모델이 호출하는 카탈로그에는 이름과 설명만 포함되며, 최대 100개의 스킬을 담을 수 있고 각 항목은 약 250자로 제한됩니다. 지침 본문은 카탈로그에 포함되지 않습니다.
- 수동 및 상시 적용(always-apply) 호출은 해당 턴에 대해 전체 `SKILL.md` 본문을 준비하며, 최대 10개의 수동 스킬과 20개의 상시 적용 스킬, 그리고 합산하여 최대 30개의 스킬을 처리합니다. 합산 제한을 초과할 경우, 명시적인 사용자 의도가 유지되도록 상시 적용 스킬이 우선적으로 제외됩니다.

수동 호출은 명시적인 사용자 의도입니다. `user-invocable`이 false가 아닌 한, `disable-model-invocation: true`로 설정되어 모델 호출에서 숨겨진 스킬을 사용할 수 있습니다.

## Agent Scope [#agent-scope]

에이전트가 스킬을 사용하거나 작성하려면 먼저 **Enable skills**가 켜져 있어야 합니다. 별도의 **Use all skills** 스위치는 카탈로그 노출 여부를 제어합니다.

- **All:** **Use all skills**를 켜서 사용자가 나중에 추가된 스킬을 포함하여 활성화된 전체 카탈로그를 볼 수 있도록 노출합니다.
- **선택됨:** **Use all skills**를 끄고 개별 Skills를 추가하여 해당 항목만 노출하세요.
- **작성 전용:** **Use all skills**를 끄고 선택된 Skill이 없는 상태로 두십시오. 기존 카탈로그 항목은 노출되지 않지만, 사용자가 Skill 생성 권한을 가지고 있는 경우 에이전트가 대화 중에 Skill을 생성할 수 있습니다.
- **비활성화됨:** **Enable skills**를 끄면 카탈로그 사용과 런타임 저작 기능을 모두 비활성화할 수 있습니다.

이를 통해 관리자는 Skills 기능을 전역적으로 노출하면서도 각 에이전트가 사용할 수 있는 스킬 세트를 집중적으로 관리할 수 있습니다.

**Use all skills**를 끄면 이 스위치를 활성화하기 전에 선택되었던 상태로 복원됩니다. 기존 에이전트는 명시적인 범위 없이 활성화된 Skills가 전체 카탈로그를 의미하는 레거시 동작을 유지합니다.

## 런타임 스킬 작성 (Runtime Skill Authoring) [#runtime-skill-authoring]

Skills가 활성화된 에이전트는 작업 중에 재사용 가능한 Skill 파일을 생성하거나 편집할 수 있습니다. 런타임 파일은 업로드된 번들과 동일한 `skills/{skillName}/...` 네임스페이스를 사용하므로, 에이전트는 성공적인 워크플로우의 일환으로 `SKILL.md` 및 관련 참조, 스크립트 또는 에셋을 작성할 수 있습니다.

Authoring은 일반적인 Skills 권한 모델을 따릅니다:

- 새로운 Skill을 생성하려면 사용자의 Skill **Create** 권한이 필요합니다.
- 기존 Skill을 수정하려면 편집 권한이 있어야 하며, 해당 에이전트의 활성 카탈로그 범위에 포함되어 있어야 합니다. 배포된 Skill 및 GitHub와 동기화된 Skill은 읽기 전용으로 유지됩니다.
- 저작 전용(authoring-only) 에이전트는 사용자의 기존 카탈로그를 받지 않고도 새로운 Skill을 생성할 수 있습니다.

런타임 저작(Runtime authoring)은 배포 기능이나 사용자 권한을 우회하지 않습니다. Agents 엔드포인트 기능에서 `skills`를 제거하면 해당 기능이 숨겨지며, 에이전트에서 **Enable skills**를 끄면 해당 저작 도구가 비활성화됩니다.

## 활성 및 공유된 스킬 [#active-and-shared-skills]

사용자는 **Available to agent** 스위치를 사용하여 스킬을 활성화하거나 비활성화할 수 있습니다. 소유 및 배포된 스킬은 기본적으로 활성화되어 있습니다. 공유 스킬은 사용자가 재정의하기 전까지 관리자가 구성한 기본값을 사용합니다.

비활성 스킬은 다음에서 제외됩니다:

- `$` 팝오버
- 모델이 호출하는 스킬 카탈로그
- 항상 프라이밍 적용

스킬을 공유하면 표준 공유 대화 상자를 통해 특정 사용자, 그룹 또는 역할에 뷰어, 편집자 또는 소유자 권한을 부여할 수 있으며, 이를 위해서는 역할에 공유 권한이 필요합니다. 전체 모델에 대한 내용은 [Access Control](/docs/features/access_control)을 참조하세요.

## 번들 파일 (Bundled Files) [#bundled-files]

업로드된 스킬 번들에는 `SKILL.md`와 함께 다음과 같은 파일이 포함될 수 있습니다:

- `references/...`
- `scripts/...`
- `assets/...`

백엔드는 해당 파일들을 스킬과 함께 저장합니다. 에이전트는 스킬이 활성화되어 있고 범위 내에 있을 때 스킬 파일을 해석할 수 있습니다. 중첩된 파일은 상대 경로를 유지하며 모델이 인식하는 `skills/{skillName}/...` 네임스페이스를 통해 주소가 지정됩니다. 스킬 뷰어에서 상대 Markdown 링크는 현재 파일로부터 해석되며 참조된 파일을 동일한 스킬 내에서 엽니다. Code Interpreter가 활성화되면 동일한 파일들이 `/mnt/data/skills/{skillName}/...`에 마운트되어 셸 및 코드 작업에서 직접 사용할 수 있습니다. `SKILL.md`를 수정하면 스킬 버전이 올라갑니다. 코드나 프로그래밍 방식의 실행 전에 LibreChat은 모든 마운트된 파일 참조가 해당 버전과 일치하는지 확인하며, 참조가 오래된 경우 전체 번들을 다시 업로드합니다.

스킬 페이지에는 **New File**, **New Folder**, **Upload File** 작업이 포함된 파일 트리도 있으며, 파일당 최대 10MB까지 추가할 수 있습니다. `SKILL.md` 자체는 해당 위치에서 예약되어 있으므로, 대신 스킬 본문을 수정하세요.

<Callout type="note" title="작성 팁">
  `description`을 구체적으로 유지하세요. 이는 모델이 호출하는 기술에 대한 가장 강력한 신호입니다. 짧거나 모호한 설명은 트리거가 제대로 작동하지 않게 만듭니다.
</Callout>

## 배포 기술 [#deployment-skills]

관리자는 `DEPLOYMENT_SKILLS_DIR`을 사용하여 파일 시스템에서 읽기 전용 Skills를 배포할 수 있습니다.

```bash filename=".env"
DEPLOYMENT_SKILLS_DIR=./skill
```

디렉터리는 프로젝트 루트의 `./skill`로 기본 설정되어 있습니다. 각 Skill은 `SKILL.md`를 포함하는 자체 하위 디렉터리에 위치하며, 함께 번들된 파일들도 그 옆에 위치합니다. LibreChat은 시작 시 배포된 Skill을 로드하고, Skills 기능이 활성화된 사용자에게 이를 노출합니다.

배포 기술:

- UI에서 읽기 전용입니다
- `deployment`를 소스로 사용하세요
- 동일한 이름을 가진 기존 Skills보다 우선합니다
- 파일이 추가, 제거 또는 변경된 후에는 LibreChat을 다시 시작해야 합니다.

실험적인 [Agent Plugins](/docs/features/agent_plugins)은 읽기 전용 배포 Skill을 관련 MCP 서버와 함께 번들로 묶을 수도 있습니다. 독립형 배포 디렉토리에 있는 Skill은 동일한 이름을 가진 플러그인 Skill보다 우선합니다.

## GitHub Skill Sync [#github-skill-sync]

관리자는 `librechat.yaml`의 `skillSync.github`를 사용하여 GitHub 저장소에서 Skills를 미러링할 수 있습니다. 이는 팀 전체에서 선별된 Skill 세트를 공유하는 실용적인 방법입니다.

```yaml filename="librechat.yaml"
skillSync:
  github:
    enabled: true
    intervalMinutes: 60
    runOnStartup: true
    sources:
      - id: librechat-skills
        owner: your-org
        repo: your-skills-repo
        ref: main
        paths:
          - skills
        skillDiscoveryDepth: 2
        token: '${GITHUB_SKILLS_TOKEN}'
```

GitHub Skill Sync:

- `SKILL.md`에 대해 구성된 저장소 경로를 스캔합니다.
- 각 `SKILL.md`가 포함된 디렉토리를 스킬 루트로 취급하며, 설정된 경로의 `skillDiscoveryDepth` 레벨 내에서 탐색합니다.
- 각 스킬 옆에 번들된 파일을 가져옵니다
- `source: "github"`을 사용하여 미러링된 Skills를 저장합니다.
- 업스트림 저장소가 변경될 때 미러링된 Skills를 업데이트합니다
- 구성된 소스에 더 이상 존재하지 않는 미러링된 Skills를 제거합니다.
- 소스 내의 다른 Skill이 유효하지 않거나 충돌하더라도 유효한 Skill을 게시합니다
- 관리자에게 부분적으로 성공한 실행 및 제한된 건너뛴 스킬(skipped-Skill) 세부 정보를 보고합니다.
- 예약 실행, 시작 시 실행, 그리고 관리자가 수동으로 트리거하는 실행을 지원합니다

건너뛴 Skill은 존재하는 경우 마지막으로 알려진 정상 미러(last-known-good mirror)를 유지합니다. 인증, 속도 제한, 동기화 소유권 상실 또는 롤백 실패와 같은 소스 전체의 오류는 여전히 전체 소스 실행을 실패하게 만듭니다.

선택한 저장소에 대해 읽기 전용 Contents 및 Metadata 권한이 있는 GitHub 세분화된 개인 액세스 토큰(fine-grained personal access token)을 사용하세요. 모든 필드, 자격 증명 옵션, 테넌트 범위 지정 및 관리자 동기화 엔드포인트에 대한 자세한 내용은 [Skill Sync Object Structure](/docs/configuration/librechat_yaml/object_structure/skill_sync)를 참조하세요.
