# Agents: 맞춤형 AI 어시스턴트 구축 [#agents-build-custom-ai-assistants]

LibreChat의 AI Agents 기능은 다양한 모델 제공업체를 기반으로 하는 맞춤형 AI 어시스턴트를 생성하기 위한 유연한 프레임워크를 제공합니다.

이 기능은 OpenAI의 Assistants API 및 ChatGPT의 GPT와 유사하지만, 더 폭넓은 모델 지원과 노코드(no-code) 구현을 통해 전문적인 기능을 갖춘 정교한 어시스턴트를 구축할 수 있게 해줍니다.

## 시작하기 [#getting-started]

새로운 에이전트를 생성하려면, endpoint 메뉴에서 "Agents"를 선택하고 사이드 패널(Side Panel)에 있는 Agent Builder 패널을 여세요.

![Agents - Endpoints Menu](/images/agents/endpoints_menu.png)

생성 양식에는 다음이 포함됩니다:

- **Avatar**: 사용자 지정 아바타를 업로드하여 에이전트를 개인화하세요
- **Name**: 에이전트의 고유한 이름을 선택하세요
- **Description**: 에이전트의 목적에 대한 선택적 세부 정보
- **Instructions**: 에이전트의 동작을 정의하는 시스템 지침
- **Model**: 사용 가능한 공급자 및 모델 중에서 선택하세요

**Tools** 및 **Skills** 컨트롤은 내장 기능, 도구, MCP 서버, Actions 및 Skills를 위한 검색 가능한 라이브러리를 엽니다. 항목을 선택하여 구성한 다음 에이전트를 저장하세요.

**기존 에이전트는 사이드 패널 상단의 드롭다운에서 선택할 수 있습니다.**

- **채팅 입력창에서 "@"를 사용하여 언급할 수도 있습니다.**

![Agents - Mention](/images/agents/mention.png)

### Tool Library [#tool-library]

Agent Builder는 활성화된 항목을 **Tools** 및 **Skills** 섹션으로 분리하여 유지합니다. **Add tools**를 열어 전체 카탈로그를 검색하거나 **Official**, **Tools**, **MCP**, 또는 **Actions**별로 필터링할 수 있습니다. **Made by you**는 사용자가 생성한 MCP 서버와 Actions를 모아두며, **Favorites**는 즐겨찾기로 표시한 항목을 여러 에이전트에서 사용할 수 있도록 보관합니다. 각 사용자는 최대 100개의 도구 라이브러리 즐겨찾기를 저장할 수 있습니다.

빌더를 떠나지 않고 항목을 구성하려면 항목을 선택하세요. **Create new** 메뉴는 사용자에게 MCP 서버 또는 Action을 생성할 권한이 있는 경우에만 나타납니다. File Search, File Context 또는 Code Interpreter와 같은 파일 기반 기능을 제거하면, 첨부된 파일을 여전히 검토해야 할 때 파일 관리자가 열립니다.

Skills는 자체적인 선택 도구를 사용하며, 개별적으로 선택하거나 전체 접근 가능한 카탈로그로 활성화할 수 있습니다. [Skills](/docs/features/skills#agent-scope)를 참조하세요.

운영자는 실험적인 [Agent Plugins](/docs/features/agent_plugins)을 사용하여 배포 Skills와 MCP 서버를 시작 시 로드되는 패키지로 묶을 수도 있습니다.

### 모델 구성 [#model-configuration]

모델 매개변수 인터페이스를 통해 에이전트의 응답을 미세 조정할 수 있습니다:

- Temperature (응답 창의성을 위한 0-1 범위의 척도)
- 최대 컨텍스트 토큰
- 최대 출력 토큰
- 추가적인 공급자별 설정

### 버전 기록 [#version-history]

편집 권한이 있는 사용자는 Agent Builder에서 **Version History**를 열어 타임라인에 저장된 구성을 검토할 수 있습니다. 각 항목은 저장된 시점을 보여주며 도구 및 기능에 대한 요약 정보를 제공합니다. 이전 항목을 복원하려면 확인이 필요하며, 현재 에이전트 구성이 해당 저장된 상태로 대체됩니다. 저장은 항상 에이전트의 현재 변경 사항을 적용하며, 결과 구성이 최신 기록 항목과 일치하는 경우 LibreChat은 중복 항목을 추가하지 않습니다.

## 에이전트 기능 (Agent Capabilities) [#agent-capabilities]

> **참고:** 모든 기능은 `librechat.yaml` 구성 파일을 통해 전환할 수 있습니다. 자세한 내용은 [docs/configuration/librechat_yaml/object_structure/agents#capabilities](/docs/configuration/librechat_yaml/object_structure/agents#capabilities)를 참조하세요.

### Code Interpreter [#code-interpreter]

활성화되면, Code Interpreter 기능은 에이전트가 다음을 수행할 수 있도록 합니다:

- 다음과 같은 여러 언어로 코드를 실행하세요:
  - Python, JavaScript, TypeScript, Go, C, C++, Java, PHP, Rust 및 Fortran
- LibreChat Code Interpreter API를 통해 안전하게 파일 처리하기
- 로컬 설정, 구성 또는 샌드박스 배포 없이 코드 실행
- 파일 업로드 및 다운로드를 원활하게 처리하세요
- [Code Interpreter API에 대한 추가 정보](/docs/features/code_interpreter)
  - 오픈 소스 [code-interpreter](https://github.com/ClickHouse/code-interpreter) 서비스(자체 호스팅) 기반

대화에서 필요한 모든 Code Interpreter 파일이 현재 샌드박스로 복원되지 못할 경우, LibreChat은 모델을 호출하기 전에 에이전트를 중지하고 사용자에게 파일을 다시 첨부하도록 요청합니다. 이는 오래되었거나 액세스할 수 없는 파일 참조로 실행이 계속되는 것을 방지합니다.

#### 상태 유지 코드 세션 (Stateful Code Sessions) [#stateful-code-sessions]

Stateful code sessions을 사용하면 에이전트가 대화당 하나의 샌드박스 작업 공간을 재사용할 수 있습니다. 파일, 설치된 패키지 및 작업 상태는 일반적으로 코드 실행 간에 유지되므로, 반복적인 분석 및 다단계 파일 작업에 유용합니다.

<Callout type="warning" title="매우 실험적인 기능">
  Stateful Code Sessions는 초기 실험 단계에 있습니다. 해당 기능의 동작, 구성, 지속성 특성 및 기반 통합 방식은 크게 변경될 수 있습니다. 현재 구현을 안정적인 프로덕션 계약으로 간주하지 마십시오.
</Callout>

이 기능은 선택 사항입니다. 관리자가 [agent capabilities](/docs/configuration/librechat_yaml/object_structure/agents#capabilities)에 `stateful_code_sessions`를 추가해야 하며, 에이전트에서 Code Interpreter가 활성화되어 있어야 하고, 에이전트의 고급 설정에서 **Stateful code sessions**가 켜져 있어야 합니다. 작업 공간은 언제든지 초기화될 수 있습니다. 중요한 출력물은 `/mnt/data`에 저장하고, 그 외의 경우에는 세션 상태를 영구 저장소로 의존하지 마십시오.

### File Search [#file-search]

File Search 기능은 다음을 가능하게 합니다:

- RAG (Retrieval-Augmented Generation) 기능
- 업로드된 문서에 대한 의미론적(Semantic) 검색
- 파일 내용을 기반으로 한 문맥 인식 응답
- 에이전트 및 채팅 스레드 수준 모두에서 파일 첨부 지원

### 파일 컨텍스트 [#file-context]

File Context 기능은 에이전트가 파일에서 추출한 텍스트를 시스템 지침의 일부로 저장할 수 있도록 합니다:

- 문서 구조와 서식을 유지하면서 텍스트 추출
- 다중 열 텍스트 및 혼합 콘텐츠를 포함한 복잡한 레이아웃 처리
- 표, 수식 및 기타 특수 콘텐츠 처리
- 다국어 콘텐츠 작업하기
- 텍스트는 데이터베이스 내 에이전트의 instructions에 저장됩니다.
- **OCR 서비스 불필요** - 기본적으로 텍스트 파싱을 사용하며 대체 방법을 지원합니다
- **OCR로 향상됨** - OCR이 구성된 경우, 이미지 및 스캔된 문서에 대한 추출 품질이 향상됩니다.
- "Upload as Text"와 동일한 처리 로직을 사용합니다: **OCR > STT > 텍스트 파싱**
- [OCR 구성에 대한 자세한 정보](/docs/features/ocr)

**참고:** 파일 컨텍스트는 에이전트의 시스템 지침에 추출된 텍스트를 포함합니다. 개별 대화에서 임시 문서 질문을 하려면 채팅에서 [Upload as Text](/docs/features/upload_as_text) 기능을 사용하세요.

### Model Context Protocol (MCP) [#model-context-protocol-mcp]

MCP는 애플리케이션이 거대 언어 모델(LLM)에 컨텍스트를 제공하는 방식을 표준화하는 개방형 프로토콜로, AI 도구와 데이터 소스를 위한 범용 어댑터 역할을 합니다.

더 자세한 정보는 [MCP](/docs/features/mcp) 문서를 참조하세요.

#### MCP 도구를 사용하는 Agents [#agents-with-mcp-tools]

1. `librechat.yaml` 파일에서 MCP 서버를 구성하세요
2. LibreChat을 재시작하여 연결을 초기화하세요
3. 에이전트 생성 또는 편집
4. Agent Builder에서 **Add tools**를 열고 **MCP**를 선택하세요.
5. 추가하려는 MCP 서버를 선택하세요. 각 서버는 단일 항목으로 표시됩니다.
6. 에이전트에 변경 사항을 저장하세요

이 예시에서는 **[Spotify MCP server](https://github.com/LibreChat-AI/spotify-mcp)**를 에이전트에 추가했습니다.

![Agents - MCP](/images/agents/mcp_tools_v2.png)

#### MCP 도구 관리 [#managing-mcp-tools]

MCP 서버가 에이전트에 추가되면, 사용 가능한 특정 도구를 세부적으로 조정할 수 있습니다:

- MCP 서버를 추가한 후, 해당 서버를 확장하여 사용 가능한 모든 도구를 확인하세요.
- 필요에 따라 개별 도구를 선택/선택 해제하세요
- 예를 들어, Spotify MCP 서버는 약 20개의 도구(검색, 재생 제어, 재생 목록 관리 등)를 제공합니다.
- 이 세밀한 제어를 통해 에이전트가 필요한 도구만 사용하도록 제한할 수 있습니다.

`{{LIBRECHAT_BODY_*}}`를 사용하는 요청 범위(request-scoped) 서버는 채팅 실행 시 해당 값들이 제공되기 전까지 도구를 열거할 수 없습니다. 따라서 Agent Builder는 도구별 토글 대신 전체 서버에 대한 하나의 런타임 도구 선택 항목을 표시하며, 해당 선택을 해제하면 서버 연결이 끊어집니다. OAuth 이후, LibreChat은 권한 부여 상태를 유지하며 연결을 위해 첫 번째 적격 실행이 발생할 때까지 대기합니다.

에이전트가 MCP 도구를 명시적으로 선택했으나 실행 시작 시 해결할 수 있는 도구가 없는 경우, LibreChat은 도구 없이 조용히 계속 진행하는 대신 연결 및 액세스 안내와 함께 실행을 중단합니다. 서버를 다시 연결하거나 인증하고, 도구 액세스 권한을 확인한 후 실행을 다시 시도하세요.

![Agents - MCP Tools](/images/agents/mcp_agent_tools.png)

더 알아보기:

- [MCP 서버 구성하기](/docs/features/mcp)
- [Model Context Protocol 소개](https://modelcontextprotocol.io/introduction)

### Deferred Tools [#deferred-tools]

Deferred tools를 사용하면 에이전트가 많은 MCP 도구에 액세스할 때 이를 모두 LLM 컨텍스트에 미리 로드할 필요가 없습니다. 대신, deferred tools는 **Tool Search** 메커니즘을 통해 런타임에 검색할 수 있습니다.

이는 에이전트가 수십 개의 도구가 포함된 다수의 MCP 서버에 액세스할 때 특히 유용합니다. 모든 도구를 로드하면 컨텍스트 윈도우의 상당 부분을 차지하여 응답 품질이 저하될 수 있기 때문입니다.

**작동 방식:**

- "deferred"로 표시된 도구는 초기 LLM 컨텍스트에서 제외됩니다.
- `ToolSearch` 도구가 자동으로 추가되어, LLM이 필요에 따라 지연 로드된(deferred) 도구를 검색하고 불러올 수 있게 합니다.
- 일단 발견되면, 해당 도구는 남은 대화 동안 계속 사용할 수 있습니다.

**지연된 도구(deferred tools) 구성:**

1. Agent Builder를 열고 MCP 도구를 추가하세요
2. 모든 MCP 도구의 드롭다운을 클릭하세요
3. "Defer Loading" 토글 — 지연된 도구는 시계 아이콘으로 표시됩니다

**참고:** `deferred_tools` 기능은 기본적으로 활성화되어 있습니다. 이 기능은 [`librechat.yaml` 에이전트 구성](/docs/configuration/librechat_yaml/object_structure/agents#capabilities)을 통해 전환할 수 있습니다.

### 활동 그룹 [#activity-groups]

Activity groups는 연속된 에이전트 추론 및 도구 호출 블록을 생성된 한 줄 헤더 아래로 축소하여 긴 실행 과정을 더 쉽게 훑어볼 수 있게 합니다. 관리자는 `activityLabel`을 통해 이를 활성화할 수 있으며, 더 빠른 모델, 다른 구성된 endpoint, 사용자 지정 프롬프트 및 실행당 제한을 사용할 수 있습니다. 헤더 생성은 별도의 모델 호출이며, 해당 토큰과 비용이 기록됩니다. [Agent Activity Groups](/docs/configuration/librechat_yaml/object_structure/shared_endpoint_settings#agent-activity-groups)를 참조하세요.

관리자는 `activityPhaseLabel`을 독립적으로 활성화하여 최종 답변이 나오기 전에 두 개 이상의 논리적 활동을 접을 수 있는 상위 요약으로 묶을 수 있습니다. 이를 통해 긴 실행 과정에서 각 하위 활동을 유지하면서도 더 높은 수준의 개요를 제공할 수 있습니다. 단계 요약(Phase summaries)은 자체 모델, endpoint, 프롬프트 및 실행당 제한을 사용하며, 설정되지 않은 경우 활동 레이블 및 실행 설정으로 대체됩니다.

짧은 진행 상황 텍스트는 상위 단계(parent phase) 내부에 유지됩니다. 에이전트가 본격적인 답변을 시작하면, LibreChat은 해당 텍스트 이전에 단계를 닫아 사용자에게 보이는 결과가 접힌 요약 외부로 유지되도록 합니다. 한 번의 실행으로 이후 추론이나 도구가 또 다른 논리적 활동 블록을 시작할 때 여러 개의 상위 단계를 생성할 수 있습니다. 지속되는 단계 경계는 형식이 잘못되었거나 생략된 콘텐츠 부분이 압축될 때 재기준(rebased)되므로, 다시 로드한 후에도 그룹화가 정렬된 상태로 유지됩니다.

### 도구 의도 레이블 (Tool Intent Labels) [#tool-intent-labels]

도구 인텐트(Tool intent) 레이블은 일반적인 실시간 도구 상태를 해당 호출에 대해 모델이 작성한 짧은 설명으로 대체합니다. 관리자는 `tool_intents` [에이전트 기능](/docs/configuration/librechat_yaml/object_structure/agents#capabilities)을 선택적으로 추가해야 합니다. 기본 도구는 레이블을 자동으로 사용하며, 에이전트 빌더(Agent Builder)에서는 MCP 서버를 확장하고 개별 도구 또는 전체 서버에 대해 **Intent label**을 켜면 됩니다.

Model Specs의 경우, [`describeIntent`](/docs/configuration/librechat_yaml/object_structure/model_specs#describeintent)를 사용하여 모든 적격 도구를 활성화하거나 선택된 도구 ID를 지정할 수 있습니다. Intent 필드는 모델로 전송되는 도구 스키마에 추가되므로, 선택적 활성화를 통해 스키마 토큰 오버헤드를 줄일 수 있습니다.

의도(Intent) 레이블은 프로그래밍 전용 MCP 도구에는 적용되지 않습니다. 이는 샌드박스 코드 내부에서 이루어지는 호출이 개별 도구 카드를 렌더링하지 않기 때문입니다.

### Programmatic Tool Calling [#programmatic-tool-calling]

Programmatic Tool Calling (PTC)을 사용하면 에이전트가 모델에서 각 도구를 직접 호출하는 대신 [Code Interpreter](/docs/features/code_interpreter) 샌드박스 내부에서 선택된 MCP 도구를 실행할 수 있습니다. 모델은 Code Interpreter 기반의 오케스트레이션 도구를 수신하고, 생성된 도구 함수를 호출하는 샌드박스 코드를 작성하며, 답변을 반환하기 전에 루프, 조건문, 재시도 및 결과 처리를 사용할 수 있습니다.

이는 여러 리소스를 쿼리하거나, 결과 페이지를 넘기거나, 출력을 비교하거나, 에이전트가 설명하기 전에 도구 응답을 변환하는 등 다단계 도구 워크플로우에 유용합니다.

**프로그래밍 방식 도구 구성:**

1. [`librechat.yaml` 에이전트 기능](/docs/configuration/librechat_yaml/object_structure/agents#capabilities)에서 `programmatic_tools`와 `execute_code`를 모두 활성화하세요.
2. 에이전트에서 Code Interpreter를 활성화하세요.
3. MCP 도구를 추가하고, MCP 서버를 확장하며, 개별 도구 또는 전체 서버에 대해 **Programmatic**을 토글합니다. Programmatic 도구는 코드 아이콘으로 표시됩니다.

**참고:** `programmatic_tools`는 옵트인(opt-in) 방식이며 기본 에이전트 기능 목록에 포함되어 있지 않습니다. PTC는 또한 Tool Call Server 구성 요소가 포함된 Code Interpreter 배포가 필요합니다. 에이전트에 등록된 도구만 샌드박스에서 호출할 수 있으며, 등록되지 않은 도구 호출은 거부됩니다.

### Background Tool Calls [#background-tool-calls]

백그라운드 도구 호출(Background tool calls)을 사용하면 에이전트가 시간이 오래 걸리는 적격한 MCP 또는 Code Interpreter 도구를 시작하고, 계속 작업을 수행하다가 나중에 결과를 폴링(poll)할 수 있습니다. 초기 호출은 즉시 작업 참조(task reference)를 반환하며, 에이전트는 `check_background_task`를 통해 상태와 결과를 검색합니다.

이 기능을 사용하려면 관리자가 `run_in_background` [에이전트 기능](/docs/configuration/librechat_yaml/object_structure/agents#capabilities)을 선택적으로 추가해야 합니다. 그런 다음 에이전트 빌더(Agent Builder)에서 적합한 도구를 구성하십시오:

- **Code Interpreter:** 에이전트에서 Code Interpreter를 활성화합니다. 코드 실행 및 셸 명령은 기본적으로 백그라운드 실행이 가능합니다. 이를 원치 않으면 도구 설정에서 **Background execution**을 끄십시오.
- **MCP:** MCP 서버를 열고 개별 도구 또는 전체 서버를 **Background**로 표시하세요.

이 설정들은 백그라운드 실행을 허용하지만 강제하지는 않습니다. 모델은 호출 시마다 적격한 도구를 백그라운드에서 실행할지 여부를 결정합니다.

LibreChat 채팅에서 백그라운드 코드가 완료되면, 해당 stdout 및 생성된 파일은 이후의 폴링(poll)이 아닌 원래의 코드 호출 위치에 나타납니다. 생성된 파일은 후속 턴을 위해 유지됩니다.

백그라운드 작업 상태는 현재 프로세스 로컬(process-local)입니다. 결과는 동일한 서버 프로세스의 이후 턴에서 수집될 수 있지만, 재시작 시 유지되지 않으며 복제본 간에 공유되지 않습니다.

### 사용자 및 도구 승인 요청 (Ask User and Tool Approval) [#ask-user-and-tool-approval]

**Ask User** 도구는 에이전트가 실행을 일시 중지하여 누락된 정보를 요청하거나, 선택지를 제시하거나, 진행 방법을 확인하도록 합니다. 한 번의 호출로 최대 4개의 관련 질문을 단일 양식으로 그룹화할 수 있습니다. 각 질문은 자유 형식의 답변을 받거나 에이전트가 설정한 단일 또는 다중 선택지를 받을 수 있습니다. 사용자는 모든 질문에 답변한 후 한 번에 제출하거나 양식을 건너뛸 수 있습니다. 모델이 호출을 준비하는 동안 LibreChat은 질문을 진행 상황 카드(progress card)로 스트리밍하며, 준비가 완료되면 대화형 양식으로 대체됩니다. 제출 후에는 답변과 함께 동일한 실행이 재개됩니다. 도구 마켓플레이스에서 **Ask User**를 추가할 수 있으며, 관리자는 기본 `ask_user_question` 기능을 제거하여 이를 숨길 수 있습니다.

제출된 답변은 재개(resume) 작업과 함께 유지되므로, 재개된 실행이 초기화되는 동안 중단하더라도 수락된 답변은 삭제되지 않습니다.

각 질문은 최대 80자까지의 선택적 제목, 최대 2,000자까지의 질문 텍스트, 최대 4,000자까지의 선택적 지원 컨텍스트, 그리고 최대 12개의 선택지를 포함할 수 있습니다. 선택지 레이블은 280자, 선택지 값은 500자, 그리고 제출된 각 답변은 16,000자까지로 제한됩니다.

관리자는 일치하는 도구 호출이 실행되기 전에 검토를 요구할 수도 있습니다. 도구에 따라 사용자는 승인, 거부, 인수 편집 또는 직접 응답을 수행할 수 있습니다. 일시 중지된 실행은 체크포인트가 생성되므로 결정 후 재개할 수 있으며, 기본 MongoDB 체크포인터를 사용하는 경우 다른 복제본에서도 재개할 수 있습니다. 도구 승인은 기본적으로 비활성화되어 있습니다. [`toolApproval` 및 `checkpointer`](/docs/configuration/librechat_yaml/object_structure/agents#toolapproval)를 참조하세요.

### Skills [#skills]

Skills를 사용하면 에이전트가 `SKILL.md` 정의에서 재사용 가능한 지침을 로드할 수 있습니다. 이는 채팅에서 `$`를 사용하여 수동으로 선택하거나, 스킬 카탈로그를 통해 모델이 자동으로 검색하게 하거나, 모든 턴에 항상 적용되도록 설정할 수 있습니다.

작성, 호출 및 액세스 제어에 대한 자세한 내용은 [Skills](/docs/features/skills)를 참조하세요.

### Memory [#memory]

**Memory** 도구는 사용자가 명시적으로 무언가를 기억하거나 잊어달라고 요청할 때 에이전트가 구조화된 사용자 메모리를 저장, 업데이트 또는 삭제할 수 있도록 합니다. Memory는 배포를 위해 구성되어야 하며, 사용자 역할 및 개인화 설정에서 허용되어야 하고, 에이전트에서 활성화되어야 합니다.

기본적으로 에이전트는 사용자의 공유 개인 메모리 풀을 사용합니다. **Keep memories separate for this agent**를 켜면 사용자별, 에이전트별 전용 파티션을 제공할 수 있습니다. 격리된 에이전트는 기존의 공유 메모리나 다른 격리된 에이전트가 생성한 메모리를 볼 수 없습니다. 사용자는 메모리 패널에서 개인 메모리 또는 에이전트별 메모리로 필터링할 수 있습니다. [User Memory](/docs/features/memory#agent-memory)를 참조하세요.

### Artifacts [#artifacts]

Artifacts 기능은 에이전트가 대화형 콘텐츠를 생성하고 표시할 수 있도록 지원합니다:

- React 컴포넌트, HTML 코드 및 Mermaid 다이어그램 생성
- 명확성과 상호작용을 위해 별도의 UI 창에 콘텐츠를 표시합니다
- 에이전트 수준에서 아티팩트별 지침을 구성하세요
- [Artifacts에 대한 추가 정보](/docs/features/artifacts)

활성화되면 다음 세 가지 지침 모드 중 하나를 선택하세요:

- **Normal**: React, HTML, SVG, Markdown 및 Mermaid에 대한 표준 아티팩트(artifact) 지침을 추가합니다.
- **shadcn/ui**: 표준 지침과 더불어 shadcn/ui 컴포넌트 라이브러리를 사용하여 인터페이스를 구축하기 위한 가이드를 추가합니다.
- **Custom**: 아티팩트 렌더링은 활성화된 상태로 유지하지만 내장된 아티팩트 지침을 주입하지 않으므로, 에이전트 고유의 지침이 모든 제어권을 갖게 됩니다.

에이전트 수준에서 아티팩트를 구성하는 것이 권장되는 방식입니다. 이는 기존의 앱 전체 구성보다 더 세밀한 제어가 가능하기 때문입니다.

**Custom**을 선택하는 경우, 지침에 최소한 기본 아티팩트 형식을 포함하세요.

다음은 필요한 최소한의 지침에 대한 간단한 예시입니다:

````md
When creating content that should be displayed as an artifact, use the following format:

:::artifact{identifier="unique-identifier" type="mime-type" title="Artifact Title"}

```
Your artifact content here
```

:::

For the type attribute, use one of:

- "text/html" for HTML content
- "application/vnd.mermaid" for Mermaid diagrams
- "application/vnd.react" for React components
- "image/svg+xml" for SVG images
````

### 도구 [#tools]

Agents는 다양한 내장 도구로 강화할 수도 있습니다:

- **[OpenAI Image Tools](/docs/features/image_gen#openai-image-tools)**: **[GPT-Image-1](https://platform.openai.com/docs/models/gpt-image-1)**을 사용한 이미지 생성 및 편집
- **[Gemini Image Tools](/docs/configuration/tools/gemini_image_gen)**: Gemini 이미지 모델을 사용한 이미지 생성 및 이미지 컨텍스트 편집
- **[DALL-E-3](/docs/features/image_gen#dalle-legacy)**: 텍스트 설명을 통한 이미지 생성
- **[Stable Diffusion](/docs/features/image_gen#stable-diffusion-local)** / **[Flux](/docs/features/image_gen#flux)**: 텍스트-투-이미지 생성
- **[Wolfram](/docs/configuration/tools/wolfram)**: 계산 및 수학적 기능
- **[OpenWeather](/docs/configuration/tools/openweather)**: 날씨 데이터 검색
- **[Google Search](/docs/configuration/tools/google_search)**: 웹 검색 기능에 대한 액세스
- **[Calculator](/docs/configuration/tools/calculator)**: 수학적 계산
- **[Tavily Search](/docs/configuration/tools/tavily)**: 다양한 데이터 소스 통합 기능을 갖춘 고급 검색 API
- **[Azure AI Search](/docs/configuration/tools/azure_ai_search)**: Azure AI Search 인덱스에서 정보 검색
- **[Traversaal](/docs/configuration/tools/traversaal)**: LLM 에이전트를 위한 강력한 검색 API

#### 이미지 도구를 사용하여 에이전트 만들기 [#create-an-agent-with-image-tools]

1. `.env` 파일에 `IMAGE_GEN_OAI_API_KEY`(OpenAI Image Tools의 경우)와 같은 이미지 도구 자격 증명을 추가하세요.
2. LibreChat을 재시작하여 새로운 환경 변수가 로드되도록 하세요.
3. endpoint 메뉴에서 **Agents**를 선택하세요.
4. 사이드 패널에서 Agent Builder를 열고 에이전트를 생성하거나 편집하세요.
5. 에이전트의 **Tools** 목록을 열고 **OpenAI Image Tools**, **Gemini Image Tools**, **DALL-E-3**, **Stable Diffusion** 또는 **Flux**를 선택한 다음 에이전트를 저장하세요.
6. 해당 에이전트와 채팅을 시작하고 이미지를 생성하거나 편집하도록 요청하세요.

`IMAGE_GEN_OAI_MODEL`과 같은 모델 변수를 포함한 전체 이미지 설정 가이드는 [이미지 생성 및 편집](/docs/features/image_gen)을 참조하세요.

- [`librechat.yaml`](/docs/configuration/librechat_yaml) 구성 파일을 사용하여 도구를 비활성화할 수 있습니다:
  - [더 많은 정보](/docs/configuration/librechat_yaml/object_structure/agents#capabilities)

  - [추가 정보](/docs/configuration/librechat_yaml/object_structure/actions#alloweddomains)
- OpenAPI 사양의 작업(operation) 수준에서 'x-strict': true 플래그를 추가할 수 있다는 점을 참고하세요.
이를 지원하는 OpenAI 모델을 사용하는 경우, 'strict' 모드가 활성화된 함수 호출이 자동으로 생성됩니다.
  - Strict mode는 json의 일부 하위 집합만 지원합니다. 자세한 내용은 https://platform.openai.com/docs/guides/structured-outputs 에서 확인하세요.

### Handoffs [#handoffs]

Handoff는 기본 에이전트가 관련 컨텍스트와 함께 대화를 전문가 에이전트로 전달할 수 있도록 합니다. **Advanced settings**에서 orchestration 섹션을 열고 최대 10개의 handoff 에이전트를 추가하세요. 구성된 각 handoff는 전문가의 전문 지식이 필요할 때 모델이 동적으로 선택할 수 있는 transfer 도구를 생성합니다.

각 핸드오프(handoff)에 대해 모델이 올바른 전문가를 선택하도록 돕는 설명을 추가할 수 있습니다. 또한 기본 에이전트가 전문가를 위해 어떤 콘텐츠를 생성해야 하는지 설명하는 패스스루(passthrough) 지침을 제공할 수 있으며, 선택적으로 `instructions`라는 기본 콘텐츠 매개변수 이름을 변경할 수도 있습니다. 핸드오프는 항상 Agent Builder에서 사용할 수 있으며, Agent Chain 및 Subagents와 달리 엔드포인트 기능을 활성화할 필요가 없습니다.

### Agent Chain [#agent-chain]

Agent Chain 기능은 Mixture-of-Agents (MoA) 접근 방식을 지원하여, 함께 작동하는 에이전트 시퀀스를 생성할 수 있게 합니다:

- 복잡한 작업을 위한 전문 에이전트 체인 생성
- 체인의 각 에이전트는 이전 에이전트의 출력에 접근할 수 있습니다.
- 에이전트 체인의 최대 단계 수를 구성합니다
- **참고:** 이 기능은 Agent Builder의 고급 설정(Advanced Settings) 패널에서 액세스할 수 있습니다.
- **참고:** 이 기능은 현재 베타 버전이며 변경될 수 있습니다.
  - 현재 체이닝할 수 있는 에이전트의 최대 개수는 10개이지만, 향후 설정 가능하도록 변경될 수 있습니다.

이 기능은 LibreChat에 계층화된 Mixture-of-Agents 아키텍처를 도입합니다. [동명의 "Mixture-of-Agents" 논문](https://arxiv.org/abs/2406.04692)에 설명된 바와 같이, 각 에이전트는 이전 계층에 있는 에이전트들의 모든 출력을 응답 생성 시 보조 정보로 활용합니다.

### Subagents [#subagents]

Subagents를 사용하면 에이전트가 집중적인 작업을 격리된 하위 실행(child run)으로 위임할 수 있습니다. 하위 에이전트는 자체 컨텍스트 창과 도구 실행 흐름을 가지며, 모든 중간 단계를 부모 컨텍스트에 채우는 대신 간결한 결과만을 부모에게 반환합니다.

Subagents는 Agent Chain과 다릅니다. chain runs는 여러 에이전트를 그래프 참여자로 조정하는 반면, subagents는 에이전트가 범위가 지정된 위임을 위한 도구 호출(tool call)로서 생성합니다. 설정 및 제한 사항은 [Subagents](/docs/features/subagents)를 참조하세요.

### 고급 설정 [#advanced-settings]

"capabilities" 외에 에이전트에 대한 고급 설정(에이전트 양식의 고급 보기에서 찾을 수 있음)입니다.

#### 최대 에이전트 단계 (Max Agent Steps) [#max-agent-steps]

이 설정은 에이전트가 "run" 내에서 수행할 수 있는 단계 수를 제한할 수 있게 해주며, 이는 최종 응답이 제공되기 전의 에이전트 루프를 의미합니다.

설정하지 않을 경우 기본값은 25단계이지만, 필요에 따라 조정할 수 있습니다. 관리자의 경우 [`librechat.yaml`](/docs/configuration/librechat_yaml/object_structure/agents#recursionlimit) 파일에서 전역 기본값과 전역 최댓값을 설정할 수 있습니다.

관리자는 [Agent stream circuit breakers](/docs/configuration/librechat_yaml/object_structure/agents#stream-circuit-breakers)를 사용하여 스트리밍되는 도구 호출(tool-call) 인수 및 모델 델타 이벤트를 제한할 수도 있습니다.

"단계(step)"는 AI API 요청 또는 도구 사용 회차(LLM이 단일 요청에서 제공하는 도구 호출 수에 따라 1개 또는 다수의 도구)를 의미합니다.

단일 비도구 응답은 1단계입니다. 단일 도구 사용 라운드는 일반적으로 3단계로 구성됩니다:

1. API 요청 -> 2. 도구 사용 (1개 또는 다수의 도구) -> 3. 후속 API 요청

## 파일 관리 [#file-management]

Agents는 파일을 다루는 여러 가지 방법을 지원합니다:

### 채팅 인터페이스에서 [#in-chat-interface]

에이전트와 대화할 때, 네 가지 업로드 옵션을 사용할 수 있습니다:

1. **이미지 업로드**
   - 네이티브 비전 모델 지원을 위해 이미지를 업로드합니다
   - 이미지를 모델 제공업체로 직접 전송합니다

2. **텍스트로 업로드** (`context` 기능 필요)
   - 대화에 전체 문서 내용을 추출하고 포함합니다
   - 기본적으로 텍스트 파싱을 사용하며, 설정된 경우 OCR을 통해 향상됩니다.
   - 현재 대화에만 콘텐츠가 존재합니다
   - [Upload as Text](/docs/features/upload_as_text)를 참조하세요.

3. **파일 검색을 위한 업로드** (`file_search` 기능이 필요하며, ON으로 설정해야 함)
   - 벡터 저장소를 사용한 의미론적 검색(RAG)을 활용합니다
   - 도구 사용을 통해 관련 청크를 반환합니다
   - 대용량 문서/다중 파일에 최적화됨
   - 구조화된 데이터(CSV, Excel, JSON 등)에는 최적화되어 있지 않음

4. **코드 인터프리터용 업로드** (`execute_code` 기능이 필요하며, ON으로 설정해야 함)
   - 코드 인터프리터 환경에 파일을 추가합니다
   - 구조화된 데이터(CSV, Excel, JSON 등)에 최적화되어 있습니다.
   - [Code Interpreter](/docs/features/code_interpreter)에 대한 추가 정보

### Agent Builder에서 [#in-agent-builder]

에이전트를 구성할 때, 다양한 카테고리의 파일을 첨부할 수 있습니다:

1. **이미지 업로드**: 에이전트가 참조할 수 있는 시각적 콘텐츠용
2. **파일 검색 업로드(File Search Upload)**: RAG 기능을 위한 문서
3. **Code Interpreter 업로드**: 코드 처리를 위한 파일
4. **파일 컨텍스트**: 에이전트 지침을 보완하기 위해 텍스트가 추출된 문서

**File Context**는 `context` 기능을 사용하며 ["Upload as Text"](/docs/features/upload_as_text)와 동일하게 작동합니다. 기본적으로 텍스트 파싱을 사용하며, 설정 시 OCR을 통해 향상됩니다. 텍스트는 업로드 시점에 추출되어 에이전트의 지침(instructions)에 저장됩니다. 이는 문서, PDF, 코드 파일 또는 텍스트가 포함된 이미지로부터 에이전트에게 지속적인 지식을 제공하는 데 이상적입니다.

**처리 우선순위:** OCR > STT > 텍스트 파싱 (Upload as Text와 동일)

**참고:** 추출된 텍스트는 에이전트의 시스템 지침의 일부로 포함됩니다.

## 공유 및 권한 [#sharing-and-permissions]

에이전트는 LibreChat의 세분화된 [access control](/docs/features/access_control) 시스템을 사용합니다. 각 에이전트에는 고유한 액세스 제어 목록(ACL)이 있으며, 선택한 권한 수준에 따라 특정 **사용자**, **그룹**, **역할** 또는 **공개**로 공유할 수 있습니다.

### 액세스 역할 [#access-roles]

에이전트를 공유할 때, 피공유자에게는 다음 세 가지 역할 중 하나가 할당됩니다:

| 역할 | 권한 부여 대상이 할 수 있는 작업 |
| ---------- | ----------------------------------------------------------------------------------------------------- |
| **Viewer** | 대화에서 에이전트 사용; 빌더를 열거나 지침, 도구, 첨부 파일을 볼 수 없음 |
| **Editor** | 보기 + 에이전트의 지침, 모델, 도구 및 파일 수정 |
| **Owner** | 전체 제어: 에이전트 보기, 편집, 삭제 및 재공유 |

원작자와 관리자는 ACL과 관계없이 항상 모든 권한을 유지합니다.

### 에이전트 공유하기 [#sharing-an-agent]

1. Agent Builder에서 에이전트를 엽니다.
2. 바닥글에 있는 **Share** 버튼을 클릭하세요(작성자이거나, 관리자이거나, 해당 에이전트에 대한 `SHARE` 권한을 부여받은 경우에 표시됩니다).
3. 사용자 선택기에서 사용자, 그룹 또는 역할을 검색하고 각각에 역할을 할당하세요.
4. 선택적으로 **Public**을 토글하여 해당 인스턴스의 모든 사용자가 에이전트를 볼 수 있도록 설정할 수 있습니다(`SHARE_PUBLIC` 기능 권한이 필요합니다).

에이전트 카드와 랜딩 뷰에는 구성된 지원 연락처가 표시됩니다. 설정된 연락처가 없는 경우, LibreChat은 확인 가능한 첫 번째 소유자의 표시 이름으로 대체할 수 있지만, 지원 연락처로 명시적으로 구성되지 않은 한 소유자의 이메일 주소는 노출하지 않습니다.

주체(principals), 권한 비트(permission bits), 그리고 ACL이 역할 기반 기능 권한과 어떻게 구성되는지에 대한 자세한 내용은 [Access Control](/docs/features/access_control)을 참조하세요.

### 관리자 제어 [#administrator-controls]

관리자는 에이전트 빌더 UI 내에서 전역 권한 설정에 액세스할 수 있습니다:

- 모든 사용자 간의 에이전트 공유 활성화/비활성화
- 에이전트 사용 권한 제어
- 에이전트 생성 권한 관리
- 플랫폼 전체 설정 구성

인스턴스에 대해 처음 생성된 계정은 관리자 계정입니다. 추가 관리자를 추가해야 하는 경우, [MongoDB](/docs/configuration/mongodb/mongodb_auth)에 접속하여 사용자의 프로필을 업데이트할 수 있습니다:

```
db.users.updateOne(
  { email: 'USER_EMAIL_ADDRESS' },
  { $set: { role: 'ADMIN' } }
)
```

모든 사용자에 대한 에이전트 사용은 설정(config)을 통해 비활성화할 수도 있습니다. [자세한 정보](/docs/configuration/librechat_yaml/object_structure/interface).

기능 수준 권한(누가 에이전트를 _사용_, _생성_, _공유_ 또는 _공개 공유_할 수 있는지)은 각 역할(사용자 지정 역할 포함)에 대해 [**LibreChat 관리자 패널**](/docs/features/admin_panel)에서 관리됩니다. `librechat.yaml`의 [`interface.agents`](/docs/configuration/librechat_yaml/object_structure/interface#agents) 블록을 통해 시작 시 기본 제공 `USER` 역할에 대한 기본값을 설정할 수는 있지만, 향후 수정 사항은 관리자 패널을 사용하는 것이 권장됩니다.

### 사용자 수준 공유 [#user-level-sharing]

개별 사용자는 다음을 수행할 수 있습니다:

- 특정 사용자, 그룹 또는 역할과 에이전트를 공유합니다(해당 역할에 대해 `SHARE`가 활성화된 경우).
- 인스턴스의 모든 사용자에게 에이전트를 공개합니다 (`SHARE_PUBLIC`이 활성화된 경우)
- 각 수신자에게 서로 다른 액세스 수준(Viewer / Editor / Owner)을 부여하세요.
- 공유 대화 상자에서 언제든지 액세스 권한을 다시 공유하거나 취소할 수 있습니다.

## Steering 및 대기 중인 메시지 [#steering-and-queued-messages]

Agent가 응답하는 동안 다음 두 가지 방법 중 하나로 다른 메시지를 보낼 수 있습니다:

- **Steer**는 현재 실행 중인 작업의 다음 도구 또는 에이전트 단계에 메시지를 삽입하여, 에이전트가 작업을 완료하기 전에 스스로 조정할 수 있도록 합니다.
- **Queue**는 메시지를 보관했다가 현재 응답이 완료된 후 일반적인 후속 턴으로 전송합니다.

**Interrupt & steer**는 다음 공급자 안전 경계에서 생성을 중지하고, 부분 응답을 유지하며, 메시지를 삽입한 다음, 동일한 어시스턴트 응답을 재개합니다. 전용 작성기 컨트롤을 사용하거나, 전송 버튼 메뉴에서 선택하거나, `Command/Ctrl + Shift + .`를 누르세요. 배포 환경에서 활성 공급자 스트림을 중단할 수 없는 경우, 이 작업은 일반적인 steering으로 대체됩니다.

**Settings → Chat**에서 **While generating, Enter will**은 기본 동작을 선택합니다. 전송 버튼 메뉴를 통해 개별 메시지에 대해 해당 선택을 재정의할 수 있으며, **Steering interrupts generation**은 일반적인 스티어링(steering) 시 생성 중단 요청 여부를 제어합니다.

대기 중인 steer는 서버가 이를 실행(run)에 삽입할 때까지 작성기(composer) 위에 나타납니다. 승인되면 해당 메뉴를 통해 메시지를 편집용으로 되찾거나, 대기열에 있는 후속 메시지로 변환하거나, 취소하여 텍스트와 첨부 파일을 작성기로 복원할 수 있습니다. LibreChat은 더 최신의 초안을 덮어쓰지 않도록 방지합니다. 작성기를 더 이상 사용할 수 없는 경우, 되찾은 메시지를 대신 대기열에 보존합니다. 실패한 steer는 재시도, 편집, 대기열 추가 또는 제거가 가능하도록 유지됩니다.

대기 중인 후속 작업은 즉시 전송하거나, 실행이 활성화된 상태에서 steer로 변환하거나, **Interrupt & steer now**로 에스컬레이션하거나, 편집하거나, 제거할 수 있습니다. 진행 중인 steer는 도구 경계(tool boundary)를 기다리는 동안 동일한 에스컬레이션 옵션을 제공합니다. 대기 중인 메시지를 제거하면 가능한 경우 빈 작성기(composer)로 복원됩니다. 하나의 활성 실행은 최대 10개의 보류 중인 steer를 수용할 수 있으며, 각 steer는 최대 10개의 파일을 포함할 수 있고 [`STEER_MAX_LENGTH`](/docs/configuration/dotenv#agent-conversation-controls)에 의해 제한됩니다.

Redis 기반의 다중 복제본 배포는 복제본 간의 중단 및 복구 동작에 의존하기 전에 [generation protocol v2 rollout](/docs/configuration/redis#generation-protocol-rollout)을 완료해야 합니다.

### 참고 사항 [#notes]

- 지침, 모델 매개변수, 첨부 파일 및 도구는 편집 권한이 있는 사용자에게만 노출됩니다.
  - 에이전트는 대화 과정에서 지침이나 파일을 포함하여 첨부된 모든 데이터를 유출할 수 있으므로, 편집자(Editor)/소유자(Owner) 권한을 부여하거나 에이전트를 공개하기 전에 지침이 이러한 위험에 대해 충분히 견고한지 확인하십시오.
- 원작자, 관리자, 그리고 소유자 권한을 가진 피허가자만이 공유된 에이전트를 삭제할 수 있습니다.
- 에이전트는 공유되지 않는 한 작성자만 볼 수 있습니다.

- 에이전트의 "File Context"에 파일을 추가하여 파일의 전체 내용을 에이전트의 시스템 지침(system instructions) 일부로 포함하세요.

## 마이그레이션 필요 (v0.8.0-rc3+) [#migration-required-v080-rc3]

<Callout type="warning" title="중요: 에이전트 권한 마이그레이션 필요">
  v0.8.0-rc3 버전부터 LibreChat은 에이전트를 위한 새로운 ACL(Access Control List) 기반 권한 시스템을 사용합니다. 이전 버전에서 업그레이드하는 경우, 기존 에이전트에 계속 액세스할 수 있도록 에이전트 권한 마이그레이션을 실행해야 합니다.
</Callout>

### 마이그레이션의 역할 [#what-the-migration-does]

에이전트 권한 마이그레이션은 에이전트를 단순한 소유권 모델에서 다음과 같은 다중 권한 수준을 갖춘 정교한 ACL 기반 시스템으로 전환합니다:

- **OWNER**: 에이전트에 대한 전체 제어 권한
- **EDITOR**: 에이전트를 보거나 수정할 수 있습니다
- **VIEWER**: 에이전트에 대한 읽기 전용 액세스 권한

이 마이그레이션을 실행하지 않으면, 기존 에이전트는 새로운 권한 인식 API endpoint를 통해 액세스할 수 없게 됩니다.

### 마이그레이션 실행하기 [#running-the-migration]

배포 방식에 따라 적절한 명령어를 선택하세요:

#### 1. 기본 `docker-compose.yml`의 경우 (`docker compose up`을 사용하여 앱을 시작하는 경우): [#1-for-the-default-docker-composeyml-if-you-use-docker-compose-up-to-start-the-app]

**변경 사항 미리보기 (dry run):**

```bash
docker compose exec api npm run migrate:agent-permissions:dry-run
```

**마이그레이션 실행:**

```bash
docker compose exec api npm run migrate:agent-permissions
```

**사용자 지정 배치 크기 (대규모 데이터셋용):**

```bash
docker compose exec api npm run migrate:agent-permissions:batch
```

#### 2. `deploy-compose.yml`의 경우 [#2-for-the-deploy-composeyml]

[Ubuntu Docker 가이드](/docs/remote/docker_linux)를 따랐다면:

**변경 사항 미리보기 (dry run):**

```bash
docker exec -it LibreChat-API /bin/sh -c "cd .. && npm run migrate:agent-permissions:dry-run"
```

**마이그레이션 실행:**

```bash
docker exec -it LibreChat-API /bin/sh -c "cd .. && npm run migrate:agent-permissions"
```

**사용자 지정 배치 크기 (대규모 데이터셋용):**

```bash
docker exec -it LibreChat-API /bin/sh -c "cd .. && npm run migrate:agent-permissions:batch"
```

#### 3. 로컬 개발 환경 (프로젝트 루트에서): [#3-for-local-development-from-project-root]

**변경 사항 미리보기 (dry run):**

```bash
npm run migrate:agent-permissions:dry-run
```

**마이그레이션 실행:**

```bash
npm run migrate:agent-permissions
```

**사용자 지정 배치 크기 (대규모 데이터셋용):**

```bash
npm run migrate:agent-permissions:batch
```

### 마이그레이션 중 발생하는 일 [#what-happens-during-migration]

- **Private Agents**: 생성자에게만 액세스 권한이 유지됩니다(OWNER 권한을 받음)
- **공유 에이전트(Shared Agents)**: 이전에 공유된 에이전트인 경우, 공개 에이전트(모든 사용자에게 공유됨)로서 적절한 ACL 항목이 부여됩니다.
- **시스템 감지**: LibreChat은 시작 시 마이그레이션되지 않은 에이전트를 자동으로 감지하여 경고를 표시합니다.

Agent Builder UI를 통해 결과로 생성된 에이전트 권한을 조정할 수 있습니다.

<Callout type="info" title="참고">
  동일한 마이그레이션 프로세스가 프롬프트에도 적용됩니다. 기존 프롬프트가 있는 경우, 동일한 명령어를 사용하되 명령어 이름에서 `agent`를 `prompt`로 변경하여 프롬프트 권한 마이그레이션을 실행하세요.
</Callout>

## 다음 단계는 무엇인가요? [#whats-next]

LibreChat Agents는 LibreChat 내의 경험 전반에 걸쳐 특정 작업 및 워크플로우를 위한 에이전트를 통해 향후 파이프라인을 간소화할 수 있는 앱의 새로운 시대를 열어줍니다.

향후 업데이트에는 다음이 포함될 예정입니다:

- 현재 Agent 경험에 대한 일반적인 개선 사항
- 복잡한 워크플로우를 위한 멀티 에이전트 오케스트레이션
- 다양한 기능을 위한 에이전트 사용자 지정 기능: 제목 지정(채팅 스레드 이름 지정), 메모리 관리(사용자 컨텍스트/기록), 프롬프트 향상(입력 지원/예측)
- 더 많은 도구, 구성 가능한 도구 매개변수, 동적 도구 생성.

또한, 이번 업데이트는 LibreChat의 새로운 패러다임을 제시합니다. 기본 아키텍처가 앱에 꼭 필요한 쇄신을 제공하여 사용자 경험과 전반적인 앱 성능을 모두 최적화하기 때문입니다.

주목할 만한 최적화 중 하나를 강조하자면, 약 1000 토큰의 AI 생성은 기존 endpoint(작성 시점 기준으로 Agents 및 AWS Bedrock을 제외한 모든 endpoint 옵션)를 사용할 경우 약 1MB의 데이터를 전송하게 됩니다.

에이전트를 사용하면 동일한 생성 작업에서 약 52kb의 데이터만 전송되므로 데이터 전송량이 95% 감소하며, 이는 서버와 사용자 기기의 부하를 그만큼 줄여줍니다.
