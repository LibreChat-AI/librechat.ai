Skills sind wiederverwendbare Anweisungsbündel für LibreChat Agents. Eine Skill basiert auf einer `SKILL.md`-Datei: Das Frontmatter beschreibt, wann die Skill verwendet werden soll, und der Markdown-Textinhalt gibt dem Agenten die Vorgehensweise, Regeln, Beispiele oder Referenzen an die Hand, denen er folgen soll.

Skills sind nützlich für wiederholbare Aufgaben wie:

- Anwenden von Marken- oder Schreibrichtlinien
- Befolgen der internen Prüflisten
- Ausführen eines Standard-Research-Workflows
- Vorbereiten eines spezialisierten Tool-Workflows
- Verpacken von wiederverwendbaren Skripten, Referenzen und Assets mit einer Anweisungsdatei

LibreChat wird nicht mit einer Skill-Bibliothek ausgeliefert. Jeder Skill stammt aus Ihrer eigenen Instanz: [in der Benutzeroberfläche geschrieben oder hochgeladen](#create-a-skill), [während eines Chats von einem Agenten erstellt](#runtime-skill-authoring), [vom Dateisystem eingebunden](#deployment-skills) oder [aus einem GitHub-Repository gespiegelt](#github-skill-sync).

## Skills aktivieren [#enable-skills]

Die `skills` Agenten-Funktion ist standardmäßig aktiviert. Administratoren können sie aus der Liste der Fähigkeiten des agents Endpunkts entfernen, um Skills vor Benutzern zu verbergen.

```yaml filename="librechat.yaml"
endpoints:
  agents:
    capabilities:
      - 'deferred_tools'
      - 'execute_code'
      - 'file_search'
      - 'web_search'
      - 'artifacts'
      - 'subagents'
      - 'actions'
      - 'context'
      - 'skills'
      - 'memory'
      - 'ask_user_question'
      - 'tools'
      - 'chain'
      - 'ocr'
```

Rollenberechtigungen steuern, wer Skills verwenden, erstellen, teilen und öffentlich teilen darf. Die Verwendung und Erstellung von Skills ist standardmäßig erlaubt; das Teilen und öffentliche Teilen ist für Nicht-Admin-Rollen standardmäßig deaktiviert. Admins ändern diese Einstellungen über die Admin-Einstellungen im Skills-Panel.

Wenn die Funktion deaktiviert ist oder Ihrer Rolle die Berechtigung zur Nutzung fehlt, erscheint Skills überhaupt nicht im Seitenbereich.

## Eine Skill verwenden [#use-a-skill]

<Steps>
<Step>

**Open Skills** über die Seitenleiste. Das Bedienfeld listet die Skills auf, die Sie besitzen, sowie die, die mit Ihnen geteilt wurden, inklusive eines Filterfelds für lange Listen. Durch das Auswählen eines Skills gelangen Sie auf dessen Seite, auf der Sie die Anweisungen lesen und die dazugehörigen Dateien durchsuchen können.

</Step>
<Step>

**Überprüfen Sie, ob die Skill verfügbar ist.** Jede Skill verfügt über einen Schalter **Für Agent verfügbar**. Skills, die Sie besitzen, sowie Deployment-Skills sind standardmäßig verfügbar; geteilte Skills folgen der vom Administrator konfigurierten Standardeinstellung, bis Sie diese überschreiben.

</Step>
<Step>

**Geben Sie dem Agenten Zugriff.** Aktivieren Sie im Agent Builder die Option **Enable skills** und entscheiden Sie dann, ob der Agent den vollständigen Katalog oder nur die von Ihnen ausgewählten Skills sehen soll. Siehe [Agent Scope](#agent-scope).

</Step>
<Step>

**Skill aufrufen.** Geben Sie `$` in das Nachrichtenfeld ein und wählen Sie einen Skill anhand seines Namens aus. Es wird nichts in Ihren Nachrichtentext eingefügt: Der Skill wird für diesen Turn in die Warteschlange gestellt und als Chip über dem Eingabefeld angezeigt. Das Modell kann auch von sich aus einen Skill auswählen, und `always-apply`-Skills erfordern überhaupt keine Aktion.

</Step>
</Steps>

## Eine Skill erstellen [#create-a-skill]

Öffnen Sie **Skills** über das Seitenpanel und verwenden Sie die **+**-Schaltfläche, die zwei Wege bietet:

- **Skill-Anweisungen schreiben** — ein Dialog mit einem Namen, einer Beschreibung und dem Anweisungstext.
- **Skill hochladen** — eine `.md`-, `.zip`- oder `.skill`-Datei, die eine `SKILL.md` enthält.

Ein Agent kann während seiner Arbeit auch eine Skill für dich erstellen, ohne dass du dieses Panel aufrufen musst. Siehe [Runtime Skill Authoring](#runtime-skill-authoring).

Minimales `SKILL.md`:

```md filename="SKILL.md"
---
name: brand-guidelines
description: Use when writing public-facing content that must follow the company voice and terminology.
---

# Brand Guidelines

Write in a concise, practical tone.
Prefer active voice.
Use product terminology consistently.
```

Schlüssel werden unabhängig von der Groß-/Kleinschreibung abgeglichen, und boolesche Felder akzeptieren nur `true` oder `false`. Das Entfernen eines booleschen Schlüssels beim späteren Speichern löscht diesen, sodass das Löschen von `disable-model-invocation` den Modellaufruf wiederherstellt.

Erkannte frontmatter-Felder werden einer Typenprüfung unterzogen. Nicht erkannte Felder werden als begrenzte, JSON-sichere Metadaten beibehalten, anstatt den Skill ungültig zu machen; tief verschachtelte oder zu große Erweiterungswerte werden weiterhin abgelehnt.

Halten Sie die `description` eines von einem Modell aufgerufenen Skills bei 250 Zeichen oder weniger und platzieren Sie die wichtigsten Auslösephrasen zuerst. Längere Beschreibungen können zwar weiterhin importiert werden, aber LibreChat kürzt diese im für das Modell sichtbaren Katalog und protokolliert eine Warnung, in der jeder betroffene Skill benannt wird.

### Benennung und Größenbeschränkungen [#naming-and-size-limits]

- `name` ist erforderlich, muss dem Muster `^[a-z0-9][a-z0-9-]*$` entsprechen und ist auf 64 Zeichen begrenzt. Es muss unter Ihren eigenen Skills eindeutig sein; das erneute Hochladen eines bestehenden Namens führt zu einem Konfliktfehler, anstatt ihn zu überschreiben.
- Namen dürfen nicht mit `anthropic-` oder `claude-` beginnen und dürfen nicht exakt `help`, `clear`, `compact`, `model`, `exit`, `quit`, `settings`, `anthropic` oder `claude` lauten. Diese Namen würden echte Befehle überschreiben.
- `description` ist erforderlich und auf 1024 Zeichen begrenzt. Beschreibungen unter 20 Zeichen werden mit einer Warnung akzeptiert, da sie selten zuverlässig ausgelöst werden.
- Der Anweisungstext ist auf 100.000 Zeichen begrenzt.

### Ein Bundle hochladen [#upload-a-bundle]

Ein `.zip`- oder `.skill`-Archiv muss eine `SKILL.md` im Stammverzeichnis des Archivs oder genau eine Ordnerebene tiefer enthalten. Ein einzelner umschließender Ordner wird beim Import entfernt; tiefer liegende Strukturen werden nicht erkannt.

    <FileTree.Folder name="references" defaultOpen>
      <FileTree.File name="tone-examples.md" />

    <FileTree.Folder name="scripts">
      <FileTree.File name="lint-copy.py" />
    </FileTree.Folder>
  </FileTree.Folder>

Import-Limits:

- Akzeptierte Erweiterungen: `.md`, `.zip`, `.skill`.
- Standardmäßig 50 MB pro Upload. Administratoren können dies mit [`fileConfig.skills.fileSizeLimit`](/docs/configuration/librechat_yaml/object_structure/file_config#skills) in der `librechat.yaml` ändern.
- Bis zu 500 Einträge pro Archiv und 10 MB pro gebündelter Datei.
- Ein `.md`-Upload ohne Frontmatter-`name` leitet den Skill-Namen vom Dateinamen ab.
- Einträge mit unsicheren Pfaden, wie z. B. Traversal- oder absolute Pfade, werden als Fehler gemeldet und übersprungen; der Rest des Skills wird weiterhin importiert.

Skills, die aus `DEPLOYMENT_SKILLS_DIR` oder via GitHub Skill Sync stammen, sind schreibgeschützt. Nur Skills, die innerhalb von LibreChat erstellt wurden, können in der UI bearbeitet werden.

## Aufrufmodi [#invocation-modes]

Skills können einen Agenten auf drei Arten erreichen:

- **Manuell**: Der Benutzer gibt `$` im Chat ein und wählt eine Fähigkeit aus dem Popover aus.
- **Model-invoked**: das Modell wählt eine Fähigkeit aus dem injizierten Fähigkeitskatalog aus und ruft das Skill-Tool auf.
- **Always apply**: die Fähigkeit wird bei Aktivierung in jede Interaktion eingebunden.

Was tatsächlich in den Kontext gelangt, unterscheidet sich je nach Pfad:

- Der vom Modell aufgerufene Katalog enthält nur Namen und Beschreibungen, bis zu 100 Skills, wobei jeder Eintrag auf etwa 250 Zeichen gekürzt wird. Anweisungstexte sind nicht Teil des Katalogs.
- Manuelle und „Always-apply“-Aufrufe bereiten den vollständigen `SKILL.md`-Text für diesen Turn vor, bis zu 10 manuelle und 20 „Always-apply“-Skills, sowie 30 in Kombination. Wenn das kombinierte Limit überschritten wird, werden „Always-apply“-Skills zuerst verworfen, damit die explizite Benutzerabsicht erhalten bleibt.

Die manuelle Aufrufung ist eine explizite Benutzerabsicht. Sie kann Skills verwenden, die für die Modellaufrufung mit `disable-model-invocation: true` verborgen sind, sofern `user-invocable` nicht auf false gesetzt ist.

## Agent-Geltungsbereich [#agent-scope]

Agenten müssen **Enable skills** aktiviert haben, bevor sie Skills verwenden oder erstellen können. Der separate Schalter **Use all skills** steuert die Sichtbarkeit im Katalog.

- **Alle:** Aktivieren Sie **Use all skills**, um den gesamten aktiven Katalog anzuzeigen, der für den Benutzer sichtbar ist, einschließlich später hinzugefügter Skills.
- **Ausgewählt:** Lassen Sie **Use all skills** deaktiviert und fügen Sie einzelne Skills hinzu, um nur diese Einträge verfügbar zu machen.
- **Nur für Autoren:** Lassen Sie **Use all skills** deaktiviert, ohne ausgewählte Skills. Bestehende Katalogeinträge werden nicht angezeigt, aber der Agent kann während einer Unterhaltung einen Skill erstellen, wenn der Benutzer über die Berechtigung zur Skill-Erstellung verfügt.
- **Deaktiviert:** Deaktivieren Sie **Enable skills**, um sowohl die Katalognutzung als auch die Laufzeit-Erstellung zu deaktivieren.

Dies ermöglicht es Administratoren, die Skills-Funktion global bereitzustellen und gleichzeitig das nutzbare Skill-Set jedes Agenten fokussiert zu halten.

Das Deaktivieren von **Use all skills** stellt die Auswahl wieder her, die vor dem Aktivieren des Schalters aktiv war. Bestehende Agents behalten das Legacy-Verhalten bei, bei dem aktivierte Skills ohne expliziten Geltungsbereich den vollständigen Katalog bedeuten.

## Runtime Skill Authoring [#runtime-skill-authoring]

Ein Agent mit aktivierten Skills kann während seiner Arbeit wiederverwendbare Skill-Dateien erstellen oder bearbeiten. Laufzeitdateien verwenden denselben `skills/{skillName}/...` Namespace wie hochgeladene Bundles, sodass der Agent `SKILL.md` sowie unterstützende Referenzen, Skripte oder Assets als Teil eines erfolgreichen Workflows erstellen kann.

Die Erstellung folgt dem normalen Berechtigungsmodell für Skills:

- Das Erstellen eines neuen Skill erfordert die **Create**-Berechtigung des Benutzers für Skill.
- Das Bearbeiten einer bestehenden Skill erfordert sowohl Bearbeitungszugriff als auch die Aufnahme in den aktiven Katalogbereich des Agenten; bereitgestellte und über GitHub synchronisierte Skills bleiben schreibgeschützt.
- Ein reiner Authoring-Agent kann eine neue Skill erstellen, ohne den bestehenden Katalog des Benutzers zu erhalten.

Die Laufzeit-Erstellung umgeht weder die Bereitstellungsfunktionen noch die Benutzerberechtigungen. Das Entfernen von `skills` aus den Fähigkeiten des Agents-endpoint verbirgt die Funktion, und das Deaktivieren von **Enable skills** beim Agent schaltet dessen Erstellungswerkzeuge aus.

## Aktive und geteilte Skills [#active-and-shared-skills]

Benutzer können Skills mit dem Schalter **Available to agent** aktivieren oder deaktivieren. Eigene und bereitgestellte Skills sind standardmäßig aktiv. Geteilte Skills verwenden den vom Administrator konfigurierten Standardwert, bis der Benutzer diesen überschreibt.

Inaktive Skills sind ausgeschlossen von:

- Das `$`-Popover
- Der vom Modell aufgerufene Skill-Katalog
- Immer anwendendes Priming

Das Teilen einer Skill gewährt bestimmten Benutzern, Gruppen oder Rollen Lese-, Bearbeitungs- oder Eigentümerzugriff über den Standard-Freigabedialog und erfordert die Freigabeberechtigung für Ihre Rolle. Siehe [Access Control](/docs/features/access_control) für das vollständige Modell.

## Gebündelte Dateien [#bundled-files]

Hochgeladene Skill-Bundles können neben der `SKILL.md` weitere Dateien enthalten, wie zum Beispiel:

- `references/...`
- `scripts/...`
- `assets/...`

Das Backend speichert diese Dateien zusammen mit der Skill. Der Agent kann Skill-Dateien auflösen, wenn die Skill aktiv und im Gültigkeitsbereich ist. Verschachtelte Dateien behalten ihre relativen Pfade bei und werden über den für das Modell sichtbaren Namespace `skills/{skillName}/...` adressiert. Im Skill-Viewer werden relative Markdown-Links von der aktuellen Datei aus aufgelöst und öffnen die referenzierte Datei innerhalb derselben Skill. Wenn der Code Interpreter aktiviert ist, werden dieselben Dateien unter `/mnt/data/skills/{skillName}/...` gemountet, sodass Shell- und Code-Operationen sie direkt verwenden können. Das Bearbeiten von `SKILL.md` erhöht die Skill-Version; vor der Code-Ausführung oder programmatischen Ausführung überprüft LibreChat, ob jede gemountete Dateireferenz mit dieser Version übereinstimmt, und lädt das vollständige Paket erneut hoch, wenn eine Referenz veraltet ist.

Die Seite einer Skill verfügt außerdem über einen Dateibaum mit den Aktionen **Neue Datei**, **Neuer Ordner** und **Datei hochladen**, wobei pro hinzugefügter Datei bis zu 10 MB möglich sind. `SKILL.md` selbst ist dort reserviert: Bearbeiten Sie stattdessen den Hauptteil der Skill.

<Callout type="note" title="Tipp zum Erstellen">
  Halten Sie die `description` spezifisch. Sie ist das stärkste Signal für vom Modell aufgerufene Fähigkeiten. Eine kurze oder vage Beschreibung führt zu einer zu geringen Auslösewahrscheinlichkeit.
</Callout>

## Bereitstellungsfähigkeiten [#deployment-skills]

Admins können schreibgeschützte Skills über das Dateisystem mit `DEPLOYMENT_SKILLS_DIR` bereitstellen.

```bash filename=".env"
DEPLOYMENT_SKILLS_DIR=./skill
```

Das Verzeichnis ist standardmäßig auf `./skill` im Projektstammverzeichnis eingestellt. Jede Skill befindet sich in einem eigenen Unterverzeichnis, das eine `SKILL.md` sowie alle dazugehörigen Dateien enthält. LibreChat lädt bereitgestellte Skills beim Start und stellt sie Benutzern zur Verfügung, bei denen die Skills-Funktion aktiviert ist.

Bereitstellungsfähigkeiten:

- Sind in der UI schreibgeschützt
- Verwenden Sie `deployment` als deren Quelle
- Haben Vorrang vor gespeicherten Skills mit demselben Namen
- Ein Neustart von LibreChat ist erforderlich, nachdem Dateien hinzugefügt, entfernt oder geändert wurden

Experimentelle [Agent Plugins](/docs/features/agent_plugins) können auch schreibgeschützte Deployment-Skills zusammen mit zugehörigen MCP-Servern bündeln. Ein Skill im eigenständigen Deployment-Verzeichnis hat Vorrang vor einem Plugin-Skill mit demselben Namen.

## GitHub Skill Sync [#github-skill-sync]

Admins können Skills aus GitHub-Repositories mit `skillSync.github` in der `librechat.yaml` spiegeln. Dies ist der praktische Weg, um eine kuratierte Auswahl an Skills innerhalb eines Teams zu teilen.

```yaml filename="librechat.yaml"
skillSync:
  github:
    enabled: true
    intervalMinutes: 60
    runOnStartup: true
    sources:
      - id: librechat-skills
        owner: your-org
        repo: your-skills-repo
        ref: main
        paths:
          - skills
        skillDiscoveryDepth: 2
        token: '${GITHUB_SKILLS_TOKEN}'
```

GitHub Skill Sync:

- Durchsucht konfigurierte Repository-Pfade nach `SKILL.md`
- Behandelt das Verzeichnis, das jedes `SKILL.md` enthält, als Skill-Wurzel innerhalb von `skillDiscoveryDepth` Ebenen des konfigurierten Pfads
- Importiert gebündelte Dateien neben jeder Skill
- Speichert gespiegelte Skills mit `source: "github"`
- Aktualisiert gespiegelte Skills, wenn sich das Upstream-Repository ändert
- Entfernt gespiegelte Skills, die in der konfigurierten Quelle nicht mehr existieren
- Veröffentlicht gültige Skills, selbst wenn ein anderer Skill in der Quelle ungültig ist oder in Konflikt steht
- Meldet teilweise erfolgreiche Ausführungen und Details zu übersprungenen Skills mit Begrenzung an Administratoren
- Unterstützt geplante, beim Start ausgeführte und manuell durch Administratoren ausgelöste Durchläufe

Ein übersprungener Skill behält sein zuletzt bekanntes, funktionierendes Spiegelbild bei, sofern eines existiert. Quellenweite Fehler wie Authentifizierung, Ratenbegrenzung, verlorener Synchronisierungsbesitz oder ein fehlgeschlagenes Rollback führen weiterhin zum Abbruch des gesamten Quellendurchlaufs.

Verwenden Sie ein fein abgestimmtes GitHub Personal Access Token mit schreibgeschützten Berechtigungen für Contents und Metadata für das ausgewählte Repository. Siehe [Skill Sync Object Structure](/docs/configuration/librechat_yaml/object_structure/skill_sync) für alle Felder, Anmeldeoptionen, Tenant-Scoping und Admin-Sync-Endpunkte.
