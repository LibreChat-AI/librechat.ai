# Agentes: Crie Assistentes de IA Personalizados [#agents-build-custom-ai-assistants]

O recurso de AI Agents do LibreChat oferece uma estrutura flexível para a criação de assistentes de IA personalizados, alimentados por diversos provedores de modelos.

Este recurso é semelhante à Assistants API da OpenAI e aos GPTs do ChatGPT, mas com suporte a uma gama mais ampla de modelos e uma implementação sem código (no-code), permitindo que você crie assistentes sofisticados com capacidades especializadas.

## Primeiros Passos [#getting-started]

Para criar um novo agente, selecione "Agents" no menu de endpoint e abra o painel Agent Builder encontrado no Side Panel.

![Agentes - Menu de endpoints](/images/agents/endpoints_menu.png)

O formulário de criação inclui:

- **Avatar**: Faça upload de um avatar personalizado para personalizar seu agente
- **Nome**: Escolha um nome distinto para o seu agente
- **Description**: Detalhes opcionais sobre o propósito do seu agente
- **Instruções**: Instruções de sistema que definem o comportamento do seu agente
- **Modelo**: Selecione a partir dos provedores e modelos disponíveis

Os controles de **Tools** e **Skills** abrem bibliotecas pesquisáveis para recursos integrados, ferramentas, servidores MCP, Actions e Skills. Selecione um item para configurá-lo e, em seguida, salve o agente.

**Agentes existentes podem ser selecionados no menu suspenso superior do Painel Lateral.**

- **Também por menção com "@" na entrada de chat.**

![Agentes - Menção](/images/agents/mention.png)

### Biblioteca de Ferramentas [#tool-library]

O Agent Builder mantém itens habilitados em seções separadas de **Tools** e **Skills**. Abra **Add tools** para pesquisar no catálogo completo ou filtrá-lo por **Official**, **Tools**, **MCP** ou **Actions**. **Made by you** reúne servidores MCP e Actions que você criou, enquanto **Favorites** mantém itens marcados como favoritos disponíveis em todos os agentes. Cada usuário pode salvar até 100 favoritos na biblioteca de ferramentas.

Selecione um item para configurá-lo sem sair do construtor. O menu **Create new** aparece apenas quando o usuário tem permissão para criar servidores MCP ou Actions. Remover uma capacidade baseada em arquivo, como File Search, File Context ou Code Interpreter, abre seu gerenciador de arquivos quando arquivos anexados ainda precisam ser revisados.

As Skills usam seu próprio seletor e podem ser selecionadas individualmente ou habilitadas como o catálogo completo acessível. Veja [Skills](/docs/features/skills#agent-scope).

Operadores também podem usar [Agent Plugins](/docs/features/agent_plugins) experimentais para agrupar Skills de implantação e servidores MCP em pacotes carregados na inicialização.

### Configuração de Modelo [#model-configuration]

A interface de parâmetros do modelo permite o ajuste fino das respostas do seu agente:

- Temperatura (escala de 0 a 1 para a criatividade da resposta)
- Tokens de contexto máximos
- Máximo de tokens de saída
- Configurações adicionais específicas do provedor

### Histórico de Versões [#version-history]

Usuários com acesso de edição podem abrir o **Version History** a partir do Agent Builder para inspecionar as configurações salvas em uma linha do tempo. Cada entrada mostra quando foi salva e resume suas ferramentas e capacidades. Restaurar uma entrada anterior requer confirmação e substitui a configuração atual do agente por aquele estado salvo. Salvar sempre aplica as alterações atuais do Agent, mesmo quando a configuração resultante corresponde à entrada de histórico mais recente e o LibreChat não adiciona uma entrada duplicada.

## Capacidades dos Agentes [#agent-capabilities]

> **Nota:** Todas as capacidades podem ser alternadas através do arquivo de configuração `librechat.yaml`. Veja [docs/configuration/librechat_yaml/object_structure/agents#capabilities](/docs/configuration/librechat_yaml/object_structure/agents#capabilities) para mais informações.

### Code Interpreter [#code-interpreter]

Quando ativado, o recurso Code Interpreter permite que seu agente:

- Execute código em várias linguagens, incluindo:
  - Python, JavaScript, TypeScript, Go, C, C++, Java, PHP, Rust e Fortran
- Processe arquivos de forma segura através da API de Code Interpreter do LibreChat
- Execute código sem configuração local, definições ou implantação de sandbox
- Gerencie uploads e downloads de arquivos de forma integrada
- [Mais informações sobre a API do Code Interpreter](/docs/features/code_interpreter)
  - **Desenvolvido pelo serviço de código aberto [code-interpreter](https://github.com/ClickHouse/code-interpreter) (auto-hospedado)**

Quando todos os arquivos necessários do Code Interpreter de uma conversa falham ao serem restaurados no sandbox atual, o LibreChat interrompe o Agent antes de invocar o modelo e solicita que o usuário anexe os arquivos novamente. Isso evita que a execução continue com referências de arquivos obsoletas ou inacessíveis.

#### Sessões de Código Stateful [#stateful-code-sessions]

Sessões de código stateful permitem que um agente reutilize um workspace de sandbox por conversa. Arquivos, pacotes instalados e o estado de trabalho geralmente são mantidos entre as execuções de código, o que é útil para análises iterativas e trabalho com arquivos em várias etapas.

<Callout type="warning" title="Altamente experimental">
  As Stateful Code Sessions estão em uma fase inicial de experimentação. Seu comportamento, configuração, características de persistência e integração subjacente podem mudar substancialmente. Não trate a implementação atual como um contrato de produção estável.
</Callout>

Este recurso é opcional. Um administrador deve adicionar `stateful_code_sessions` às [capacidades do agente](/docs/configuration/librechat_yaml/object_structure/agents#capabilities), o Code Interpreter deve estar habilitado no agente e **Stateful code sessions** deve estar ativado nas configurações avançadas do agente. O workspace pode ser redefinido a qualquer momento. Salve saídas importantes em `/mnt/data` e não confie no estado da sessão como armazenamento durável.

### File Search [#file-search]

A funcionalidade File Search permite:

- Funcionalidade de RAG (Retrieval-Augmented Generation)
- Busca semântica em documentos enviados
- Respostas com reconhecimento de contexto baseadas no conteúdo de arquivos
- Suporte a anexos de arquivos tanto em nível de agente quanto de thread de chat

### Contexto de Arquivo [#file-context]

A funcionalidade de File Context permite que seu agente armazene texto extraído de arquivos como parte de suas instruções de sistema:

- Extraia texto mantendo a estrutura e a formatação do documento
- Processar layouts complexos, incluindo texto em várias colunas e conteúdo misto
- Lidar com tabelas, equações e outros conteúdos especializados
- Trabalhe com conteúdo multilíngue
- O texto é armazenado nas instruções do agente no banco de dados
- **Nenhum serviço de OCR necessário** - Usa análise de texto por padrão com métodos de fallback
- **Aprimorado por OCR** - Se o OCR estiver configurado, a qualidade da extração melhora para imagens e documentos digitalizados
- Usa a mesma lógica de processamento que "Upload as Text": **OCR > STT > text parsing**
- [Mais informações sobre a configuração de OCR](/docs/features/ocr)

**Nota:** O File Context inclui texto extraído nas instruções de sistema do agente. Para perguntas sobre documentos temporários em conversas individuais, use [Upload as Text](/docs/features/upload_as_text) a partir do chat.

### Model Context Protocol (MCP) [#model-context-protocol-mcp]

MCP é um protocolo aberto que padroniza como as aplicações fornecem contexto para Large Language Models (LLMs), atuando como um adaptador universal para ferramentas de IA e fontes de dados.

Para mais informações, consulte a documentação sobre [MCP](/docs/features/mcp).

#### Agentes com MCP Tools [#agents-with-mcp-tools]

1. Configure servidores MCP no seu arquivo `librechat.yaml`
2. Reinicie o LibreChat para inicializar as conexões
3. Criar ou editar um agente
4. Abra **Add tools** no Agent Builder e selecione **MCP**
5. Selecione o(s) servidor(es) MCP que você deseja adicionar; cada servidor aparece como uma única entrada
6. Salve suas alterações no agente

Neste exemplo, adicionamos o **[Spotify MCP server](https://github.com/LibreChat-AI/spotify-mcp)** a um agente.

![Agentes - MCP](/images/agents/mcp_tools_v2.png)

#### Gerenciando Ferramentas MCP [#managing-mcp-tools]

Assim que um servidor MCP for adicionado a um agente, você poderá ajustar quais ferramentas específicas estarão disponíveis:

- Após adicionar um servidor MCP, expanda-o para ver todas as ferramentas disponíveis
- Marque/desmarque ferramentas individuais conforme necessário
- Por exemplo, o servidor MCP do Spotify fornece cerca de 20 ferramentas (pesquisa, controle de reprodução, gerenciamento de playlists, etc.)
- Esse controle granular permite que você limite os agentes apenas às ferramentas de que eles precisam

Servidores com escopo de solicitação que usam `{{LIBRECHAT_BODY_*}}` não podem enumerar ferramentas até que uma execução de chat forneça esses valores. Portanto, o Agent Builder mostra uma seleção de ferramentas de tempo de execução para o servidor completo em vez de alternadores por ferramenta; limpar essa seleção desconecta o servidor. Após o OAuth, o LibreChat mantém a autorização e aguarda até a primeira execução elegível para conectar.

Se um Agent selecionar explicitamente ferramentas MCP, mas nenhuma puder ser resolvida quando uma execução for iniciada, o LibreChat interrompe a execução com orientações de conexão e acesso em vez de continuar silenciosamente sem elas. Reconecte ou autentique o servidor, verifique o acesso à ferramenta e tente executar novamente.

![Agentes - Ferramentas MCP](/images/agents/mcp_agent_tools.png)

Saiba mais:

- [Configurando Servidores MCP](/docs/features/mcp)
- [Introdução ao Model Context Protocol](https://modelcontextprotocol.io/introduction)

### Ferramentas Diferidas [#deferred-tools]

Ferramentas adiadas (deferred tools) permitem que agentes tenham acesso a muitas ferramentas MCP sem carregá-las todas no contexto do LLM antecipadamente. Em vez disso, as ferramentas adiadas são detectáveis em tempo de execução por meio de um mecanismo de **Busca de Ferramentas** (Tool Search).

Isso é especialmente útil quando um agente tem acesso a muitos servidores MCP com dezenas de ferramentas — carregá-las todas consumiria uma grande parte da janela de contexto e degradaria a qualidade da resposta.

**Como funciona:**

- Ferramentas marcadas como "deferred" são excluídas do contexto inicial do LLM
- Uma ferramenta `ToolSearch` é adicionada automaticamente, permitindo que o LLM descubra e carregue ferramentas adiadas sob demanda.
- Uma vez descoberta, a ferramenta fica disponível para o restante da conversa

**Configurando ferramentas adiadas (deferred tools):**

1. Abra o Agent Builder e adicione ferramentas MCP
2. Clique no menu suspenso em qualquer ferramenta MCP
3. Alternar "Adiar Carregamento" — ferramentas adiadas exibem um ícone de relógio

**Nota:** A funcionalidade `deferred_tools` está habilitada por padrão. Ela pode ser alternada através da configuração de agentes no [`librechat.yaml`](/docs/configuration/librechat_yaml/object_structure/agents#capabilities).

### Grupos de Atividade [#activity-groups]

Os grupos de atividade recolhem cada bloco contíguo de raciocínio do Agent e chamadas de ferramenta sob um cabeçalho gerado de uma linha, tornando execuções longas mais fáceis de analisar. Os administradores os habilitam com `activityLabel` e podem usar um modelo mais rápido, outro endpoint configurado, um prompt personalizado e limites por execução. A geração do cabeçalho é uma chamada de modelo separada cujos tokens e custo são registrados. Veja [Agent Activity Groups](/docs/configuration/librechat_yaml/object_structure/shared_endpoint_settings#agent-activity-groups).

Administradores podem habilitar independentemente `activityPhaseLabel` para agrupar duas ou mais atividades lógicas em um resumo pai recolhido antes da resposta final. Isso fornece a execuções longas um esboço de nível superior, preservando cada atividade filha. Os resumos de fase usam seu próprio modelo, endpoint, prompt e limite por execução, com fallback para o rótulo da atividade e as configurações de execução.

O texto de progresso curto permanece dentro de sua fase pai. Quando o Agent inicia uma resposta substancial, o LibreChat fecha a fase antes desse texto para que o resultado exibido ao usuário permaneça fora do resumo recolhido. Uma execução pode criar múltiplas fases pai quando raciocínios posteriores ou ferramentas iniciam outro bloco de atividade lógica. Os limites de fase persistidos são rebaseados quando partes de conteúdo malformadas ou omitidas são compactadas, de modo que o agrupamento permaneça alinhado após a recarga.

### Rótulos de Intenção de Ferramenta [#tool-intent-labels]

Os rótulos de intenção de ferramenta (tool intent labels) substituem status genéricos de ferramentas em tempo real por uma breve descrição escrita pelo modelo para aquela chamada específica. Os administradores devem adicionar a capacidade de agente `tool_intents` [agent capability](/docs/configuration/librechat_yaml/object_structure/agents#capabilities). Ferramentas nativas usam rótulos automaticamente; no Construtor de Agentes (Agent Builder), expanda um servidor MCP e ative **Intent label** para ferramentas individuais ou para o servidor completo.

Para Model Specs, [`describeIntent`](/docs/configuration/librechat_yaml/object_structure/model_specs#describeintent) pode habilitar todas as ferramentas elegíveis ou selecionar IDs de ferramentas resolvidos. Os campos de intenção (intent) são adicionados ao esquema da ferramenta enviado ao modelo, portanto, a habilitação seletiva pode reduzir a sobrecarga de tokens do esquema.

Os rótulos de intenção (intent labels) não se aplicam a ferramentas MCP apenas programáticas, pois as chamadas feitas dentro do código sandbox não renderizam cartões de ferramentas individuais.

### Programmatic Tool Calling [#programmatic-tool-calling]

O Programmatic Tool Calling (PTC) permite que agentes executem ferramentas MCP selecionadas de dentro do sandbox do [Code Interpreter](/docs/features/code_interpreter) em vez de chamar cada ferramenta diretamente do modelo. O modelo recebe uma ferramenta de orquestração baseada no Code Interpreter, escreve código em sandbox que chama funções de ferramenta geradas e pode usar loops, condicionais, novas tentativas e processamento de resultados antes de retornar uma resposta.

Isso é útil para fluxos de trabalho de ferramentas com várias etapas, como consultar diversos recursos, paginar resultados, comparar saídas ou transformar respostas de ferramentas antes que o agente as explique.

**Configurando ferramentas programáticas:**

1. Enable both `programmatic_tools` and `execute_code` in the [`librechat.yaml` agents capabilities](/docs/configuration/librechat_yaml/object_structure/agents#capabilities).
2. Habilite o Code Interpreter no agente.
3. Adicione ferramentas MCP, expanda um servidor MCP e alterne **Programmatic** para ferramentas individuais ou para o servidor completo. Ferramentas Programmatic exibem um ícone de código.

**Nota:** `programmatic_tools` é opcional e não está incluído na lista de capacidades padrão dos agentes. O PTC também requer uma implementação do Code Interpreter com o componente Tool Call Server. Apenas ferramentas registradas para o agente podem ser chamadas a partir do sandbox; chamadas de ferramentas não registradas são rejeitadas.

### Chamadas de Ferramentas em Segundo Plano [#background-tool-calls]

Chamadas de ferramenta em segundo plano permitem que um agente inicie uma ferramenta MCP ou Code Interpreter elegível de longa execução, continue trabalhando e verifique o resultado posteriormente. A chamada inicial retorna imediatamente com uma referência de tarefa; o agente recupera o status e os resultados através de `check_background_task`.

Para usar este recurso, um administrador deve adicionar a capacidade de agente `run_in_background` [agent capability](/docs/configuration/librechat_yaml/object_structure/agents#capabilities). Em seguida, configure as ferramentas elegíveis no Construtor de Agentes:

- **Code Interpreter:** Habilite o Code Interpreter no agente. A execução de código e os comandos de shell tornam-se elegíveis para execução em segundo plano por padrão; desative **Background execution** nas configurações da ferramenta para optar por não utilizá-la.
- **MCP:** Abra um servidor MCP e marque ferramentas individuais, ou o servidor completo, como **Background**.

Essas configurações permitem a execução em segundo plano, mas não a forçam. O modelo decide, a cada chamada, se deve executar uma ferramenta elegível em segundo plano.

No chat do LibreChat, quando o código em segundo plano termina, seu stdout e os arquivos gerados aparecem na chamada de código original em vez da verificação posterior. Os arquivos gerados também são persistidos para turnos subsequentes.

O estado da tarefa em segundo plano é atualmente local ao processo. Os resultados podem ser coletados em um turno posterior no mesmo processo de servidor, mas eles não sobrevivem a uma reinicialização e não são compartilhados entre réplicas.

### Solicitar Aprovação do Usuário e da Ferramenta [#ask-user-and-tool-approval]

A ferramenta **Ask User** permite que um agente pause uma execução para solicitar informações ausentes, apresentar opções ou confirmar como proceder. Uma única chamada pode agrupar até quatro perguntas relacionadas em um único formulário. Cada pergunta aceita uma resposta de formato livre ou opções de seleção única ou múltipla definidas pelo agente; o usuário responde a todas as perguntas e envia uma única vez, ou ignora o formulário. Enquanto o modelo prepara a chamada, o LibreChat transmite as perguntas para um cartão de progresso; o formulário interativo o substitui quando estiver pronto. Após o envio, a mesma execução é retomada com as respostas. Adicione o **Ask User** a partir do marketplace de Tools; administradores podem remover a capacidade padrão `ask_user_question` para ocultá-la.

As respostas enviadas são persistidas com a ação de retomar, portanto, parar enquanto a execução retomada é inicializada não descarta as respostas aceitas.

Cada pergunta aceita um título opcional de até 80 caracteres, texto da pergunta de até 2.000 caracteres, contexto de suporte opcional de até 4.000 caracteres e até 12 opções. Os rótulos das opções são limitados a 280 caracteres, os valores das opções a 500 caracteres e cada resposta enviada a 16.000 caracteres.

Os administradores também podem exigir uma revisão antes que as chamadas de ferramentas correspondentes sejam executadas. Dependendo da ferramenta, os usuários podem aprovar, rejeitar, editar argumentos ou responder diretamente. As execuções pausadas são salvas em pontos de verificação (checkpoints) para que possam ser retomadas após a decisão, inclusive em outra réplica quando o checkpointer padrão do MongoDB é utilizado. A aprovação de ferramentas é desativada por padrão; veja [`toolApproval` e `checkpointer`](/docs/configuration/librechat_yaml/object_structure/agents#toolapproval).

### Skills [#skills]

Skills permitem que agentes carreguem instruções reutilizáveis a partir de definições em `SKILL.md`. Elas podem ser selecionadas manualmente no chat com `$`, descobertas automaticamente pelo modelo através do catálogo de skills ou sempre aplicadas a cada turno.

Para detalhes sobre autoria, invocação e controle de acesso, consulte [Skills](/docs/features/skills).

### Memória [#memory]

A ferramenta **Memory** permite que um agente salve, atualize ou exclua memórias estruturadas do usuário quando este solicita explicitamente que ele se lembre ou esqueça algo. O Memory deve ser configurado para a implantação, permitido pela função e pelas configurações de personalização do usuário e ativado no agente.

Por padrão, um agente usa o pool de memória pessoal compartilhado do usuário. Ative **Manter memórias separadas para este agente** para fornecer a ele uma partição privada por usuário e por agente. O agente isolado não verá memórias compartilhadas existentes ou memórias criadas por outros agentes isolados. Os usuários podem filtrar o painel de Memória por memórias pessoais ou específicas do agente. Veja [Memória do Usuário](/docs/features/memory#agent-memory).

### Artifacts [#artifacts]

A funcionalidade de Artifacts permite que seu agente gere e exiba conteúdo interativo:

- Crie componentes React, código HTML e diagramas Mermaid
- Exibir conteúdo em uma janela de interface separada para maior clareza e interação
- Configure instruções específicas para artefatos no nível do agente
- [Mais informações sobre Artifacts](/docs/features/artifacts)

Quando ativado, escolha um dos três modos de instrução:

- **Normal**: Adiciona as instruções de artefato padrão para React, HTML, SVG, Markdown e Mermaid.
- **shadcn/ui**: Adiciona as instruções padrão, além de orientações para a criação de interfaces com a biblioteca de componentes shadcn/ui.
- **Custom**: Mantém a renderização de artefatos ativada, mas não injeta instruções internas de artefatos, dando controle total às instruções do próprio agente.

Configurar artifacts no nível do agente é a abordagem preferida, pois permite um controle mais granular em comparação com a configuração legada de todo o aplicativo.

Se você selecionar **Custom**, inclua no mínimo o formato básico de artefato em suas instruções.

Aqui está um exemplo simples das instruções mínimas necessárias:

````md
When creating content that should be displayed as an artifact, use the following format:

:::artifact{identifier="unique-identifier" type="mime-type" title="Artifact Title"}

```
Your artifact content here
```

:::

For the type attribute, use one of:

- "text/html" for HTML content
- "application/vnd.mermaid" for Mermaid diagrams
- "application/vnd.react" for React components
- "image/svg+xml" for SVG images
````

### Ferramentas [#tools]

Os Agents também podem ser aprimorados com várias ferramentas integradas:

- **[Ferramentas de Imagem da OpenAI](/docs/features/image_gen#openai-image-tools)**: Geração e edição de imagens usando **[GPT-Image-1](https://platform.openai.com/docs/models/gpt-image-1)**
- **[Gemini Image Tools](/docs/configuration/tools/gemini_image_gen)**: Geração de imagens e edição com contexto de imagem usando modelos de imagem do Gemini
- **[DALL-E-3](/docs/features/image_gen#dalle-legacy)**: Geração de imagens a partir de descrições de texto
- **[Stable Diffusion](/docs/features/image_gen#stable-diffusion-local)** / **[Flux](/docs/features/image_gen#flux)**: Geração de texto para imagem
- **[Wolfram](/docs/configuration/tools/wolfram)**: Recursos computacionais e matemáticos
- **[OpenWeather](/docs/configuration/tools/openweather)**: Recuperação de dados meteorológicos
- **[Google Search](/docs/configuration/tools/google_search)**: Acesso à funcionalidade de pesquisa na web
- **[Calculator](/docs/configuration/tools/calculator)**: Cálculos matemáticos
- **[Tavily Search](/docs/configuration/tools/tavily)**: API de pesquisa avançada com integração de diversas fontes de dados
- **[Azure AI Search](/docs/configuration/tools/azure_ai_search)**: Recuperação de informações de índices do Azure AI Search
- **[Traversaal](/docs/configuration/tools/traversaal)**: Uma API de busca robusta para Agentes de LLM

#### Criar um Agente com Ferramentas de Imagem [#create-an-agent-with-image-tools]

1. Adicione as credenciais da ferramenta de imagem ao `.env`, como `IMAGE_GEN_OAI_API_KEY` para as ferramentas de imagem da OpenAI.
2. Reinicie o LibreChat para que as novas variáveis de ambiente sejam carregadas.
3. Selecione **Agents** no menu de endpoint.
4. Abra o Agent Builder no painel lateral e crie ou edite um agente.
5. Abra a lista de **Tools** do agente, selecione **OpenAI Image Tools**, **Gemini Image Tools**, **DALL-E-3**, **Stable Diffusion** ou **Flux** e, em seguida, salve o agente.
6. Inicie um chat com esse agente e peça para ele gerar ou editar uma imagem.

Para o guia completo de configuração de imagens, incluindo variáveis de modelo como `IMAGE_GEN_OAI_MODEL`, consulte [Geração e Edição de Imagens](/docs/features/image_gen).

- As ferramentas podem ser desativadas usando o arquivo de configuração [`librechat.yaml`](/docs/configuration/librechat_yaml):
  - [Mais informações](/docs/configuration/librechat_yaml/object_structure/agents#capabilities)

  - [Mais informações](/docs/configuration/librechat_yaml/object_structure/actions#alloweddomains)
- Observe que você pode adicionar a flag 'x-strict': true no nível da operação na especificação OpenAPI para actions.
  Se estiver usando um modelo OpenAI que suporte isso, isso gerará automaticamente chamadas de função com o modo 'strict' ativado.
  - O modo estrito suporta apenas um subconjunto parcial de json. Leia https://platform.openai.com/docs/guides/structured-outputs para obter detalhes.

### Handoffs [#handoffs]

As transferências (handoffs) permitem que um agente principal transfira uma conversa para um agente especialista com o contexto relevante. Em **Advanced settings**, abra a seção de orquestração e adicione até 10 agentes de transferência. Cada transferência configurada cria uma ferramenta de transferência que o modelo pode escolher dinamicamente quando a especialidade do especialista for necessária.

Para cada transferência (handoff), você pode adicionar uma descrição que ajuda o modelo a escolher o especialista certo. Você também pode fornecer instruções de passagem (passthrough) descrevendo qual conteúdo o agente principal deve gerar para o especialista e, opcionalmente, renomear o parâmetro de conteúdo de seu padrão, `instructions`. As transferências estão sempre disponíveis no Agent Builder; ao contrário do Agent Chain e dos Subagents, elas não exigem que uma capacidade de endpoint esteja habilitada.

### Cadeia de Agentes [#agent-chain]

A funcionalidade Agent Chain permite uma abordagem de Mixture-of-Agents (MoA), permitindo que você crie uma sequência de agentes que trabalham em conjunto:

- Crie cadeias de agentes especializados para tarefas complexas
- Cada agente na cadeia pode acessar as saídas de agentes anteriores
- Configure o número máximo de passos para a cadeia do agente
- **Nota:** Acesse este recurso no painel de Configurações Avançadas no Agent Builder
- **Nota:** Este recurso está atualmente em beta e pode estar sujeito a alterações
  - O máximo atual de agentes que podem ser encadeados é 10, mas isso poderá ser configurável no futuro.

Este recurso introduz uma arquitetura de Mixture-of-Agents em camadas ao LibreChat, onde cada agente utiliza todas as saídas dos agentes da camada anterior como informação auxiliar para gerar sua resposta, conforme descrito no [artigo homônimo "Mixture-of-Agents"](https://arxiv.org/abs/2406.04692).

### Subagentes [#subagents]

Subagents permitem que um agente delegue uma tarefa específica para uma execução filha isolada. O filho obtém sua própria janela de contexto e fluxo de execução de ferramentas, retornando então um resultado compacto para o pai, em vez de preencher o contexto do pai com cada etapa intermediária.

Subagents são diferentes de Agent Chain: o chain runs coordena múltiplos agentes como participantes de um grafo, enquanto subagents são gerados por um agente como uma chamada de ferramenta para delegação de escopo. Para configuração e limites, veja [Subagents](/docs/features/subagents).

### Configurações Avançadas [#advanced-settings]

Configurações avançadas para seu agente (encontradas na visualização Advanced do formulário de Agent) fora de "capabilities."

#### Max Agent Steps [#max-agent-steps]

Esta configuração permite limitar o número de passos que um agente pode realizar em uma "execução" (run), o que se refere ao loop do agente antes que uma resposta final seja fornecida.

Se deixado sem configuração, o padrão é 25 passos, mas você pode ajustar isso para atender às suas necessidades. Para administradores, é possível definir um padrão global, bem como um máximo global no arquivo [`librechat.yaml`](/docs/configuration/librechat_yaml/object_structure/agents#recursionlimit).

Administradores também podem limitar argumentos de chamadas de ferramenta transmitidos (streamed) e eventos de delta do modelo com [Agent stream circuit breakers](/docs/configuration/librechat_yaml/object_structure/agents#stream-circuit-breakers).

Um "step" refere-se a uma requisição de API de IA ou a uma rodada de uso de ferramentas (1 ou várias ferramentas, dependendo de quantas chamadas de ferramenta o LLM fornecer a partir de uma única requisição).

Uma resposta única, sem ferramentas, é 1 passo. Uma rodada singular de uso de ferramentas geralmente consiste em 3 passos:

1. Requisição de API -> 2. Uso de Ferramentas (1 ou muitas ferramentas) -> 3. Requisição de API de Acompanhamento

## Gerenciamento de Arquivos [#file-management]

Os Agents suportam várias maneiras de trabalhar com arquivos:

### Na Interface de Chat [#in-chat-interface]

Ao conversar com um agente, você tem quatro opções de upload:

1. **Fazer upload de imagens**
   - Faz upload de imagens para suporte nativo a modelos de visão
   - Envia imagens diretamente para o provedor do modelo

2. **Upload como Texto** (requer a capacidade `context`)
   - Extrai e inclui o conteúdo completo do documento na conversa
   - Usa análise de texto por padrão; aprimorado por OCR se configurado
   - O conteúdo existe apenas na conversa atual
   - Veja [Upload as Text](/docs/features/upload_as_text)

3. **Upload para File Search** (requer a capacidade `file_search`, ativada)
   - Usa busca semântica (RAG) com armazenamentos de vetores
   - Retorna blocos relevantes via uso de ferramentas
   - Ideal para documentos grandes/múltiplos arquivos
   - Sub-ótimo para dados estruturados (CSV, Excel, JSON, etc.)

4. **Upload para Code Interpreter** (requer a funcionalidade `execute_code`, ativada)
   - Adiciona arquivos ao ambiente do interpretador de código
   - Ideal para dados estruturados (CSV, Excel, JSON, etc.)
   - Mais informações sobre o [Code Interpreter](/docs/features/code_interpreter)

### No Agent Builder [#in-agent-builder]

Ao configurar um agente, você pode anexar arquivos em diferentes categorias:

1. **Upload de Imagem**: Para conteúdo visual que o agente pode referenciar
2. **Upload de Pesquisa de Arquivos**: Documentos para capacidades de RAG
3. **Code Interpreter Upload**: Arquivos para processamento de código
4. **Contexto de Arquivo**: Documentos com texto extraído para complementar as instruções do agente

**File Context** usa a capacidade `context` e funciona exatamente como ["Upload as Text"](/docs/features/upload_as_text) - ele usa análise de texto por padrão e é aprimorado por OCR quando configurado. O texto é extraído no momento do upload e armazenado nas instruções do agente. Isso é ideal para fornecer aos agentes conhecimento persistente a partir de documentos, PDFs, arquivos de código ou imagens com texto.

**Prioridade de processamento:** OCR > STT > análise de texto (o mesmo que Upload como Texto)

**Nota:** O texto extraído é incluído como parte das instruções de sistema do agente.

## Compartilhamento e Permissões [#sharing-and-permissions]

Os Agents utilizam o sistema granular de [controle de acesso](/docs/features/access_control) do LibreChat. Cada agent possui sua própria Lista de Controle de Acesso (ACL) e pode ser compartilhado com **usuários**, **grupos**, **funções** específicos ou **publicamente**, cada um em um nível de permissão escolhido.

### Funções de Acesso [#access-roles]

Ao compartilhar um agente, é atribuída ao beneficiário uma de três funções:

| Função | O que o beneficiário pode fazer |
| ---------- | ----------------------------------------------------------------------------------------------------- |
| **Viewer** | Usar o agente em conversas; não pode abrir o construtor nem ver instruções, ferramentas ou arquivos anexados |
| **Editor** | Visualizar + modificar as instruções, modelo, ferramentas e arquivos do agente |
| **Owner** | Controle total: visualizar, editar, excluir e compartilhar novamente o agente |

O autor original e os administradores sempre mantêm controle total, independentemente da ACL.

### Compartilhando um Agent [#sharing-an-agent]

1. Abra o agente no Agent Builder
2. Clique no botão **Share** no rodapé (visível quando você é o autor, um administrador ou recebeu a permissão `SHARE` naquele agente específico)
3. Pesquise por usuários, grupos ou funções no seletor de pessoas e atribua uma função a cada um
4. Opcionalmente, alterne **Public** para tornar o agente visível para todos na instância (requer a permissão de recurso `SHARE_PUBLIC`)

Os cartões de agente e as visualizações de página inicial exibem o contato de suporte configurado. Quando nenhum é definido, o LibreChat pode recorrer ao nome de exibição do primeiro proprietário identificável, mas não expõe o endereço de e-mail do proprietário, a menos que tenha sido configurado explicitamente como o contato de suporte.

Para detalhes completos sobre principais, bits de permissão e como ACLs se compõem com permissões de recursos baseadas em funções, veja [Access Control](/docs/features/access_control).

### Controles do Administrador [#administrator-controls]

Os administradores têm acesso às configurações globais de permissão dentro da interface do usuário do construtor de agentes:

- Habilitar/desabilitar o compartilhamento de agentes para todos os usuários
- Controlar permissões de uso de agentes
- Gerenciar direitos de criação de agentes
- Configure as definições de toda a plataforma

A primeira conta criada para sua instância é um administrador. Se você precisar adicionar um administrador adicional, você pode [acessar o MongoDB](/docs/configuration/mongodb/mongodb_auth) e atualizar o perfil do usuário:

```
db.users.updateOne(
  { email: 'USER_EMAIL_ADDRESS' },
  { $set: { role: 'ADMIN' } }
)
```

O uso de agentes para todos os usuários também pode ser desativado via configuração, [mais informações](/docs/configuration/librechat_yaml/object_structure/interface).

As permissões em nível de recurso (quem pode _usar_, _criar_, _compartilhar_ ou _compartilhar publicamente_ agentes) são gerenciadas a partir do [**Painel de Administração do LibreChat**](/docs/features/admin_panel) em cada função, incluindo quaisquer funções personalizadas. O bloco [`interface.agents`](/docs/configuration/librechat_yaml/object_structure/interface#agents) no `librechat.yaml` ainda pode definir padrões para a função `USER` integrada na inicialização, mas o painel de administração é a forma recomendada para editá-los daqui em diante.

### Compartilhamento em Nível de Usuário [#user-level-sharing]

Usuários individuais podem:

- Compartilhe seus agentes com usuários, grupos ou funções específicos (se `SHARE` estiver habilitado para a função deles)
- Tornar os agentes visíveis para todos na instância (se `SHARE_PUBLIC` estiver habilitado)
- Conceda a cada destinatário um nível de acesso diferente (Visualizador / Editor / Proprietário)
- Compartilhe novamente ou revogue o acesso a qualquer momento a partir da caixa de diálogo de compartilhamento

## Steering e Mensagens em Fila [#steering-and-queued-messages]

Enquanto um Agent está respondendo, você pode enviar outra mensagem de duas maneiras:

- **Steer** insere a mensagem na execução atual no seu próximo passo de ferramenta ou agente, para que o agente possa ajustar seu trabalho antes de finalizar.
- **Queue** retém a mensagem e a envia como um turno de acompanhamento normal após a conclusão da resposta atual.

**Interrupt & steer** interrompe a geração no próximo limite seguro do provedor, mantém a resposta parcial, insere a mensagem e retoma a mesma resposta do assistente. Use o controle dedicado no compositor, escolha-o no menu do botão de envio ou pressione `Command/Ctrl + Shift + .`. A ação recorre ao direcionamento comum quando a implantação não consegue interromper o fluxo ativo do provedor.

Em **Settings → Chat**, **While generating, Enter will** escolhe a ação padrão. O menu do botão de envio pode substituir essa escolha para uma mensagem individual, e **Steering interrupts generation** controla se o direcionamento comum também solicita uma interrupção.

Os steers pendentes aparecem acima do composer até que o servidor os insira na execução. Uma vez reconhecidos, o menu deles pode recuperar a mensagem para edição, convertê-la em um follow-up na fila ou cancelá-la e restaurar seu texto e anexos para o composer. O LibreChat evita sobrescrever um rascunho mais recente; se o composer não estiver mais disponível, ele preserva a mensagem recuperada na fila. Um steer com falha permanece disponível para tentar novamente, editar, colocar na fila ou remover.

Follow-ups na fila podem ser enviados imediatamente, convertidos em um steer enquanto a execução ainda está ativa, escalados para **Interrupt & steer now**, editados ou removidos. Steers em andamento oferecem a mesma escalação quando ainda estão aguardando um limite de ferramenta. Remover uma mensagem na fila a restaura para um compositor vazio quando possível. Uma execução ativa aceita até 10 steers pendentes; cada steer pode incluir até 10 arquivos e é limitado por [`STEER_MAX_LENGTH`](/docs/configuration/dotenv#agent-conversation-controls).

Implantações com múltiplas réplicas baseadas em Redis devem concluir a [implementação do protocolo de geração v2](/docs/configuration/redis#generation-protocol-rollout) antes de depender do comportamento de interrupção e recuperação entre réplicas.

### Notas [#notes]

- Instruções, parâmetros de modelo, arquivos anexados e ferramentas só são expostos ao usuário se ele tiver permissões de edição.
  - Um agente pode vazar quaisquer dados anexados, sejam instruções ou arquivos, através da conversa, portanto, certifique-se de que suas instruções sejam robustas contra isso antes de conceder acesso de Editor/Proprietário ou tornar o agente público.
- Apenas autores originais, administradores e beneficiários com permissão de Owner podem excluir agentes compartilhados
- Agentes são privados para os autores, a menos que sejam compartilhados

## Recapitulação [#recap]

1. Selecione "Agents" no menu suspenso de endpoint
2. Abra o painel do Agent Builder
3. Preencha os detalhes necessários do agente
4. Configure as capacidades desejadas (Code Interpreter, File Search, File Context, etc.)
5. Adicione as ferramentas e arquivos necessários
6. Defina as permissões de compartilhamento, se desejar
7. Crie e comece a usar seu agente

Ao conversar com agentes, você pode:

- Use "Upload as Text" para incluir o conteúdo completo do documento nas conversas (análise de texto por padrão, aprimorada por OCR)
- Use "Upload for File Search" para busca semântica em documentos (requer RAG API)
- Adicione arquivos ao "File Context" do agente para incluir o conteúdo completo de um arquivo como parte das instruções de sistema do agente.

## Migração Necessária (v0.8.0-rc3+) [#migration-required-v080-rc3]

<Callout type="warning" title="Importante: Migração de Permissões de Agente Necessária">
  A partir da versão v0.8.0-rc3, o LibreChat utiliza um novo sistema de permissões baseado em Lista de Controle de Acesso (ACL) para agentes. Se você estiver atualizando de uma versão anterior, você deve executar a migração de permissões de agentes para que os agentes existentes permaneçam acessíveis.
</Callout>

### O que a migração faz [#what-the-migration-does]

A migração de permissões de agentes transita seus agentes de um modelo simples de propriedade para um sistema sofisticado baseado em ACL com múltiplos níveis de permissão:

- **OWNER**: Controle total sobre o agente
- **EDITOR**: Pode visualizar e modificar o agente
- **VIEWER**: Acesso somente leitura ao agente

Sem executar esta migração, os agentes existentes ficarão inacessíveis através dos novos endpoints da API com reconhecimento de permissões.

### Executando a Migração [#running-the-migration]

Escolha o comando apropriado com base no seu método de implantação:

#### 1. Para o `docker-compose.yml` padrão (se você usa `docker compose up` para iniciar o aplicativo): [#1-for-the-default-docker-composeyml-if-you-use-docker-compose-up-to-start-the-app]

**Visualizar alterações (dry run):**

```bash
docker compose exec api npm run migrate:agent-permissions:dry-run
```

**Executar migração:**

```bash
docker compose exec api npm run migrate:agent-permissions
```

**Tamanho de lote personalizado (para grandes conjuntos de dados):**

```bash
docker compose exec api npm run migrate:agent-permissions:batch
```

#### 2. Para o `deploy-compose.yml` [#2-for-the-deploy-composeyml]

Se você seguiu o [Ubuntu Docker Guide](/docs/remote/docker_linux):

**Visualizar alterações (dry run):**

```bash
docker exec -it LibreChat-API /bin/sh -c "cd .. && npm run migrate:agent-permissions:dry-run"
```

**Executar migração:**

```bash
docker exec -it LibreChat-API /bin/sh -c "cd .. && npm run migrate:agent-permissions"
```

**Tamanho de lote personalizado (para grandes conjuntos de dados):**

```bash
docker exec -it LibreChat-API /bin/sh -c "cd .. && npm run migrate:agent-permissions:batch"
```

#### 3. Para desenvolvimento local (a partir da raiz do projeto): [#3-for-local-development-from-project-root]

**Visualizar alterações (dry run):**

```bash
npm run migrate:agent-permissions:dry-run
```

**Executar migração:**

```bash
npm run migrate:agent-permissions
```

**Tamanho de lote personalizado (para grandes conjuntos de dados):**

```bash
npm run migrate:agent-permissions:batch
```

### O que acontece durante a migração [#what-happens-during-migration]

- **Agentes Privados**: Permanecem acessíveis apenas aos seus criadores (recebem permissão de OWNER)
- **Agentes Compartilhados**: Se um agente foi compartilhado anteriormente, ele receberá entradas de ACL apropriadas como um Agente Público (compartilhado com todos os usuários)
- **Detecção do Sistema**: O LibreChat detecta automaticamente agentes não migrados na inicialização e exibe um aviso

Você pode ajustar as permissões do agente resultante através da interface do Agent Builder.

<Callout type="info" title="Nota">
  O mesmo processo de migração se aplica aos prompts. Se você também tiver prompts existentes, execute a migração de permissões de prompt usando os mesmos comandos, mas substitua `agent` por `prompt` nos nomes dos comandos.
</Callout>

## O que vem a seguir? [#whats-next]

Os Agents do LibreChat inauguram uma nova era para o aplicativo, onde pipelines futuros podem ser otimizados por meio de Agents para tarefas e fluxos de trabalho específicos em toda a sua experiência no LibreChat.

Atualizações futuras incluirão:

- Melhorias gerais na experiência atual de Agentes
- Orquestração multi-agente para fluxos de trabalho complexos
- Capacidade de personalizar agentes para várias funções: titulação (nomeação de tópicos de chat), gerenciamento de memória (contexto/histórico do usuário) e aprimoramento de prompts (assistência/previsões de entrada)
- Mais ferramentas, parâmetros de ferramenta configuráveis, criação dinâmica de ferramentas.

Além disso, a atualização introduz um novo paradigma para o LibreChat, já que sua arquitetura subjacente proporciona uma renovação muito necessária para o aplicativo, otimizando tanto a experiência do usuário quanto o desempenho geral do aplicativo.

Para destacar uma otimização notável, uma geração de IA de aproximadamente 1000 tokens transferirá cerca de 1 MB de dados usando endpoints tradicionais (no momento em que este artigo foi escrito, qualquer opção de endpoint além de Agents e AWS Bedrock).

Ao usar um agente, a mesma geração transferirá cerca de 52 kb de dados, uma redução de 95% na transferência de dados, o que representa uma carga muito menor no servidor e no dispositivo do usuário.
