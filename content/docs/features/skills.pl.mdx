Umiejętności (Skills) to pakiety instrukcji wielokrotnego użytku dla Agentów LibreChat. Umiejętność opiera się na pliku `SKILL.md`: frontmatter opisuje, kiedy należy użyć danej umiejętności, a treść w formacie markdown dostarcza agentowi procedurę, zasady, przykłady lub odniesienia, których ma przestrzegać.

Umiejętności (Skills) są przydatne w powtarzalnych zadaniach, takich jak:

- Stosowanie wytycznych dotyczących marki lub pisania
- Przestrzeganie wewnętrznych list kontrolnych przeglądu
- Uruchamianie standardowego procesu badawczego
- Przygotowywanie wyspecjalizowanego przepływu pracy narzędzi
- Pakowanie skryptów wielokrotnego użytku, referencji i zasobów wraz z plikiem instrukcji

## Włączanie umiejętności [#enable-skills]

Funkcja agenta `skills` jest domyślnie włączona. Administratorzy mogą usunąć ją z listy funkcji endpointu agents, aby ukryć Skills przed użytkownikami.

```yaml filename="librechat.yaml"
endpoints:
  agents:
    capabilities:
      - 'deferred_tools'
      - 'execute_code'
      - 'file_search'
      - 'web_search'
      - 'artifacts'
      - 'subagents'
      - 'actions'
      - 'context'
      - 'skills'
      - 'memory'
      - 'ask_user_question'
      - 'tools'
      - 'chain'
      - 'ocr'
```

Uprawnienia ról kontrolują również to, kto może używać, tworzyć, udostępniać i publicznie udostępniać umiejętności (skills).

## Umiejętności wdrażania [#deployment-skills]

Administratorzy mogą wdrażać umiejętności (Skills) tylko do odczytu z systemu plików za pomocą `DEPLOYMENT_SKILLS_DIR`.

```bash filename=".env"
DEPLOYMENT_SKILLS_DIR=./skill
```

Katalog domyślnie znajduje się w `./skill` w głównym folderze projektu. LibreChat ładuje wdrożone Skills podczas uruchamiania i udostępnia je użytkownikom z włączoną funkcją Skills.

Umiejętności wdrażania:

- Są tylko do odczytu w interfejsie użytkownika
- Użyj `deployment` jako ich źródła
- Mają pierwszeństwo przed zapisanymi Skills o tej samej nazwie
- Wymagany jest restart LibreChat po dodaniu, usunięciu lub zmianie plików

Eksperymentalne [Agent Plugins](/docs/features/agent_plugins) mogą również łączyć umiejętności (Skills) wdrożeniowe tylko do odczytu wraz z powiązanymi serwerami MCP. Umiejętność w samodzielnym katalogu wdrożeniowym ma pierwszeństwo przed umiejętnością wtyczki o tej samej nazwie.

## GitHub Skill Sync [#github-skill-sync]

Administratorzy mogą synchronizować (mirror) Skills z repozytoriów GitHub za pomocą `skillSync.github` w pliku `librechat.yaml`.

```yaml filename="librechat.yaml"
skillSync:
  github:
    enabled: true
    intervalMinutes: 60
    runOnStartup: true
    sources:
      - id: librechat-skills
        owner: your-org
        repo: your-skills-repo
        ref: main
        paths:
          - skills
        skillDiscoveryDepth: 2
        token: '${GITHUB_SKILLS_TOKEN}'
```

GitHub Skill Sync:

- Skanuje skonfigurowane ścieżki repozytorium w poszukiwaniu `SKILL.md`
- Importuje spakowane pliki obok każdej umiejętności
- Przechowuje zduplikowane (mirrored) umiejętności (Skills) z `source: "github"`
- Aktualizuje odzwierciedlone Skills, gdy zmienia się repozytorium nadrzędne
- Usuwa zduplikowane Skills, które nie istnieją już w skonfigurowanym źródle
- Publikuje poprawne Skills nawet wtedy, gdy inny Skill w źródle jest nieprawidłowy lub powoduje konflikt
- Raportuje częściowo udane uruchomienia oraz szczegóły pominiętych Skillów z ograniczeniami do administratorów
- Obsługuje uruchomienia zaplanowane, przy starcie oraz ręcznie wyzwalane przez administratora

Pominięta Skill zachowuje swoje ostatnie znane poprawne odzwierciedlenie (mirror), jeśli takie istnieje. Błędy dotyczące całego źródła, takie jak uwierzytelnianie, limity szybkości (rate limiting), utrata własności synchronizacji lub nieudane wycofanie zmian (rollback), nadal powodują niepowodzenie całego uruchomienia źródła.

Użyj precyzyjnego osobistego tokenu dostępu (fine-grained personal access token) GitHub z uprawnieniami tylko do odczytu (read-only) dla Contents i Metadata dla wybranego repozytorium. Zobacz [Struktura obiektu synchronizacji umiejętności](/docs/configuration/librechat_yaml/object_structure/skill_sync), aby uzyskać informacje o wszystkich polach, opcjach poświadczeń, zakresach dzierżawy (tenant scoping) oraz punktach końcowych synchronizacji administratora.

## Tworzenie umiejętności (Skill) [#create-a-skill]

Otwórz **Skills** z panelu bocznego. Możesz napisać umiejętność bezpośrednio w LibreChat lub przesłać plik `.md`, `.zip` lub `.skill`, który zawiera `SKILL.md`.

Minimalny `SKILL.md`:

```md filename="SKILL.md"
---
name: brand-guidelines
description: Use when writing public-facing content that must follow the company voice and terminology.
---

# Brand Guidelines

Write in a concise, practical tone.
Prefer active voice.
Use product terminology consistently.
```

## Tryby wywołania [#invocation-modes]

Umiejętności mogą dotrzeć do agenta na trzy sposoby:

- **Manual**: użytkownik wpisuje `$` na czacie i wybiera umiejętność z wyskakującego okienka.
- **Model-invoked**: model wybiera umiejętność z wstrzykniętego katalogu umiejętności i wywołuje narzędzie umiejętności.
- **Zawsze stosuj**: umiejętność jest przygotowywana w każdej turze, gdy jest aktywna.

Ręczne wywołanie jest jawną intencją użytkownika. Może ono korzystać z umiejętności, które są ukryte przed wywołaniem przez model za pomocą `disable-model-invocation: true`, o ile `user-invocable` nie jest ustawione na false.

## Zakres Agenta [#agent-scope]

Agenci muszą mieć włączoną opcję **Enable skills**, zanim będą mogli używać lub tworzyć Skills. Osobny przełącznik **Use all skills** kontroluje widoczność w katalogu.

- **Wszystkie:** włącz **Użyj wszystkich umiejętności** (Use all skills), aby udostępnić użytkownikowi pełny aktywny katalog, w tym umiejętności dodane później.
- **Wybrano:** pozostaw opcję **Use all skills** wyłączoną i dodaj poszczególne Skills, aby udostępnić tylko te wpisy.
- **Tylko tworzenie:** pozostaw opcję **Use all skills** wyłączoną bez wybranych umiejętności (Skills). Istniejące wpisy w katalogu nie są udostępniane, ale agent może utworzyć umiejętność w trakcie rozmowy, jeśli użytkownik posiada uprawnienia do tworzenia umiejętności (Skill create permission).
- **Wyłączone:** wyłącz **Enable skills**, aby wyłączyć zarówno korzystanie z katalogu, jak i tworzenie w czasie wykonywania.

Pozwala to administratorom na globalne udostępnienie funkcji Skills, przy jednoczesnym zachowaniu ukierunkowanego zestawu umiejętności dla każdego agenta.

Wyłączenie opcji **Use all skills** przywraca wybór, który był aktywny przed włączeniem tego przełącznika. Istniejący agenci zachowują starsze zachowanie, w którym włączone Skills bez określonego zakresu oznaczają pełny katalog.

## Tworzenie umiejętności w czasie wykonywania (Runtime Skill Authoring) [#runtime-skill-authoring]

Agent z włączonymi Skills może tworzyć lub edytować pliki Skills wielokrotnego użytku podczas pracy. Pliki wykonywane w czasie rzeczywistym używają tej samej przestrzeni nazw `skills/{skillName}/...`, co przesłane pakiety, dzięki czemu agent może tworzyć `SKILL.md` oraz powiązane referencje, skrypty lub zasoby w ramach pomyślnego przepływu pracy.

Tworzenie treści odbywa się zgodnie z normalnym modelem uprawnień Skills:

- Tworzenie nowej Umiejętności (Skill) wymaga uprawnienia użytkownika **Create** (Tworzenie) dla Umiejętności.
- Edytowanie istniejącej Umiejętności (Skill) wymaga zarówno uprawnień do edycji, jak i uwzględnienia w aktywnym zakresie katalogu agenta; wdrożone oraz zsynchronizowane z GitHubem Umiejętności pozostają w trybie tylko do odczytu.
- Agent typu „tylko tworzenie” (authoring-only) może utworzyć nową Skill bez otrzymywania istniejącego katalogu użytkownika.

Tworzenie w czasie wykonywania (runtime authoring) nie omija możliwości wdrożenia ani uprawnień użytkownika. Usunięcie `skills` z możliwości endpointu Agents ukrywa tę funkcję, a wyłączenie **Enable skills** w agencie dezaktywuje jego narzędzia do tworzenia.

## Aktywne i udostępnione umiejętności [#active-and-shared-skills]

Użytkownicy mogą włączać lub wyłączać umiejętności. Umiejętności własne i wdrożone są domyślnie aktywne. Udostępnione umiejętności korzystają z domyślnych ustawień skonfigurowanych przez administratora, dopóki użytkownik ich nie zmieni.

Nieaktywne umiejętności są wykluczone z:

- Wyskakujące okienko `$`
- Katalog umiejętności wywoływanych przez model
- Zawsze stosuj priming

## Dołączone pliki [#bundled-files]

Przesłane pakiety umiejętności mogą zawierać pliki obok `SKILL.md`, takie jak:

- `references/...`
- `scripts/...`
- `assets/...`

Backend przechowuje te pliki wraz z umiejętnością (skill). Agent może rozpoznawać pliki umiejętności, gdy umiejętność jest aktywna i znajduje się w zakresie. Zagnieżdżone pliki zachowują swoje ścieżki względne i są adresowane poprzez przestrzeń nazw `skills/{skillName}/...` widoczną dla modelu. W przeglądarce umiejętności (Skill viewer) względne linki Markdown są rozwiązywane względem bieżącego pliku i otwierają przywołany plik w ramach tej samej umiejętności. Gdy włączony jest Code Interpreter, te same pliki są montowane w `/mnt/data/skills/{skillName}/...`, dzięki czemu operacje powłoki i kodu mogą z nich bezpośrednio korzystać. Edycja `SKILL.md` powoduje zwiększenie wersji umiejętności; przed wykonaniem kodu lub operacji programowych, LibreChat weryfikuje, czy każde odwołanie do zamontowanego pliku odpowiada tej wersji, i przesyła ponownie cały pakiet, jeśli jakiekolwiek odwołanie jest nieaktualne.

<Callout type="note" title="Wskazówka dotycząca tworzenia">
  Utrzymuj `description` konkretnym. Jest to najsilniejszy sygnał dla umiejętności wywoływanych przez model. Krótki lub niejasny opis spowoduje zbyt rzadkie wyzwalanie.
</Callout>
