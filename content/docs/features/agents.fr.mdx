# Agents : Créez des assistants IA personnalisés [#agents-build-custom-ai-assistants]

La fonctionnalité d'agents IA de LibreChat fournit un cadre flexible pour créer des assistants IA personnalisés alimentés par divers fournisseurs de modèles.

Cette fonctionnalité est similaire à l'Assistants API d'OpenAI et aux GPT de ChatGPT, mais avec une prise en charge de modèles plus large et une implémentation sans code, vous permettant de créer des assistants sophistiqués dotés de capacités spécialisées.

## Démarrage [#getting-started]

Pour créer un nouvel agent, sélectionnez "Agents" dans le menu endpoint et ouvrez le panneau Agent Builder situé dans le Side Panel.

![Agents - Menu des endpoints](/images/agents/endpoints_menu.png)

Le formulaire de création comprend :

- **Avatar** : Téléchargez un avatar personnalisé pour personnaliser votre agent
- **Nom** : Choisissez un nom distinctif pour votre agent
- **Description** : Détails optionnels sur l'objectif de votre agent
- **Instructions** : Instructions système qui définissent le comportement de votre agent
- **Modèle** : Sélectionnez parmi les fournisseurs et modèles disponibles

Les contrôles **Tools** et **Skills** ouvrent des bibliothèques consultables pour les fonctionnalités intégrées, les outils, les serveurs MCP, les Actions et les Skills. Sélectionnez un élément pour le configurer, puis enregistrez l'agent.

**Les agents existants peuvent être sélectionnés depuis le menu déroulant en haut du panneau latéral.**

- **Également par mention avec "@" dans la zone de saisie du chat.**

![Agents - Mention](/images/agents/mention.png)

### Bibliothèque d'outils [#tool-library]

Le générateur d'agents conserve les éléments activés dans des sections **Outils** et **Compétences** distinctes. Ouvrez **Ajouter des outils** pour parcourir le catalogue complet ou le filtrer par **Officiel**, **Outils**, **MCP** ou **Actions**. **Créé par vous** rassemble les serveurs MCP et les Actions que vous avez créés, tandis que **Favoris** permet de garder les éléments marqués d'une étoile accessibles sur tous les agents. Chaque utilisateur peut enregistrer jusqu'à 100 favoris dans la bibliothèque d'outils.

Sélectionnez un élément pour le configurer sans quitter le générateur. Le menu **Create new** n'apparaît que lorsque l'utilisateur a la permission de créer des serveurs MCP ou des Actions. La suppression d'une fonctionnalité basée sur des fichiers, telle que File Search, File Context ou Code Interpreter, ouvre son gestionnaire de fichiers lorsque des fichiers joints doivent encore être examinés.

Les Skills utilisent leur propre sélecteur et peuvent être sélectionnés individuellement ou activés en tant que catalogue complet accessible. Voir [Skills](/docs/features/skills#agent-scope).

Les opérateurs peuvent également utiliser des [Agent Plugins](/docs/features/agent_plugins) expérimentaux pour regrouper les Skills de déploiement et les serveurs MCP dans des packages chargés au démarrage.

### Configuration du modèle [#model-configuration]

L'interface des paramètres du modèle permet d'affiner les réponses de votre agent :

- Température (échelle de 0 à 1 pour la créativité des réponses)
- Nombre maximal de jetons de contexte
- Nombre maximal de jetons de sortie
- Paramètres supplémentaires spécifiques au fournisseur

### Historique des versions [#version-history]

Les utilisateurs disposant d'un accès en modification peuvent ouvrir l'**Historique des versions** depuis le Constructeur d'agents pour inspecter les configurations enregistrées dans une chronologie. Chaque entrée indique quand elle a été enregistrée et résume ses outils et capacités. La restauration d'une entrée antérieure nécessite une confirmation et remplace la configuration actuelle de l'agent par cet état enregistré. L'enregistrement applique toujours les modifications actuelles de l'agent, même lorsque la configuration résultante correspond à la dernière entrée de l'historique et que LibreChat n'ajoute pas d'entrée en double.

## Capacités des agents [#agent-capabilities]

> **Remarque :** Toutes les fonctionnalités peuvent être activées ou désactivées via le fichier de configuration `librechat.yaml`. Consultez [docs/configuration/librechat_yaml/object_structure/agents#capabilities](/docs/configuration/librechat_yaml/object_structure/agents#capabilities) pour plus d'informations.

### Code Interpreter [#code-interpreter]

Lorsqu'elle est activée, la fonctionnalité Code Interpreter permet à votre agent de :

- Exécutez du code dans plusieurs langages, notamment :
  - Python, JavaScript, TypeScript, Go, C, C++, Java, PHP, Rust et Fortran
- Traitez les fichiers de manière sécurisée via l'API Code Interpreter de LibreChat
- Exécutez du code sans configuration locale, paramétrage ou déploiement de sandbox
- Gérez les téléchargements et les envois de fichiers en toute transparence
- [Plus d'informations sur l'API Code Interpreter](/docs/features/code_interpreter)
  - **Propulsé par le service open-source [code-interpreter](https://github.com/ClickHouse/code-interpreter) (auto-hébergé)**

Lorsque tous les fichiers requis pour l'interpréteur de code d'une conversation ne parviennent pas à être restaurés dans le sandbox actuel, LibreChat arrête l'Agent avant d'invoquer le modèle et demande à l'utilisateur de joindre à nouveau les fichiers. Cela empêche l'exécution de se poursuivre avec des références de fichiers obsolètes ou inaccessibles.

#### Sessions de code avec état [#stateful-code-sessions]

Les sessions de code avec état permettent à un agent de réutiliser un espace de travail sandbox par conversation. Les fichiers, les paquets installés et l'état de fonctionnement sont généralement conservés entre les exécutions de code, ce qui est utile pour l'analyse itérative et le travail sur fichiers en plusieurs étapes.

<Callout type="warning" title="Hautement expérimental">
  Les Stateful Code Sessions sont dans une phase d'expérimentation précoce. Leur comportement, leur configuration, leurs caractéristiques de persistance et leur intégration sous-jacente peuvent changer de manière substantielle. Ne considérez pas l'implémentation actuelle comme un contrat de production stable.
</Callout>

Cette fonctionnalité est optionnelle. Un administrateur doit ajouter `stateful_code_sessions` aux [capacités de l'agent](/docs/configuration/librechat_yaml/object_structure/agents#capabilities), l'interpréteur de code doit être activé sur l'agent, et les **Sessions de code avec état** (**Stateful code sessions**) doivent être activées dans les paramètres avancés de l'agent. L'espace de travail peut être réinitialisé à tout moment. Enregistrez les sorties importantes sous `/mnt/data` et ne comptez pas sur l'état de la session comme stockage durable.

### Recherche de fichiers [#file-search]

La fonctionnalité File Search permet :

- Fonctionnalité RAG (Retrieval-Augmented Generation)
- Recherche sémantique dans les documents téléchargés
- Réponses contextuelles basées sur le contenu des fichiers
- Prise en charge des pièces jointes au niveau de l'agent et du fil de discussion

### Contexte de fichier [#file-context]

La fonctionnalité File Context permet à votre agent de stocker le texte extrait de fichiers en tant que partie de ses instructions système :

- Extraire le texte tout en conservant la structure et la mise en forme du document
- Traiter des mises en page complexes, y compris du texte en colonnes multiples et du contenu mixte
- Gérer les tableaux, les équations et autres contenus spécialisés
- Travailler avec du contenu multilingue
- Le texte est stocké dans les instructions de l'agent dans la base de données
- **Aucun service OCR requis** - Utilise l'analyse de texte par défaut avec des méthodes de secours
- **Amélioré par OCR** - Si l'OCR est configuré, la qualité d'extraction s'améliore pour les images et les documents numérisés
- Utilise la même logique de traitement que « Télécharger en tant que texte » : **OCR > STT > analyse de texte**
- [Plus d'informations sur la configuration de l'OCR](/docs/features/ocr)

**Note :** Le contexte de fichier inclut le texte extrait dans les instructions système de l'agent. Pour des questions sur des documents temporaires dans des conversations individuelles, utilisez [Upload as Text](/docs/features/upload_as_text) depuis le chat.

### Model Context Protocol (MCP) [#model-context-protocol-mcp]

MCP est un protocole ouvert qui standardise la manière dont les applications fournissent du contexte aux Large Language Models (LLMs), agissant comme un adaptateur universel pour les outils d'IA et les sources de données.

Pour plus d'informations, consultez la documentation sur [MCP](/docs/features/mcp).

#### Agents avec des outils MCP [#agents-with-mcp-tools]

1. Configurez les serveurs MCP dans votre fichier `librechat.yaml`
2. Redémarrez LibreChat pour initialiser les connexions
3. Créer ou modifier un agent
4. Ouvrez **Add tools** dans le Agent Builder et sélectionnez **MCP**
5. Sélectionnez le(s) serveur(s) MCP que vous souhaitez ajouter ; chaque serveur apparaît comme une entrée unique
6. Enregistrez vos modifications apportées à l'agent

Dans cet exemple, nous avons ajouté le **[serveur MCP Spotify](https://github.com/LibreChat-AI/spotify-mcp)** à un agent.

![Agents - MCP](/images/agents/mcp_tools_v2.png)

#### Gestion des outils MCP [#managing-mcp-tools]

Une fois qu'un serveur MCP est ajouté à un agent, vous pouvez affiner les outils spécifiques qui sont disponibles :

- Après avoir ajouté un serveur MCP, développez-le pour voir tous les outils disponibles
- Cochez/décochez les outils individuels selon vos besoins
- Par exemple, le serveur MCP Spotify fournit environ 20 outils (recherche, contrôle de lecture, gestion de playlist, etc.)
- Ce contrôle granulaire vous permet de limiter les agents aux seuls outils dont ils ont besoin

Les serveurs à portée de requête qui utilisent `{{LIBRECHAT_BODY_*}}` ne peuvent pas énumérer les outils tant qu'une exécution de chat ne fournit pas ces valeurs. L'Agent Builder affiche donc une sélection d'outils d'exécution pour l'ensemble du serveur au lieu de bascules par outil ; effacer cette sélection détache le serveur. Après l'OAuth, LibreChat conserve l'autorisation et attend la première exécution éligible pour se connecter.

Si un Agent sélectionne explicitement des outils MCP mais qu'aucun ne peut être résolu au démarrage d'une exécution, LibreChat arrête l'exécution avec des conseils de connexion et d'accès au lieu de continuer silencieusement sans eux. Reconnectez ou authentifiez le serveur, vérifiez l'accès aux outils et réessayez l'exécution.

![Agents - Outils MCP](/images/agents/mcp_agent_tools.png)

En savoir plus :

- [Configuration des serveurs MCP](/docs/features/mcp)
- [Introduction au Model Context Protocol](https://modelcontextprotocol.io/introduction)

### Outils différés [#deferred-tools]

Les outils différés permettent aux agents d'accéder à de nombreux outils MCP sans avoir à tous les charger dans le contexte du LLM au préalable. Au lieu de cela, les outils différés sont détectables au moment de l'exécution via un mécanisme de **Recherche d'outils** (Tool Search).

Ceci est particulièrement utile lorsqu'un agent a accès à de nombreux serveurs MCP dotés de dizaines d'outils ; les charger tous consommerait une grande partie de la fenêtre de contexte et dégraderait la qualité des réponses.

**Comment ça fonctionne :**

- Les outils marqués comme « deferred » sont exclus du contexte initial du LLM.
- Un outil `ToolSearch` est automatiquement ajouté, permettant au LLM de découvrir et de charger des outils différés à la demande.
- Une fois découvert, l'outil est disponible pour le reste de la conversation

**Configuration des outils différés :**

1. Ouvrez le Agent Builder et ajoutez des outils MCP
2. Cliquez sur le menu déroulant de n'importe quel outil MCP
3. Activer « Defer Loading » — les outils différés affichent une icône d'horloge

**Remarque :** La fonctionnalité `deferred_tools` est activée par défaut. Elle peut être activée ou désactivée via la configuration des agents dans [`librechat.yaml`](/docs/configuration/librechat_yaml/object_structure/agents#capabilities).

### Groupes d'activité [#activity-groups]

Les groupes d'activité réduisent chaque bloc contigu de raisonnement d'Agent et d'appels d'outils sous un en-tête généré sur une seule ligne, facilitant ainsi la lecture des longues exécutions. Les administrateurs peuvent les activer avec `activityLabel` et utiliser un modèle plus rapide, un autre endpoint configuré, un prompt personnalisé et des limites par exécution. La génération de l'en-tête est un appel de modèle distinct dont les jetons et le coût sont enregistrés. Voir [Agent Activity Groups](/docs/configuration/librechat_yaml/object_structure/shared_endpoint_settings#agent-activity-groups).

Les administrateurs peuvent activer indépendamment `activityPhaseLabel` pour regrouper deux activités logiques ou plus dans un résumé parent réduit avant la réponse finale. Cela donne aux exécutions longues un aperçu de haut niveau tout en préservant chaque activité enfant. Les résumés de phase utilisent leur propre modèle, endpoint, prompt et limite par exécution, avec une solution de repli vers les paramètres de l'activity-label et de l'exécution.

Le texte de progression court reste à l'intérieur de sa phase parente. Lorsque l'Agent commence une réponse substantielle, LibreChat ferme la phase avant ce texte afin que le résultat destiné à l'utilisateur reste en dehors du résumé réduit. Une exécution peut créer plusieurs phases parentes lorsque le raisonnement ultérieur ou les outils entament un autre bloc d'activité logique. Les limites de phase persistées sont réinitialisées lorsque des parties de contenu mal formées ou omises sont compactées, de sorte que le regroupement reste aligné après le rechargement.

### Étiquettes d'intention des outils [#tool-intent-labels]

Les étiquettes d'intention d'outil remplacent les statuts d'outils en direct génériques par une courte description rédigée par le modèle pour cet appel spécifique. Les administrateurs doivent ajouter la fonctionnalité d'agent `tool_intents` [agent capability](/docs/configuration/librechat_yaml/object_structure/agents#capabilities) pour l'activer. Les outils natifs utilisent automatiquement les étiquettes ; dans le constructeur d'agent (Agent Builder), développez un serveur MCP et activez **Intent label** pour des outils individuels ou pour l'ensemble du serveur.

Pour les Model Specs, [`describeIntent`](/docs/configuration/librechat_yaml/object_structure/model_specs#describeintent) peut activer chaque outil éligible ou sélectionner des IDs d'outils résolus. Les champs d'intention s'ajoutent au schéma d'outil envoyé au modèle, donc une activation sélective peut réduire la surcharge de jetons du schéma.

Les étiquettes d'intention (intent labels) ne s'appliquent pas aux outils MCP purement programmatiques, car les appels effectués au sein du code en sandbox ne génèrent pas de cartes d'outils individuelles.

### Appel d'outils programmatique [#programmatic-tool-calling]

Programmatic Tool Calling (PTC) permet aux agents d'exécuter des outils MCP sélectionnés depuis l'intérieur du bac à sable [Code Interpreter](/docs/features/code_interpreter) au lieu d'appeler chaque outil directement depuis le modèle. Le modèle reçoit un outil d'orchestration basé sur Code Interpreter, écrit du code en bac à sable qui appelle les fonctions d'outils générées, et peut utiliser des boucles, des conditions, des tentatives et le traitement des résultats avant de renvoyer une réponse.

Ceci est utile pour les flux de travail d'outils en plusieurs étapes, tels que l'interrogation de plusieurs ressources, la pagination des résultats, la comparaison des sorties ou la transformation des réponses des outils avant que l'agent ne les explique.

**Configuration des outils programmatiques :**

1. Activez à la fois `programmatic_tools` et `execute_code` dans les [`librechat.yaml` agents capabilities](/docs/configuration/librechat_yaml/object_structure/agents#capabilities).
2. Activez l'interpréteur de code sur l'agent.
3. Ajoutez des outils MCP, étendez un serveur MCP et activez **Programmatic** pour des outils individuels ou pour le serveur complet. Les outils Programmatic affichent une icône de code.

**Note :** `programmatic_tools` est une option à activer et n'est pas incluse dans la liste des capacités par défaut des agents. PTC nécessite également un déploiement de Code Interpreter avec le composant Tool Call Server. Seuls les outils enregistrés pour l'agent peuvent être appelés depuis le bac à sable (sandbox) ; les appels d'outils non enregistrés sont rejetés.

### Appels d'outils en arrière-plan [#background-tool-calls]

Les appels d'outils en arrière-plan permettent à un agent de lancer un outil MCP ou Code Interpreter éligible et de longue durée, de continuer à travailler, puis d'interroger le résultat ultérieurement. L'appel initial renvoie immédiatement une référence de tâche ; l'agent récupère ensuite le statut et les résultats via `check_background_task`.

Pour utiliser cette fonctionnalité, un administrateur doit ajouter la capacité d'agent `run_in_background` [agent capability](/docs/configuration/librechat_yaml/object_structure/agents#capabilities) avec consentement. Configurez ensuite les outils éligibles dans le générateur d'agents (Agent Builder) :

- **Code Interpreter :** Activez Code Interpreter sur l'agent. L'exécution de code et les commandes shell deviennent éligibles à l'exécution en arrière-plan par défaut ; désactivez **Background execution** dans ses paramètres d'outil pour refuser cette option.
- **MCP :** Ouvrez un serveur MCP et marquez des outils individuels, ou le serveur complet, comme **Background**.

Ces paramètres permettent l'exécution en arrière-plan mais ne l'imposent pas. Le modèle décide pour chaque appel s'il doit exécuter un outil éligible en arrière-plan.

Dans le chat LibreChat, lorsque le code en arrière-plan se termine, sa sortie standard (stdout) et les fichiers générés apparaissent sur l'appel de code original plutôt que lors du sondage ultérieur. Les fichiers générés sont également conservés pour les tours suivants.

L'état des tâches en arrière-plan est actuellement local au processus. Les résultats peuvent être collectés lors d'un tour ultérieur sur le même processus serveur, mais ils ne survivent pas à un redémarrage et ne sont pas partagés entre les répliques.

### Demander l'approbation de l'utilisateur et de l'outil [#ask-user-and-tool-approval]

L'outil **Ask User** permet à un agent de suspendre une exécution pour demander des informations manquantes, présenter des choix ou confirmer la marche à suivre. Un seul appel peut regrouper jusqu'à quatre questions connexes dans un formulaire unique. Chaque question accepte une réponse libre ou des choix uniques ou multiples définis par l'agent ; l'utilisateur répond à toutes les questions et soumet le formulaire en une fois, ou peut ignorer le formulaire. Pendant que le modèle prépare l'appel, LibreChat diffuse les questions dans une carte de progression ; le formulaire interactif la remplace lorsqu'il est prêt. Après la soumission, la même exécution reprend avec les réponses. Ajoutez **Ask User** depuis la marketplace des outils ; les administrateurs peuvent supprimer la capacité par défaut `ask_user_question` pour la masquer.

Les réponses soumises sont conservées avec l'action resume, donc arrêter pendant l'initialisation de l'exécution reprise ne supprime pas les réponses acceptées.

Chaque question accepte un titre optionnel allant jusqu'à 80 caractères, un texte de question allant jusqu'à 2 000 caractères, un contexte de support optionnel allant jusqu'à 4 000 caractères, et jusqu'à 12 choix. Les étiquettes de choix sont limitées à 280 caractères, les valeurs de choix à 500 caractères, et chaque réponse soumise à 16 000 caractères.

Les administrateurs peuvent également exiger une révision avant l'exécution des appels d'outils correspondants. Selon l'outil, les utilisateurs peuvent approuver, rejeter, modifier les arguments ou répondre directement. Les exécutions en pause sont enregistrées dans des points de contrôle afin de pouvoir reprendre après la décision, y compris sur une autre réplique lorsque le checkpointer MongoDB par défaut est utilisé. L'approbation des outils est désactivée par défaut ; voir [`toolApproval` et `checkpointer`](/docs/configuration/librechat_yaml/object_structure/agents#toolapproval).

### Compétences [#skills]

Les Skills permettent aux agents de charger des instructions réutilisables à partir de définitions `SKILL.md`. Ils peuvent être sélectionnés manuellement depuis le chat avec `$`, découverts automatiquement par le modèle via le catalogue de skills, ou toujours appliqués à chaque tour.

Pour plus de détails sur la création, l'invocation et le contrôle d'accès, consultez [Skills](/docs/features/skills).

### Mémoire [#memory]

L'outil **Memory** permet à un agent d'enregistrer, de mettre à jour ou de supprimer des souvenirs structurés de l'utilisateur lorsque celui-ci demande explicitement de se souvenir ou d'oublier quelque chose. Memory doit être configuré pour le déploiement, autorisé par le rôle et les paramètres de personnalisation de l'utilisateur, et activé sur l'agent.

Par défaut, un agent utilise le pool de mémoire personnelle partagée de l'utilisateur. Activez **Keep memories separate for this agent** pour lui attribuer une partition privée par utilisateur et par agent. L'agent isolé ne verra pas les mémoires partagées existantes ni les mémoires créées par d'autres agents isolés. Les utilisateurs peuvent filtrer le panneau Memory par mémoires personnelles ou spécifiques à l'agent. Voir [User Memory](/docs/features/memory#agent-memory).

### Artifacts [#artifacts]

La fonctionnalité Artifacts permet à votre agent de générer et d'afficher du contenu interactif :

- Créer des composants React, du code HTML et des diagrammes Mermaid
- Afficher le contenu dans une fenêtre d'interface utilisateur séparée pour plus de clarté et d'interaction
- Configurez les instructions spécifiques aux artefacts au niveau de l'agent
- [Plus d'informations sur les Artifacts](/docs/features/artifacts)

Lorsqu'il est activé, choisissez l'un des trois modes d'instruction :

- **Normal** : Ajoute les instructions d'artefact standard pour React, HTML, SVG, Markdown et Mermaid.
- **shadcn/ui** : Ajoute les instructions standard ainsi que des conseils pour la création d'interfaces avec la bibliothèque de composants shadcn/ui.
- **Custom** : Maintient le rendu des artefacts activé mais n'injecte aucune instruction d'artefact intégrée, donnant ainsi un contrôle total aux instructions propres à l'agent.

La configuration des artifacts au niveau de l'agent est l'approche privilégiée, car elle permet un contrôle plus granulaire par rapport à la configuration héritée à l'échelle de l'application.

Si vous sélectionnez **Custom**, incluez au minimum le format d'artefact de base dans vos instructions.

Voici un exemple simple des instructions minimales nécessaires :

````md
When creating content that should be displayed as an artifact, use the following format:

:::artifact{identifier="unique-identifier" type="mime-type" title="Artifact Title"}

```
Your artifact content here
```

:::

For the type attribute, use one of:

- "text/html" for HTML content
- "application/vnd.mermaid" for Mermaid diagrams
- "application/vnd.react" for React components
- "image/svg+xml" for SVG images
````

#### Créer un Agent avec des outils d'image [#create-an-agent-with-image-tools]

1. Ajoutez les identifiants de l'outil d'image au fichier `.env`, tels que `IMAGE_GEN_OAI_API_KEY` pour les outils d'image OpenAI.
2. Redémarrez LibreChat afin que les nouvelles variables d'environnement soient chargées.
3. Sélectionnez **Agents** dans le menu endpoint.
4. Ouvrez le Agent Builder depuis le panneau latéral et créez ou modifiez un agent.
5. Ouvrez la liste des **Tools** de l'agent, sélectionnez **OpenAI Image Tools**, **Gemini Image Tools**, **DALL-E-3**, **Stable Diffusion** ou **Flux**, puis enregistrez l'agent.
6. Démarrez une discussion avec cet agent et demandez-lui de générer ou de modifier une image.

Pour le guide complet de configuration des images, incluant les variables de modèle telles que `IMAGE_GEN_OAI_MODEL`, consultez [Image Generation & Editing](/docs/features/image_gen).

- Les outils peuvent être désactivés en utilisant le fichier de configuration [`librechat.yaml`](/docs/configuration/librechat_yaml) :
  - [Plus d'informations](/docs/configuration/librechat_yaml/object_structure/agents#capabilities)

### Actions [#actions]

![Agents - Menu des endpoints](/images/agents/actions.png)

**Cliquer sur le bouton ci-dessus ouvrira un formulaire où vous pourrez saisir l'URL de la spécification OpenAPI et créer une action :**

![Agents - Menu des endpoints](/images/agents/actions_panel.png)

- Les Actions peuvent être désactivées en utilisant le fichier de configuration [`librechat.yaml`](/docs/configuration/librechat_yaml) :
  - [Plus d'informations](/docs/configuration/librechat_yaml/object_structure/agents#capabilities)
- Des domaines individuels peuvent être ajoutés à la liste blanche pour les actions des agents :

  - Le mode strict ne prend en charge qu'un sous-ensemble partiel de json. Lisez https://platform.openai.com/docs/guides/structured-outputs pour plus de détails.

### Transferts [#handoffs]

Les transferts permettent à un agent principal de transférer une conversation à un agent spécialisé avec le contexte pertinent. Dans **Advanced settings**, ouvrez la section orchestration et ajoutez jusqu'à 10 agents de transfert. Chaque transfert configuré crée un outil de transfert que le modèle peut choisir dynamiquement lorsque l'expertise du spécialiste est requise.

Pour chaque transfert, vous pouvez ajouter une description qui aide le modèle à choisir le bon spécialiste. Vous pouvez également fournir des instructions de transmission décrivant le contenu que l'agent principal doit générer pour le spécialiste et, éventuellement, renommer le paramètre de contenu par défaut, `instructions`. Les transferts sont toujours disponibles dans le Agent Builder ; contrairement à Agent Chain et aux sous-agents, ils ne nécessitent pas l'activation d'une capacité d'endpoint.

### Chaîne d'agents [#agent-chain]

La fonctionnalité Agent Chain permet une approche de type Mixture-of-Agents (MoA), vous permettant de créer une séquence d'agents qui travaillent ensemble :

- Créez des chaînes d'agents spécialisés pour des tâches complexes
- Chaque agent de la chaîne peut accéder aux sorties des agents précédents
- Configurer le nombre maximal d'étapes pour la chaîne de l'agent
- **Remarque :** Accédez à cette fonctionnalité depuis le panneau Advanced Settings dans le Agent Builder
- **Note :** Cette fonctionnalité est actuellement en version bêta et peut être sujette à des changements.
  - Le maximum actuel d'agents pouvant être enchaînés est de 10, mais cela pourrait être configurable à l'avenir.

Cette fonctionnalité introduit une architecture de Mixture-of-Agents en couches dans LibreChat, où chaque agent utilise toutes les sorties des agents de la couche précédente comme informations auxiliaires pour générer sa réponse, tel que décrit dans [le document éponyme "Mixture-of-Agents"](https://arxiv.org/abs/2406.04692).

### Sous-agents [#subagents]

Les sous-agents permettent à un agent de déléguer une tâche ciblée à une exécution enfant isolée. L'enfant dispose de sa propre fenêtre de contexte et de son propre flux d'exécution d'outils, puis renvoie un résultat compact au parent au lieu d'encombrer le contexte du parent avec chaque étape intermédiaire.

Les Subagents sont différents de l'Agent Chain : les chaînes d'exécution coordonnent plusieurs agents en tant que participants à un graphe, tandis que les subagents sont générés par un agent en tant qu'appel d'outil pour une délégation ciblée. Pour la configuration et les limites, voir [Subagents](/docs/features/subagents).

### Paramètres avancés [#advanced-settings]

Paramètres avancés pour votre agent (situés dans la vue Advanced du formulaire Agent) en dehors des « capabilities ».

#### Étapes maximales de l'agent [#max-agent-steps]

Ce paramètre vous permet de limiter le nombre d'étapes qu'un agent peut effectuer lors d'une « exécution » (run), ce qui fait référence à la boucle de l'agent avant qu'une réponse finale ne soit donnée.

S'il n'est pas configuré, la valeur par défaut est de 25 étapes, mais vous pouvez l'ajuster selon vos besoins. Pour les administrateurs, vous pouvez définir une valeur par défaut globale ainsi qu'un maximum global dans le fichier [`librechat.yaml`](/docs/configuration/librechat_yaml/object_structure/agents#recursionlimit).

Les administrateurs peuvent également limiter les arguments d'appels d'outils en streaming et les événements delta du modèle avec les [disjoncteurs de flux d'agent](/docs/configuration/librechat_yaml/object_structure/agents#stream-circuit-breakers).

Une « étape » (step) fait référence soit à une requête d'API d'IA, soit à un cycle d'utilisation d'outils (un ou plusieurs outils, selon le nombre d'appels d'outils fournis par le LLM à partir d'une seule requête).

Une réponse unique sans outil correspond à 1 étape. Un cycle singulier d'utilisation d'outil correspond généralement à 3 étapes :

1. Requête API -> 2. Utilisation d'outils (1 ou plusieurs outils) -> 3. Requête API de suivi

## Gestion des fichiers [#file-management]

Les Agents prennent en charge plusieurs façons de travailler avec des fichiers :

### Dans l'interface de chat [#in-chat-interface]

Lorsque vous discutez avec un agent, vous disposez de quatre options de téléchargement :

1. **Télécharger des images**
   - Téléverse des images pour la prise en charge native des modèles de vision
   - Envoie les images directement au fournisseur de modèle

2. **Télécharger en tant que texte** (nécessite la capacité `context`)
   - Extrait et inclut le contenu complet du document dans la conversation
   - Utilise l'analyse de texte par défaut ; amélioré par l'OCR si configuré
   - Le contenu n'existe que dans la conversation actuelle
   - Voir [Upload as Text](/docs/features/upload_as_text)

3. **Téléchargement pour la recherche de fichiers** (nécessite la fonctionnalité `file_search`, activée)
   - Utilise la recherche sémantique (RAG) avec des magasins de vecteurs
   - Renvoie des segments pertinents via l'utilisation d'outils
   - Optimal pour les documents volumineux/fichiers multiples
   - Sous-optimal pour les données structurées (CSV, Excel, JSON, etc.)

4. **Téléchargement pour Code Interpreter** (nécessite la fonctionnalité `execute_code`, activée)
   - Ajoute des fichiers à l'environnement de l'interpréteur de code
   - Optimal pour les données structurées (CSV, Excel, JSON, etc.)
   - Plus d'informations sur [Code Interpreter](/docs/features/code_interpreter)

### Dans Agent Builder [#in-agent-builder]

Lors de la configuration d'un agent, vous pouvez joindre des fichiers dans différentes catégories :

1. **Téléchargement d'images** : Pour le contenu visuel auquel l'agent peut se référer
2. **Téléchargement pour la recherche de fichiers** : Documents pour les capacités de RAG
3. **Code Interpreter Upload** : Fichiers pour le traitement de code
4. **Contexte du fichier** : Documents avec du texte extrait pour compléter les instructions de l'agent

**File Context** utilise la capacité `context` et fonctionne exactement comme ["Upload as Text"](/docs/features/upload_as_text) - il utilise l'analyse de texte par défaut et est amélioré par l'OCR lorsqu'il est configuré. Le texte est extrait au moment du téléchargement et stocké dans les instructions de l'agent. C'est idéal pour donner aux agents des connaissances persistantes à partir de documents, de PDF, de fichiers de code ou d'images contenant du texte.

**Priorité de traitement :** OCR > STT > analyse de texte (identique à Téléverser en tant que texte)

**Remarque :** Le texte extrait est inclus dans les instructions système de l'agent.

## Partage et autorisations [#sharing-and-permissions]

Les Agents utilisent le système de [contrôle d'accès](/docs/features/access_control) granulaire de LibreChat. Chaque agent possède sa propre liste de contrôle d'accès (ACL) et peut être partagé avec des **utilisateurs**, **groupes**, **rôles** spécifiques, ou **publiquement**, chacun avec un niveau de permission choisi.

### Rôles d'accès [#access-roles]

Lors du partage d'un agent, le bénéficiaire se voit attribuer l'un des trois rôles suivants :

| Rôle | Ce que le bénéficiaire peut faire |
| ---------- | ----------------------------------------------------------------------------------------------------- |
| **Viewer** | Utiliser l'agent dans les conversations ; ne peut pas ouvrir le constructeur ni voir les instructions, les outils ou les fichiers joints |
| **Editor** | Voir + modifier les instructions, le modèle, les outils et les fichiers de l'agent |
| **Owner** | Contrôle total : voir, modifier, supprimer et repartager l'agent |

L'auteur original et les administrateurs conservent toujours un contrôle total, indépendamment de l'ACL.

### Partage d'un Agent [#sharing-an-agent]

1. Ouvrez l'agent dans le Agent Builder
2. Cliquez sur le bouton **Share** dans le pied de page (visible lorsque vous êtes l'auteur, un administrateur, ou que vous avez reçu la permission `SHARE` sur cet agent spécifique)
3. Recherchez des utilisateurs, des groupes ou des rôles dans le sélecteur de personnes et attribuez un rôle à chacun.
4. Activez éventuellement **Public** pour rendre l'agent visible à tous sur l'instance (nécessite l'autorisation de fonctionnalité `SHARE_PUBLIC`)

Les cartes d'agent et les vues de page d'accueil affichent le contact de support configuré. Lorsqu'aucun n'est défini, LibreChat peut utiliser par défaut le nom d'affichage du premier propriétaire identifiable, mais ne divulgue pas l'adresse e-mail du propriétaire à moins qu'elle n'ait été explicitement configurée comme contact de support.

Pour plus de détails sur les principaux, les bits de permission et la manière dont les ACL se combinent avec les permissions de fonctionnalités basées sur les rôles, consultez [Access Control](/docs/features/access_control).

### Contrôles administrateur [#administrator-controls]

Les administrateurs ont accès aux paramètres de permission globaux dans l'interface utilisateur du générateur d'agents :

- Activer/désactiver le partage d'agents pour tous les utilisateurs
- Contrôler les autorisations d'utilisation des agents
- Gérer les droits de création d'agents
- Configurer les paramètres à l'échelle de la plateforme

Le premier compte créé pour votre instance est un administrateur. Si vous devez ajouter un administrateur supplémentaire, vous pouvez [accéder à MongoDB](/docs/configuration/mongodb/mongodb_auth) et mettre à jour le profil de l'utilisateur :

```
db.users.updateOne(
  { email: 'USER_EMAIL_ADDRESS' },
  { $set: { role: 'ADMIN' } }
)
```

L'utilisation d'agents pour tous les utilisateurs peut également être désactivée via la configuration, [plus d'informations](/docs/configuration/librechat_yaml/object_structure/interface).

Les autorisations au niveau des fonctionnalités (qui peut _utiliser_, _créer_, _partager_ ou _partager publiquement_ des agents) sont gérées depuis le [**Panneau d'administration LibreChat**](/docs/features/admin_panel) pour chaque rôle, y compris les rôles personnalisés. Le bloc [`interface.agents`](/docs/configuration/librechat_yaml/object_structure/interface#agents) dans `librechat.yaml` peut toujours définir des valeurs par défaut pour le rôle `USER` intégré au démarrage, mais le panneau d'administration est la méthode recommandée pour les modifier à l'avenir.

### Partage au niveau de l'utilisateur [#user-level-sharing]

Les utilisateurs individuels peuvent :

- Partager leurs agents avec des utilisateurs, groupes ou rôles spécifiques (si `SHARE` est activé pour leur rôle)
- Rendre les agents visibles pour tout le monde sur l'instance (si `SHARE_PUBLIC` est activé)
- Attribuez à chaque destinataire un niveau d'accès différent (Viewer / Editor / Owner)
- Partagez à nouveau ou révoquez l'accès à tout moment depuis la boîte de dialogue de partage

## Pilotage et messages en file d'attente [#steering-and-queued-messages]

Pendant qu'un Agent répond, vous pouvez envoyer un autre message de deux manières :

- **Steer** insère le message dans l'exécution actuelle à sa prochaine étape d'outil ou d'agent, afin que l'agent puisse ajuster son travail avant de terminer.
- **Queue** conserve le message et l'envoie comme un tour de suivi normal une fois que la réponse actuelle est terminée.

**Interrupt & steer** arrête la génération à la prochaine limite sécurisée du fournisseur, conserve la réponse partielle, insère le message et reprend la même réponse de l'assistant. Utilisez le contrôle dédié dans le compositeur, choisissez-le depuis le menu du bouton d'envoi, ou appuyez sur `Command/Ctrl + Shift + .`. L'action revient à un pilotage ordinaire lorsque le déploiement ne peut pas interrompre le flux actif du fournisseur.

Sous **Paramètres → Chat**, **Pendant la génération, Entrée va** choisit l'action par défaut. Le menu du bouton d'envoi peut outrepasser ce choix pour un message individuel, et **L'orientation interrompt la génération** contrôle si l'orientation ordinaire demande également une interruption.

Les steers en attente apparaissent au-dessus du compositeur jusqu'à ce que le serveur les insère dans l'exécution. Une fois reconnus, leur menu permet de récupérer le message pour le modifier, de le convertir en suivi mis en file d'attente, ou de l'annuler pour restaurer son texte et ses pièces jointes dans le compositeur. LibreChat évite d'écraser un brouillon plus récent ; si le compositeur n'est plus disponible, il conserve le message récupéré dans la file d'attente. Un steer ayant échoué reste disponible pour être réessayé, modifié, mis en file d'attente ou supprimé.

Les suivis en file d'attente peuvent être envoyés immédiatement, convertis en une orientation (steer) pendant que l'exécution est toujours active, escaladés vers **Interrompre et orienter maintenant**, modifiés ou supprimés. Les orientations en cours offrent la même escalade lorsqu'elles sont en attente d'une limite d'outil. La suppression d'un message en file d'attente le restaure dans un compositeur vide lorsque cela est possible. Une exécution active accepte jusqu'à 10 orientations en attente ; chaque orientation peut inclure jusqu'à 10 fichiers et est limitée par [`STEER_MAX_LENGTH`](/docs/configuration/dotenv#agent-conversation-controls).

Les déploiements multi-réplicas basés sur Redis doivent terminer le [déploiement du protocole de génération v2](/docs/configuration/redis#generation-protocol-rollout) avant de pouvoir s'appuyer sur le comportement d'interruption et de récupération entre les réplicas.

### Notes [#notes]

- Les Instructions, les paramètres du modèle, les fichiers joints et les outils ne sont exposés à l'utilisateur que s'il dispose des autorisations de modification.
  - Un agent peut divulguer toute donnée jointe, qu'il s'agisse d'instructions ou de fichiers, au cours d'une conversation. Assurez-vous donc que vos instructions sont robustes face à ce risque avant d'accorder un accès Éditeur/Propriétaire ou de rendre l'agent public.
- Seuls les auteurs originaux, les administrateurs et les bénéficiaires disposant de l'autorisation Owner peuvent supprimer des agents partagés.
- Les Agents sont privés pour leurs auteurs sauf s'ils sont partagés

## Migration requise (v0.8.0-rc3+) [#migration-required-v080-rc3]

<Callout type="warning" title="Important : Migration des permissions d'agent requise">
  À partir de la version v0.8.0-rc3, LibreChat utilise un nouveau système de permissions basé sur une liste de contrôle d'accès (ACL) pour les agents. Si vous effectuez une mise à niveau depuis une version antérieure, vous devez exécuter la migration des permissions des agents pour que les agents existants restent accessibles.
</Callout>

### Ce que fait la migration [#what-the-migration-does]

La migration des permissions d'agent fait passer vos agents d'un modèle de propriété simple à un système sophistiqué basé sur des ACL avec plusieurs niveaux de permission :

- **OWNER**: Contrôle total sur l'agent
- **EDITOR** : Peut voir et modifier l'agent
- **VIEWER** : Accès en lecture seule à l'agent

Sans exécuter cette migration, les agents existants seront inaccessibles via les nouveaux endpoints d'API prenant en charge les permissions.

### Exécution de la migration [#running-the-migration]

Choisissez la commande appropriée en fonction de votre méthode de déploiement :

#### 1. Pour le `docker-compose.yml` par défaut (si vous utilisez `docker compose up` pour démarrer l'application) : [#1-for-the-default-docker-composeyml-if-you-use-docker-compose-up-to-start-the-app]

**Prévisualiser les changements (simulation) :**

```bash
docker compose exec api npm run migrate:agent-permissions:dry-run
```

**Exécuter la migration :**

```bash
docker compose exec api npm run migrate:agent-permissions
```

**Taille de lot personnalisée (pour les grands jeux de données) :**

```bash
docker compose exec api npm run migrate:agent-permissions:batch
```

#### 2. Pour le `deploy-compose.yml` [#2-for-the-deploy-composeyml]

Si vous avez suivi le [Guide Docker Ubuntu](/docs/remote/docker_linux) :

**Prévisualiser les changements (simulation) :**

```bash
docker exec -it LibreChat-API /bin/sh -c "cd .. && npm run migrate:agent-permissions:dry-run"
```

**Exécuter la migration :**

```bash
docker exec -it LibreChat-API /bin/sh -c "cd .. && npm run migrate:agent-permissions"
```

**Taille de lot personnalisée (pour les grands jeux de données) :**

```bash
docker exec -it LibreChat-API /bin/sh -c "cd .. && npm run migrate:agent-permissions:batch"
```

#### 3. Pour le développement local (depuis la racine du projet) : [#3-for-local-development-from-project-root]

**Prévisualiser les changements (simulation) :**

```bash
npm run migrate:agent-permissions:dry-run
```

**Exécuter la migration :**

```bash
npm run migrate:agent-permissions
```

**Taille de lot personnalisée (pour les grands jeux de données) :**

```bash
npm run migrate:agent-permissions:batch
```

### Ce qui se passe pendant la migration [#what-happens-during-migration]

- **Agents privés** : Restent accessibles uniquement à leurs créateurs (reçoivent l'autorisation OWNER)
- **Agents partagés** : Si un agent a été précédemment partagé, il recevra les entrées ACL appropriées en tant qu'Agent public (partagé avec tous les utilisateurs)
- **Détection du système** : LibreChat détecte automatiquement les agents non migrés au démarrage et affiche un avertissement

Vous pouvez ajuster les permissions de l'agent résultant via l'interface utilisateur du Agent Builder.

<Callout type="info" title="Note">
  Le même processus de migration s'applique aux prompts. Si vous avez également des prompts existants, exécutez la migration des permissions de prompt en utilisant les mêmes commandes, mais remplacez `agent` par `prompt` dans les noms des commandes.
</Callout>

## Quelle est la prochaine étape ? [#whats-next]

Les Agents LibreChat marquent le début d'une nouvelle ère pour l'application, où les futurs pipelines pourront être rationalisés grâce à des Agents dédiés à des tâches et des flux de travail spécifiques tout au long de votre expérience dans LibreChat.

Les futures mises à jour incluront :

- Améliorations générales de l'expérience Agent actuelle
- Orchestration multi-agents pour des flux de travail complexes
- Capacité de personnaliser les agents pour diverses fonctions : titrage (nommage des fils de discussion), gestion de la mémoire (contexte/historique de l'utilisateur) et amélioration des prompts (assistance/prédictions de saisie)
- Plus d'outils, paramètres d'outils configurables, création d'outils dynamique.

De plus, cette mise à jour introduit un nouveau paradigme pour LibreChat, car son architecture sous-jacente apporte un rafraîchissement indispensable à l'application, optimisant à la fois l'expérience utilisateur et les performances globales de l'application.

Pour souligner une optimisation notable, une génération d'IA d'environ 1000 tokens transférera environ 1 Mo de données en utilisant les endpoints traditionnels (au moment de la rédaction, toute option d'endpoint autre que Agents et AWS Bedrock).

En utilisant un agent, la même génération transférera environ 52 ko de données, soit une réduction de 95 % du transfert de données, ce qui représente une charge bien moindre pour le serveur et l'appareil de l'utilisateur.

Les AI Agents dans LibreChat offrent un moyen puissant de créer des assistants spécialisés sans connaissances en programmation, tout en conservant la flexibilité de travailler avec vos modèles et fournisseurs d'IA préférés.
