Skills 是 LibreChat Agent 可重用的指令包。一个 Skill 以 `SKILL.md` 文件为核心：Frontmatter 用于描述何时应使用该 Skill，而 Markdown 正文则为 Agent 提供需要遵循的流程、规则、示例或参考信息。

Skills 对于可重复的工作非常有用，例如：

- 应用品牌或写作指南
- 遵循内部审查清单
- 运行标准研究工作流
- 启动专门的工具工作流
- 将可重用的脚本、引用和资源与指令文件打包在一起

LibreChat 不提供内置的技能库。每一项技能都来自您自己的实例：[在 UI 中编写或上传](#create-a-skill)、[在聊天过程中由智能体创建](#runtime-skill-authoring)、[从文件系统挂载](#deployment-skills)，或[从 GitHub 仓库同步](#github-skill-sync)。

## 启用 Skills [#enable-skills]

`skills` 代理功能默认处于启用状态。管理员可以将其从 agents 端点的功能列表中移除，以向用户隐藏 Skills。

```yaml filename="librechat.yaml"
endpoints:
  agents:
    capabilities:
      - 'deferred_tools'
      - 'execute_code'
      - 'file_search'
      - 'web_search'
      - 'artifacts'
      - 'subagents'
      - 'actions'
      - 'context'
      - 'skills'
      - 'memory'
      - 'ask_user_question'
      - 'tools'
      - 'chain'
      - 'ocr'
```

角色权限控制着谁可以使用、创建、共享以及公开共享 Skills。默认情况下允许使用和创建 Skills；对于非管理员角色，共享和公开共享功能默认处于关闭状态。管理员可以在 Skills 面板的管理员设置中更改这些权限。

如果该功能被禁用，或者您的角色缺乏使用权限，Skills 将根本不会出现在侧边栏中。

## 使用 Skill [#use-a-skill]

<Steps>
<Step>

从侧边栏打开 **Open Skills**。该面板列出了您拥有的技能以及与您共享的技能，并为长列表提供了筛选框。选择一项技能将打开其页面，您可以在其中阅读说明并浏览其捆绑的文件。

</Step>
<Step>

**检查该技能是否可用。** 每个技能都有一个 **Available to agent** 开关。您拥有的技能和部署技能默认为可用；共享技能遵循管理员配置的默认设置，直到您覆盖它们为止。

</Step>
<Step>

**授予智能体访问权限。** 在智能体构建器中，开启 **Enable skills**，然后决定智能体是查看完整目录还是仅查看你选择的技能。请参阅 [Agent Scope](#agent-scope)。

</Step>
<Step>

**调用技能。** 在消息框中输入 `$` 并按名称选择一个技能。消息文本中不会插入任何内容：该技能会被加入当前对话的队列，并显示在输入框上方的卡片中。模型也可以自行选择技能，而 `always-apply` 类型的技能则无需任何操作。

</Step>
</Steps>

## 创建 Skill [#create-a-skill]

从侧边栏打开 **Skills** 并使用 **+** 按钮，该按钮提供两条路径：

- **编写技能指令** — 一个包含名称、描述和指令主体的对话框。
- **上传技能** — 一个包含 `SKILL.md` 的 `.md`、`.zip` 或 `.skill` 文件。

智能体也可以在工作时为您创建技能，而无需通过此面板。请参阅 [Runtime Skill Authoring](#runtime-skill-authoring)。

最小的 `SKILL.md`：

```md filename="SKILL.md"
---
name: brand-guidelines
description: Use when writing public-facing content that must follow the company voice and terminology.
---

# Brand Guidelines

Write in a concise, practical tone.
Prefer active voice.
Use product terminology consistently.
```

键匹配不区分大小写，布尔字段仅接受 `true` 或 `false`。在后续保存时移除布尔键会将其清除，因此删除 `disable-model-invocation` 将恢复模型调用。

已识别的 frontmatter 字段会经过类型检查。未识别的字段将作为有界且符合 JSON 安全的元数据保留，而不会导致 Skill 无效；深度嵌套或过大的扩展值仍会被拒绝。

请将模型调用的 Skill 的 `description` 保持在 250 个字符或以内，并将最重要的触发短语放在最前面。较长的描述仍然可以导入，但 LibreChat 会在模型可见的目录中截断它们，并记录一条警告，列出每个受影响的 Skill。

### 命名和大小限制 [#naming-and-size-limits]

- `name` 是必填项，必须符合 `^[a-z0-9][a-z0-9-]*$` 正则表达式，且长度限制为 64 个字符。它在您自己的技能中必须是唯一的；重新上传已存在的名称会导致冲突错误，而不是覆盖原有内容。
- 名称不能以 `anthropic-` 或 `claude-` 开头，且不能完全等于 `help`、`clear`、`compact`、`model`、`exit`、`quit`、`settings`、`anthropic` 或 `claude`。这些名称会覆盖真实的命令。
- `description` 是必填项，且限制在 1024 个字符以内。少于 20 个字符的描述虽然可以接受，但会触发警告，因为此类描述通常难以可靠地触发。
- 指令正文限制为 100,000 个字符。

### 上传 Bundle [#upload-a-bundle]

`.zip` 或 `.skill` 归档文件必须在归档根目录或仅深一层级的文件夹中包含 `SKILL.md`。导入时会移除单个外层包装文件夹；更深层级的布局将无法被识别。

<FileTree>
  <FileTree.Folder name="brand-guidelines" defaultOpen>
    <FileTree.File name="SKILL.md" />
    <FileTree.Folder name="references" defaultOpen>
      <FileTree.File name="tone-examples.md" />
    </FileTree.Folder>
    <FileTree.Folder name="scripts">
      <FileTree.File name="lint-copy.py" />
    </FileTree.Folder>
  </FileTree.Folder>
</FileTree>

导入限制：

- 支持的扩展名：`.md`, `.zip`, `.skill`。
- 默认情况下，每次上传限制为 50 MB。管理员可以通过 `librechat.yaml` 中的 [`fileConfig.skills.fileSizeLimit`](/docs/configuration/librechat_yaml/object_structure/file_config#skills) 进行更改。
- 每个归档最多 500 个条目，每个打包文件最多 10 MB。
- 一个没有 frontmatter `name` 的 `.md` 上传文件会从文件名中获取技能名称。
- 包含不安全路径（如路径遍历或绝对路径）的条目会被报告为错误并跳过；其余技能仍会正常导入。

来自 `DEPLOYMENT_SKILLS_DIR` 或 GitHub Skill Sync 的技能是只读的。只有在 LibreChat 内部创建的技能才能在 UI 中进行编辑。

## 调用模式 [#invocation-modes]

Skills 可以通过以下三种方式到达 agent：

- **手动**: 用户在聊天中输入 `$` 并从弹窗中选择一个技能。
- **Model-invoked**：模型从注入的技能目录中选择一项技能并调用该技能工具。
- **Always apply**：当启用时，该技能会在每一轮对话中被预加载。

实际进入上下文的内容因路径而异：

- 模型调用的目录仅包含名称和描述，最多支持 100 个技能，每个条目被截断至约 250 个字符。指令主体不包含在目录中。
- 手动和始终应用（always-apply）的调用会为该轮对话预置完整的 `SKILL.md` 正文，最多支持 10 个手动技能和 20 个始终应用技能，总计上限为 30 个。当超过组合上限时，会优先丢弃始终应用技能，以确保明确的用户意图得以保留。

手动调用是明确的用户意图。只要 `user-invocable` 不为 false，它就可以使用在模型调用中通过 `disable-model-invocation: true` 隐藏的技能。

## Agent Scope [#agent-scope]

Agents 必须开启 **Enable skills** 才能使用或创建 Skills。独立的 **Use all skills** 开关用于控制目录的可见性。

- **全部：** 开启 **使用所有技能 (Use all skills)** 以向用户展示完整的活动目录，包括后续添加的技能。
- **已选择：** 关闭 **Use all skills** 并添加单独的 Skills 以仅公开这些条目。
- **仅限创作：** 请保持 **Use all skills** 为关闭状态，且不选择任何 Skills。现有的目录条目不会被公开，但当用户拥有 Skill 创建权限时，Agent 可以在对话中创建 Skill。
- **已禁用：** 关闭 **Enable skills** 以同时禁用目录使用和运行时创作。

这允许管理员全局启用 Skills 功能，同时保持每个智能体可用的技能集保持专注。

关闭 **Use all skills** 将恢复启用该开关之前的选择状态。现有的 Agent 将保留旧版行为，即在未明确范围的情况下启用的 Skills 将意味着使用完整目录。

## 运行时技能创作 (Runtime Skill Authoring) [#runtime-skill-authoring]

启用了 Skills 的 Agent 可以在工作时创建或编辑可复用的 Skill 文件。运行时文件使用与上传的包相同的 `skills/{skillName}/...` 命名空间，因此 Agent 可以将 `SKILL.md` 以及相关的引用、脚本或资源作为成功工作流的一部分进行编写。

编写遵循常规的 Skills 权限模型：

- 创建新的 Skill 需要用户的 Skill **Create** 权限。
- 编辑现有 Skill 需要同时具备编辑权限并将其包含在智能体的活跃目录范围内；部署的 Skill 和通过 GitHub 同步的 Skill 保持只读状态。
- 仅限创作的智能体可以在不接收用户现有目录的情况下创建新的 Skill。

运行时创作不会绕过部署能力或用户权限。从 Agents endpoint 功能中移除 `skills` 会隐藏该功能，而在智能体上关闭 **Enable skills** 则会禁用其创作工具。

## 活跃和共享的 Skills [#active-and-shared-skills]

用户可以通过 **Available to agent** 开关来切换技能的启用或禁用状态。自有技能和部署技能默认为启用。共享技能将使用管理员配置的默认设置，直到用户对其进行覆盖。

未激活的技能将从以下内容中排除：

- `$` 气泡框
- 模型调用的技能目录
- 始终应用预设 (Always-apply priming)

共享技能可以通过标准的共享对话框向特定用户、组或角色授予查看者、编辑者或所有者权限，这需要您的角色具备共享权限。有关完整模型，请参阅 [Access Control](/docs/features/access_control)。

## 捆绑文件 [#bundled-files]

上传的技能包可以包含除 `SKILL.md` 之外的文件，例如：

- `references/...`
- `scripts/...`
- `assets/...`

后端会将这些文件与 Skill 一起存储。当 Skill 处于激活状态且在作用域内时，Agent 可以解析 Skill 文件。嵌套文件保留其相对路径，并通过面向模型的 `skills/{skillName}/...` 命名空间进行寻址。在 Skill 查看器中，相对 Markdown 链接会从当前文件开始解析，并在同一个 Skill 内打开引用的文件。当启用 Code Interpreter 时，相同的文件会被挂载到 `/mnt/data/skills/{skillName}/...`，以便 shell 和代码操作可以直接使用它们。编辑 `SKILL.md` 会提升 Skill 版本；在进行代码或程序化执行之前，LibreChat 会验证每个挂载的文件引用是否与该版本匹配，并在任何引用过期时重新上传完整的包。

技能页面还包含一个文件树，提供 **New File**（新建文件）、**New Folder**（新建文件夹）和 **Upload File**（上传文件）操作，每个添加的文件最大支持 10 MB。其中的 `SKILL.md` 为保留文件：请改为编辑技能主体内容。

<Callout type="note" title="创作提示">
  保持 `description` 的具体性。它是模型调用技能时最强的信号。简短或模糊的描述会导致触发不足。
</Callout>

## 部署技巧 [#deployment-skills]

管理员可以通过 `DEPLOYMENT_SKILLS_DIR` 从文件系统发布只读的 Skills。

```bash filename=".env"
DEPLOYMENT_SKILLS_DIR=./skill
```

该目录默认为项目根目录下的 `./skill`。每个 Skill 都位于其各自的子目录中，其中包含一个 `SKILL.md` 文件以及随附的任何捆绑文件。LibreChat 会在启动时加载部署的 Skills，并将其提供给启用了 Skills 功能的用户。

部署技能：

- 在 UI 中为只读
- 使用 `deployment` 作为它们的来源
- 优先于同名的持久化 Skills
- 在添加、移除或更改文件后，需要重启 LibreChat

实验性的 [Agent Plugins](/docs/features/agent_plugins) 也可以将只读部署的 Skills 与相关的 MCP 服务器打包在一起。独立部署目录中的 Skill 优先级高于同名的插件 Skill。

## GitHub Skill Sync [#github-skill-sync]

管理员可以通过 `librechat.yaml` 中的 `skillSync.github` 从 GitHub 仓库镜像 Skills。这是在团队中共享一组精选 Skills 的实用方法。

```yaml filename="librechat.yaml"
skillSync:
  github:
    enabled: true
    intervalMinutes: 60
    runOnStartup: true
    sources:
      - id: librechat-skills
        owner: your-org
        repo: your-skills-repo
        ref: main
        paths:
          - skills
        skillDiscoveryDepth: 2
        token: '${GITHUB_SKILLS_TOKEN}'
```

GitHub Skill Sync:

- 扫描配置的仓库路径以查找 `SKILL.md`
- 将包含每个 `SKILL.md` 的目录视为一个技能根目录，位于配置路径的 `skillDiscoveryDepth` 层级内。
- 在每个技能旁边导入捆绑文件
- 存储带有 `source: "github"` 的镜像 Skills
- 当上游仓库发生变更时，同步更新镜像的 Skills
- 移除在已配置的源中不再存在的镜像 Skills
- 即使源中的另一个 Skill 无效或冲突，也会发布有效的 Skill
- 向管理员报告部分成功的运行以及受限的已跳过技能详情
- 支持定时、启动时以及手动管理员触发的运行

被跳过的 Skill 在存在已知良好镜像时会保留该镜像。源范围内的故障（例如身份验证、速率限制、同步所有权丢失或回滚失败）仍会导致整个源运行失败。

使用具有所选存储库的只读 Contents 和 Metadata 权限的 GitHub 细粒度个人访问令牌。有关所有字段、凭据选项、租户范围和管理员同步端点的信息，请参阅 [Skill Sync Object Structure](/docs/configuration/librechat_yaml/object_structure/skill_sync)。
