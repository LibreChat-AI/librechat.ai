Skills zijn herbruikbare instructiebundels voor LibreChat Agents. Een skill is gecentreerd rond een `SKILL.md` bestand: frontmatter beschrijft wanneer de skill moet worden gebruikt, en de markdown-body geeft de agent de procedure, regels, voorbeelden of referenties om te volgen.

Skills zijn nuttig voor herhaalbaar werk zoals:

- Merk- of schrijfrichtlijnen toepassen
- Het volgen van interne controlelijsten
- Een standaard onderzoeksworkflow uitvoeren
- Het voorbereiden van een gespecialiseerde tool-workflow
- Het verpakken van herbruikbare scripts, referenties en assets met een instructiebestand

## Skills inschakelen [#enable-skills]

De `skills` agent-functionaliteit is standaard ingeschakeld. Beheerders kunnen deze verwijderen uit de lijst met functionaliteiten van het agents endpoint om Skills te verbergen voor gebruikers.

```yaml filename="librechat.yaml"
endpoints:
  agents:
    capabilities:
      - 'deferred_tools'
      - 'execute_code'
      - 'file_search'
      - 'web_search'
      - 'artifacts'
      - 'subagents'
      - 'actions'
      - 'context'
      - 'skills'
      - 'memory'
      - 'ask_user_question'
      - 'tools'
      - 'chain'
      - 'ocr'
```

Rolmachtigingen bepalen ook wie skills kan gebruiken, aanmaken, delen en openbaar kan delen.

## Deployment Skills [#deployment-skills]

Admins kunnen read-only Skills vanuit het bestandssysteem verzenden met `DEPLOYMENT_SKILLS_DIR`.

```bash filename=".env"
DEPLOYMENT_SKILLS_DIR=./skill
```

De directory staat standaard ingesteld op `./skill` in de hoofdmap van het project. LibreChat laadt deployment Skills bij het opstarten en stelt deze beschikbaar aan gebruikers met de Skills-functionaliteit ingeschakeld.

Deployment-vaardigheden:

- Zijn alleen-lezen in de UI
- Gebruik `deployment` als hun bron
- Krijgen voorrang op opgeslagen Skills met dezelfde naam
- Een herstart van LibreChat is vereist nadat bestanden zijn toegevoegd, verwijderd of gewijzigd

Experimentele [Agent Plugins](/docs/features/agent_plugins) kunnen ook read-only deployment Skills bundelen samen met gerelateerde MCP servers. Een Skill in de standalone deployment directory krijgt voorrang op een plugin Skill met dezelfde naam.

## GitHub Skill Sync [#github-skill-sync]

Beheerders kunnen Skills spiegelen vanuit GitHub-repositories met `skillSync.github` in `librechat.yaml`.

```yaml filename="librechat.yaml"
skillSync:
  github:
    enabled: true
    intervalMinutes: 60
    runOnStartup: true
    sources:
      - id: librechat-skills
        owner: your-org
        repo: your-skills-repo
        ref: main
        paths:
          - skills
        skillDiscoveryDepth: 2
        token: '${GITHUB_SKILLS_TOKEN}'
```

GitHub Skill Sync:

- Scant geconfigureerde repository-paden op `SKILL.md`
- Importeert gebundelde bestanden naast elke skill
- Slaat gespiegelde Skills op met `source: "github"`
- Werkt gespiegelde Skills bij wanneer de upstream repository wijzigt
- Verwijdert gespiegelde Skills die niet langer bestaan in de geconfigureerde bron
- Publiceert geldige Skills, zelfs wanneer een andere Skill in de bron ongeldig is of conflicteert
- Rapporteert gedeeltelijk geslaagde runs en details over overgeslagen-Skill aan beheerders
- Ondersteunt geplande, opstart- en handmatig door de beheerder geactiveerde uitvoeringen

Een overgeslagen Skill behoudt zijn laatst bekende goede mirror wanneer deze bestaat. Bronbrede fouten zoals authenticatie, rate limiting, verloren synchronisatie-eigendom of een mislukte rollback zorgen er nog steeds voor dat de volledige bronuitvoering mislukt.

Gebruik een GitHub fine-grained personal access token met read-only Contents en Metadata permissies voor de geselecteerde repository. Zie [Skill Sync Object Structure](/docs/configuration/librechat_yaml/object_structure/skill_sync) voor alle velden, credential-opties, tenant-scoping en admin sync-endpoints.

## Een Skill aanmaken [#create-a-skill]

Open **Skills** vanuit het zijpaneel. Je kunt een skill rechtstreeks in LibreChat schrijven of een `.md`-, `.zip`- of `.skill`-bestand uploaden dat `SKILL.md` bevat.

Minimaal `SKILL.md`:

```md filename="SKILL.md"
---
name: brand-guidelines
description: Use when writing public-facing content that must follow the company voice and terminology.
---

# Brand Guidelines

Write in a concise, practical tone.
Prefer active voice.
Use product terminology consistently.
```

## Aanroepmodi [#invocation-modes]

Skills kunnen een agent op drie manieren bereiken:

- **Handmatig**: de gebruiker typt `$` in de chat en selecteert een skill uit het popover-menu.
- **Model-invoked**: het model kiest een vaardigheid uit de geïnjecteerde vaardighedencatalogus en roept de vaardigheidstool aan.
- **Altijd toepassen**: de skill wordt in elke beurt geactiveerd wanneer deze is ingeschakeld.

Handmatige aanroeping is expliciete gebruikersintentie. Het kan skills gebruiken die verborgen zijn voor modelaanroeping met `disable-model-invocation: true`, zolang `user-invocable` niet op false staat.

## Agent Scope [#agent-scope]

Agents moeten **Enable skills** ingeschakeld hebben voordat ze Skills kunnen gebruiken of aanmaken. De afzonderlijke **Use all skills** schakelaar regelt de zichtbaarheid in de catalogus.

- **Alles:** schakel **Use all skills** in om de volledige actieve catalogus zichtbaar te maken voor de gebruiker, inclusief Skills die later zijn toegevoegd.
- **Geselecteerd:** laat **Use all skills** uitgeschakeld en voeg individuele Skills toe om alleen die items bloot te stellen.
- **Alleen voor auteurs:** laat **Use all skills** uitgeschakeld zonder geselecteerde Skills. Bestaande catalogusvermeldingen worden niet getoond, maar de agent kan tijdens een gesprek een Skill aanmaken wanneer de gebruiker toestemming heeft om Skills aan te maken.
- **Uitgeschakeld:** schakel **Enable skills** uit om zowel het gebruik van de catalogus als het runtime-authoring uit te schakelen.

Hiermee kunnen beheerders de Skills-functie globaal beschikbaar maken, terwijl de bruikbare vaardighedenset van elke agent gericht blijft.

Het uitschakelen van **Use all skills** herstelt de selectie die actief was voordat de schakelaar werd ingeschakeld. Bestaande agents behouden het legacy-gedrag waarbij Skills die zijn ingeschakeld zonder expliciete scope de volledige catalogus betekenen.

## Runtime Skill Authoring [#runtime-skill-authoring]

Een agent met ingeschakelde Skills kan herbruikbare Skill-bestanden aanmaken of bewerken terwijl deze werkt. Runtime-bestanden gebruiken dezelfde `skills/{skillName}/...` namespace als geüploade bundels, waardoor de agent `SKILL.md` en ondersteunende referenties, scripts of assets kan schrijven als onderdeel van een succesvolle workflow.

Authoring volgt het normale Skills-toestemmingsmodel:

- Voor het aanmaken van een nieuwe Skill is de **Create**-toestemming voor Skills van de gebruiker vereist.
- Het bewerken van een bestaande Skill vereist zowel bewerkingsrechten als opname in het actieve catalogusbereik van de agent; implementaties en via GitHub gesynchroniseerde Skills blijven alleen-lezen.
- Een agent die alleen voor authoring bedoeld is, kan een nieuwe Skill aanmaken zonder de bestaande catalogus van de gebruiker te ontvangen.

Runtime authoring omzeilt de deployment-mogelijkheden of gebruikersrechten niet. Het verwijderen van `skills` uit de mogelijkheden van de Agents endpoint verbergt de functie, en het uitschakelen van **Enable skills** op de agent deactiveert de authoring-tools ervan.

## Actieve en Gedeelde Skills [#active-and-shared-skills]

Gebruikers kunnen skills in- of uitschakelen. Skills in eigen bezit en deployment-skills staan standaard op actief. Gedeelde skills gebruiken de door de beheerder geconfigureerde standaardinstelling totdat de gebruiker deze overschrijft.

Inactieve skills worden uitgesloten van:

- De `$` popover
- De door het model aangeroepen skill-catalogus
- Altijd-toepassen priming

## Gebundelde bestanden [#bundled-files]

Geüploade skill-bundels kunnen naast `SKILL.md` ook bestanden bevatten, zoals:

- `references/...`
- `scripts/...`
- `assets/...`

De backend slaat die bestanden op bij de skill. De agent kan skill-bestanden oplossen wanneer de skill actief is en binnen het bereik valt. Geneste bestanden behouden hun relatieve paden en worden geadresseerd via de `skills/{skillName}/...` namespace die naar het model is gericht. In de Skill-viewer worden relatieve Markdown-links opgelost vanuit het huidige bestand en openen ze het verwezen bestand binnen dezelfde Skill. Wanneer Code Interpreter is ingeschakeld, worden dezelfde bestanden gekoppeld op `/mnt/data/skills/{skillName}/...`, zodat shell- en code-operaties ze direct kunnen gebruiken. Het bewerken van `SKILL.md` verhoogt de Skill-versie; vóór code-uitvoering of programmatische uitvoering verifieert LibreChat of elke gekoppelde bestandsverwijzing overeenkomt met die versie en uploadt de volledige bundel opnieuw wanneer een verwijzing verouderd is.

<Callout type="note" title="Auteurstip">
  Houd `description` specifiek. Dit is het sterkste signaal voor door het model aangeroepen vaardigheden. Een korte of vage beschrijving zal leiden tot onder-activering.
</Callout>
