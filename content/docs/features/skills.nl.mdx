Skills zijn herbruikbare instructiebundels voor LibreChat Agents. Een skill is gecentreerd rond een `SKILL.md` bestand: frontmatter beschrijft wanneer de skill moet worden gebruikt, en de markdown-body geeft de agent de procedure, regels, voorbeelden of referenties om te volgen.

Skills zijn nuttig voor herhaalbaar werk zoals:

- Merk- of schrijfrichtlijnen toepassen
- Het volgen van interne controlelijsten
- Een standaard onderzoeksworkflow uitvoeren
- Het voorbereiden van een gespecialiseerde tool-workflow
- Het verpakken van herbruikbare scripts, referenties en assets met een instructiebestand

LibreChat wordt niet geleverd met een bibliotheek met skills. Elke skill is afkomstig van je eigen instantie: [geschreven of geüpload in de UI](#create-a-skill), [gemaakt door een agent tijdens een chat](#runtime-skill-authoring), [gekoppeld vanuit het bestandssysteem](#deployment-skills), of [gespiegeld vanuit een GitHub-repository](#github-skill-sync).

## Skills inschakelen [#enable-skills]

De `skills` agent-functionaliteit is standaard ingeschakeld. Beheerders kunnen deze verwijderen uit de lijst met functionaliteiten van het agents endpoint om Skills te verbergen voor gebruikers.

```yaml filename="librechat.yaml"
endpoints:
  agents:
    capabilities:
      - 'deferred_tools'
      - 'execute_code'
      - 'file_search'
      - 'web_search'
      - 'artifacts'
      - 'subagents'
      - 'actions'
      - 'context'
      - 'skills'
      - 'memory'
      - 'ask_user_question'
      - 'tools'
      - 'chain'
      - 'ocr'
```

Rolmachtigingen bepalen wie skills kan gebruiken, maken, delen en openbaar kan delen. Het gebruiken en maken van skills is standaard toegestaan; delen en openbaar delen staan standaard uit voor niet-beheerdersrollen. Beheerders kunnen dit wijzigen via de beheerdersinstellingen in het Skills-paneel.

Als de functionaliteit is uitgeschakeld, of als je rol niet over de gebruiksrechten beschikt, verschijnt Skills helemaal niet in het zijpaneel.

## Een Skill gebruiken [#use-a-skill]

<Steps>
<Step>

**Open Skills** vanuit het zijpaneel. Het paneel bevat een lijst met de skills die je bezit en de skills die met je zijn gedeeld, inclusief een filtervak voor lange lijsten. Door een skill te selecteren, open je de bijbehorende pagina waar je de instructies kunt lezen en de gebundelde bestanden kunt bekijken.

</Step>
<Step>

**Controleer of de skill beschikbaar is.** Elke skill heeft een **Available to agent** schakelaar. Skills die je zelf bezit en deployment-skills staan standaard op beschikbaar; gedeelde skills volgen de standaardinstelling van de beheerder totdat je deze overschrijft.

</Step>
<Step>

**Geef de agent toegang.** Schakel in de agent builder **Enable skills** in en bepaal vervolgens of de agent de volledige catalogus ziet of alleen de skills die je selecteert. Zie [Agent Scope](#agent-scope).

</Step>
<Step>

**Roep de skill aan.** Typ `$` in het berichtvenster en selecteer een skill op naam. Er wordt niets in je berichttekst ingevoegd: de skill wordt in de wachtrij geplaatst voor die beurt en weergegeven als een chip boven het invoerveld. Het model kan ook zelf een skill kiezen, en voor `always-apply` skills is helemaal geen actie vereist.

</Step>
</Steps>

## Een Skill aanmaken [#create-a-skill]

Open **Skills** vanuit het zijpaneel en gebruik de **+** knop, die twee paden biedt:

- **Schrijf vaardigheidsinstructies** — een dialoogvenster met een naam, een beschrijving en de instructietekst.
- **Upload a skill** — een `.md`, `.zip`, of `.skill` bestand dat een `SKILL.md` bevat.

Een agent kan ook een skill voor je aanmaken terwijl deze werkt, zonder dit paneel te gebruiken. Zie [Runtime Skill Authoring](#runtime-skill-authoring).

Minimaal `SKILL.md`:

```md filename="SKILL.md"
---
name: brand-guidelines
description: Use when writing public-facing content that must follow the company voice and terminology.
---

# Brand Guidelines

Write in a concise, practical tone.
Prefer active voice.
Use product terminology consistently.
```

Sleutels worden hoofdletterongevoelig vergeleken en booleaanse velden accepteren alleen `true` of `false`. Het verwijderen van een booleaanse sleutel bij een latere opslag wist deze, dus het verwijderen van `disable-model-invocation` herstelt de model-aanroep.

Herkende frontmatter-velden worden gecontroleerd op type. Niet-herkende velden worden behouden als begrensde, JSON-veilige metadata in plaats van de Skill ongeldig te maken; diep geneste of te grote extensiewaarden worden nog steeds geweigerd.

Houd de `description` van een door het model aangeroepen Skill op 250 tekens of minder en plaats de belangrijkste triggerfrasen vooraan. Langere beschrijvingen kunnen nog steeds worden geïmporteerd, maar LibreChat kort ze in de voor het model zichtbare catalogus in en logt een waarschuwing met de naam van elke betreffende Skill.

### Naamgeving en groottelimieten [#naming-and-size-limits]

- `name` is vereist, moet voldoen aan `^[a-z0-9][a-z0-9-]*$` en is beperkt tot 64 tekens. Het moet uniek zijn onder je eigen skills; het opnieuw uploaden van een bestaande naam resulteert in een conflictfout in plaats van het overschrijven ervan.
- Namen mogen niet beginnen met `anthropic-` of `claude-`, en mogen niet exact `help`, `clear`, `compact`, `model`, `exit`, `quit`, `settings`, `anthropic` of `claude` zijn. Deze namen zouden echte commando's overschaduwen.
- `description` is verplicht en beperkt tot 1024 tekens. Beschrijvingen van minder dan 20 tekens worden geaccepteerd met een waarschuwing, omdat deze zelden betrouwbaar worden geactiveerd.
- De instructie-body is beperkt tot 100.000 tekens.

### Een bundel uploaden [#upload-a-bundle]

Een `.zip` of `.skill` archief moet `SKILL.md` bevatten in de hoofdmap van het archief of exact één map diep. Een enkele omsluitende map wordt bij het importeren verwijderd; diepere structuren worden niet herkend.

<FileTree>
  <FileTree.Folder name="brand-guidelines" defaultOpen>
    <FileTree.File name="SKILL.md" />
    <FileTree.Folder name="references" defaultOpen>
      <FileTree.File name="tone-examples.md" />
    </FileTree.Folder>
    <FileTree.Folder name="scripts">
      <FileTree.File name="lint-copy.py" />
    </FileTree.Folder>
  </FileTree.Folder>
</FileTree>

Importlimieten:

- Geaccepteerde extensies: `.md`, `.zip`, `.skill`.
- Standaard 50 MB per upload. Beheerders kunnen dit wijzigen met [`fileConfig.skills.fileSizeLimit`](/docs/configuration/librechat_yaml/object_structure/file_config#skills) in `librechat.yaml`.
- Tot 500 items per archief, en 10 MB per gebundeld bestand.
- Een `.md` upload zonder frontmatter `name` leidt de skill-naam af van de bestandsnaam.
- Invoer met onveilige paden, zoals traversal- of absolute paden, wordt gerapporteerd als fouten en overgeslagen; de rest van de skill wordt nog steeds geïmporteerd.

Skills die afkomstig zijn uit `DEPLOYMENT_SKILLS_DIR` of GitHub Skill Sync zijn alleen-lezen. Alleen skills die binnen LibreChat zijn gemaakt, kunnen in de UI worden bewerkt.

## Aanroepmodi [#invocation-modes]

Skills kunnen een agent op drie manieren bereiken:

- **Handmatig**: de gebruiker typt `$` in de chat en selecteert een skill uit het popover-menu.
- **Model-invoked**: het model kiest een vaardigheid uit de geïnjecteerde vaardighedencatalogus en roept de vaardigheidstool aan.
- **Altijd toepassen**: de skill wordt in elke beurt geactiveerd wanneer deze is ingeschakeld.

Wat er daadwerkelijk in de context terechtkomt, verschilt per pad:

- De door het model aangeroepen catalogus bevat alleen namen en beschrijvingen, tot maximaal 100 vaardigheden, waarbij elk item is ingekort tot ongeveer 250 tekens. Instructieteksten maken geen deel uit van de catalogus.
- Handmatige en always-apply aanroepen bereiden de volledige `SKILL.md` body voor die beurt voor, tot maximaal 10 handmatige en 20 always-apply skills, en 30 in totaal. Wanneer het gecombineerde maximum wordt overschreden, worden always-apply skills als eerste verwijderd, zodat de expliciete intentie van de gebruiker behouden blijft.

Handmatige aanroeping is expliciete gebruikersintentie. Het kan skills gebruiken die verborgen zijn voor modelaanroeping met `disable-model-invocation: true`, zolang `user-invocable` niet op false staat.

## Agent Scope [#agent-scope]

Agents moeten **Enable skills** ingeschakeld hebben voordat ze Skills kunnen gebruiken of aanmaken. De afzonderlijke **Use all skills** schakelaar regelt de zichtbaarheid in de catalogus.

- **Alles:** schakel **Use all skills** in om de volledige actieve catalogus zichtbaar te maken voor de gebruiker, inclusief Skills die later zijn toegevoegd.
- **Geselecteerd:** laat **Use all skills** uitgeschakeld en voeg individuele Skills toe om alleen die items bloot te stellen.
- **Alleen voor auteurs:** laat **Use all skills** uitgeschakeld zonder geselecteerde Skills. Bestaande catalogusvermeldingen worden niet getoond, maar de agent kan tijdens een gesprek een Skill aanmaken wanneer de gebruiker toestemming heeft om Skills aan te maken.
- **Uitgeschakeld:** schakel **Enable skills** uit om zowel het gebruik van de catalogus als het runtime-authoring uit te schakelen.

Hiermee kunnen beheerders de Skills-functie globaal beschikbaar maken, terwijl de bruikbare vaardighedenset van elke agent gericht blijft.

Het uitschakelen van **Use all skills** herstelt de selectie die actief was voordat de schakelaar werd ingeschakeld. Bestaande agents behouden het legacy-gedrag waarbij Skills die zijn ingeschakeld zonder expliciete scope de volledige catalogus betekenen.

## Runtime Skill Authoring [#runtime-skill-authoring]

Een agent met ingeschakelde Skills kan herbruikbare Skill-bestanden aanmaken of bewerken terwijl deze werkt. Runtime-bestanden gebruiken dezelfde `skills/{skillName}/...` namespace als geüploade bundels, waardoor de agent `SKILL.md` en ondersteunende referenties, scripts of assets kan schrijven als onderdeel van een succesvolle workflow.

Authoring volgt het normale Skills-toestemmingsmodel:

- Voor het aanmaken van een nieuwe Skill is de **Create**-toestemming voor Skills van de gebruiker vereist.
- Het bewerken van een bestaande Skill vereist zowel bewerkingsrechten als opname in het actieve catalogusbereik van de agent; implementaties en via GitHub gesynchroniseerde Skills blijven alleen-lezen.
- Een agent die alleen voor authoring bedoeld is, kan een nieuwe Skill aanmaken zonder de bestaande catalogus van de gebruiker te ontvangen.

Runtime authoring omzeilt de deployment-mogelijkheden of gebruikersrechten niet. Het verwijderen van `skills` uit de mogelijkheden van de Agents endpoint verbergt de functie, en het uitschakelen van **Enable skills** op de agent deactiveert de authoring-tools ervan.

## Actieve en Gedeelde Skills [#active-and-shared-skills]

Gebruikers kunnen skills in- of uitschakelen met de schakelaar **Available to agent**. Skills die in eigen bezit zijn of via deployment zijn toegevoegd, staan standaard op actief. Gedeelde skills gebruiken de door de beheerder geconfigureerde standaardinstelling totdat de gebruiker deze overschrijft.

Inactieve skills worden uitgesloten van:

- De `$` popover
- De door het model aangeroepen skill-catalogus
- Altijd-toepassen priming

Het delen van een skill verleent viewer-, editor- of eigenaar-toegang aan specifieke gebruikers, groepen of rollen via het standaard dialoogvenster voor delen, en vereist de share-toestemming voor jouw rol. Zie [Access Control](/docs/features/access_control) voor het volledige model.

## Gebundelde bestanden [#bundled-files]

Geüploade skill-bundels kunnen naast `SKILL.md` ook bestanden bevatten, zoals:

- `references/...`
- `scripts/...`
- `assets/...`

De backend slaat die bestanden op bij de skill. De agent kan skill-bestanden oplossen wanneer de skill actief is en binnen het bereik valt. Geneste bestanden behouden hun relatieve paden en worden geadresseerd via de `skills/{skillName}/...` namespace die naar het model is gericht. In de Skill-viewer worden relatieve Markdown-links opgelost vanuit het huidige bestand en openen ze het verwezen bestand binnen dezelfde Skill. Wanneer Code Interpreter is ingeschakeld, worden dezelfde bestanden gekoppeld op `/mnt/data/skills/{skillName}/...`, zodat shell- en code-operaties ze direct kunnen gebruiken. Het bewerken van `SKILL.md` verhoogt de Skill-versie; vóór code-uitvoering of programmatische uitvoering verifieert LibreChat of elke gekoppelde bestandsverwijzing overeenkomt met die versie en uploadt de volledige bundel opnieuw wanneer een verwijzing verouderd is.

De pagina van een skill bevat ook een bestandsstructuur met acties voor **Nieuw bestand**, **Nieuwe map** en **Bestand uploaden**, tot maximaal 10 MB per toegevoegd bestand. `SKILL.md` zelf is daar gereserveerd: bewerk in plaats daarvan de body van de skill.

<Callout type="note" title="Auteurstip">
  Houd `description` specifiek. Dit is het sterkste signaal voor door het model aangeroepen vaardigheden. Een korte of vage beschrijving zal leiden tot onder-activering.
</Callout>

## Deployment Skills [#deployment-skills]

Admins kunnen read-only Skills vanuit het bestandssysteem verzenden met `DEPLOYMENT_SKILLS_DIR`.

```bash filename=".env"
DEPLOYMENT_SKILLS_DIR=./skill
```

De directory staat standaard ingesteld op `./skill` in de hoofdmap van het project. Elke skill bevindt zich in een eigen submap met een `SKILL.md`, inclusief eventuele gebundelde bestanden ernaast. LibreChat laadt deployment Skills bij het opstarten en stelt deze beschikbaar aan gebruikers bij wie de Skills-functionaliteit is ingeschakeld.

Deployment-vaardigheden:

- Zijn alleen-lezen in de UI
- Gebruik `deployment` als hun bron
- Krijgen voorrang op opgeslagen Skills met dezelfde naam
- Een herstart van LibreChat is vereist nadat bestanden zijn toegevoegd, verwijderd of gewijzigd

Experimentele [Agent Plugins](/docs/features/agent_plugins) kunnen ook read-only deployment Skills bundelen samen met gerelateerde MCP servers. Een Skill in de standalone deployment directory krijgt voorrang op een plugin Skill met dezelfde naam.

## GitHub Skill Sync [#github-skill-sync]

Admins kunnen Skills spiegelen vanuit GitHub-repositories met `skillSync.github` in `librechat.yaml`. Dit is de praktische manier om een samengestelde set skills te delen binnen een team.

```yaml filename="librechat.yaml"
skillSync:
  github:
    enabled: true
    intervalMinutes: 60
    runOnStartup: true
    sources:
      - id: librechat-skills
        owner: your-org
        repo: your-skills-repo
        ref: main
        paths:
          - skills
        skillDiscoveryDepth: 2
        token: '${GITHUB_SKILLS_TOKEN}'
```

GitHub Skill Sync:

- Scant geconfigureerde repository-paden op `SKILL.md`
- Behandelt de map die elke `SKILL.md` bevat als een skill-root, binnen `skillDiscoveryDepth` niveaus van het geconfigureerde pad
- Importeert gebundelde bestanden naast elke skill
- Slaat gespiegelde Skills op met `source: "github"`
- Werkt gespiegelde Skills bij wanneer de upstream repository wijzigt
- Verwijdert gespiegelde Skills die niet langer bestaan in de geconfigureerde bron
- Publiceert geldige Skills, zelfs wanneer een andere Skill in de bron ongeldig is of conflicteert
- Rapporteert gedeeltelijk geslaagde runs en details over overgeslagen-Skill aan beheerders
- Ondersteunt geplande, opstart- en handmatig door de beheerder geactiveerde uitvoeringen

Een overgeslagen Skill behoudt zijn laatst bekende goede mirror wanneer deze bestaat. Bronbrede fouten zoals authenticatie, rate limiting, verloren synchronisatie-eigendom of een mislukte rollback zorgen er nog steeds voor dat de volledige bronuitvoering mislukt.

Gebruik een GitHub fine-grained personal access token met read-only Contents en Metadata permissies voor de geselecteerde repository. Zie [Skill Sync Object Structure](/docs/configuration/librechat_yaml/object_structure/skill_sync) voor alle velden, credential-opties, tenant-scoping en admin sync-endpoints.
