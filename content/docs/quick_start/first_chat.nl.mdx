LibreChat is software die je zelf host en wordt geleverd zonder eigen API-sleutel. Zodra je instance draait, leiden deze stappen je van de inlogpagina naar een werkend gesprek.

<Callout type="info" title="Nog niets actief?">

Installeer eerst LibreChat: [Quick Start](/docs/quick_start) voor de Docker-methode van 5 minuten, [Local Installation](/docs/local) voor Docker, npm of Helm, of [Remote Hosting](/docs/remote) om het op een server te implementeren.

Om LibreChat te proberen voordat je iets installeert, draait het project een gratis publieke demo op [chat.librechat.ai](https://chat.librechat.ai). Deze is bedoeld voor evaluatie, niet voor privégegevens.

</Callout>

  <Step>

### Open LibreChat in je browser [#open-librechat-in-your-browser]

Een lokale Docker- of npm-installatie serveert de app op [http://localhost:3080](http://localhost:3080). De poort is afkomstig van `PORT`. Als je deze hebt gewijzigd, of een andere hostpoort hebt toegewezen in `docker-compose.override.yml`, gebruik dan die in plaats daarvan.

Overal elders is het adres het adres dat je deployment je geeft: het domein dat Railway toewijst, je `username-projectname.hf.space` URL op Hugging Face, het server-IP of domein voor je externe Docker- of Kubernetes-installatie. `DOMAIN_CLIENT` is een aparte instelling, het adres dat LibreChat in de links plaatst die het genereert, dus verwijs hiermee naar diezelfde publieke URL in plaats van het adres uit je browserbalk over te nemen.

Als er niets wordt geladen, zie [If nothing loads](#if-nothing-loads) hieronder.

  </Step>
  <Step>

### Maak je account aan [#create-your-account]

E-mailregistratie is standaard ingeschakeld (`ALLOW_REGISTRATION=true`) en er zijn geen standaard inloggegevens: klik op **Sign up** en kies je eigen e-mailadres en wachtwoord.

Niet elk exemplaar biedt dat formulier aan. Als er geen **Sign up** is, gebruik dan een aanbieder-knop als die wordt getoond, of het inlogformulier als het exemplaar verifieert via een directory: beide kunnen je account aanmaken bij de eerste keer inloggen. Wanneer er niets wordt aangeboden, of wanneer inloggen wordt geweigerd omdat je account niet bestaat, vraag dan degene die het exemplaar beheert om er een. Welke besturingselementen verschijnen, wordt bepaald door de [authentication settings](/docs/configuration/authentication) van het exemplaar.

<Callout type="info" title="Eerste account = Admin in Single-Tenant implementaties">

In een unscoped single-tenant deployment wordt het eerste geregistreerde account het admin-account, en krijgt elk account daarna standaard de `USER` rol. Tenant-scoped deployments promoveren niet automatisch de eerste gebruiker in elke tenant; provisioneer tenant-beheerders via een vertrouwde administratieve flow ([Authentication](/docs/features/authentication)).

Een OpenID-implementatie kan de standaardrol in beide richtingen overschrijven: `OPENID_ADMIN_ROLE` verhoogt een overeenkomend account naar admin, en generieke rolsynchronisatie (`OPENID_ROLE_SYNC_ENABLED`) koppelt providerrollen aan andere niet-admin rollen. Zie [OpenID Connect](/docs/configuration/dotenv#openid-connect).

</Callout>

Als je [OAuth2/OIDC](/docs/configuration/authentication/OAuth2-OIDC) of [SAML](/docs/configuration/authentication/SAML) hebt geconfigureerd, gebruik dan de knop van die provider in plaats van het formulier.

[LDAP/AD](/docs/configuration/authentication/ldap) voegt geen knop toe. Meld u aan via hetzelfde e-mail- en wachtwoordformulier en voer uw directory-gebruikersnaam in plaats van het e-mailadres in wanneer de server `LDAP_LOGIN_USES_USERNAME=true` heeft ingesteld.

  </Step>
  <Step>

### Geef een model een API-sleutel [#give-a-model-an-api-key]

LibreChat communiceert met AI-providers met jouw inloggegevens, en `.env.example` levert de vooraf geconfigureerde providers als `user_provided`:

```bash filename=".env"
OPENAI_API_KEY=user_provided
ANTHROPIC_API_KEY=user_provided
GOOGLE_KEY=user_provided
```

Met die waarde levert elke gebruiker zijn eigen sleutel vanuit de web-UI: selecteer de endpoint, open het tandwielpictogram ernaast en vul het dialoogvenster **Set API Key** in.

Die waarde is alleen een standaardwaarde wanneer de installatie start vanuit `.env.example`, wat geldt voor Docker en npm. Een Helm-release, een Railway-service of een Hugging Face Space bevat alleen de variabelen die je zelf instelt, dus een endpoint waarvan je de inloggegevens nooit hebt ingesteld, wordt helemaal niet geladen en er verschijnt geen dialoogvenster voor de sleutel. Stel de variabele daar in op `user_provided` voordat je verwacht dat gebruikers hun eigen sleutels meebrengen, en herstart de workload zodat actieve pods of containers deze oppikken. Hetzelfde dialoogvenster is bereikbaar via **Settings → Data & Privacy → API keys**, waar sleutels later ook kunnen worden bekeken en gewijzigd.

Als je geen endpoint-dropdown en geen tandwielpictogram ziet, houdt deze instantie de selector verborgen via [model specs](/docs/configuration/librechat_yaml/object_structure/model_specs) of de `interface`-instellingen ervan. Stel je eerste sleutel in via **Settings → Data & Privacy → API keys**, waar de endpoints worden vermeld die zijn geconfigureerd om een door de gebruiker verstrekte sleutel te accepteren.

Om in plaats daarvan een sleutel eenmalig voor iedereen te configureren, stelt u de echte sleutel in op de plek van `user_provided` en start u LibreChat opnieuw op. Op Docker moet u de containers opnieuw aanmaken met `docker compose up -d`, waarbij u `-f ./deploy-compose.yml` toevoegt als dat het bestand is waar uw stack vandaan draait: `docker compose restart` behoudt de omgeving die de container al heeft, waardoor de oude waarde blijft bestaan. Er wordt aan geen enkele gebruiker om invoer gevraagd en de sleutel blijft op de server staan. Waar u dit instelt, hangt af van hoe u het heeft geïnstalleerd: `.env` voor Docker en npm, een Kubernetes Secret voor [Helm](/docs/local/helm_chart#configuration), de variabelen van de service in het Railway-dashboard, of Space Secrets op [Hugging Face](/docs/remote/huggingface). Stappen per provider vindt u in [AI Setup](/docs/configuration/pre_configured_ai).

<Callout type="warn" title="Een gedeelde sleutel op een openbare URL is voor iedereen om te gebruiken">

Registratie staat standaard open, dus op een instantie die bereikbaar is via internet kan iedereen die de URL vindt zich aanmelden en jouw sleutel gebruiken. Voordat je een server-side sleutel configureert op een publieke implementatie, moet je ervoor zorgen dat niemand die je niet bedoeld hebt een account kan krijgen. Het e-mailformulier, elke provider-knop en elke directory waartegen je authenticeert, creëren elk gebruikers op hun eigen voorwaarden, dus het sluiten van één methode betekent niet dat ze allemaal gesloten zijn; [Authentication](/docs/configuration/authentication) behandelt de instellingen achter elk daarvan. Het op `user_provided` laten staan van de providers voorkomt dit probleem volledig.

</Callout>

<Callout type="info" title="Geen betaalde API-sleutel?">

Draai een model op je eigen hardware met [Ollama](/docs/configuration/librechat_yaml/ai_endpoints/ollama), of bereik vele aanbieders via een gateway zoals [OpenRouter](/docs/configuration/librechat_yaml/ai_endpoints/openrouter). Beide worden toegevoegd als [custom endpoints](/docs/quick_start/custom_endpoints).

</Callout>

  </Step>
  <Step>

### Verstuur je eerste bericht [#send-your-first-message]

Kies een endpoint en model uit de selector bovenaan de chat, typ je prompt en verstuur deze. Waar de instantie de selector verbergt, heeft deze al voor je gekozen: typ en verstuur. Het antwoord wordt gestreamd en het gesprek wordt opgeslagen, zodat je er vanuit de zijbalk naar kunt terugkeren.

  </Step>
</Steps>

## Als er niets wordt geladen [#if-nothing-loads]

Een pagina die nooit verschijnt is een installatieprobleem, en de controle hangt af van hoe je hebt geïnstalleerd:

- **Docker.** Controleer of de containers actief zijn met `docker compose ps` en lees vervolgens de API-logs met `docker compose logs api`. Op een server die is opgezet met de [Docker on Linux](/docs/remote/docker_linux) handleiding, draait de stack vanuit een niet-standaard compose-bestand, dus gebruik `sudo docker compose -f ./deploy-compose.yml ps` en `sudo docker compose -f ./deploy-compose.yml logs api`. Meer informatie in [Docker troubleshooting](/docs/local/docker#troubleshooting).
- **npm.** LibreChat draait in de terminal waar je `npm run backend` hebt gestart, dus lees de output van die terminal. Als het proces is afgesloten, start het dan opnieuw en lees de foutmelding die wordt weergegeven.
- **[Helm](/docs/local/helm_chart) of een andere Kubernetes-installatie.** Controleer of de pods actief zijn met `kubectl get pods -n <release-namespace>`, lees de API-pod uit met `kubectl logs -n <release-namespace> <pod>`, en bevestig dat de service of ingress daadwerkelijk de poort blootstelt waar je naartoe browset. Beide commando's gebruiken standaard je huidige namespace, dus een lege lijst betekent meestal dat je in de verkeerde namespace kijkt.
- **Railway of een andere host.** Open de deployment-logs in het dashboard van de provider (in Railway is dit de **View logs**-knop bij de service) en navigeer naar de publieke URL die de provider heeft toegewezen in plaats van `localhost`.

## Als geen enkel model antwoordt [#if-no-model-answers]

- **Het endpoint zelf ontbreekt in de selector.** Drie afzonderlijke instellingen kunnen dit verbergen, dus controleer ze allemaal. `ENDPOINTS` in `.env`: wanneer dit is ingesteld, worden alleen de daar genoemde endpoints geladen. [Model specs](/docs/configuration/librechat_yaml/object_structure/model_specs) in `librechat.yaml`: waar deze de selector beperken, is alleen wat je hebt vermeld en alles in `modelSpecs.addedEndpoints` bereikbaar. En de eigen sleutel van de provider: een op sleutels gebaseerd endpoint zonder geconfigureerde waarde wordt niet geladen, dus stel de sleutel (of `user_provided`) in waar je installatie de omgeving bewaart, en start vervolgens opnieuw op door de containers opnieuw aan te maken met `docker compose up -d` op Docker. Een endpoint dat in plaats daarvan inloggegevens uit zijn omgeving haalt, zoals [Bedrock](/docs/configuration/pre_configured_ai/bedrock) uit de AWS credential chain, vereist dat de regio is ingesteld en een werkende chain in plaats van een sleutel.
- **Het endpoint is aanwezig, maar het model dat je wilt niet.** Waar de lijst vandaan komt, bepaalt wat je moet controleren. Bij een `user_provided` sleutel kan LibreChat niet aan de provider vragen welke modellen er bestaan, dus biedt het een ingebouwde lijst aan: benoem de modellen die je wilt met de `_MODELS` variabele van de provider, bijvoorbeeld [`OPENAI_MODELS`](/docs/configuration/pre_configured_ai/openai). Bij een echte server-side sleutel waarbij `_MODELS` niet is ingesteld, worden sommige providers gevraagd om hun lijst, waardoor een beperkte of niet-werkende sleutel deze kan inkorten; andere, waaronder [Google](/docs/configuration/pre_configured_ai/google), halen deze nooit op en vereisen dat `_MODELS` is ingesteld, ongeacht de sleutel. Controleer de specifieke pagina van die provider in [AI Setup](/docs/configuration/pre_configured_ai) voordat je iets anders wijzigt. Een [custom endpoint](/docs/configuration/librechat_yaml/object_structure/custom_endpoint) zoals Ollama of OpenRouter negeert `_MODELS` volledig: de lijst komt van `models.default` en `models.fetch` in het eigen `librechat.yaml` blok. En als je `librechat.yaml` [Model Specs](/docs/configuration/librechat_yaml/object_structure/model_specs) definieert, kies je uit die lijst in plaats van uit de eigen modellen van het endpoint.
- **Het antwoord mislukt met een authenticatie- of ongeldige-sleutelfout.** De sleutel is onjuist, verlopen of heeft geen toegang tot het geselecteerde model. Voer deze opnieuw in via het dialoogvenster **Set API Key**, of corrigeer de waarde in de omgeving van je installatie en start opnieuw op.
