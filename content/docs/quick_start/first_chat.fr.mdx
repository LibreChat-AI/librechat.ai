LibreChat est un logiciel que vous hébergez vous-même, et il est fourni sans aucune clé API propre. Une fois votre instance en cours d'exécution, ces étapes vous mèneront de la page de connexion à une conversation fonctionnelle.

<Callout type="info" title="Rien ne tourne encore ?">

Installez d'abord LibreChat : [Démarrage rapide](/docs/quick_start) pour la méthode Docker en 5 minutes, [Installation locale](/docs/local) pour Docker, npm ou Helm, ou [Hébergement distant](/docs/remote) pour le déployer sur un serveur.

Pour essayer LibreChat avant d'installer quoi que ce soit, le projet propose une démo publique gratuite sur [chat.librechat.ai](https://chat.librechat.ai). Elle est destinée à l'évaluation, et non aux données privées.

</Callout>

<Steps>
  <Step>

### Ouvrez LibreChat dans votre navigateur [#open-librechat-in-your-browser]

Une installation locale via Docker ou npm sert l'application sur [http://localhost:3080](http://localhost:3080). Le port provient de `PORT`. Si vous l'avez modifié, ou si vous avez mappé un port hôte différent dans `docker-compose.override.yml`, utilisez celui-ci à la place.

Partout ailleurs, l'adresse est celle que votre déploiement vous fournit : le domaine assigné par Railway, votre URL `username-projectname.hf.space` sur Hugging Face, l'adresse IP du serveur ou le domaine devant votre installation Docker ou Kubernetes distante. `DOMAIN_CLIENT` est un paramètre distinct, l'adresse que LibreChat insère dans les liens qu'il génère ; pointez-la donc vers cette même URL publique plutôt que d'y lire votre adresse de navigation.

Si rien ne se charge, consultez [If nothing loads](#if-nothing-loads) ci-dessous.

  </Step>
  <Step>

### Créez votre compte [#create-your-account]

L'inscription par e-mail est activée par défaut (`ALLOW_REGISTRATION=true`), et il n'y a pas d'identifiants par défaut : cliquez sur **Sign up** et choisissez votre propre e-mail et mot de passe.

Toutes les instances ne proposent pas ce formulaire. S'il n'y a pas de bouton **Sign up**, utilisez un bouton de fournisseur s'il en est affiché un, ou le formulaire de connexion si l'instance s'authentifie auprès d'un répertoire : l'un ou l'autre peut créer votre compte lors de la première connexion. Si aucune option n'est proposée, ou si la connexion est refusée parce que votre compte n'existe pas, demandez-en un à la personne qui gère l'instance. Les contrôles qui apparaissent sont déterminés par les [authentication settings](/docs/configuration/authentication) de l'instance.

<Callout type="info" title="Premier compte = Administrateur dans les déploiements à locataire unique">

Dans un déploiement mono-locataire sans portée (unscoped), le premier compte enregistré devient le compte administrateur, et chaque compte suivant reçoit le rôle `USER` par défaut. Les déploiements avec portée de locataire (tenant-scoped) ne promeuvent pas automatiquement le premier utilisateur de chaque locataire ; provisionnez les administrateurs de locataire via un flux administratif approuvé ([Authentication](/docs/features/authentication)).

Un déploiement OpenID peut remplacer le rôle par défaut dans les deux sens : `OPENID_ADMIN_ROLE` élève un compte correspondant au statut d'administrateur, et la synchronisation générique des rôles (`OPENID_ROLE_SYNC_ENABLED`) mappe les rôles du fournisseur vers d'autres rôles non-administrateur. Voir [OpenID Connect](/docs/configuration/dotenv#openid-connect).

</Callout>

Si vous avez configuré [OAuth2/OIDC](/docs/configuration/authentication/OAuth2-OIDC) ou [SAML](/docs/configuration/authentication/SAML), utilisez le bouton de ce fournisseur au lieu du formulaire.

[LDAP/AD](/docs/configuration/authentication/ldap) n'ajoute aucun bouton. Connectez-vous via le même formulaire d'e-mail et de mot de passe, en saisissant votre nom d'utilisateur de répertoire à la place de l'e-mail lorsque le serveur définit `LDAP_LOGIN_USES_USERNAME=true`.

  </Step>
  <Step>

### Donner une clé API à un modèle [#give-a-model-an-api-key]

LibreChat communique avec les fournisseurs d'IA avec vos identifiants, et `.env.example` fournit les fournisseurs préconfigurés en tant que `user_provided` :

```bash filename=".env"
OPENAI_API_KEY=user_provided
ANTHROPIC_API_KEY=user_provided
GOOGLE_KEY=user_provided
```

Avec cette valeur, chaque utilisateur fournit sa propre clé depuis l'interface web : sélectionnez l'endpoint, ouvrez l'icône en forme d'engrenage à côté de celui-ci, et remplissez la boîte de dialogue **Set API Key**.

Cette valeur n'est une valeur par défaut que lorsque l'installation démarre à partir de `.env.example`, ce qui concerne Docker et npm. Une version Helm, un service Railway ou un espace Hugging Face ne contient que les variables que vous avez définies ; ainsi, un endpoint dont vous n'avez jamais configuré les identifiants ne se chargera pas du tout, et aucune boîte de dialogue de clé n'apparaîtra pour celui-ci. Définissez la variable sur `user_provided` à cet endroit avant de permettre aux utilisateurs d'apporter leurs propres clés, puis redémarrez la charge de travail afin que les pods ou conteneurs en cours d'exécution prennent en compte ce changement. La même boîte de dialogue est accessible depuis **Paramètres → Données et confidentialité → Clés API**, là où les clés peuvent également être examinées et renouvelées ultérieurement.

Si vous ne voyez aucun menu déroulant d'endpoint ni aucune icône d'engrenage, cette instance maintient le sélecteur masqué, via [model specs](/docs/configuration/librechat_yaml/object_structure/model_specs) ou ses paramètres d' `interface`. Configurez votre première clé depuis **Paramètres → Données et confidentialité → Clés API**, qui liste les endpoints configurés pour accepter une clé fournie par l'utilisateur.

Pour configurer une clé une fois pour tout le monde, définissez la clé réelle à la place de `user_provided` et redémarrez LibreChat. Sur Docker, recréez les conteneurs avec `docker compose up -d`, en ajoutant `-f ./deploy-compose.yml` s'il s'agit du fichier à partir duquel votre pile s'exécute : `docker compose restart` conserve l'environnement que le conteneur possède déjà, donc l'ancienne valeur persiste. Aucun utilisateur n'est invité à saisir une clé, et celle-ci reste sur le serveur. L'endroit où vous la définissez dépend de votre méthode d'installation : `.env` pour Docker et npm, un Kubernetes Secret pour [Helm](/docs/local/helm_chart#configuration), les variables du service dans le tableau de bord Railway, ou les Space Secrets sur [Hugging Face](/docs/remote/huggingface). Les étapes fournisseur par fournisseur se trouvent dans [AI Setup](/docs/configuration/pre_configured_ai).

<Callout type="warn" title="Une clé partagée sur une URL publique peut être utilisée par n'importe qui">

L'inscription est ouverte par défaut. Par conséquent, sur une instance accessible depuis Internet, quiconque trouve l'URL peut s'inscrire et utiliser votre clé. Avant de configurer une clé côté serveur sur un déploiement public, assurez-vous que personne que vous n'avez pas autorisé ne puisse créer de compte. Le formulaire d'e-mail, chaque bouton de fournisseur et tout répertoire contre lequel vous vous authentifiez créent des utilisateurs selon leurs propres conditions ; fermer l'un ne signifie donc pas les fermer tous. La section [Authentication](/docs/configuration/authentication) couvre les paramètres de chacun. Laisser les fournisseurs sur `user_provided` permet d'éviter entièrement ce problème.

</Callout>

<Callout type="info" title="Pas de clé API payante ?">

Exécutez un modèle sur votre propre matériel avec [Ollama](/docs/configuration/librechat_yaml/ai_endpoints/ollama), ou accédez à de nombreux fournisseurs via une passerelle telle qu'[OpenRouter](/docs/configuration/librechat_yaml/ai_endpoints/openrouter). Les deux sont ajoutés en tant que [custom endpoints](/docs/quick_start/custom_endpoints).

</Callout>

  </Step>
  <Step>

### Envoyez votre premier message [#send-your-first-message]

Choisissez un endpoint et un modèle dans le sélecteur en haut du chat, saisissez votre prompt et envoyez-le. Lorsque l'instance masque le sélecteur, c'est qu'elle a déjà fait le choix pour vous : saisissez et envoyez. La réponse s'affiche en streaming et la conversation est enregistrée afin que vous puissiez y revenir depuis la barre latérale.

  </Step>
</Steps>

## Si rien ne se charge [#if-nothing-loads]

Une page qui ne s'affiche jamais est un problème d'installation, et la vérification dépend de la manière dont vous avez effectué l'installation :

- **Docker.** Confirmez que les conteneurs sont en cours d'exécution avec `docker compose ps`, puis lisez les journaux de l'API avec `docker compose logs api`. Sur un serveur configuré avec le guide [Docker on Linux](/docs/remote/docker_linux), la pile s'exécute à partir d'un fichier compose non par défaut, utilisez donc `sudo docker compose -f ./deploy-compose.yml ps` et `sudo docker compose -f ./deploy-compose.yml logs api`. Plus d'informations dans [Docker troubleshooting](/docs/local/docker#troubleshooting).
- **npm.** LibreChat s'exécute dans le terminal où vous avez lancé `npm run backend`, consultez donc la sortie de ce terminal. Si le processus s'est arrêté, relancez-le et lisez l'erreur qu'il affiche.
- **[Helm](/docs/local/helm_chart) ou une autre installation Kubernetes.** Vérifiez que les pods sont en cours d'exécution avec `kubectl get pods -n <release-namespace>`, lisez les logs du pod API avec `kubectl logs -n <release-namespace> <pod>`, et confirmez que le service ou l'ingress expose réellement le port sur lequel vous naviguez. Les deux commandes utilisent votre namespace actuel par défaut, donc une liste vide signifie généralement que vous n'êtes pas dans le bon.
- **Railway ou un autre hébergeur.** Ouvrez les journaux de déploiement dans le tableau de bord du fournisseur (dans Railway, le bouton **View logs** sur le service), et accédez à l'URL publique que le fournisseur a attribuée plutôt qu'à `localhost`.

## Si aucun modèle ne répond [#if-no-model-answers]

- **L'endpoint lui-même est absent du sélecteur.** Trois paramètres distincts peuvent le masquer, vérifiez donc chacun d'entre eux. `ENDPOINTS` dans `.env` : lorsqu'il est défini, seuls les endpoints qui y sont nommés sont chargés. [Model specs](/docs/configuration/librechat_yaml/object_structure/model_specs) dans `librechat.yaml` : lorsqu'ils limitent le sélecteur, seules les spécifications que vous avez listées et tout ce qui se trouve dans `modelSpecs.addedEndpoints` sont accessibles. Et la clé propre au fournisseur : un endpoint basé sur une clé sans valeur configurée ne se chargera pas ; définissez donc sa clé (ou `user_provided`) là où votre installation conserve ses variables d'environnement, puis redémarrez en recréant les conteneurs avec `docker compose up -d` sur Docker. Un endpoint qui récupère ses identifiants depuis son environnement, comme [Bedrock](/docs/configuration/pre_configured_ai/bedrock) via la chaîne d'identifiants AWS par exemple, nécessite que sa région soit définie et qu'une chaîne fonctionnelle soit présente plutôt qu'une clé.
- **L'endpoint est présent, mais le modèle que vous souhaitez ne l'est pas.** La provenance de la liste détermine ce qu'il faut vérifier. Avec une clé `user_provided`, LibreChat ne peut pas demander au fournisseur quels modèles existent, il propose donc une liste intégrée : nommez les modèles que vous souhaitez avec la variable `_MODELS` du fournisseur, par exemple [`OPENAI_MODELS`](/docs/configuration/pre_configured_ai/openai). Avec une véritable clé côté serveur et `_MODELS` non défini, certains fournisseurs sont interrogés pour obtenir leur liste, donc une clé restreinte ou défaillante peut la raccourcir ; d'autres, dont [Google](/docs/configuration/pre_configured_ai/google), ne récupèrent jamais la liste et nécessitent que `_MODELS` soit défini, quelle que soit la clé. Consultez la page spécifique de ce fournisseur dans [Configuration de l'IA](/docs/configuration/pre_configured_ai) avant de modifier quoi que ce soit d'autre. Un [endpoint personnalisé](/docs/configuration/librechat_yaml/object_structure/custom_endpoint) tel qu'Ollama ou OpenRouter ignore totalement `_MODELS` : sa liste provient de `models.default` et `models.fetch` dans son propre bloc `librechat.yaml`. Et si votre `librechat.yaml` définit des [Model Specs](/docs/configuration/librechat_yaml/object_structure/model_specs), vous choisissez dans cette liste au lieu des modèles propres à l'endpoint.
- **La réponse échoue avec une erreur d'authentification ou de clé invalide.** La clé est incorrecte, expirée ou n'a pas accès au modèle sélectionné. Saisissez-la à nouveau dans la boîte de dialogue **Set API Key**, ou corrigez la valeur dans l'environnement de votre installation et redémarrez.
