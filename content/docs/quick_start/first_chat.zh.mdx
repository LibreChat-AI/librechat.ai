LibreChat 是您自行托管的软件，它本身不附带任何 API key。在您的实例运行后，请按照以下步骤从登录页面开始进行对话。

<Callout type="info" title="还没有运行任何内容？">

请先安装 LibreChat：参考 [快速开始](/docs/quick_start) 进行 5 分钟 Docker 部署，参考 [本地安装](/docs/local) 使用 Docker、npm 或 Helm，或参考 [远程托管](/docs/remote) 将其部署在服务器上。

在安装任何内容之前，如果您想尝试 LibreChat，该项目在 [chat.librechat.ai](https://chat.librechat.ai) 提供了一个免费的公共演示。它仅供评估使用，不适用于处理私有数据。

</Callout>

<Steps>
  <Step>

### 在浏览器中打开 LibreChat [#open-librechat-in-your-browser]

本地 Docker 或 npm 安装会将应用部署在 [http://localhost:3080](http://localhost:3080)。该端口由 `PORT` 决定。如果你更改了端口，或者在 `docker-compose.override.yml` 中映射了不同的主机端口，请使用该端口。

在其他任何地方，地址都是您的部署所提供的地址：Railway 分配的域名、您在 Hugging Face 上的 `username-projectname.hf.space` URL，或是您远程 Docker 或 Kubernetes 安装前端的服务器 IP 或域名。`DOMAIN_CLIENT` 是一个单独的设置，即 LibreChat 在其生成的链接中放入的地址，因此请将其指向该相同的公共 URL，而不是直接读取您浏览器中的地址。

如果没有任何内容加载，请参阅下方的 [If nothing loads](#if-nothing-loads)。

  </Step>
  <Step>

### 创建您的账户 [#create-your-account]

默认情况下启用电子邮件注册（`ALLOW_REGISTRATION=true`），且没有默认凭据：请点击 **Sign up** 并选择您自己的电子邮件和密码。

并非每个 LibreChat 实例都提供该表单。如果没有**注册 (Sign up)** 选项，请在显示的情况下使用提供商按钮，或者如果实例针对目录进行身份验证，则使用登录表单：两者都可能在首次登录时创建您的帐户。如果没有提供这些选项，或者因为您的帐户不存在而拒绝登录，请向该实例的管理员索取帐户。显示哪些控件由实例的 [authentication settings](/docs/configuration/authentication) 决定。

<Callout type="info" title="单租户部署中的第一个账户即为管理员">

在非作用域的单租户部署中，第一个注册的账户将成为管理员账户，后续的所有账户默认获得 `USER` 角色。租户作用域部署不会自动提升每个租户中的第一个用户；请通过受信任的管理流程（[Authentication](/docs/features/authentication)）来配置租户管理员。

OpenID 部署可以通过两种方式覆盖默认角色：`OPENID_ADMIN_ROLE` 将匹配的账户提升为管理员，而通用角色同步 (`OPENID_ROLE_SYNC_ENABLED`) 则将提供商的角色映射到其他非管理员角色。请参阅 [OpenID Connect](/docs/configuration/dotenv#openid-connect)。

</Callout>

如果您配置了 [OAuth2/OIDC](/docs/configuration/authentication/OAuth2-OIDC) 或 [SAML](/docs/configuration/authentication/SAML)，请使用该提供商的按钮，而不是使用表单。

[LDAP/AD](/docs/configuration/authentication/ldap) 不会添加任何按钮。请在相同的电子邮件和密码表单中登录；当服务器设置 `LDAP_LOGIN_USES_USERNAME=true` 时，请输入您的目录用户名以代替电子邮件。

  </Step>
  <Step>

### 为模型提供 API 密钥 [#give-a-model-an-api-key]

LibreChat 使用您的凭据与 AI 提供商进行通信，而 `.env.example` 中预配置的提供商被设置为 `user_provided`：

```bash filename=".env"
OPENAI_API_KEY=user_provided
ANTHROPIC_API_KEY=user_provided
GOOGLE_KEY=user_provided
```

使用该值后，每位用户都可以从 Web UI 提供自己的密钥：选择 endpoint，点击其旁边的齿轮图标，然后在 **Set API Key** 对话框中填入密钥。

该值仅在从 `.env.example` 开始安装（即 Docker 和 npm）时作为默认值。Helm 发行版、Railway 服务或 Hugging Face Space 仅包含您设置的变量，因此如果您从未设置某个 endpoint 的凭据，它将根本不会加载，也不会出现相应的密钥对话框。在期望用户提供自己的密钥之前，请先将该变量设置为 `user_provided`，并重启工作负载，以便正在运行的 pod 或容器能够获取该设置。同样的对话框也可以通过 **Settings → Data & Privacy → API keys** 访问，这也是稍后查看和轮换密钥的地方。

如果您没有看到 endpoint 下拉菜单和齿轮图标，说明该实例通过 [model specs](/docs/configuration/librechat_yaml/object_structure/model_specs) 或其 `interface` 设置隐藏了选择器。请从 **Settings → Data & Privacy → API keys** 设置您的第一个密钥，该页面列出了配置为接受用户提供密钥的 endpoint。

若要改为统一为所有人配置一个密钥，请将 `user_provided` 替换为真实的密钥并重启 LibreChat。在 Docker 上，请使用 `docker compose up -d` 重新创建容器（如果您的堆栈运行于该文件，请添加 `-f ./deploy-compose.yml`）：`docker compose restart` 会保留容器已有的环境变量，因此旧值依然存在。系统不会提示用户，且密钥将保留在服务器上。设置位置取决于您的安装方式：Docker 和 npm 使用 `.env`，[Helm](/docs/local/helm_chart#configuration) 使用 Kubernetes Secret，Railway 仪表板使用服务变量，[Hugging Face](/docs/remote/huggingface) 使用 Space Secrets。各提供商的具体步骤请参阅 [AI Setup](/docs/configuration/pre_configured_ai)。

<Callout type="warn" title="公共 URL 上的共享密钥任何人都可以使用">

注册功能默认是开启的，因此在互联网可访问的实例上，任何找到该 URL 的人都可以注册并使用您的密钥进行计费。在公共部署中配置服务器端密钥之前，请确保您不希望访问的人无法获得账户。电子邮件表单、每个提供商按钮以及您进行身份验证的任何目录都会根据各自的条款创建用户，因此关闭其中一个并不能关闭所有入口；[Authentication](/docs/configuration/authentication) 涵盖了每个选项背后的设置。将提供商保留为 `user_provided` 可以完全避免此问题。

</Callout>

<Callout type="info" title="没有付费 API key？">

通过 [Ollama](/docs/configuration/librechat_yaml/ai_endpoints/ollama) 在您自己的硬件上运行模型，或通过 [OpenRouter](/docs/configuration/librechat_yaml/ai_endpoints/openrouter) 等网关连接众多提供商。两者均可作为 [自定义端点](/docs/quick_start/custom_endpoints) 添加。

</Callout>

  </Step>
  <Step>

### 发送您的第一条消息 [#send-your-first-message]

从聊天界面顶部的选择器中选择一个 endpoint 和模型，输入您的提示词并发送。如果实例隐藏了选择器，则说明系统已为您选好：直接输入并发送即可。回复会以流式传输显示，对话也会自动保存，以便您随时从侧边栏返回查看。

  </Step>
</Steps>

## 如果没有任何内容加载 [#if-nothing-loads]

如果页面从未出现，则说明安装存在问题，具体的检查方法取决于您的安装方式：

- **Docker.** 使用 `docker compose ps` 确认容器正在运行，然后使用 `docker compose logs api` 读取 API 日志。在按照 [Docker on Linux](/docs/remote/docker_linux) 指南设置的服务器上，堆栈是从非默认的 compose 文件运行的，因此请使用 `sudo docker compose -f ./deploy-compose.yml ps` 和 `sudo docker compose -f ./deploy-compose.yml logs api`。更多信息请参阅 [Docker troubleshooting](/docs/local/docker#troubleshooting)。
- **npm.** LibreChat 在你运行 `npm run backend` 的终端中运行，因此请查看该终端的输出。如果进程已退出，请重新启动它并查看其打印的错误信息。
- **[Helm](/docs/local/helm_chart) 或其他 Kubernetes 安装。** 请使用 `kubectl get pods -n <release-namespace>` 检查 Pod 是否正在运行，使用 `kubectl logs -n <release-namespace> <pod>` 读取 API Pod 的日志，并确认 Service 或 Ingress 确实暴露了您正在访问的端口。这两个命令默认使用您当前的命名空间，因此如果列表为空，通常意味着命名空间不正确。
- **Railway 或其他主机。** 在提供商的仪表板中打开部署日志（在 Railway 中，即服务上的 **View logs** 按钮），并浏览提供商分配的公共 URL，而不是 `localhost`。

## 如果没有模型回答 [#if-no-model-answers]

- **选择器中缺少该 endpoint 本身。** 有三个独立的设置可能会将其隐藏，请逐一检查。`.env` 中的 `ENDPOINTS`：当设置此项时，只有其中命名的 endpoint 才会加载。`librechat.yaml` 中的 [Model specs](/docs/configuration/librechat_yaml/object_structure/model_specs)：它们会限制选择器，只有你列出的 specs 以及 `modelSpecs.addedEndpoints` 中的任何内容才是可访问的。以及提供商自身的密钥：未配置值的基于密钥的 endpoint 不会加载，因此请在你安装环境的存储位置设置其密钥（或 `user_provided`），然后重启，并在 Docker 上使用 `docker compose up -d` 重新创建容器。对于从其环境获取凭据的 endpoint（例如来自 AWS 凭据链的 [Bedrock](/docs/configuration/pre_configured_ai/bedrock)），则需要设置其区域并确保凭据链正常工作，而不是使用密钥。
- **Endpoint 存在，但你想要的模型不在列表中。** 列表的来源决定了需要检查的内容。对于 `user_provided` 密钥，LibreChat 无法向提供商查询存在哪些模型，因此它提供了一个内置列表：你需要使用提供商的 `_MODELS` 变量来指定你想要使用的模型，例如 [`OPENAI_MODELS`](/docs/configuration/pre_configured_ai/openai)。对于真实的服务器端密钥，如果未设置 `_MODELS`，系统会向部分提供商请求其模型列表，因此受限或失效的密钥可能会导致列表缩短；而其他提供商（包括 [Google](/docs/configuration/pre_configured_ai/google)）则从不主动获取列表，无论密钥如何，都需要设置 `_MODELS`。在进行任何其他更改之前，请先查看 [AI 设置](/docs/configuration/pre_configured_ai) 中该提供商对应的页面。像 Ollama 或 OpenRouter 这样的 [自定义 endpoint](/docs/configuration/librechat_yaml/object_structure/custom_endpoint) 会完全忽略 `_MODELS`：其列表来源于 `librechat.yaml` 中对应配置块里的 `models.default` 和 `models.fetch`。此外，如果你的 `librechat.yaml` 定义了 [Model Specs](/docs/configuration/librechat_yaml/object_structure/model_specs)，你将从该列表中进行选择，而不是从 endpoint 自身的模型列表中选择。
- **回复因身份验证或密钥无效错误而失败。** 密钥错误、已过期或无权访问所选模型。请在 **Set API Key** 对话框中重新输入，或在安装环境的配置中修复该值并重启。
