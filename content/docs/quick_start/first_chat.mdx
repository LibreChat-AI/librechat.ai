title: Your First Chat
icon: MessageSquare
description: Open a running LibreChat instance, create your account, add a model API key, and send your first message.

LibreChat is software you host yourself, and it ships with no API key of its own. Once your instance is running, these steps take you from the login page to a working conversation.

<Callout type="info" title="Nothing running yet?">

Install LibreChat first: [Quick Start](/docs/quick_start) for the 5-minute Docker path, [Local Installation](/docs/local) for Docker, npm, or Helm, or [Remote Hosting](/docs/remote) to deploy it on a server.

To try LibreChat before installing anything, the project runs a free public demo at [chat.librechat.ai](https://chat.librechat.ai). It is meant for evaluation, not for private data.

</Callout>

<Steps>
  <Step>

### Open LibreChat in your browser

A local Docker or npm install serves the app at [http://localhost:3080](http://localhost:3080). The port comes from `PORT` in your `.env`. If you changed it, or mapped a different host port in `docker-compose.override.yml`, use that one instead.

For a deployed instance, use the public URL you configured as `DOMAIN_CLIENT`.

If nothing loads, see [If nothing loads](#if-nothing-loads) below.

  </Step>
  <Step>

### Create your account

Email registration is enabled by default (`ALLOW_REGISTRATION=true`), and there are no default credentials: click **Sign up** and choose your own email and password.

<Callout type="info" title="First Account = Admin in Single-Tenant Deployments">

In an unscoped single-tenant deployment, the first account registered becomes the admin account, and every account after it gets the `USER` role by default. Tenant-scoped deployments do not auto-promote the first user in each tenant; provision tenant administrators through a trusted administrative flow ([Authentication](/docs/features/authentication)).

An OpenID deployment can override the default role either way: `OPENID_ADMIN_ROLE` elevates a matching account to admin, and generic role sync (`OPENID_ROLE_SYNC_ENABLED`) maps provider roles onto other non-admin roles. See [OpenID Connect](/docs/configuration/dotenv#openid-connect).

</Callout>

If you configured [OAuth2/OIDC](/docs/configuration/authentication/OAuth2-OIDC) or [SAML](/docs/configuration/authentication/SAML), use that provider's button instead of the form.

[LDAP/AD](/docs/configuration/authentication/ldap) adds no button. Sign in on the same email and password form, entering your directory username in place of the email when the server sets `LDAP_LOGIN_USES_USERNAME=true`.

  </Step>
  <Step>

### Give a model an API key

LibreChat talks to AI providers with your credentials, and `.env.example` ships the pre-configured providers as `user_provided`:

```bash filename=".env"
OPENAI_API_KEY=user_provided
ANTHROPIC_API_KEY=user_provided
GOOGLE_KEY=user_provided
```

With that default, every user supplies their own key from the web UI: select the endpoint, open the gear icon next to it, and fill in the **Set API Key** dialog. Keys can be reviewed or rotated later under **Settings → Data controls → API keys**.

To configure a key once for everyone instead, replace `user_provided` with the real key in `.env` and restart LibreChat. No user is prompted, and the key stays on the server. Provider-by-provider steps live in [AI Setup](/docs/configuration/pre_configured_ai).

<Callout type="info" title="No paid API key?">

Run a model on your own hardware with [Ollama](/docs/configuration/librechat_yaml/ai_endpoints/ollama), or reach many providers through a gateway such as [OpenRouter](/docs/configuration/librechat_yaml/ai_endpoints/openrouter). Both are added as [custom endpoints](/docs/quick_start/custom_endpoints).

</Callout>

  </Step>
  <Step>

### Send your first message

Pick an endpoint and model from the selector at the top of the chat, type your prompt, and send it. The reply streams in, and the conversation is saved so you can return to it from the sidebar.

  </Step>
</Steps>

## If nothing loads

A page that never appears is an install problem, and the check depends on how you installed:

- **Docker.** Confirm the containers are running with `docker compose ps`, then read the API logs with `docker compose logs api`. More in [Docker troubleshooting](/docs/local/docker#troubleshooting).
- **npm.** LibreChat runs in the terminal where you started `npm run backend`, so read that terminal's output. If the process has exited, start it again and read the error it prints.
- **[Helm](/docs/local/helm_chart) or another Kubernetes install.** Check that the pods are running with `kubectl get pods`, read the API pod with `kubectl logs <pod>`, and confirm the service or ingress actually exposes the port you are browsing to.
- **Railway or another host.** Open the deployment logs in the provider's dashboard (in Railway, the **View logs** button on the service), and browse to the public URL the provider assigned rather than `localhost`.

## If no model answers

- **The endpoint itself is missing from the selector.** Three separate settings can hide it, so check each. `ENDPOINTS` in `.env`: when it is set, only the endpoints named there load at all. [Model specs](/docs/configuration/librechat_yaml/object_structure/model_specs) in `librechat.yaml`: defining them hides the endpoint dropdown altogether unless `interface.modelSelect` is set to `true`, leaving only the specs you listed. And the provider's own key: an endpoint with no value configured does not load, so set its key in `.env` (or to `user_provided`) and restart.
- **The endpoint is there, but the model you want is not.** The key is not the problem; the list LibreChat can offer is. With a `user_provided` key, LibreChat cannot ask the provider which models exist, so it offers a built-in list. Name the models you want with the provider's `_MODELS` variable, for example [`OPENAI_MODELS`](/docs/configuration/pre_configured_ai/openai). If your `librechat.yaml` defines [model specs](/docs/configuration/librechat_yaml/object_structure/model_specs), you pick from that list instead of the endpoint's own models.
- **The reply fails with an authentication or invalid-key error.** The key is wrong, expired, or has no access to the selected model. Re-enter it in the **Set API Key** dialog, or fix the value in `.env` and restart.
