LibreChat adalah perangkat lunak yang Anda host sendiri, dan tidak disertai dengan API key bawaan. Setelah instance Anda berjalan, langkah-langkah ini akan memandu Anda dari halaman login hingga ke percakapan yang berfungsi.

<Callout type="info" title="Belum ada yang berjalan?">

Instal LibreChat terlebih dahulu: [Quick Start](/docs/quick_start) untuk jalur Docker 5 menit, [Local Installation](/docs/local) untuk Docker, npm, atau Helm, atau [Remote Hosting](/docs/remote) untuk men-deploy-nya di server.

Untuk mencoba LibreChat sebelum menginstal apa pun, proyek ini menjalankan demo publik gratis di [chat.librechat.ai](https://chat.librechat.ai). Demo ini ditujukan untuk evaluasi, bukan untuk data pribadi.

</Callout>

<Steps>
  <Step>

### Buka LibreChat di browser Anda [#open-librechat-in-your-browser]

Instalasi Docker atau npm lokal menyajikan aplikasi di [http://localhost:3080](http://localhost:3080). Port tersebut berasal dari `PORT`. Jika Anda mengubahnya, atau memetakan port host yang berbeda di `docker-compose.override.yml`, gunakan port tersebut sebagai gantinya.

Di tempat lain, alamatnya adalah alamat yang diberikan oleh penyebaran Anda: domain yang ditetapkan oleh Railway, URL `username-projectname.hf.space` Anda di Hugging Face, atau IP server atau domain di depan instalasi Docker atau Kubernetes jarak jauh Anda. `DOMAIN_CLIENT` adalah pengaturan terpisah, yaitu alamat yang dimasukkan LibreChat ke dalam tautan yang dihasilkannya, jadi arahkan pengaturan tersebut ke URL publik yang sama alih-alih membaca alamat peramban Anda darinya.

Jika tidak ada yang dimuat, lihat [If nothing loads](#if-nothing-loads) di bawah.

  </Step>
  <Step>

### Buat akun Anda [#create-your-account]

Pendaftaran email diaktifkan secara default (`ALLOW_REGISTRATION=true`), dan tidak ada kredensial default: klik **Sign up** dan pilih email serta kata sandi Anda sendiri.

Tidak semua instance menawarkan formulir tersebut. Jika tidak ada **Sign up**, gunakan tombol penyedia jika ditampilkan, atau formulir login jika instance melakukan autentikasi terhadap direktori: keduanya dapat membuat akun Anda saat pertama kali masuk. Jika tidak ada yang ditawarkan, atau saat masuk ditolak karena akun Anda tidak ada, mintalah kepada pengelola instance tersebut. Kontrol mana yang muncul ditentukan oleh [authentication settings](/docs/configuration/authentication) pada instance tersebut.

<Callout type="info" title="Akun Pertama = Admin dalam Deployment Single-Tenant">

Dalam penyebaran *single-tenant* tanpa cakupan (*unscoped*), akun pertama yang didaftarkan menjadi akun admin, dan setiap akun setelahnya mendapatkan peran `USER` secara *default*. Penyebaran dengan cakupan *tenant* (*tenant-scoped*) tidak secara otomatis mempromosikan pengguna pertama di setiap *tenant*; sediakan administrator *tenant* melalui alur administratif tepercaya ([Authentication](/docs/features/authentication)).

Penyebaran OpenID dapat mengganti peran default ke kedua arah: `OPENID_ADMIN_ROLE` meningkatkan akun yang cocok menjadi admin, dan sinkronisasi peran generik (`OPENID_ROLE_SYNC_ENABLED`) memetakan peran penyedia ke peran non-admin lainnya. Lihat [OpenID Connect](/docs/configuration/dotenv#openid-connect).

</Callout>

Jika Anda telah mengonfigurasi [OAuth2/OIDC](/docs/configuration/authentication/OAuth2-OIDC) atau [SAML](/docs/configuration/authentication/SAML), gunakan tombol penyedia tersebut alih-alih formulir.

[LDAP/AD](/docs/configuration/authentication/ldap) tidak menambahkan tombol apa pun. Masuklah pada formulir email dan kata sandi yang sama, dengan memasukkan nama pengguna direktori Anda sebagai pengganti email saat server menetapkan `LDAP_LOGIN_USES_USERNAME=true`.

  </Step>
  <Step>

### Berikan kunci API ke model [#give-a-model-an-api-key]

LibreChat berkomunikasi dengan penyedia AI menggunakan kredensial Anda, dan `.env.example` menyertakan penyedia yang telah dikonfigurasi sebelumnya sebagai `user_provided`:

```bash filename=".env"
OPENAI_API_KEY=user_provided
ANTHROPIC_API_KEY=user_provided
GOOGLE_KEY=user_provided
```

Dengan nilai tersebut, setiap pengguna memberikan kunci mereka sendiri dari UI web: pilih endpoint, buka ikon roda gigi di sebelahnya, dan isi dialog **Set API Key**.

Nilai tersebut hanyalah default jika instalasi dimulai dari `.env.example`, yang berarti Docker dan npm. Rilis Helm, layanan Railway, atau Hugging Face Space hanya membawa variabel yang Anda tetapkan, sehingga endpoint yang kredensialnya tidak pernah Anda atur tidak akan dimuat sama sekali, dan dialog kunci tidak akan muncul untuknya. Tetapkan variabel ke `user_provided` di sana sebelum mengharapkan pengguna untuk membawa kunci mereka sendiri, dan lakukan *roll* pada beban kerja agar pod atau kontainer yang berjalan dapat mengambilnya. Dialog yang sama dapat diakses dari **Settings → Data & Privacy → API keys**, yang juga merupakan tempat kunci ditinjau dan dirotasi nantinya.

Jika Anda tidak melihat menu tarik-turun endpoint dan ikon roda gigi, instans ini menyembunyikan pemilih tersebut, melalui [model specs](/docs/configuration/librechat_yaml/object_structure/model_specs) atau pengaturan `interface`-nya. Atur kunci pertama Anda dari **Settings → Data & Privacy → API keys**, yang mencantumkan endpoint yang dikonfigurasi untuk menerima kunci yang disediakan pengguna.

Untuk mengonfigurasi kunci sekali saja bagi semua orang, atur kunci yang sebenarnya sebagai pengganti `user_provided` dan mulai ulang LibreChat. Pada Docker, buat ulang kontainer dengan `docker compose up -d`, tambahkan `-f ./deploy-compose.yml` jika itu adalah file yang dijalankan oleh stack Anda: `docker compose restart` akan mempertahankan lingkungan yang sudah dimiliki kontainer, sehingga nilai lama tetap ada. Tidak ada pengguna yang diminta memasukkan kunci, dan kunci tersebut tetap berada di server. Di mana Anda mengaturnya bergantung pada cara Anda menginstal: `.env` untuk Docker dan npm, Kubernetes Secret untuk [Helm](/docs/local/helm_chart#configuration), variabel layanan di dasbor Railway, atau Space Secrets di [Hugging Face](/docs/remote/huggingface). Langkah-langkah per penyedia tersedia di [AI Setup](/docs/configuration/pre_configured_ai).

<Callout type="warn" title="Kunci bersama pada URL publik dapat digunakan oleh siapa saja">

Pendaftaran terbuka secara default, jadi pada instance yang dapat diakses dari internet, siapa pun yang menemukan URL tersebut dapat mendaftar dan menggunakan kunci Anda. Sebelum Anda mengonfigurasi kunci sisi server pada deployment publik, pastikan tidak ada orang yang tidak Anda inginkan yang dapat membuat akun. Formulir email, setiap tombol penyedia, dan direktori apa pun yang Anda gunakan untuk autentikasi semuanya membuat pengguna dengan ketentuan mereka masing-masing, jadi menutup satu metode tidak berarti menutup semuanya; [Authentication](/docs/configuration/authentication) membahas pengaturan di balik masing-masing metode tersebut. Membiarkan penyedia tetap pada `user_provided` akan menghindari masalah ini sepenuhnya.

</Callout>

<Callout type="info" title="Tidak punya kunci API berbayar?">

Jalankan model pada perangkat keras Anda sendiri dengan [Ollama](/docs/configuration/librechat_yaml/ai_endpoints/ollama), atau jangkau banyak penyedia melalui gateway seperti [OpenRouter](/docs/configuration/librechat_yaml/ai_endpoints/openrouter). Keduanya ditambahkan sebagai [custom endpoints](/docs/quick_start/custom_endpoints).

</Callout>

  </Step>
  <Step>

### Kirim pesan pertama Anda [#send-your-first-message]

Pilih endpoint dan model dari pemilih di bagian atas obrolan, ketik prompt Anda, lalu kirim. Jika instance menyembunyikan pemilih tersebut, berarti sistem telah memilihnya untuk Anda: cukup ketik dan kirim. Balasan akan muncul secara streaming, dan percakapan akan disimpan sehingga Anda dapat kembali membukanya dari bilah sisi.

  </Step>
</Steps>

## Jika tidak ada yang dimuat [#if-nothing-loads]

Halaman yang tidak pernah muncul adalah masalah instalasi, dan pemeriksaannya bergantung pada bagaimana Anda melakukan instalasi:

- **Docker.** Pastikan kontainer sedang berjalan dengan `docker compose ps`, kemudian baca log API dengan `docker compose logs api`. Pada server yang disiapkan dengan panduan [Docker on Linux](/docs/remote/docker_linux), stack berjalan dari file compose non-default, jadi gunakan `sudo docker compose -f ./deploy-compose.yml ps` dan `sudo docker compose -f ./deploy-compose.yml logs api`. Selengkapnya di [Docker troubleshooting](/docs/local/docker#troubleshooting).
- **npm.** LibreChat berjalan di terminal tempat Anda menjalankan `npm run backend`, jadi bacalah output terminal tersebut. Jika proses telah keluar, jalankan kembali dan baca pesan kesalahan yang dicetaknya.
- **[Helm](/docs/local/helm_chart) atau instalasi Kubernetes lainnya.** Periksa apakah pod sedang berjalan dengan `kubectl get pods -n <release-namespace>`, baca pod API dengan `kubectl logs -n <release-namespace> <pod>`, dan pastikan service atau ingress benar-benar mengekspos port yang sedang Anda akses. Kedua perintah tersebut secara default menggunakan namespace Anda saat ini, jadi daftar yang kosong biasanya berarti Anda berada di namespace yang salah.
- **Railway atau host lainnya.** Buka log deployment di dasbor penyedia (di Railway, tombol **View logs** pada layanan tersebut), dan buka URL publik yang ditetapkan oleh penyedia alih-alih `localhost`.

## Jika tidak ada model yang menjawab [#if-no-model-answers]

- **Endpoint itu sendiri tidak ada di pemilih.** Tiga pengaturan terpisah dapat menyembunyikannya, jadi periksa masing-masing. `ENDPOINTS` di `.env`: saat diatur, hanya endpoint yang disebutkan di sana yang akan dimuat. [Model specs](/docs/configuration/librechat_yaml/object_structure/model_specs) di `librechat.yaml`: di mana mereka membatasi pemilih, hanya spesifikasi yang Anda cantumkan dan apa pun di `modelSpecs.addedEndpoints` yang dapat dijangkau. Dan kunci penyedia itu sendiri: endpoint berbasis kunci tanpa nilai yang dikonfigurasi tidak akan dimuat, jadi atur kuncinya (atau `user_provided`) di mana pun instalasi Anda menyimpan lingkungannya, lalu mulai ulang, buat ulang kontainer dengan `docker compose up -d` di Docker. Endpoint yang mengambil kredensial dari lingkungannya, contohnya [Bedrock](/docs/configuration/pre_configured_ai/bedrock) dari rantai kredensial AWS, memerlukan wilayahnya diatur dan rantai yang berfungsi alih-alih kunci.
- **Endpoint tersedia, tetapi model yang Anda inginkan tidak.** Dari mana daftar tersebut berasal menentukan apa yang perlu diperiksa. Dengan kunci `user_provided`, LibreChat tidak dapat menanyakan kepada penyedia model apa saja yang tersedia, sehingga LibreChat menawarkan daftar bawaan: sebutkan model yang Anda inginkan dengan variabel `_MODELS` milik penyedia tersebut, contohnya [`OPENAI_MODELS`](/docs/configuration/pre_configured_ai/openai). Dengan kunci sisi server yang asli dan `_MODELS` dibiarkan tidak diatur, beberapa penyedia akan dimintai daftarnya, sehingga kunci yang dibatasi atau gagal dapat memperpendek daftar tersebut; penyedia lain, termasuk [Google](/docs/configuration/pre_configured_ai/google), tidak pernah mengambil data dan memerlukan `_MODELS` untuk diatur apa pun kuncinya. Periksa halaman penyedia tersebut di [AI Setup](/docs/configuration/pre_configured_ai) sebelum mengubah hal lainnya. [Custom endpoint](/docs/configuration/librechat_yaml/object_structure/custom_endpoint) seperti Ollama atau OpenRouter mengabaikan `_MODELS` sepenuhnya: daftarnya berasal dari `models.default` dan `models.fetch` di dalam blok `librechat.yaml`-nya sendiri. Dan jika `librechat.yaml` Anda mendefinisikan [Model Specs](/docs/configuration/librechat_yaml/object_structure/model_specs), Anda memilih dari daftar tersebut alih-alih model milik endpoint itu sendiri.
- **Balasan gagal dengan kesalahan autentikasi atau kunci tidak valid.** Kunci tersebut salah, kedaluwarsa, atau tidak memiliki akses ke model yang dipilih. Masukkan kembali kunci tersebut di dialog **Set API Key**, atau perbaiki nilainya di lingkungan instalasi Anda dan mulai ulang.
