LibreChatは、ヘルスエンドポイントを含むすべてのレスポンスに対して、ベースラインとなる一連のHTTPセキュリティヘッダーを送信します。nonceベースのContent Security Policy (CSP) は別途利用可能ですが、既存の統合環境で適用前に監査を行えるよう、デフォルトでは無効になっています。

## ベースラインヘッダー [#baseline-headers]

`SECURITY_HEADERS=false` に設定されていない限り、ベースラインヘッダーは有効になります。この変数はグローバルなキルスイッチであり、ベースラインヘッダーとCSPの両方を無効にします。

| 変数 | デフォルト | 動作 |
| --- | --- | --- |
| `SECURITY_HEADERS` | `true` | すべてのベースラインヘッダーを有効にします。`false` にすると CSP も無効になります。 |
| `HSTS_ENABLED` | `true` | `Strict-Transport-Security` を送信します。ブラウザは HTTPS 通信時のみこれを尊重します。 |
| `HSTS_MAX_AGE` | `31536000` | HSTS の有効期間（秒単位）。負ではない整数である必要があります。 |
| `HSTS_INCLUDE_SUBDOMAINS` | `false` | すべてのサブドメインに HSTS を適用します。すべてのサブドメインで HTTPS を使用している場合のみ有効にしてください。 |
| `HSTS_PRELOAD` | `false` | HSTS の `preload` トークンを追加します。 |
| `X_FRAME_OPTIONS` | `SAMEORIGIN` | `SAMEORIGIN`、`DENY`、または `off` を受け入れます。 |
| `REFERRER_POLICY` | `no-referrer` | `Referrer-Policy` を設定します。省略する場合は `off` を使用してください。 |
| `CROSS_ORIGIN_OPENER_POLICY` | `same-origin` | `Cross-Origin-Opener-Policy` を設定します。省略する場合は `off` を使用してください。 |
| `CROSS_ORIGIN_RESOURCE_POLICY` | `same-origin` | `Cross-Origin-Resource-Policy` を設定します。省略する場合は `off` を使用してください。 |

Helmet は `X-Content-Type-Options: nosniff` も送信します。無効な値はログに記録され、ドキュメント化されたデフォルト値にフォールバックされます。

許可されるopenerポリシーは `same-origin`、`same-origin-allow-popups`、`noopener-allow-popups`、および `unsafe-none` です。許可されるリソースポリシーは `same-origin`、`same-site`、および `cross-origin` です。許可されるリファラーポリシーは `no-referrer`、`no-referrer-when-downgrade`、`same-origin`、`origin`、`strict-origin`、`origin-when-cross-origin`、`strict-origin-when-cross-origin`、および `unsafe-url` です。

```bash filename=".env"
SECURITY_HEADERS=true
HSTS_ENABLED=true
HSTS_MAX_AGE=31536000
HSTS_INCLUDE_SUBDOMAINS=false
HSTS_PRELOAD=false
X_FRAME_OPTIONS=SAMEORIGIN
REFERRER_POLICY=no-referrer
CROSS_ORIGIN_OPENER_POLICY=same-origin
CROSS_ORIGIN_RESOURCE_POLICY=same-origin
```

アップストリームプロキシもこれらのヘッダーを書き込む場合は、1つの信頼できるポリシーを維持し、ブラウザが受け取る最終的なレスポンスを確認してください。

## Content Security Policy [#content-security-policy]

CSPはオプトイン方式です。LibreChatはSPAのレスポンスごとに新しいnonceを生成し、シェル内の実行可能なスクリプトおよびmodule-preloadリンクに適用します。

<Callout type="warning" title="レポートのみモードで開始">
  `CSP_REPORT_ONLY=true` でCSPを有効にし、実際のデプロイ環境から違反を収集し、必要なソースのみを追加した上で、アプリ、認証、ストレージ、テレメトリ、および埋め込みコンテンツのフローがクリーンであることを確認してから適用してください。
</Callout>

```bash filename=".env"
CSP_ENABLED=true
CSP_REPORT_ONLY=true
CSP_REPORT_URI=https://reports.example.com/csp

# Examples for deployment-specific services
CSP_CONNECT_SRC_EXTRA="https://telemetry.example.com wss://stream.example.com"
CSP_FRAME_SRC_EXTRA=https://tenant.sharepoint.com
CSP_IMG_SRC_EXTRA=https://cdn.example.com
```

`CSP_REPORT_ONLY` defaults to `true`. Only a recognized false value switches to enforcement; an unrecognized value is logged and remains report-only. While CSP is enabled, LibreChat forces the SPA shell to `Cache-Control: no-store` and ignores `INDEX_CACHE_CONTROL`, `INDEX_PRAGMA`, and `INDEX_EXPIRES` for that response so a nonce cannot be reused from cache.

### CSP 変数 [#csp-variables]

| 変数 | デフォルト | 動作 |
| --- | --- | --- |
| `CSP_ENABLED` | `false` | SPAシェルに対してnonceベースのCSPを有効にします。 |
| `CSP_REPORT_ONLY` | `true` | `Content-Security-Policy-Report-Only`を送信します。強制するには`false`に設定してください。 |
| `CSP_REPORT_URI` | 空 | レガシーな`report-uri`ディレクティブを追加します。 |
| `CSP_ALLOW_WASM` | `true` | HEIC変換で使用されるWebAssemblyのコンパイルを許可します。 |
| `CSP_ALLOW_DATA_WORKERS` | `true` | Monacoのローダーで使用される`data:`ワーカーを許可します。 |
| `CSP_FRAME_ANCESTORS` | `'self'` | `frame-ancestors`のソースリスト全体を置き換えます。 |
| `CSP_ADDITIONAL_DIRECTIVES` | 空 | セミコロンで区切られた生のディレクティブを追加します。 |

これらの変数は、対応する組み込みディレクティブにソースを追加します。

- `CSP_DEFAULT_SRC_EXTRA`
- `CSP_SCRIPT_SRC_EXTRA`
- `CSP_STYLE_SRC_EXTRA`
- `CSP_IMG_SRC_EXTRA`
- `CSP_FONT_SRC_EXTRA`
- `CSP_CONNECT_SRC_EXTRA`
- `CSP_MEDIA_SRC_EXTRA`
- `CSP_FRAME_SRC_EXTRA`
- `CSP_WORKER_SRC_EXTRA`
- `CSP_FORM_ACTION_EXTRA`

ソースリストは、カンマまたはスペースで区切ることができます。これらはLibreChatのデフォルトを置き換えるのではなく、追加します。`CSP_FRAME_ANCESTORS` は例外であり、デフォルトの `'self'` 値を意図的に置き換えます。

デフォルトのスクリプトポリシーでは `'strict-dynamic'` が使用されます。`CSP_SCRIPT_SRC_EXTRA` を設定すると `'strict-dynamic'` が削除され、リストされたスクリプトホストが有効になります。LibreChat でコードを実行することを信頼できるオリジンのみをリストしてください。

もし他のオリジンがLibreChatをフレーム内に埋め込む必要がある場合は、`X-Frame-Options`を削除する前に`frame-ancestors`を適用してください：

```bash filename=".env"
CSP_ENABLED=true
CSP_REPORT_ONLY=false
X_FRAME_OPTIONS=off
CSP_FRAME_ANCESTORS="'self' https://portal.example.com"
```

CSPが無効またはレポート専用（report-only）の状態では、`X_FRAME_OPTIONS=off` を設定しないでください。レポート専用ポリシーは違反を記録するだけでフレーミングを制限しないため、先に `X-Frame-Options` を削除すると、あらゆるオリジンがデプロイメントをフレーム内に埋め込めるようになってしまいます。`frame-ancestors` をサポートしていないブラウザでは、このクロスオリジン設定においてフレーミング制限が適用されません。

これらの設定が `.env` のどこにあるかについては、[環境変数リファレンス](/docs/configuration/dotenv#security-headers-and-content-security-policy)を参照してください。
