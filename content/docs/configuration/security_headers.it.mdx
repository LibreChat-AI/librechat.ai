LibreChat invia un set di base di intestazioni di sicurezza HTTP su ogni risposta, inclusi gli endpoint di integrità. Una Content Security Policy (CSP) basata su nonce è disponibile separatamente ed è disabilitata per impostazione predefinita, in modo che le integrazioni esistenti possano essere verificate prima dell'applicazione.

## Intestazioni di base [#baseline-headers]

Gli header di base sono abilitati a meno che `SECURITY_HEADERS=false`. Tale variabile è l'interruttore globale: disabilita sia gli header di base che la CSP.

| Variabile | Predefinito | Comportamento |
| --- | --- | --- |
| `SECURITY_HEADERS` | `true` | Abilita tutte le intestazioni di base. `false` disabilita anche la CSP. |
| `HSTS_ENABLED` | `true` | Invia `Strict-Transport-Security`. I browser lo rispettano solo su HTTPS. |
| `HSTS_MAX_AGE` | `31536000` | Durata HSTS in secondi. Deve essere un numero intero non negativo. |
| `HSTS_INCLUDE_SUBDOMAINS` | `false` | Applica HSTS a ogni sottodominio. Abilitare solo quando tutti i sottodomini utilizzano HTTPS. |
| `HSTS_PRELOAD` | `false` | Aggiunge il token `preload` HSTS. |
| `X_FRAME_OPTIONS` | `SAMEORIGIN` | Accetta `SAMEORIGIN`, `DENY` o `off`. |
| `REFERRER_POLICY` | `no-referrer` | Imposta `Referrer-Policy`; utilizzare `off` per ometterla. |
| `CROSS_ORIGIN_OPENER_POLICY` | `same-origin` | Imposta `Cross-Origin-Opener-Policy`; utilizzare `off` per ometterla. |
| `CROSS_ORIGIN_RESOURCE_POLICY` | `same-origin` | Imposta `Cross-Origin-Resource-Policy`; utilizzare `off` per ometterla. |

Helmet invia anche `X-Content-Type-Options: nosniff`. I valori non validi vengono registrati e il sistema ripristina i valori predefiniti documentati.

Le policy di apertura accettate sono `same-origin`, `same-origin-allow-popups`, `noopener-allow-popups` e `unsafe-none`. Le policy delle risorse accettate sono `same-origin`, `same-site` e `cross-origin`. Le policy del referrer accettate sono `no-referrer`, `no-referrer-when-downgrade`, `same-origin`, `origin`, `strict-origin`, `origin-when-cross-origin`, `strict-origin-when-cross-origin` e `unsafe-url`.

```bash filename=".env"
SECURITY_HEADERS=true
HSTS_ENABLED=true
HSTS_MAX_AGE=31536000
HSTS_INCLUDE_SUBDOMAINS=false
HSTS_PRELOAD=false
X_FRAME_OPTIONS=SAMEORIGIN
REFERRER_POLICY=no-referrer
CROSS_ORIGIN_OPENER_POLICY=same-origin
CROSS_ORIGIN_RESOURCE_POLICY=same-origin
```

Se un proxy upstream scrive anch'esso queste intestazioni, mantieni una policy autorevole e verifica la risposta finale visualizzata dal browser.

## Content Security Policy [#content-security-policy]

CSP è opzionale (opt-in). LibreChat crea un nuovo nonce per ogni risposta SPA e lo applica agli script eseguibili e ai link di module-preload nella shell.

<Callout type="warning" title="Avvia in modalità solo report">
  Abilita CSP con `CSP_REPORT_ONLY=true`, raccogli le violazioni dal tuo deployment reale, aggiungi solo le fonti necessarie e applica l'imposizione solo dopo che i flussi dell'app, dell'autenticazione, dell'archiviazione, della telemetria e dei contenuti incorporati sono puliti.
</Callout>

```bash filename=".env"
CSP_ENABLED=true
CSP_REPORT_ONLY=true
CSP_REPORT_URI=https://reports.example.com/csp

# Examples for deployment-specific services
CSP_CONNECT_SRC_EXTRA="https://telemetry.example.com wss://stream.example.com"
CSP_FRAME_SRC_EXTRA=https://tenant.sharepoint.com
CSP_IMG_SRC_EXTRA=https://cdn.example.com
```

`CSP_REPORT_ONLY` è impostato su `true` per impostazione predefinita. Solo un valore riconosciuto come false attiva l'applicazione delle regole; un valore non riconosciuto viene registrato e rimane in modalità report-only. Quando CSP è abilitato, LibreChat forza la shell SPA su `Cache-Control: no-store` e ignora `INDEX_CACHE_CONTROL`, `INDEX_PRAGMA` e `INDEX_EXPIRES` per quella risposta, in modo che un nonce non possa essere riutilizzato dalla cache.

### Variabili CSP [#csp-variables]

| Variabile | Predefinito | Comportamento |
| --- | --- | --- |
| `CSP_ENABLED` | `false` | Abilita la CSP basata su nonce per la shell SPA. |
| `CSP_REPORT_ONLY` | `true` | Invia `Content-Security-Policy-Report-Only`; impostare su `false` per applicarla. |
| `CSP_REPORT_URI` | vuoto | Aggiunge la direttiva legacy `report-uri`. |
| `CSP_ALLOW_WASM` | `true` | Consente la compilazione WebAssembly utilizzata dalla conversione HEIC. |
| `CSP_ALLOW_DATA_WORKERS` | `true` | Consente i worker `data:` utilizzati dal loader di Monaco. |
| `CSP_FRAME_ANCESTORS` | `'self'` | Sostituisce l'elenco completo delle origini `frame-ancestors`. |
| `CSP_ADDITIONAL_DIRECTIVES` | vuoto | Aggiunge direttive raw separate da punto e virgola. |

Queste variabili aggiungono le fonti alla direttiva integrata corrispondente:

- `CSP_DEFAULT_SRC_EXTRA`
- `CSP_SCRIPT_SRC_EXTRA`
- `CSP_STYLE_SRC_EXTRA`
- `CSP_IMG_SRC_EXTRA`
- `CSP_FONT_SRC_EXTRA`
- `CSP_CONNECT_SRC_EXTRA`
- `CSP_MEDIA_SRC_EXTRA`
- `CSP_FRAME_SRC_EXTRA`
- `CSP_WORKER_SRC_EXTRA`
- `CSP_FORM_ACTION_EXTRA`

Gli elenchi di origine possono essere separati da virgole o spazi. Questi vengono aggiunti ai valori predefiniti di LibreChat anziché sostituirli. `CSP_FRAME_ANCESTORS` costituisce l'eccezione, poiché sostituisce intenzionalmente il valore predefinito `'self'`.

La policy predefinita degli script utilizza `'strict-dynamic'`. L'impostazione di `CSP_SCRIPT_SRC_EXTRA` rimuove `'strict-dynamic'` in modo che gli host di script elencati possano avere effetto. Elenca solo le origini di cui ti fidi per eseguire codice in LibreChat.

Se un'altra origine deve includere LibreChat in un frame, applica `frame-ancestors` prima di rimuovere `X-Frame-Options`:

```bash filename=".env"
CSP_ENABLED=true
CSP_REPORT_ONLY=false
X_FRAME_OPTIONS=off
CSP_FRAME_ANCESTORS="'self' https://portal.example.com"
```

Non impostare `X_FRAME_OPTIONS=off` mentre CSP è disabilitato o in modalità report-only. Una policy report-only registra le violazioni ma non limita il framing, quindi rimuovere `X-Frame-Options` per primo consentirebbe a qualsiasi origine di incorniciare (frame) il deployment. I browser senza supporto per `frame-ancestors` non applicheranno alcuna restrizione di framing in questa configurazione cross-origin.

Consulta il [riferimento alle variabili d'ambiente](/docs/configuration/dotenv#security-headers-and-content-security-policy) per sapere dove si trovano queste impostazioni nel file `.env`.
