LibreChat wysyła podstawowy zestaw nagłówków bezpieczeństwa HTTP w każdej odpowiedzi, w tym dla endpointów sprawdzających stan (health endpoints). Oparta na nonce polityka Content Security Policy (CSP) jest dostępna oddzielnie i domyślnie wyłączona, aby istniejące integracje mogły zostać poddane audytowi przed jej wymuszeniem.

## Nagłówki bazowe [#baseline-headers]

Nagłówki bazowe są włączone, chyba że ustawiono `SECURITY_HEADERS=false`. Ta zmienna jest globalnym wyłącznikiem: dezaktywuje ona zarówno nagłówki bazowe, jak i CSP.

| Zmienna | Domyślnie | Zachowanie |
| --- | --- | --- |
| `SECURITY_HEADERS` | `true` | Włącza wszystkie podstawowe nagłówki. `false` wyłącza również CSP. |
| `HSTS_ENABLED` | `true` | Wysyła `Strict-Transport-Security`. Przeglądarki honorują to tylko przez HTTPS. |
| `HSTS_MAX_AGE` | `31536000` | Czas życia HSTS w sekundach. Musi być liczbą całkowitą nieujemną. |
| `HSTS_INCLUDE_SUBDOMAINS` | `false` | Stosuje HSTS do każdej subdomeny. Włącz tylko wtedy, gdy wszystkie subdomeny używają HTTPS. |
| `HSTS_PRELOAD` | `false` | Dodaje token `preload` do HSTS. |
| `X_FRAME_OPTIONS` | `SAMEORIGIN` | Akceptuje `SAMEORIGIN`, `DENY` lub `off`. |
| `REFERRER_POLICY` | `no-referrer` | Ustawia `Referrer-Policy`; użyj `off`, aby pominąć. |
| `CROSS_ORIGIN_OPENER_POLICY` | `same-origin` | Ustawia `Cross-Origin-Opener-Policy`; użyj `off`, aby pominąć. |
| `CROSS_ORIGIN_RESOURCE_POLICY` | `same-origin` | Ustawia `Cross-Origin-Resource-Policy`; użyj `off`, aby pominąć. |

Helmet wysyła również `X-Content-Type-Options: nosniff`. Nieprawidłowe wartości są rejestrowane w logach, a system powraca do udokumentowanych wartości domyślnych.

Akceptowane zasady otwierania (opener policies) to `same-origin`, `same-origin-allow-popups`, `noopener-allow-popups` oraz `unsafe-none`. Akceptowane zasady dotyczące zasobów (resource policies) to `same-origin`, `same-site` oraz `cross-origin`. Akceptowane zasady dotyczące referrera (referrer policies) to `no-referrer`, `no-referrer-when-downgrade`, `same-origin`, `origin`, `strict-origin`, `origin-when-cross-origin`, `strict-origin-when-cross-origin` oraz `unsafe-url`.

```bash filename=".env"
SECURITY_HEADERS=true
HSTS_ENABLED=true
HSTS_MAX_AGE=31536000
HSTS_INCLUDE_SUBDOMAINS=false
HSTS_PRELOAD=false
X_FRAME_OPTIONS=SAMEORIGIN
REFERRER_POLICY=no-referrer
CROSS_ORIGIN_OPENER_POLICY=same-origin
CROSS_ORIGIN_RESOURCE_POLICY=same-origin
```

Jeśli serwer proxy wyższego rzędu również zapisuje te nagłówki, należy zachować jedną wiarygodną politykę i zweryfikować ostateczną odpowiedź widzianą przez przeglądarkę.

## Content Security Policy [#content-security-policy]

CSP jest opcjonalne (opt-in). LibreChat tworzy nowy nonce dla każdej odpowiedzi SPA i stosuje go do wykonywalnych skryptów oraz linków module-preload w powłoce (shell).

<Callout type="warning" title="Uruchom w trybie tylko raportowania">
  Włącz CSP za pomocą `CSP_REPORT_ONLY=true`, zbieraj naruszenia ze swojego rzeczywistego wdrożenia, dodawaj tylko wymagane źródła i wymuszaj dopiero wtedy, gdy przepływy aplikacji, uwierzytelniania, przechowywania, telemetrii i osadzonych treści będą poprawne.
</Callout>

```bash filename=".env"
CSP_ENABLED=true
CSP_REPORT_ONLY=true
CSP_REPORT_URI=https://reports.example.com/csp

# Examples for deployment-specific services
CSP_CONNECT_SRC_EXTRA="https://telemetry.example.com wss://stream.example.com"
CSP_FRAME_SRC_EXTRA=https://tenant.sharepoint.com
CSP_IMG_SRC_EXTRA=https://cdn.example.com
```

`CSP_REPORT_ONLY` domyślnie przyjmuje wartość `true`. Tylko rozpoznana wartość false przełącza na wymuszanie; nierozpoznana wartość jest logowana i pozostaje w trybie raportowania. Gdy CSP jest włączone, LibreChat wymusza dla powłoki SPA nagłówek `Cache-Control: no-store` i ignoruje `INDEX_CACHE_CONTROL`, `INDEX_PRAGMA` oraz `INDEX_EXPIRES` dla tej odpowiedzi, aby nonce nie mógł zostać ponownie użyty z pamięci podręcznej.

### Zmienne CSP [#csp-variables]

| Zmienna | Domyślnie | Zachowanie |
| --- | --- | --- |
| `CSP_ENABLED` | `false` | Włącza CSP oparte na nonce dla powłoki SPA. |
| `CSP_REPORT_ONLY` | `true` | Wysyła `Content-Security-Policy-Report-Only`; ustaw `false`, aby wymusić. |
| `CSP_REPORT_URI` | puste | Dodaje starszą dyrektywę `report-uri`. |
| `CSP_ALLOW_WASM` | `true` | Zezwala na kompilację WebAssembly używaną przez konwersję HEIC. |
| `CSP_ALLOW_DATA_WORKERS` | `true` | Zezwala na workerów `data:` używanych przez loader Monaco. |
| `CSP_FRAME_ANCESTORS` | `'self'` | Zastępuje pełną listę źródeł `frame-ancestors`. |
| `CSP_ADDITIONAL_DIRECTIVES` | puste | Dodaje surowe dyrektywy oddzielone średnikami. |

Te zmienne dołączają źródła do pasującej wbudowanej dyrektywy:

- `CSP_DEFAULT_SRC_EXTRA`
- `CSP_SCRIPT_SRC_EXTRA`
- `CSP_STYLE_SRC_EXTRA`
- `CSP_IMG_SRC_EXTRA`
- `CSP_FONT_SRC_EXTRA`
- `CSP_CONNECT_SRC_EXTRA`
- `CSP_MEDIA_SRC_EXTRA`
- `CSP_FRAME_SRC_EXTRA`
- `CSP_WORKER_SRC_EXTRA`
- `CSP_FORM_ACTION_EXTRA`

Listy źródeł mogą być rozdzielane przecinkami lub spacjami. Są one dodawane do wartości domyślnych LibreChat, a nie zastępują ich. Wyjątkiem jest `CSP_FRAME_ANCESTORS`, ponieważ celowo zastępuje on domyślną wartość `'self'`.

Domyślna polityka skryptów używa `'strict-dynamic'`. Ustawienie `CSP_SCRIPT_SRC_EXTRA` usuwa `'strict-dynamic'`, dzięki czemu wymienione hosty skryptów mogą zacząć działać. Wymieniaj tylko te źródła, którym ufasz w kwestii wykonywania kodu w LibreChat.

Jeśli inne źródło musi osadzać LibreChat, wymuś `frame-ancestors` przed usunięciem `X-Frame-Options`:

```bash filename=".env"
CSP_ENABLED=true
CSP_REPORT_ONLY=false
X_FRAME_OPTIONS=off
CSP_FRAME_ANCESTORS="'self' https://portal.example.com"
```

Nie ustawiaj `X_FRAME_OPTIONS=off`, gdy CSP jest wyłączone lub działa w trybie report-only. Polityka typu report-only rejestruje naruszenia, ale nie ogranicza ramkowania (framing), więc usunięcie `X-Frame-Options` w pierwszej kolejności pozwoliłoby dowolnemu źródłu (origin) na ramkowanie wdrożenia. Przeglądarki bez wsparcia dla `frame-ancestors` nie wymuszą ograniczenia ramkowania w tej konfiguracji między źródłami (cross-origin).

Zobacz [odniesienie do zmiennych środowiskowych](/docs/configuration/dotenv#security-headers-and-content-security-policy), aby dowiedzieć się, gdzie te ustawienia znajdują się w pliku `.env`.
