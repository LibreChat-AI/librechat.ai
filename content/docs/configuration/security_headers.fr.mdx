LibreChat envoie un ensemble de base d'en-têtes de sécurité HTTP sur chaque réponse, y compris pour les endpoints de santé. Une Content Security Policy (CSP) basée sur un nonce est disponible séparément et est désactivée par défaut afin que les intégrations existantes puissent être auditées avant son application.

## En-têtes de référence [#baseline-headers]

Les en-têtes de base sont activés sauf si `SECURITY_HEADERS=false`. Cette variable est l'interrupteur global : elle désactive à la fois les en-têtes de base et la CSP.

| Variable | Default | Behavior |
| --- | --- | --- |
| `SECURITY_HEADERS` | `true` | Active tous les en-têtes de base. `false` désactive également la CSP. |
| `HSTS_ENABLED` | `true` | Envoie `Strict-Transport-Security`. Les navigateurs ne le respectent que via HTTPS. |
| `HSTS_MAX_AGE` | `31536000` | Durée de vie HSTS en secondes. Doit être un entier non négatif. |
| `HSTS_INCLUDE_SUBDOMAINS` | `false` | Applique HSTS à chaque sous-domaine. À activer uniquement si tous les sous-domaines utilisent HTTPS. |
| `HSTS_PRELOAD` | `false` | Ajoute le jeton `preload` HSTS. |
| `X_FRAME_OPTIONS` | `SAMEORIGIN` | Accepte `SAMEORIGIN`, `DENY` ou `off`. |
| `REFERRER_POLICY` | `no-referrer` | Définit `Referrer-Policy` ; utilisez `off` pour l'omettre. |
| `CROSS_ORIGIN_OPENER_POLICY` | `same-origin` | Définit `Cross-Origin-Opener-Policy` ; utilisez `off` pour l'omettre. |
| `CROSS_ORIGIN_RESOURCE_POLICY` | `same-origin` | Définit `Cross-Origin-Resource-Policy` ; utilisez `off` pour l'omettre. |

Helmet envoie également `X-Content-Type-Options: nosniff`. Les valeurs invalides sont consignées dans les journaux et le système revient aux valeurs par défaut documentées.

Les politiques d'ouverture acceptées sont `same-origin`, `same-origin-allow-popups`, `noopener-allow-popups` et `unsafe-none`. Les politiques de ressources acceptées sont `same-origin`, `same-site` et `cross-origin`. Les politiques de référent acceptées sont `no-referrer`, `no-referrer-when-downgrade`, `same-origin`, `origin`, `strict-origin`, `origin-when-cross-origin`, `strict-origin-when-cross-origin` et `unsafe-url`.

```bash filename=".env"
SECURITY_HEADERS=true
HSTS_ENABLED=true
HSTS_MAX_AGE=31536000
HSTS_INCLUDE_SUBDOMAINS=false
HSTS_PRELOAD=false
X_FRAME_OPTIONS=SAMEORIGIN
REFERRER_POLICY=no-referrer
CROSS_ORIGIN_OPENER_POLICY=same-origin
CROSS_ORIGIN_RESOURCE_POLICY=same-origin
```

Si un proxy en amont écrit également ces en-têtes, conservez une politique faisant autorité et vérifiez la réponse finale vue par le navigateur.

## Content Security Policy [#content-security-policy]

La CSP est optionnelle (opt-in). LibreChat crée un nonce unique pour chaque réponse SPA et l'applique aux scripts exécutables ainsi qu'aux liens module-preload dans le shell.

<Callout type="warning" title="Démarrer en mode rapport uniquement">
  Activez CSP avec `CSP_REPORT_ONLY=true`, collectez les violations depuis votre déploiement réel, ajoutez uniquement les sources requises, et appliquez la restriction uniquement après que les flux de l'application, de l'authentification, du stockage, de la télémétrie et du contenu intégré soient propres.
</Callout>

```bash filename=".env"
CSP_ENABLED=true
CSP_REPORT_ONLY=true
CSP_REPORT_URI=https://reports.example.com/csp

# Examples for deployment-specific services
CSP_CONNECT_SRC_EXTRA="https://telemetry.example.com wss://stream.example.com"
CSP_FRAME_SRC_EXTRA=https://tenant.sharepoint.com
CSP_IMG_SRC_EXTRA=https://cdn.example.com
```

`CSP_REPORT_ONLY` est défini par défaut sur `true`. Seule une valeur false reconnue active l'application stricte ; une valeur non reconnue est consignée et reste en mode rapport uniquement. Lorsque CSP est activé, LibreChat force le shell SPA à `Cache-Control: no-store` et ignore `INDEX_CACHE_CONTROL`, `INDEX_PRAGMA` et `INDEX_EXPIRES` pour cette réponse afin qu'un nonce ne puisse pas être réutilisé depuis le cache.

### Variables CSP [#csp-variables]

| Variable | Default | Behavior |
| --- | --- | --- |
| `CSP_ENABLED` | `false` | Active le CSP basé sur les nonce pour le shell SPA. |
| `CSP_REPORT_ONLY` | `true` | Envoie `Content-Security-Policy-Report-Only` ; définissez sur `false` pour appliquer la politique. |
| `CSP_REPORT_URI` | empty | Ajoute la directive héritée `report-uri`. |
| `CSP_ALLOW_WASM` | `true` | Autorise la compilation WebAssembly utilisée par la conversion HEIC. |
| `CSP_ALLOW_DATA_WORKERS` | `true` | Autorise les workers `data:` utilisés par le chargeur de Monaco. |
| `CSP_FRAME_ANCESTORS` | `'self'` | Remplace la liste complète des sources `frame-ancestors`. |
| `CSP_ADDITIONAL_DIRECTIVES` | empty | Ajoute des directives brutes séparées par des points-virgules. |

Ces variables ajoutent des sources à la directive intégrée correspondante :

- `CSP_DEFAULT_SRC_EXTRA`
- `CSP_SCRIPT_SRC_EXTRA`
- `CSP_STYLE_SRC_EXTRA`
- `CSP_IMG_SRC_EXTRA`
- `CSP_FONT_SRC_EXTRA`
- `CSP_CONNECT_SRC_EXTRA`
- `CSP_MEDIA_SRC_EXTRA`
- `CSP_FRAME_SRC_EXTRA`
- `CSP_WORKER_SRC_EXTRA`
- `CSP_FORM_ACTION_EXTRA`

Les listes sources peuvent être séparées par des virgules ou des espaces. Elles s'ajoutent aux valeurs par défaut de LibreChat plutôt que de les remplacer. `CSP_FRAME_ANCESTORS` fait exception, car il remplace intentionnellement la valeur par défaut `'self'`.

La politique de script par défaut utilise `'strict-dynamic'`. La définition de `CSP_SCRIPT_SRC_EXTRA` supprime `'strict-dynamic'` afin que les hôtes de script listés puissent prendre effet. Ne listez que les origines auxquelles vous faites confiance pour exécuter du code dans LibreChat.

Si une autre origine doit intégrer LibreChat, appliquez `frame-ancestors` avant de supprimer `X-Frame-Options` :

```bash filename=".env"
CSP_ENABLED=true
CSP_REPORT_ONLY=false
X_FRAME_OPTIONS=off
CSP_FRAME_ANCESTORS="'self' https://portal.example.com"
```

Ne définissez pas `X_FRAME_OPTIONS=off` tant que CSP est désactivé ou en mode rapport uniquement (report-only). Une politique en mode rapport uniquement enregistre les violations mais ne restreint pas l'encadrement (framing) ; par conséquent, supprimer `X-Frame-Options` en premier permettrait à n'importe quelle origine d'encadrer le déploiement. Les navigateurs ne prenant pas en charge `frame-ancestors` n'appliqueront aucune restriction d'encadrement dans cette configuration inter-origines.

Consultez la [référence des variables d'environnement](/docs/configuration/dotenv#security-headers-and-content-security-policy) pour savoir où ces paramètres se trouvent dans `.env`.
