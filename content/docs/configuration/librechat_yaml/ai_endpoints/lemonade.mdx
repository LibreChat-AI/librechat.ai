AMD Lemonade (Lemonade Server) runs models locally and exposes an OpenAI-compatible API, so you can connect LibreChat to your own machine. Follow the [Lemonade documentation](https://lemonade-server.ai/docs/) to install and start Lemonade, then download a chat model before configuring LibreChat.

## Configuration

Lemonade requires no API key. The `apiKey: 'lemonade'` value below is a placeholder that satisfies the OpenAI client, not an authentication credential. Add this endpoint under `endpoints.custom` in your `librechat.yaml`:

```yaml filename="librechat.yaml"
    - name: 'lemonade'
      apiKey: 'lemonade'
      baseURL: 'http://localhost:13305/v1'
      models:
        default: ['Qwen3-0.6B-GGUF']
        fetch: true
      titleConvo: true
      titleModel: 'current_model'
      modelDisplayLabel: 'AMD Lemonade'
      iconURL: 'lemonade'
```

Replace `Qwen3-0.6B-GGUF` with the ID of a chat model installed locally in Lemonade. With `fetch: true`, LibreChat discovers models from your Lemonade server. Setting `titleModel: 'current_model'` reuses the conversation's model for title generation.

If you haven't created `librechat.yaml` yet, follow the [Custom Endpoints Quick Start Guide](/docs/quick_start/custom_endpoints). Restart LibreChat after changing the configuration.

## Docker and Network Access

When LibreChat runs in Docker, `localhost` refers to the LibreChat container, not your host machine. Replace it with `host.docker.internal` or a Lemonade hostname reachable from the container, keeping the port and `/v1` path:

```yaml filename="librechat.yaml"
baseURL: 'http://host.docker.internal:13305/v1'
```

Make sure Lemonade listens on an interface reachable from LibreChat and that your firewall permits the connection.

### User-Provided Base URLs

If you let users supply their own base URL, add the local Lemonade server's exact `host:port` to [`endpoints.allowedAddresses`](/docs/configuration/librechat_yaml/object_structure/config#endpoints). For example, merge this into your existing `endpoints` object alongside `custom`:

```yaml filename="librechat.yaml"
endpoints:
  allowedAddresses:
    - 'host.docker.internal:13305'
```

Use the host and port from the user-provided URL, without `http://` or `/v1`. This permits that private service through LibreChat's SSRF protection; it is not required for the fixed, administrator-configured `baseURL` in the first example.

## Branding

LibreChat's built-in branding recognizes `lemonade`, `AMD Lemonade`, and `Lemonade Server`. Keep `iconURL: 'lemonade'` to preserve the Lemonade logo when renaming the endpoint.
