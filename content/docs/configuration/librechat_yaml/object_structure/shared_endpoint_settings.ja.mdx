このページでは、すべての endpoint に共通する設定について説明します。ここで強調されている設定は、特に注記がない限り、["Endpoints"](/docs/configuration/librechat_yaml/object_structure/config#endpoints) フィールド配下のすべての構成で利用可能です。

## 設定例 [#example-configuration]

```yaml filename="Shared Endpoint Settings"
endpoints:
  # Individual endpoint configurations
  openAI:
    streamRate: 25
    titleModel: 'gpt-4o-mini'
    titleMethod: 'completion'
    titleTiming: 'immediate'
    titlePrompt: "Create a concise title for this conversation:\n\n{convo}"
    headers:
      X-Gateway-Metadata: '{"user_email":"{{LIBRECHAT_USER_EMAIL}}"}'

  azureOpenAI:
    streamRate: 35
    titleModel: 'grok-3'
    titleMethod: 'structured'
    titlePrompt: |
      Analyze this conversation and provide:
      1. A concise title in the detected language (5 words or less, no punctuation or quotation)
      2. Always provide a relevant emoji at the start of the title

      {convo}
    titleConvo: true

  anthropic:
    streamRate: 25
    titleModel: 'claude-3-5-haiku-20241022'
    titleMethod: 'completion'
    headers:
      X-Conversation-Id: '{{LIBRECHAT_BODY_CONVERSATIONID}}'

  bedrock:
    streamRate: 25
    titleModel: 'us.amazon.nova-lite-v1:0'
    titleEndpoint: 'anthropic'

  google:
    streamRate: 25
    titleModel: 'gemini-2.0-flash-lite'
    titlePromptTemplate: "Human: {input}\nAssistant: {output}"
    headers:
      X-Gateway-Metadata: '{"user_id":"{{LIBRECHAT_USER_ID}}"}'

  assistants:
    streamRate: 30

  azureAssistants:
    streamRate: 30

  agents:
    activityLabel: true
    activityEndpoint: 'openAI'
    activityModel: 'gpt-4.1-nano'
    activityMaxPerRun: 20
    activityCharLimit: 600
    activityPhaseLabel: true
    activityPhaseMaxPerRun: 5

  # Global configuration using 'all' - this applies shared settings across endpoints.
  # Most defined values override endpoint defaults; headers are merged and endpoint values win on collisions.
  all:
    headers:
      X-App: 'librechat'
    titleConvo: true
    titleModel: 'gpt-4.1-nano'
    titleTiming: 'immediate'
    titlePrompt: |
      Analyze this conversation and provide:
      1. The detected language of the conversation
      2. A concise title in the detected language (5 words or less, no punctuation or quotation)
      3. Always provide a relevant emoji at the start of the title
      {convo}
```

> **重要:** `all` 設定を使用する場合、定義した共有プロパティのほとんどがすべての endpoint に適用されます。上記の例では、`all` 設定によって `titleConvo`、`titleModel`、および `titlePrompt` がすべての endpoint に適用されますが、`streamRate` は `all` 内で定義されていないため、個別の設定が保持されます。`headers` は個別にマージされます。`endpoints.all.headers` の値はグローバルに適用され、キーが重複した場合は endpoint レベルのヘッダーが優先されます。アクティビティ設定は同じ順序でフィールドごとに解決されるため、無関係な `all` 設定が endpoint のアクティビティ設定を隠すことはありません。

## streamRate

**キー:**

<OptionTable
  options={[
    [
      'streamRate',
      'Number',
      'endpointからデータがストリーミングされる速度。ストリーミングデータのペースを制御するのに便利です。',
      'streamRate: 25',
    ],
  ]}
/>

**デフォルト:** プロバイダーに依存します。OpenAI、カスタム endpoint、Anthropic、Google、Bedrock、および Agents SDK を利用したストリームは、25 ms をターゲットとした適応型スムージングを使用します。レガシーな Assistants および Ollama ハンドラーは、プロバイダーごとのチャンク動作を保持し、デフォルトは 1 ms です。

Adaptive smoothing（適応的スムージング）は、最初のテキストトークンを遅延なく出力し、ストリームが遅延した場合にはチャンクサイズを大きくし、ツール呼び出しとメタデータの順序を保持します。`streamRate` に非負のミリ秒単位のターゲット値を設定してください。`streamRate: 0` に設定すると、上記のSDKベースのプロバイダーにおけるAdaptive smoothingが無効になります。

`endpoints.all` が `streamRate` なしで存在する場合、エンドポイント固有の値は保持されます。`endpoints.all.streamRate` を定義すると、明示的な `0` を含むエンドポイントの値が上書きされます。

## titleConvo

**キー:**

<OptionTable
  options={[
    [
      'titleConvo',
      'Boolean',
      'このendpointの会話タイトル自動生成を有効にします。',
      'titleConvo: true',
    ],
  ]}
/>

**デフォルト:** `false`

**注記:**

- 有効にすると、設定されたタイトル設定を使用してタイトルが自動的に生成されます。
- `titleModel` と併用するか、endpoint にデフォルトのモデルが設定されている必要があります。

**例:**

```yaml filename="titleConvo"
titleConvo: true
```

## titleTiming

**キー:**

<OptionTable
  options={[
    [
      'titleTiming',
      'String',
      '会話タイトルの生成タイミングを制御します。有効な値は "immediate" または "final" です。',
      'titleTiming: "immediate"',
    ],
  ]}
/>

**デフォルト:** `"immediate"`

**利用可能な値:**

- **`"immediate"`** - リクエストが開始されると同時に、ユーザーの最初のメッセージを使用して、モデルの応答と並行してタイトルを生成します。タイトルは通常1〜2秒以内に表示されます。
- **`"final"`** - タイトルの生成を完全な応答が完了するまで延期します。これにより、従来の動作が維持されます。

**例:**

```yaml filename="titleTiming"
endpoints:
  all:
    titleTiming: 'immediate'
```

## titleMethod

**キー:**

<OptionTable
  options={[
    [
      'titleMethod',
      'String',
      '会話タイトルの生成に使用されるメソッドを制御します。',
      'Valid values: "completion" (default), "structured", "functions" (legacy alias for "structured")',
    ],
  ]}
/>

**デフォルト:** `"completion"`

**利用可能なメソッド:**

- **`"completion"`** - ツールや関数を使用しない標準の completion API を使用します。ほとんどの LLM と互換性があります。
- **`"structured"`** - タイトル生成に構造化出力を使用します。プロバイダー/モデルによるサポートが必要です。
- **`"functions"`** - "structured" のレガシーエイリアスです。機能的には同一です。

**例:**

```yaml filename="titleMethod"
titleMethod: 'completion'
```

## titlePrompt

**キー:**

<OptionTable
  options={[
    [
      'titlePrompt',
      'String',
      'タイトル生成用のカスタムプロンプト。{convo} プレースホルダーを含める必要があります。',
      'Allows full control over how titles are generated.',
    ],
  ]}
/>

**デフォルト:**

```
Analyze this conversation and provide:
1. The detected language of the conversation
2. A concise title in the detected language (5 words or less, no punctuation or quotation)

{convo}
```

**注記:**

- 常に `{convo}` プレースホルダーを含める必要があります
- `{convo}` プレースホルダーは、フォーマットされた会話に置き換えられます。
- プロンプト内のどこにでも配置できます

**例:**

```yaml filename="titlePrompt"
titlePrompt: "Create a brief, descriptive title for the following conversation:\n\n{convo}\n\nTitle:"
```

## titlePromptTemplate

**キー:**

<OptionTable
  options={[
    [
      'titlePromptTemplate',
      'String',
      'titlePrompt内の{convo}を置き換える、会話コンテンツをフォーマットするためのテンプレート。',
      'Must include {input} and {output} placeholders.',
    ],
  ]}
/>

**デフォルト:** `"User: {input}\nAI: {output}"`

**注記:**

- `{input}` と `{output}` の両方のプレースホルダーを含める必要があります
- `{input}` はユーザーの最初のメッセージに置き換えられます
- `{output}` はAIの応答に置き換えられます
- フォーマットされた結果は、titlePrompt内の `{convo}` を置き換えます。

**例:**

```yaml filename="titlePromptTemplate"
titlePromptTemplate: "Human: {input}\n\nAssistant: {output}"
```

**キー:**

<OptionTable
  options={[

      'titleEndpoint',

      'Allows using a different, potentially cheaper model/endpoint for titles.',
    ],
  ]}
/>

**デフォルト:** 現在の会話のendpointを使用します

**許容値:**

- `openAI`
- `azureOpenAI`
- `google`
- `anthropic`
- `bedrock`
- カスタムエンドポイントの場合: 正確な [カスタムエンドポイント名](/docs/configuration/librechat_yaml/object_structure/custom_endpoint#name) を使用してください。

**例:**

```yaml filename="titleEndpoint"
# Use Anthropic for titles even when chatting with OpenAI
endpoints:
  openAI:
    titleEndpoint: 'anthropic'
    # Will use anthropic's configuration for title generation
```

## エージェントアクティビティグループ [#agent-activity-groups]

Activity groupsは、連続する推論とツール呼び出しの各ブロックを生成された1行のヘッダーの下に折りたたむことで、長いAgentの実行結果をスキャンしやすくします。ヘッダーの生成はメインのモデル応答パスの外側で実行されますが、これもモデル呼び出しであり、その使用量は記録され、課金対象となります。

親フェーズラベルが有効な場合、短い進捗テキストはアクティブなフェーズ内に留まります。フェーズは実質的な回答テキストの前に閉じられるため、結果は折りたたまれた要約の外側に残り、その後の推論やツール呼び出しのブロックが同じ実行内で別のフェーズを開始できるようになります。LibreChatは、不正な形式や省略されたコンテンツが圧縮された際に保存されたフェーズ境界をリベースし、リロード後もそれらの整合性を維持します。

<OptionTable
  options={[
    [
      'activityLabel',
      'Boolean',
      'このendpointを使用したAgent実行時に、生成されたアクティビティグループヘッダーを有効にします。',
      'false',
    ],
    [
      'activityModel',
      'String',
      'ヘッダーの生成に使用されるモデル。titleModel、次にAgentの実行モデルへとフォールバックします。実行モデルを明示的に選択するにはcurrent_modelを使用してください。',
      '',
    ],
    [
      'activityEndpoint',
      'String',
      'ヘッダー生成に使用される認証情報を持つEndpoint。デフォルトはAgentモデルプロバイダーです。',
      '',
    ],
    [
      'activityPrompt',
      'String',
      '1行のヘッダーを生成するために使用されるプロンプトを上書きします。',
      '',
    ],
    [
      'activityMaxPerRun',
      'Positive integer',
      'レスポンスあたりの最大生成アクティビティヘッダー数。追加のモデル呼び出しを制限します。',
      '20',
    ],
    [
      'activityCharLimit',
      'Positive integer',
      'ヘッダープロンプトに含まれる各ツール入力または出力エントリからの最大文字数。',
      '600',
    ],
    [
      'activityPhaseLabel',
      'Boolean',
      '少なくとも2つのアクティビティを含む各実行フェーズに対して、折りたたみ可能な親サマリーを生成します。',
      'false',
    ],
    [
      'activityPhaseModel',
      'String',
      '親フェーズの要約に使用されるモデル。activityModel、titleModel、そしてAgent実行モデルの順にフォールバックします。',
      '',
    ],
    [
      'activityPhaseEndpoint',
      'String',
      'フェーズの要約に使用される認証情報を持つendpoint。activityEndpoint、次にAgentプロバイダーの順にフォールバックします。',
      '',
    ],
    [
      'activityPhasePrompt',
      'String',
      '親フェーズの要約を生成するために使用されるプロンプトを上書きします。',
      '',
    ],
    [
      'activityPhaseMaxPerRun',
      'Positive integer',
      'レスポンスあたりの最大生成親フェーズ要約数。',
      '5',
    ],
  ]}
/>

```yaml filename="endpoints / agents / activity groups"
endpoints:
  agents:
    activityLabel: true
    activityEndpoint: 'openAI'
    activityModel: 'gpt-4.1-nano'
    activityMaxPerRun: 20
    activityCharLimit: 600
    activityPhaseLabel: true
    activityPhaseMaxPerRun: 5
```

これらのフィールドは、`endpoints.all` またはバッキングプロバイダー/カスタムエンドポイントの下に設定することもできます。値は個別に解決され、`endpoints.all`、公開されている `agents` エンドポイント、そしてバッキングプロバイダーまたはカスタムエンドポイントの順で、最初に定義された値が優先されます。`activityEndpoint` が不明な場合、LibreChat は警告をログに記録し、代わりにエージェントのプロバイダーを使用します。

親フェーズの要約は、子アクティビティのラベルとは独立しています。`activityPhaseLabel` は `activityLabel` の有無にかかわらず有効にできます。LibreChat は、少なくとも2つの論理的なアクティビティを含むフェーズに対してのみ、フェーズ要約モデルの呼び出しを行います。`activityCharLimit` も、フェーズ要約に使用されるエビデンスを制限します。フェーズモデルの選択は、`activityPhaseModel`、`activityModel`、元の endpoint の `titleModel`、そして現在の実行モデルの順で解決されます。フェーズ endpoint の選択は、`activityPhaseEndpoint`、`activityEndpoint`、そして Agent プロバイダーの順で解決されます。設定されたフェーズ endpoint が不明な場合は警告がログに記録され、Agent プロバイダーにフォールバックします。

## maxToolResultChars

**キー:**

<OptionTable
  options={[
    [
      'maxToolResultChars',
      'Number',
      'モデルに送信されるツール呼び出し結果の最大文字数を制限します。正の数である必要があります。',
      'maxToolResultChars: 50000',
    ],
  ]}
/>

**デフォルト:** 制限なし

**注記:**

- 過度に大きなツール出力がトークンを過剰に消費するのを防ぐのに役立ちます
- エンドポイントのすべてのツール呼び出し結果に適用されます

**例:**

```yaml filename="maxToolResultChars"
endpoints:
  all:
    maxToolResultChars: 50000
```

## headers

**キー:**

<OptionTable
  options={[
    [
      'headers',
      'Object/Dictionary',
      'サポートされている組み込みプロバイダーのendpointに転送されるカスタムリクエストヘッダー。',
      'Useful for AI gateways and reverse proxies that consume metadata headers while LibreChat keeps provider-native request formatting.',
    ],
  ]}
/>

**サポートされている endpoint:** `openAI`、`anthropic`、`google`、および `all`。

**例:**

```yaml filename="endpoints / headers"
endpoints:
  all:
    headers:
      X-App: 'librechat'
  anthropic:
    headers:
      X-Conversation-Id: '{{LIBRECHAT_BODY_CONVERSATIONID}}'
```

**注記:**

- 値は `${ENV_VAR}`、`{{LIBRECHAT_USER_*}}`、および `{{LIBRECHAT_BODY_CONVERSATIONID}}` のようなリクエストボディのプレースホルダーをサポートしています。
- 最終的なアウトバウンド解決ステップにおいて、認識されたユーザー、リクエストボディ、およびOpenIDのプレースホルダーで値を持たないものは、テンプレートテキストとして転送されるのではなく、空文字列になります。未知のプレースホルダー名は、設定のタイプミスが確認できるよう、変更されずにそのまま残ります。
- エンドポイントレベルのヘッダーは、キーが競合した場合に `endpoints.all.headers` を上書きします。
- プロバイダー管理の認証および必須のベータ/プロトコルヘッダーが優先されます。Anthropicのベータ値はマージされるため、カスタムのベータフラグが必須のプロバイダーフラグを上書きすることはありません。
- サポートされているプロバイダーのモデル一覧リクエストに対しても、ヘッダーが転送されます。
- ゲートウェイやリバースプロキシの背後でメタデータヘッダーを使用し、それらを消費するようにします。ネイティブプロバイダーのAPIは通常、未知のヘッダーを無視します。

---

**注記:**

- このページに表示されているすべての設定は、各 endpoint ごとに個別に、または `all` キーを使用してグローバルに設定できます。
- `all` 設定を使用する場合、すべての個別の endpoint における対応する設定が上書きされます。
- `all` キーは `baseURL` を受け付けません。
- `all` で定義されていない設定は、それぞれの endpoint の値を保持します。
- `streamRate` について: エンドポイント固有の平滑化が必要な場合は、25〜40の値を推奨します。
- 多くのユーザーに大規模にアプリを提供する場合は、より高いストリームレートを使用することが必須です。

**オーバーライド動作の例:**

```yaml
endpoints:
  openAI:
    streamRate: 25 # This will be preserved
    titleModel: 'gpt-4' # This will be overridden
    titleConvo: false # This will be overridden

  all:
    titleConvo: true
    titleModel: 'gpt-3.5-turbo'
    # streamRate not defined here, so individual values are kept
```
