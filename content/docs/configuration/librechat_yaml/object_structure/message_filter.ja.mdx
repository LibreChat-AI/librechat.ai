## 概要 [#overview]

`messageFilter` オブジェクトは、サーバーサイドのメッセージフィルターを設定します。サポートされているフィルタータイプは `messageFilter.pii` です。

`messageFilter.pii` は、送信されたメッセージテキストがモデレーション、モデルへのリクエスト、またはメッセージの永続化に到達する前に、認証情報のような形式のパターンやオペレーターが定義した正規表現に一致する場合、そのテキストを拒否します。

## 例 [#example]

```yaml filename="librechat.yaml"
messageFilter:
  pii:
    starterPatterns:
      - sk_prefix
      - bearer_header
      - api_key_header
    customPatterns:
      - id: anthropic_api_key
        label: Anthropic API key
        regex: 'sk-ant-[A-Za-z0-9_-]{20,}'
```

**組み込みのスターターパターンID:**

- `sk_prefix`: `sk-` スタイルのトークンプレフィックスと一致します。
- `bearer_header`: テキスト内のベアラートークンと一致します。
- `api_key_header`: `api-key` ヘッダー形式のテキストと一致します。

カスタムパターンは線形時間のRE2エンジンを使用します。後方参照と先読み・戻り読みはサポートされておらず、一部のエスケープはJavaScriptの正規表現と異なります。LibreChatは、設定の読み込み時にRE2がコンパイルできないパターンを拒否します。

## 動作 [#behavior]

送信されたメッセージテキストが設定済みのPIIパターンと一致した場合、LibreChatは `message_filter_pii_block` とともにHTTP `400` エラーを返し、呼び出し元に対して一致した認証情報の種類を削除するよう求めるメッセージを表示します。

フィルターのチェック項目:

- LibreChat UIを通じて送信されたチャットルートのユーザーテキスト。
- OpenAI互換のChat Completionsリクエストにおける、すべての呼び出し元から提供されたメッセージロールにわたるテキストコンテンツ。
- OpenAI互換のResponsesリクエストにおける、すべての呼び出し元が提供するメッセージロールにわたるテキストコンテンツ。

このフィルターは、リクエストボディで提供されたテキストを評価します。ファイルの内容はスキャンしません。
