## 示例 [#example]

```yaml filename="Agents Endpoint"
endpoints:
  agents:
    recursionLimit: 50
    maxRecursionLimit: 100
    maxSubagents: 20
    maxToolCallArgBytes: 65536
    maxDeltaEventsPerTurn: 100000
    maxToolCallArgBytesByTool:
      create_file: 131072
    disableBuilder: false
    # (optional) Agent Capabilities available to all users. Omit the ones you wish to exclude. Defaults to list below.
    # Opt-in capabilities: "programmatic_tools", "stateful_code_sessions", "run_in_background", and "tool_intents".
    # capabilities: ["deferred_tools", "execute_code", "file_search", "web_search", "artifacts", "subagents", "actions", "context", "skills", "memory", "ask_user_question", "tools", "chain", "ocr"]
    # (optional) File citation configuration for file_search capability
    maxCitations: 30 # Maximum total citations in responses (1-50)
    maxCitationsPerFile: 7 # Maximum citations from each file (1-10)
    minRelevanceScore: 0.45 # Minimum relevance score threshold (0.0-1.0)
    titleTiming: immediate
    activityLabel: true
    activityModel: gpt-4.1-nano
    activityPhaseLabel: true
    activityPhaseMaxPerRun: 5
    skills:
      maxCatalogSkills: 20
    statefulCodeSessions:
      allowedEnvironments: ['user', 'agent-user', 'conversation']
      environments:
        - id: managed-default
          name: Managed Code API
          type: managed
          baseURL: https://code.example.com/v1
          default: true
        - id: engineering-vm
          name: Engineering VM
          type: attached
          baseURL: https://code-bridge.example.com/v1
          pairing:
            workerId: engineering-vm
            tokenEnv: CODE_BRIDGE_ADMIN_TOKEN
        - id: personal-workers
          name: Personal Code Workers
          type: attached
          baseURL: https://code-bridge.example.com/v1
          pairing:
            allowPrincipalWorkers: true
            tokenEnv: CODE_BRIDGE_ADMIN_TOKEN
    # eventDriven:
    #   selfUrl: https://librechat.internal
    backgroundTasks:
      completionWakeups: true
    toolApproval:
      enabled: true
      mode: default
      deny: ['mcp:*:delete_*']
      ask: ['mcp:*:*']
    checkpointer:
      type: mongo
      ttl: 86400
    remoteApi:
      auth:
        oidc:
          enabled: false
```

> 此配置启用了用于 Agent 的构建器界面。

## 流式断路器 [#stream-circuit-breakers]

当提供商的流似乎正在产生失控的工具参数或无限的增量事件序列时，这些设置会停止 Agent 的运行。

<OptionTable
  options={[
    [
      'maxToolCallArgBytes',
      'Number',
      '单个流式工具调用参数的最大累计字节数。设置为 0 可禁用全局防护。',
      '65536',
    ],
    [
      'maxDeltaEventsPerTurn',
      'Number',
      '单次模型生成轮次的最大流式事件数。设置为 0 或省略此项以禁用此防护。',
      '0 (disabled)',
    ],
    [
      'maxToolCallArgBytesByTool',
      'Object',
      '按面向模型的工具名称键入的每个工具的参数字节覆盖。值为 0 将禁用该工具的防护。',
      'create_file: 131072',
    ],
  ]}
/>

LibreChat 使用 64 KiB 的全局参数限制，并为 `create_file` 提供了一个 128 KiB 的覆盖值，因为其合法负载通常较大。`maxToolCallArgBytesByTool` 中的条目会覆盖该内置设置。如果触发了任一限制，LibreChat 将中止正在进行的 provider 流并报告超出了哪个限制。

```yaml filename="endpoints / agents / stream circuit breakers"
maxToolCallArgBytes: 65536
maxDeltaEventsPerTurn: 100000
maxToolCallArgBytesByTool:
  create_file: 262144
  large_import: 524288
```

要禁用所有参数大小限制，请将全局限制和内置的 `create_file` 覆盖项均设置为 `0`：

```yaml
maxToolCallArgBytes: 0
maxToolCallArgBytesByTool:
  create_file: 0
```

<OptionTable

**默认值：** `"immediate"`

## activityLabel

设置 `activityLabel: true` 以将每个 Agent 推理和工具调用块归类在一个生成的单行标题下。使用 `activityModel`、`activityEndpoint`、`activityPrompt`、`activityMaxPerRun` 和 `activityCharLimit` 来控制额外的模型调用及其成本。有关完整的字段参考和优先级规则，请参阅 [Agent Activity Groups](/docs/configuration/librechat_yaml/object_structure/shared_endpoint_settings#agent-activity-groups)。

```yaml filename="endpoints / agents / activity groups"
activityLabel: true
activityEndpoint: openAI
activityModel: gpt-4.1-nano
activityMaxPerRun: 20
activityCharLimit: 600
activityPhaseLabel: true
activityPhaseMaxPerRun: 5
```

`activityPhaseLabel` 可以独立地在每个包含至少两个逻辑活动的运行阶段周围添加一个折叠的父级摘要。使用 `activityPhaseModel`、`activityPhaseEndpoint`、`activityPhasePrompt` 和 `activityPhaseMaxPerRun` 来调整这些调用；`activityCharLimit` 与子活动标签共享。

## capabilities

<OptionTable
  options={[
    [
      'capabilities',
      'Array/List of Strings',
      '指定可供所有用户在 agents endpoint 中使用的智能体功能。',
      'Defines the agent capabilities that are available to all users for the agents endpoint. You can omit the capabilities you wish to exclude from the list.',
    ],
  ]}
/>

**默认值：** `["deferred_tools", "execute_code", "file_search", "web_search", "artifacts", "subagents", "actions", "context", "skills", "memory", "ask_user_question", "tools", "chain", "ocr"]`

`programmatic_tools`、`stateful_code_sessions`、`run_in_background` 和 `tool_intents` 为选择性加入功能，必须显式添加。Programmatic tools 和 stateful sessions 还需要 `execute_code` 以及兼容的 Code Interpreter 部署。Agent Builder 会在没有 Code Interpreter 的情况下禁用 Programmatic MCP 选择，且当代码执行不可用时，服务器会移除过期的 programmatic caller 选项。`run_in_background` 使 Code Interpreter 工具默认符合条件，并允许针对符合条件的 MCP、Plugin 和 Action 工具进行逐个工具的选择性加入；后台代码执行同样需要 `execute_code` 和 Code Interpreter。

`stateful_code_sessions` 目前处于高度实验性阶段。它需要一个单独的 `stateful` 配置文件的代码解释器路由，并通过 [`LIBRECHAT_CODE_BASEURL_STATEFUL`](/docs/configuration/dotenv#stateful-code-interpreter-endpoint) 或 [`statefulCodeSessions.environments`](#statefulcodesessions) 进行配置。有状态请求在失败时会直接终止，而不会回退到正常的无状态服务。在 Agent Builder 中，每个启用的 Agent 都可以选择用户（user）、代理与用户（agent-and-user）或对话（conversation）的工作区范围；当配置了命名后端时，还可以选择执行环境。新创建的 Agent 默认使用用户的个人范围以及部署的默认执行环境。

**示例：**

```yaml filename="endpoints / agents / capabilities"
capabilities:
  - 'deferred_tools'
  # Optional: enables Programmatic Tool Calling for MCP tools marked Programmatic in the Agent Builder.
  # Requires execute_code and a Code Interpreter deployment with the Tool Call Server component.
  # - 'programmatic_tools'
  - 'execute_code'
  - 'file_search'
  - 'web_search'
  - 'artifacts'
  - 'subagents'
  - 'actions'
  - 'context'
  - 'skills'
  - 'memory'
  - 'ask_user_question'
  - 'tools'
  - 'chain'
  - 'ocr'
  # Optional and highly experimental: reuse a user-, agent-and-user-, or
  # conversation-scoped workspace. Requires LIBRECHAT_CODE_BASEURL_STATEFUL
  # or a named statefulCodeSessions environment.
  # - 'stateful_code_sessions'
  # Optional: allow eligible Code Interpreter, MCP, Plugin, and Action tools to run as background tasks.
  # - 'run_in_background'
  # Optional: show live model-written intent labels for native and selected MCP tools.
  # - 'tool_intents'
```

**注意：** 此字段为可选字段。如果省略，默认行为是包含 default 中列出的所有功能。

## statefulCodeSessions

配置高度实验性的有状态 Code Interpreter 工作区的共享范围和可选执行后端。

<Callout type="warning" title="高度实验性">
  Stateful Code Sessions、命名执行环境、附加工作进程以及配对功能目前处于早期实验阶段。其行为、配置、持久化特性以及集成协议可能会发生重大变化。
</Callout>

<OptionTable
  options={[
    [
      'allowedEnvironments',
      'Array/List of Strings',
      '允许的有状态工作区范围：`user`、`agent-user` 和/或 `conversation`。',
      '["user", "agent-user", "对话"]',
    ],
    [
      'environments',
      'Array of Objects',
      '在 Agent Builder 中显示的可选命名托管或挂载的 Code API 环境。',
      'Unset; LIBRECHAT_CODE_BASEURL_STATEFUL remains the stateful endpoint',
    ],
  ]}
/>

```yaml filename="endpoints / agents / statefulCodeSessions"
statefulCodeSessions:
  allowedEnvironments:
    - 'user'
    - 'agent-user'
    - 'conversation'
  environments:
    - id: managed-default
      name: Managed Code API
      type: managed
      baseURL: https://code.example.com/v1
      default: true
    - id: engineering-vm
      name: Engineering VM
      type: attached
      baseURL: https://code-bridge.example.com/v1
      owner: deployment
      pairing:
        workerId: engineering-vm
        tokenEnv: CODE_BRIDGE_ADMIN_TOKEN
    - id: personal-workers
      name: Personal Code Workers
      type: attached
      baseURL: https://code-bridge.example.com/v1
      owner: deployment
      configSchema:
        permissions:
          fileWrite:
            allowed: [allow, ask, deny]
            default: ask
          commandExecution:
            allowed: [ask, deny]
            default: ask
      pairing:
        allowPrincipalWorkers: true
        tokenEnv: CODE_BRIDGE_ADMIN_TOKEN
```

当该代码块存在时，`allowedEnvironments` 是必需的，且必须至少包含一个工作区范围。省略整个代码块即表示允许所有三个范围，并继续通过 [`LIBRECHAT_CODE_BASEURL_STATEFUL`](/docs/configuration/dotenv#stateful-code-interpreter-endpoint) 路由有状态工作。个人默认设置和 Agent Builder 仅允许使用已授权的值。如果管理员收紧了策略，已保存的个人默认设置将保持可见但处于禁用状态，且新的 Agent 将使用第一个允许的范围。现有的已启用 Agent 将保留其已保存的范围，但如果某个范围现在被禁止，则在运行时会失败并关闭，直到重新配置该 Agent 为止。

当 `environments` 非空时，每个条目都需要一个唯一的 `id`、一个显示名称 `name`、一个 `managed` 或 `attached` 类型的 `type`，以及一个不带查询字符串或片段的 HTTP(S) `baseURL`。如果列表中包含可执行环境，则必须有且仅有一个条目设置 `default: true`。随后 Agent Builder 会添加一个 **Execution environment**（执行环境）选择器；将其保留为 **Deployment default**（部署默认值）将使用该默认条目。仅包含自助服务配对控制平面的列表无需设置默认值。如果 Agent 指定的环境随后被移除或无法访问，该 Agent 将会关闭失败，而不会回退到其他后端。

- `managed` 直接指向一个由 operator 管理的有状态 Code API。
- `attached` 指向一个兼容的 Code API `remote-bridge` 后端，该后端将任务租借给一个出站的 `@librechat/code` worker。该 worker 不需要入站公共端口，但其本地执行 endpoint 仍需要适当的隔离。
- `workerId` 可选地将附加的环境路由到一个出站 worker。它是仅限服务器端的，不会通过客户端启动配置暴露。
- `owner` 默认为 `deployment`。由主体（Principal）拥有的环境是通过 LibreChat 经过身份验证的 Code Environments API 创建的，受 ACL 保护，并且仅针对授权请求进行合并；请勿将客户端提供的 URL 放入 deployment YAML 中。
- `pairing` 是可选的，且仅对部署拥有的 `attached` 条目有效。`pairing.workerId` 用于标识要注册的由操作员管理的 worker，而 `pairing.allowPrincipalWorkers: true` 则允许授权用户将绑定所有者的 worker 注册到该控制平面。当存在 `pairing` 时，必须至少提供其中一个字段。
- `pairing.tokenEnv` 指定了包含网桥管理员令牌的环境变量名称；它本身不包含令牌。除本地回环开发外，配对需要 HTTPS。
- `configSchema.permissions` 允许授权所有者为个人环境选择 `fileWrite` 和 `commandExecution` 策略，具体设置位于 **Settings > Code environments**。每个字段都需要一个非空的 `allowed` 列表，其中包含 `allow`、`ask` 和/或 `deny`；如果省略 `default`，则默认为 `ask`，且该值必须出现在 `allowed` 中。LibreChat 会拒绝管理员列表之外的存储值。
- 不要在部署的 YAML 中配置 `settings`。LibreChat 会从经过服务器验证的已认证所有者的偏好设置中提供该请求范围内的字段。
- 只有文件写入和命令执行策略是用户可配置的。隔离、网络、挂载、特权执行、入站、出站和密钥仍由管理员控制。
- 如果同时存在顶层的 `workerId` 和 `pairing.workerId`，它们必须匹配。如果一个条目设置了 `allowPrincipalWorkers: true` 且两个 worker ID 均非仅配对（pairing-only）模式：它将从执行选择器中被忽略，且不能设置 `default: true`。

附加执行会自动启用安全批准基准：文件写入以及命令或代码执行会请求确认，而只读和搜索操作则继续遵循常规工具策略。该基准的作用域限定为使用附加环境的 Agent。如果没有可用的用户设置，LibreChat 将使用 `ask`；[`toolApproval.enabled: false`](#toolapproval) 是管理员的紧急覆盖设置，用于禁用此附加环境基准。除非设置了该显式覆盖，否则不支持批准和恢复的调用方将默认拒绝执行。

附加执行需要匹配的实验性 Code Interpreter remote-bridge 构建版本。配对用于验证出站 worker 连接；它不能替代沙盒或虚拟机隔离。拥有 Code Environment 管理权限的用户可以在 **Settings > Code environments** 下进行配对、配置允许的工具策略以及撤销个人 worker。请参阅 [Stateful Code Sessions](/docs/features/code_interpreter#stateful-code-sessions)。

## eventDriven

配置用于 Agent 事件传递的受信任内部源。大多数部署应省略此代码块，并使用当前进程绑定的监听器。

<OptionTable
  options={[
    [
      'selfUrl',
      'URL',
      '覆盖当前进程绑定的受信任内部触发准入监听器。仅在交付必须经过另一个受信任的 HTTP 源时使用。',
      '',
    ],
  ]}
/>

```yaml filename="endpoints / agents / eventDriven"
endpoints:
  agents:
    eventDriven:
      selfUrl: https://librechat.internal
```

绑定的子延续（child continuations）是自动执行的。`eventDriven` 下较旧的 `childTurns`、`completionWakeups`、`coalescing`、`actorMailbox`、`checkpointForks` 和 `durableReceipts` 字段不再是配置开关，应予以移除。运行时现在直接应用这些交付保证。独立的 [`backgroundTasks.completionWakeups`](#backgroundtasks) 字段控制已完成的后台工具和分离的 Subagents 的对话交付。

对于正常的绑定监听器路径，请将 `selfUrl` 留空。仅当受信任的内部触发准入必须经过另一个 HTTP(S) 源（例如 TLS 前端）时才进行设置。当省略此字段时，`AGENT_TRIGGERS_SELF_URL` 将作为兼容性回退方案。请参阅 [Agents API events](/docs/features/agents_api#agent-events) 和 [Automatic Parent Continuation](/docs/features/subagents#automatic-parent-continuation)。

Event Actor detached Action completion 会自动从内置生成存储中选择。内存中执行是进程局部的；Redis 生成流增加了持久化重启恢复和副本切换功能。无需 `librechat.yaml` 开关或环境变量功能标志。请参阅 [Agent Event Runtime](/docs/configuration/dotenv#agent-event-runtime)。

## backgroundTasks

控制受支持的已完成后台工具和已分离的 Subagents 是否自动恢复其保存的父级 Agent。

<OptionTable
  options={[
    [
      'completionWakeups',
      'Boolean',
      '自动将受支持的后台任务补全作为延续交付。设置为 false 以仅使用轮询行为。',
      'true',
    ],
  ]}
/>

```yaml filename="endpoints / agents / backgroundTasks"
backgroundTasks:
  completionWakeups: true
```

即使省略此代码块，自动补全交付功能也会启用。设置 `completionWakeups: false` 以要求 Agent 通过 `check_background_task` 收集每一个结果。

普通的后台工具执行仍保持在进程本地，且无法在工作进程丢失后存活。一旦仅包含内容的终端结果被持久化，其交付就是持久的，并可能在另一个副本上继续。带有实时工件的任务仍需要在所属运行中进行轮询。分离的子代理（Subagents）保留其独立的持久化记录和终端结果路径。在两种模式下，手动轮询仍可用于状态、控制和恢复。请参阅 [Background Tool Calls](/docs/features/agents#background-tool-calls) 和 [Automatic Parent Continuation](/docs/features/subagents#automatic-parent-continuation)。

## toolApproval

控制 Agent 工具调用的人工审核。如果省略此代码块，则全局部署策略将被禁用。使用附加 Code 环境的 Agent 是个例外：除非管理员明确设置 `enabled: false`，否则 LibreChat 会默认启用其作用域内的询问安全策略。当审核生效时，匹配的调用会暂停，直到用户提交允许的决定，例如批准、拒绝或编辑参数。

    [

    ['ask', 'Array of strings', '始终需要审核的调用的 Glob 模式。', ''],

      'reason',
      'String',
      '在批准提示中显示的可选说明。使用 `{tool}` 插入工具名称。',
      '',
    ],
    [
      'hooks',
      'Array of objects',
      '用于上下文感知决策的可信编程策略模块。Hooks 只能收紧静态策略。',
      '',
    ],
  ]}
/>

模式使用 glob 匹配。MCP 工具可以通过 `mcp:<server>:<tool>` 进行范围限定；例如，`mcp:github:*` 会匹配来自 `github` 服务器的所有工具。LibreChat 将静态规则和钩子匹配器应用于 MCP 运行时名称和面向模型的别名，包括通过嵌套子代理（Subagents）可访问的工具。静态规则在选定模式提供回退之前，按照 `deny`、`ask`，然后是 `allow` 的顺序进行评估。因此，拒绝规则（deny rule）总是优先，即使在 `bypass` 模式下也是如此。

```yaml filename="endpoints / agents / toolApproval"
toolApproval:
  enabled: true
  mode: default
  allow:
    - 'mcp:analytics:read_*'
  deny:
    - 'mcp:*:delete_*'
  ask:
    - 'mcp:*:*'
  reason: 'Review {tool} before it runs.'
```

Hooks 在服务器启动时加载一次，并在 LibreChat 进程中执行。每个条目接受一个 `module`、一个可选的工具名称 `matcher` 正则表达式，以及一个传递给模块构建器的可选 `options` 对象。请仅加载您信任的代码。基于角色或租户的覆盖不会重新加载 hook 模块；请在 hook 内部实现上下文相关的行为。

```yaml filename="endpoints / agents / toolApproval / hooks"
toolApproval:
  enabled: true
  hooks:
    - module: '@acme/librechat-approval-hook'
      matcher: '^mcp:production:'
      options:
        requireTicket: true
```

当部署运行需要委派给超过十个子代理的编排密集型代理时，请提高此值。该值在启动时读取，并在以下三个位置强制执行：

- 针对 `subagents.agent_ids` 和 `subagents.graphs` 的 Agent 创建、更新和复制请求
- Model spec `subagents.agent_ids` 允许列表，在同一配置过程中进行验证

</Callout>

</Callout>

提高此值只会改变一个 agent 可以引用的子 agent 数量。深度、图节点和运行配置限制不受影响。请参阅 [Subagents](/docs/features/subagents#limits)。

## 智能体功能 (Agent Capabilities) [#agent-capabilities]

`capabilities` 字段允许您为智能体启用或禁用特定功能。可用的功能包括：

- **deferred_tools**: 允许智能体在运行时发现延迟加载的 MCP 工具，而不是预先将所有工具加载到上下文中。
- **programmatic_tools**: 启用在 Agent Builder 中标记为 Programmatic 的 MCP 工具的程序化工具调用（Programmatic Tool Calling）。需要 `execute_code` 以及带有 Tool Call Server 组件的 Code Interpreter 部署。此功能为选择性加入，默认情况下不启用。
- **execute_code**: 允许智能体执行代码。
- **stateful_code_sessions**：允许已启用的 Agent 在用户、Agent 与用户，或对话范围内重用同一个 Code Interpreter 工作区。需要 `execute_code`、兼容的 Code Interpreter 部署以及每个 Agent 的高级设置。新 Agent 将使用已登录用户的首选范围。此功能处于高度实验阶段，默认不启用，且在实验过程中可能会发生重大变化；请勿将当前的行为或配置视为稳定的生产环境契约。
- **file_search**: 启用该功能后，Agent 可以搜索并与文件进行交互。启用后，引用行为将由 `maxCitations`、`maxCitationsPerFile` 和 `minRelevanceScore` 设置控制。
- **web_search**: 为智能体启用网络搜索功能，允许其搜索并从互联网检索信息。
- **artifacts**: 启用代理以生成交互式工件（React 组件、HTML、Mermaid 图表）。
- **subagents**: 启用隔离上下文的子智能体运行。请参阅 [Subagents](/docs/features/subagents)。
- **actions**: 允许智能体执行预定义的操作。
- **context**: 启用聊天中的“作为文本上传”功能，以及代理的“文件上下文”功能，允许用户上传文件，并将其内容提取并直接包含在对话中。
- **skills**: 在侧边栏中启用 Skills，支持手动 `$` 调用、模型调用的 Skills 以及智能体技能白名单。请参阅 [Skills](/docs/features/skills)。
- **memory**: 当配置了 memory 且用户拥有访问权限时，允许智能体使用 `set_memory` 和 `delete_memory`。默认启用；当 memory 被禁用时，会在运行时移除该功能。
- **ask_user_question**: 允许智能体暂停并以单个表单形式提出一到四个相关问题，并在获得回答后继续执行。默认启用。
- **tools**: 授予智能体访问各种工具的权限。
- **chain**: 启用代理链（Agent Chaining）的 Beta 功能，也称为智能体混合（Mixture-of-Agents，简称 MoA）工作流。
- **ocr**: 可选功能，用于增强聊天中的“上传为文本”以及智能体的“文件上下文”功能，允许上传文件并使用 OCR 进行处理。**需要配置 OCR 服务。**
- **run_in_background**：默认使 Code Interpreter 执行和 shell 工具具备后台运行资格，并为符合条件的 MCP、Plugin 和 Action 工具启用按工具的后台运行选择。Action 级别的开关可为所有符合条件的操作启用此功能；OAuth Action 以及已定义 `run_in_background` 参数的操作将被排除在外。Agent 可以显式选择让 Code Interpreter 不在后台运行。此设置允许后台执行；模型会针对每次调用决定是否使用该功能。需要 `execute_code` 以及已配置的 Code Interpreter 部署来执行代码。此功能默认不启用。
- **tool_intents**：为符合条件的工具调用添加实时模型编写的意图标签。原生工具（包括 Code Interpreter 工具）会自动加入；MCP 工具可以在 Agent Builder 中单独或批量启用。Model Specs 使用 `describeIntent`。此功能默认不启用。

通过指定功能，您可以控制用户在与智能体交互时可使用的特性。

## 示例配置 [#example-configuration]

以下是配置 `agents` endpoint 并设置自定义能力和文件引用功能的示例：

```yaml filename="Agents Endpoint"
endpoints:
  agents:
    disableBuilder: false
    # File citation configuration
    maxCitations: 20
    maxCitationsPerFile: 5
    minRelevanceScore: 0.6
    # Custom capabilities
    capabilities:
      # Optional: enables Programmatic Tool Calling for MCP tools marked Programmatic in the Agent Builder.
      # - 'programmatic_tools'
      - 'execute_code'
      # Optional: makes Code Interpreter background-eligible and enables selected MCP, Plugin, and Action tools.
      # - 'run_in_background'
      # Optional: enables live intent labels for native and selected MCP tools.
      # - 'tool_intents'
      - 'file_search'
      - 'skills'
      - 'subagents'
      - 'actions'
      - 'artifacts'
      - 'context'
      - 'ocr'
      - 'web_search'
```

在此示例中：

- 构建器界面已启用
- 文件引用总数限制为 20 个，每个文件最多 5 个。
- 仅包含相关度在 60% 以上的来源
- LibreChat Agents 可以访问代码执行、文件搜索（带引用）、Skills、Subagents、actions、artifacts、文件上下文、OCR 服务（如果已配置）以及网络搜索功能。
- 除非你同时添加 `programmatic_tools` 和 `execute_code` 功能，否则 Programmatic Tool Calling 将保持禁用状态。
- 除非您添加 `run_in_background`，否则后台工具调用将保持禁用状态；此时 Code Interpreter 工具将默认变为可用，而符合条件的 MCP、Plugin 和 Action 工具仍需手动选择。
- 除非您添加 `tool_intents`，否则工具意图标签将保持禁用状态；原生工具会自动选择加入，而 MCP 工具仍需要逐个选择。

## 注意事项 [#notes]

- 除非您正在使用 [modelSpecs](/docs/configuration/librechat_yaml/object_structure/model_specs) 来定义可供选择的智能体列表，否则不建议禁用构建器界面。
- 文件引用配置（`maxCitations`、`maxCitationsPerFile`、`minRelevanceScore`）仅在启用 `file_search` 功能时生效。
- 相关性分数是使用向量相似度计算得出的，其中 1.0 表示完全匹配，0.0 表示完全不相似。
- 引用限制有助于在全面的信息检索与响应质量及性能之间取得平衡。
- `context` 功能无需 OCR 配置即可通过文本解析方法工作。配置 OCR 后可提升提取质量。
- `ocr` 功能需要配置 OCR 服务（请参阅 [OCR 配置](/docs/configuration/librechat_yaml/object_structure/ocr)）。
- `maxSubagents` 限制了单个 agent 可以引用的子 agent 数量。它不会改变 [Subagents](/docs/features/subagents#limits) 文档中所述的深度或图限制。
