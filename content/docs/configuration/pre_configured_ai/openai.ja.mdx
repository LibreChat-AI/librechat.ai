OpenAI APIキーを取得するには、以下の手順が必要です：

- **[https://platform.openai.com/account/api-keys](https://platform.openai.com/account/api-keys)** にアクセスします。
- アカウントを作成するか、既存のアカウントでログインしてください
- アカウントに支払い方法を追加する
- https://platform.openai.com/api-keys にアクセスしてキーを取得してください。
- 以下の環境変数をキーに設定する必要があります。または、ユーザー自身がキーを入力できるように `user_provided` に設定することも可能です。

```bash filename=".env"
OPENAI_API_KEY=user_provided
```

<Callout type="info" title="ユーザーが独自のキーを入力する場所">

`user_provided` を使用する場合、キーは一切提供しません。各ユーザーがチャットUIから自身のキーを入力します。エンドポイントメニューを開き、**OpenAI** の横にある **Set API Key** とラベル付けされた歯車アイコンをクリックします。クリックすると、キーを入力するフィールドと、キーを保持する期間（30分、2時間、12時間（デフォルト）、1日、7日、30日、または無期限）を選択するドロップダウンを備えたダイアログが開きます。

キーは暗号化され、そのユーザーのアカウントに紐づいてサーバー側に保存されます。そのため、会話ごとではなく一度入力するだけで済み、他のユーザーと共有されることもありません。同じダイアログには**取り消し (Revoke)** アクションがあり、さらに**すべて取り消し (Revoke All)** を使用して、そのユーザーが保存しているすべてのキーを消去することも可能です。

endpointメニューが非表示になっている場合（例えば、Model Specsによって `modelSelect` が無効化されている場合など）、同じダイアログには**設定**の**データコントロール**内、**APIキー**セクションからアクセスできます。

ユーザーがキーを設定するまで、そのendpointは表示されますが使用することはできません。

</Callout>

- `OPENAI_MODELS` を使用して、利用可能にするモデルを決定できます。
  - `OPENAI_API_KEY` が `user_provided` に設定されている場合 → このリストに含まれるモデルのみが利用可能になります
    - ⚠️新しいモデルは自動的には表示されません。最初にこのリストに追加する必要があります。
  - `OPENAI_API_KEY` に実際の API キーの値を設定した場合 → `OPENAI_MODELS` をコメントアウトしたままにしておくと、API 呼び出しが行われて利用可能なモデルが取得されます。これには新しいモデルも含まれるはずです。

```bash filename=".env"
OPENAI_MODELS=gpt-5.6,gpt-5.6-terra,gpt-5.6-luna,gpt-5.5,gpt-5.5-pro,chat-latest,gpt-5.4,gpt-5.4-pro,gpt-5.4-mini,gpt-5.4-nano,gpt-5.3-codex,gpt-5.2,gpt-5,gpt-5-codex,gpt-5-mini,gpt-5-nano,o3-pro,o3,o4-mini,gpt-4.1,gpt-4.1-mini,gpt-4.1-nano,o3-mini,o1-pro,o1,gpt-4o,gpt-4o-mini
```

**注記:**

- 内部的なOpenAIのデフォルトには `gpt-5.6`、`gpt-5.6-terra`、および `gpt-5.6-luna` が含まれ、その後に既存のGPT-5カタログが続きます。`gpt-5.6` はSolティアのエイリアスです。LibreChatは、これら3つのGPT-5.6ティアすべてに1,050,000トークンのコンテキストウィンドウと128,000トークンの最大出力を割り当てます。非推奨となったレガシーのデフォルトは、`OPENAI_MODELS` を使用して明示的に追加しない限り、含まれなくなりました。
- GPT-5.6は、Responses API専用の `reasoning_mode` 値である `standard` および `pro` に加え、`reasoning_context` 値である `auto`、`current_turn`、および `all_turns` をサポートしています。これらは [model specs](/docs/configuration/librechat_yaml/object_structure/model_specs#reasoning_mode) で設定可能です。
- `reasoning_effort` が `none` ではない GPT-5.6 モデルの場合、LibreChat は関数ツールとの互換性を維持するため、標準の OpenAI endpoint をデフォルトで Responses API に切り替えます。明示的に `useResponsesApi: false` を設定することで、Chat Completions を維持できます。Azure OpenAI、OpenRouter、およびカスタムまたはリバースプロキシのベース URL は自動的には切り替わりません。
- 添付ファイル付きのメッセージに対してビジョンモデルを選択する必要はありません。バックグラウンドで自動的に切り替えられるためです。ビジョンモデルを明示的に選択しなかった場合、そのモデルはビジョンリクエストにのみ使用され、リクエストが成功した後は、選択していた非ビジョンモデルが引き続き表示されます。
- OpenAI Visionモデルは、添付ファイルなしのメッセージを許可します
- OpenAI endpointは、`librechat.yaml`設定ファイルを通じて、`streamRate`、`headers`、`titleModel`、`titleMethod`、`titlePrompt`、`titlePromptTemplate`、`titleEndpoint`を含む、すべての[Shared Endpoint Settings](/docs/configuration/librechat_yaml/object_structure/shared_endpoint_settings)をサポートしています。
