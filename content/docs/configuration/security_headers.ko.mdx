LibreChat은 상태 확인 엔드포인트를 포함한 모든 응답에 기본 HTTP 보안 헤더 세트를 전송합니다. nonce 기반의 Content Security Policy(CSP)는 별도로 제공되며, 기존 통합 환경에서 적용 전 감사가 가능하도록 기본적으로 비활성화되어 있습니다.

## 기본 헤더 [#baseline-headers]

`SECURITY_HEADERS=false`로 설정하지 않는 한 기본 헤더(Baseline headers)가 활성화됩니다. 해당 변수는 전역 킬 스위치 역할을 하며, 기본 헤더와 CSP를 모두 비활성화합니다.

| 변수 | 기본값 | 동작 |
| --- | --- | --- |
| `SECURITY_HEADERS` | `true` | 모든 기본 헤더를 활성화합니다. `false`로 설정하면 CSP도 비활성화됩니다. |
| `HSTS_ENABLED` | `true` | `Strict-Transport-Security`를 전송합니다. 브라우저는 HTTPS를 통해서만 이를 준수합니다. |
| `HSTS_MAX_AGE` | `31536000` | HSTS 유지 시간(초 단위). 음수가 아닌 정수여야 합니다. |
| `HSTS_INCLUDE_SUBDOMAINS` | `false` | 모든 하위 도메인에 HSTS를 적용합니다. 모든 하위 도메인이 HTTPS를 사용하는 경우에만 활성화하세요. |
| `HSTS_PRELOAD` | `false` | HSTS `preload` 토큰을 추가합니다. |
| `X_FRAME_OPTIONS` | `SAMEORIGIN` | `SAMEORIGIN`, `DENY` 또는 `off`를 허용합니다. |
| `REFERRER_POLICY` | `no-referrer` | `Referrer-Policy`를 설정합니다. 생략하려면 `off`를 사용하세요. |
| `CROSS_ORIGIN_OPENER_POLICY` | `same-origin` | `Cross-Origin-Opener-Policy`를 설정합니다. 생략하려면 `off`를 사용하세요. |
| `CROSS_ORIGIN_RESOURCE_POLICY` | `same-origin` | `Cross-Origin-Resource-Policy`를 설정합니다. 생략하려면 `off`를 사용하세요. |

Helmet은 `X-Content-Type-Options: nosniff`도 전송합니다. 잘못된 값은 로그에 기록되며 문서화된 기본값으로 대체됩니다.

허용되는 opener 정책은 `same-origin`, `same-origin-allow-popups`, `noopener-allow-popups` 및 `unsafe-none`입니다. 허용되는 리소스 정책은 `same-origin`, `same-site` 및 `cross-origin`입니다. 허용되는 referrer 정책은 `no-referrer`, `no-referrer-when-downgrade`, `same-origin`, `origin`, `strict-origin`, `origin-when-cross-origin`, `strict-origin-when-cross-origin` 및 `unsafe-url`입니다.

```bash filename=".env"
SECURITY_HEADERS=true
HSTS_ENABLED=true
HSTS_MAX_AGE=31536000
HSTS_INCLUDE_SUBDOMAINS=false
HSTS_PRELOAD=false
X_FRAME_OPTIONS=SAMEORIGIN
REFERRER_POLICY=no-referrer
CROSS_ORIGIN_OPENER_POLICY=same-origin
CROSS_ORIGIN_RESOURCE_POLICY=same-origin
```

업스트림 프록시가 이러한 헤더를 함께 작성하는 경우, 하나의 권한 있는 정책을 유지하고 브라우저가 확인하는 최종 응답을 검증하십시오.

## Content Security Policy [#content-security-policy]

CSP는 옵트인(opt-in) 방식입니다. LibreChat은 모든 SPA 응답에 대해 새로운 nonce를 생성하며, 이를 셸(shell) 내의 실행 가능한 스크립트와 모듈 프리로드(module-preload) 링크에 적용합니다.

<Callout type="warning" title="보고 전용 모드로 시작">
  `CSP_REPORT_ONLY=true`로 CSP를 활성화하고, 실제 배포 환경에서 위반 사항을 수집한 뒤, 필요한 소스만 추가하십시오. 앱, 인증, 스토리지, 텔레메트리 및 임베디드 콘텐츠 흐름이 모두 정리된 후에만 적용(enforce)하십시오.
</Callout>

```bash filename=".env"
CSP_ENABLED=true
CSP_REPORT_ONLY=true
CSP_REPORT_URI=https://reports.example.com/csp

# Examples for deployment-specific services
CSP_CONNECT_SRC_EXTRA="https://telemetry.example.com wss://stream.example.com"
CSP_FRAME_SRC_EXTRA=https://tenant.sharepoint.com
CSP_IMG_SRC_EXTRA=https://cdn.example.com
```

`CSP_REPORT_ONLY`의 기본값은 `true`입니다. 인식된 false 값만이 강제 적용(enforcement)으로 전환되며, 인식되지 않은 값은 로그에 기록되고 계속해서 보고 전용(report-only) 상태로 유지됩니다. CSP가 활성화되어 있는 동안 LibreChat은 SPA 셸을 `Cache-Control: no-store`로 강제하며, 해당 응답에 대해서는 `INDEX_CACHE_CONTROL`, `INDEX_PRAGMA`, `INDEX_EXPIRES`를 무시하므로 캐시에서 nonce를 재사용할 수 없습니다.

### CSP 변수 [#csp-variables]

| 변수 | 기본값 | 동작 |
| --- | --- | --- |
| `CSP_ENABLED` | `false` | SPA 셸에 대한 nonce 기반 CSP를 활성화합니다. |
| `CSP_REPORT_ONLY` | `true` | `Content-Security-Policy-Report-Only`를 전송합니다. 강제하려면 `false`로 설정하세요. |
| `CSP_REPORT_URI` | 비어 있음 | 레거시 `report-uri` 지시문을 추가합니다. |
| `CSP_ALLOW_WASM` | `true` | HEIC 변환에 사용되는 WebAssembly 컴파일을 허용합니다. |
| `CSP_ALLOW_DATA_WORKERS` | `true` | Monaco 로더에서 사용하는 `data:` 워커를 허용합니다. |
| `CSP_FRAME_ANCESTORS` | `'self'` | 전체 `frame-ancestors` 소스 목록을 대체합니다. |
| `CSP_ADDITIONAL_DIRECTIVES` | 비어 있음 | 세미콜론으로 구분된 원시 지시문을 추가합니다. |

이 변수들은 일치하는 내장 지시어(directive)에 소스를 추가합니다:

- `CSP_DEFAULT_SRC_EXTRA`
- `CSP_SCRIPT_SRC_EXTRA`
- `CSP_STYLE_SRC_EXTRA`
- `CSP_IMG_SRC_EXTRA`
- `CSP_FONT_SRC_EXTRA`
- `CSP_CONNECT_SRC_EXTRA`
- `CSP_MEDIA_SRC_EXTRA`
- `CSP_FRAME_SRC_EXTRA`
- `CSP_WORKER_SRC_EXTRA`
- `CSP_FORM_ACTION_EXTRA`

소스 목록은 쉼표나 공백으로 구분할 수 있습니다. 이는 LibreChat의 기본값을 대체하는 것이 아니라 추가합니다. `CSP_FRAME_ANCESTORS`는 예외인데, 이는 의도적으로 기본값인 `'self'`를 대체하기 때문입니다.

기본 스크립트 정책은 `'strict-dynamic'`을 사용합니다. `CSP_SCRIPT_SRC_EXTRA`를 설정하면 `'strict-dynamic'`이 제거되어 나열된 스크립트 호스트가 적용될 수 있습니다. LibreChat에서 코드를 실행하도록 신뢰하는 출처만 나열하십시오.

다른 오리진이 LibreChat을 프레임으로 사용해야 하는 경우, `X-Frame-Options`를 제거하기 전에 `frame-ancestors`를 적용하세요:

```bash filename=".env"
CSP_ENABLED=true
CSP_REPORT_ONLY=false
X_FRAME_OPTIONS=off
CSP_FRAME_ANCESTORS="'self' https://portal.example.com"
```

CSP가 비활성화되어 있거나 report-only 모드일 때는 `X_FRAME_OPTIONS=off`로 설정하지 마십시오. report-only 정책은 위반 사항을 기록하지만 프레이밍을 제한하지는 않으므로, `X-Frame-Options`를 먼저 제거하면 모든 오리진이 배포 환경을 프레임화할 수 있게 됩니다. `frame-ancestors`를 지원하지 않는 브라우저는 이러한 교차 오리진 설정에서 프레이밍 제한을 적용하지 않습니다.

이 설정들이 `.env` 파일 내 어디에 위치하는지는 [환경 변수 참조](/docs/configuration/dotenv#security-headers-and-content-security-policy)를 확인하세요.
