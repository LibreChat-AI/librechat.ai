# Tenant Index Migratie [#tenant-index-migration]

Databases die zijn aangemaakt door LibreChat v0.8.7 of eerder kunnen de melding `Index build failed` geven tijdens het upgraden. Verouderde unieke indexen zoals `email_1` of `name_1` kunnen conflicteren met huidige indexen met dezelfde naam, terwijl samengestelde indexen met tenant-scope nu uniciteit afdwingen. Dit kan ook van invloed zijn op implementaties met één tenant.

De migratie is een expliciet onderhoudscommando en wordt niet uitgevoerd tijdens het opstarten. Gebruik de bijgewerkte bron of image die de onderstaande commando's biedt. Voor een bron-checkout, installeer eerst de dependencies en voer `npm run build:packages` uit.

<Steps>
  <Step>
    ### Stop writers [#stop-writers]

    Maak een back-up van MongoDB en stop vervolgens elke LibreChat API-replica en worker die naar de database schrijft. Laat MongoDB draaien.
  </Step>
  <Step>
    ### Bekijk de migratie als voorbeeld [#preview-the-migration]

    Voer de dry run uit met de normale `MONGO_URI` en `.env` verbindingsinstellingen van de deployment:

    ```bash
    npm run migrate:tenant-indexes:dry-run
    ```
  </Step>
  <Step>
    ### De migratie toepassen [#apply-the-migration]

    ```bash
    npm run migrate:tenant-indexes
    ```

    Wacht op een succesvolle afsluiting voordat u schrijvers opnieuw opstart.
  </Step>
  <Step>
    ### Herstarten en verifiëren [#restart-and-verify]

    Herstart LibreChat en bevestig dat de opstartprocedure geen indexconflicten meer rapporteert voor User, Role, Preset, AccessRole, MCPServer, AgentCategory, Message of Conversation.
  </Step>
</Steps>

## Docker Compose [#docker-compose]

Voer een eenmalige container uit vanaf de bijgewerkte image terwijl MongoDB beschikbaar blijft. Stel de werkmap in op `/app`, omdat de productie-API-image anders standaard `/app/api` gebruikt. Neem dezelfde Compose-bestandsvlaggen op die door uw implementatie worden gebruikt.

```bash
docker compose stop api
docker compose run --rm --no-deps -w /app api npm run migrate:tenant-indexes:dry-run
docker compose run --rm --no-deps -w /app api npm run migrate:tenant-indexes
docker compose up -d api
```

## Veiligheid en Herstel [#safety-and-recovery]

Het commando bouwt tenant-scoped unieke vervangingen voordat alleen bekende vervangen unieke indexen worden verwijderd, en creëert vervolgens de huidige schema-indexen. Het behoudt aangepaste indexen en huidige niet-unieke indexen, verwijdert geen documenten en gebruikt geen `syncIndexes` of `dropIndexes`. Het bouwt ook huidige indexen wanneer `MONGO_AUTO_INDEX=false`.

De dry run geeft alleen verwijderingen weer; het kan geen vervangende builds, rechten of dubbele gegevens valideren. Elke fout bij het weergeven, bouwen of verwijderen zorgt ervoor dat de opdracht mislukt. Als een vervangende build mislukt, blijven de oude beperkingen behouden. Een latere fout kan leiden tot een gedeeltelijke migratie, maar opnieuw uitvoeren voltooit veilig het resterende werk. Houd writers gestopt, corrigeer het gerapporteerde probleem en voer het opnieuw uit; los fouten niet op door elke index te verwijderen.

Index builds kunnen tijd in beslag nemen bij grote collecties.
