# Kiracı Dizini Geçişi [#tenant-index-migration]

LibreChat v0.8.7 veya önceki sürümleri tarafından oluşturulan veritabanları, yükseltme sırasında `Index build failed` hatası verebilir. `email_1` veya `name_1` gibi eski benzersiz (unique) indeksler, aynı isme sahip mevcut indekslerle çakışabilir; kiracı kapsamlı bileşik indeksler ise artık benzersizliği zorunlu kılmaktadır. Bu durum tek kiracılı (single-tenant) dağıtımları da etkileyebilir.

Geçiş işlemi açık bir bakım komutudur ve başlatma sırasında çalışmaz. Aşağıdaki komutları sağlayan güncellenmiş kaynağı veya imajı kullanın. Kaynak kod üzerinden kurulum yapıyorsanız, önce bağımlılıkları yükleyin ve `npm run build:packages` komutunu çalıştırın.

<Steps>
  <Step>
    ### Yazarları durdur [#stop-writers]

    MongoDB'yi yedekleyin, ardından veritabanına yazan her LibreChat API replikasını ve worker'ı durdurun. MongoDB'yi çalışır durumda tutun.
  </Step>
  <Step>
    ### Geçişi önizle [#preview-the-migration]

    Dağıtımın normal `MONGO_URI` ve `.env` bağlantı ayarlarıyla kuru çalışmayı (dry run) gerçekleştirin:

    ```bash
    npm run migrate:tenant-indexes:dry-run
    ```
  </Step>
  <Step>
    ### Geçişi uygula [#apply-the-migration]

    ```bash
    npm run migrate:tenant-indexes
    ```

    Herhangi bir yazıcıyı yeniden başlatmadan önce başarılı bir çıkış bekleyin.
  </Step>
  <Step>
    ### Yeniden başlatın ve doğrulayın [#restart-and-verify]

    LibreChat'i yeniden başlatın ve başlangıçta User, Role, Preset, AccessRole, MCPServer, AgentCategory, Message veya Conversation için artık dizin çakışması bildirilmediğini doğrulayın.
  </Step>
</Steps>

## Docker Compose [#docker-compose]

MongoDB erişilebilir durumdayken güncellenmiş imajdan tek seferlik bir container çalıştırın. Çalışma dizinini `/app` olarak ayarlayın, çünkü üretim API imajı aksi takdirde varsayılan olarak `/app/api` dizinini kullanır. Dağıtımınız tarafından kullanılan aynı Compose dosyası bayraklarını dahil edin.

```bash
docker compose stop api
docker compose run --rm --no-deps -w /app api npm run migrate:tenant-indexes:dry-run
docker compose run --rm --no-deps -w /app api npm run migrate:tenant-indexes
docker compose up -d api
```

## Güvenlik ve Kurtarma [#safety-and-recovery]

Bu komut, yalnızca bilinen geçersiz kılınmış benzersiz dizinleri (unique indexes) silmeden önce kiracı kapsamlı benzersiz değiştirmeler oluşturur ve ardından mevcut şema dizinlerini oluşturur. Özel dizinleri ve mevcut benzersiz olmayan dizinleri korur, belgeleri silmez ve `syncIndexes` veya `dropIndexes` kullanmaz. Ayrıca `MONGO_AUTO_INDEX=false` olduğunda mevcut dizinleri oluşturur.

Kuru çalışma (dry run) yalnızca kaldırılacak öğeleri listeler; değiştirme derlemelerini, izinleri veya yinelenen verileri doğrulayamaz. Herhangi bir listeleme, derleme veya bırakma hatası komutun başarısız olmasına neden olur. Bir değiştirme derlemesi başarısız olursa, eski kısıtlamalar kalır. Daha sonra oluşacak bir hata kısmi bir geçişe yol açabilir, ancak yeniden çalıştırmak kalan işi güvenli bir şekilde tamamlar. Yazıcıları durdurulmuş halde tutun, bildirilen sorunu düzeltin ve yeniden çalıştırın; hataları her dizini bırakarak çözmeye çalışmayın.

Dizin oluşturma işlemleri büyük koleksiyonlarda zaman alabilir.
