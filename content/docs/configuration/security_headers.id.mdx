LibreChat mengirimkan serangkaian header keamanan HTTP dasar pada setiap respons, termasuk endpoint kesehatan. Content Security Policy (CSP) berbasis nonce tersedia secara terpisah dan dinonaktifkan secara default agar integrasi yang ada dapat diaudit sebelum diberlakukan.

## Header Dasar [#baseline-headers]

Header dasar diaktifkan kecuali jika `SECURITY_HEADERS=false`. Variabel tersebut adalah tombol pemutus global: variabel ini menonaktifkan header dasar dan CSP.

| Variabel | Default | Perilaku |
| --- | --- | --- |
| `SECURITY_HEADERS` | `true` | Mengaktifkan semua header dasar. `false` juga menonaktifkan CSP. |
| `HSTS_ENABLED` | `true` | Mengirim `Strict-Transport-Security`. Browser hanya menghormatinya melalui HTTPS. |
| `HSTS_MAX_AGE` | `31536000` | Masa berlaku HSTS dalam detik. Harus berupa bilangan bulat non-negatif. |
| `HSTS_INCLUDE_SUBDOMAINS` | `false` | Menerapkan HSTS ke setiap subdomain. Aktifkan hanya jika semua subdomain menggunakan HTTPS. |
| `HSTS_PRELOAD` | `false` | Menambahkan token `preload` HSTS. |
| `X_FRAME_OPTIONS` | `SAMEORIGIN` | Menerima `SAMEORIGIN`, `DENY`, atau `off`. |
| `REFERRER_POLICY` | `no-referrer` | Mengatur `Referrer-Policy`; gunakan `off` untuk menghilangkannya. |
| `CROSS_ORIGIN_OPENER_POLICY` | `same-origin` | Mengatur `Cross-Origin-Opener-Policy`; gunakan `off` untuk menghilangkannya. |
| `CROSS_ORIGIN_RESOURCE_POLICY` | `same-origin` | Mengatur `Cross-Origin-Resource-Policy`; gunakan `off` untuk menghilangkannya. |

Helmet juga mengirimkan `X-Content-Type-Options: nosniff`. Nilai yang tidak valid akan dicatat dalam log dan kembali ke nilai default yang telah didokumentasikan.

Kebijakan opener yang diterima adalah `same-origin`, `same-origin-allow-popups`, `noopener-allow-popups`, dan `unsafe-none`. Kebijakan sumber daya yang diterima adalah `same-origin`, `same-site`, dan `cross-origin`. Kebijakan referrer yang diterima adalah `no-referrer`, `no-referrer-when-downgrade`, `same-origin`, `origin`, `strict-origin`, `origin-when-cross-origin`, `strict-origin-when-cross-origin`, dan `unsafe-url`.

```bash filename=".env"
SECURITY_HEADERS=true
HSTS_ENABLED=true
HSTS_MAX_AGE=31536000
HSTS_INCLUDE_SUBDOMAINS=false
HSTS_PRELOAD=false
X_FRAME_OPTIONS=SAMEORIGIN
REFERRER_POLICY=no-referrer
CROSS_ORIGIN_OPENER_POLICY=same-origin
CROSS_ORIGIN_RESOURCE_POLICY=same-origin
```

Jika proksi upstream juga menulis header ini, pertahankan satu kebijakan otoritatif dan verifikasi respons akhir yang dilihat oleh browser.

## Content Security Policy [#content-security-policy]

CSP bersifat opsional (opt-in). LibreChat membuat nonce baru untuk setiap respons SPA dan menerapkannya pada skrip yang dapat dieksekusi serta tautan module-preload di dalam shell.

<Callout type="warning" title="Mulai dalam mode report-only">
  Aktifkan CSP dengan `CSP_REPORT_ONLY=true`, kumpulkan pelanggaran dari deployment asli Anda, tambahkan hanya sumber yang diperlukan, dan terapkan hanya setelah alur aplikasi, autentikasi, penyimpanan, telemetri, dan konten tersemat sudah bersih.
</Callout>

```bash filename=".env"
CSP_ENABLED=true
CSP_REPORT_ONLY=true
CSP_REPORT_URI=https://reports.example.com/csp

# Examples for deployment-specific services
CSP_CONNECT_SRC_EXTRA="https://telemetry.example.com wss://stream.example.com"
CSP_FRAME_SRC_EXTRA=https://tenant.sharepoint.com
CSP_IMG_SRC_EXTRA=https://cdn.example.com
```

`CSP_REPORT_ONLY` secara default bernilai `true`. Hanya nilai false yang dikenali yang akan mengalihkan ke penegakan (enforcement); nilai yang tidak dikenali akan dicatat dalam log dan tetap dalam mode report-only. Selama CSP diaktifkan, LibreChat memaksa shell SPA ke `Cache-Control: no-store` dan mengabaikan `INDEX_CACHE_CONTROL`, `INDEX_PRAGMA`, serta `INDEX_EXPIRES` untuk respons tersebut agar nonce tidak dapat digunakan kembali dari cache.

### Variabel CSP [#csp-variables]

| Variabel | Default | Perilaku |
| --- | --- | --- |
| `CSP_ENABLED` | `false` | Mengaktifkan CSP berbasis nonce untuk shell SPA. |
| `CSP_REPORT_ONLY` | `true` | Mengirim `Content-Security-Policy-Report-Only`; atur ke `false` untuk menerapkan. |
| `CSP_REPORT_URI` | kosong | Menambahkan direktif `report-uri` warisan. |
| `CSP_ALLOW_WASM` | `true` | Mengizinkan kompilasi WebAssembly yang digunakan oleh konversi HEIC. |
| `CSP_ALLOW_DATA_WORKERS` | `true` | Mengizinkan worker `data:` yang digunakan oleh loader Monaco. |
| `CSP_FRAME_ANCESTORS` | `'self'` | Menggantikan daftar sumber `frame-ancestors` secara lengkap. |
| `CSP_ADDITIONAL_DIRECTIVES` | kosong | Menambahkan direktif mentah yang dipisahkan oleh titik koma. |

Variabel-variabel ini menambahkan sumber ke direktif bawaan yang cocok:

- `CSP_DEFAULT_SRC_EXTRA`
- `CSP_SCRIPT_SRC_EXTRA`
- `CSP_STYLE_SRC_EXTRA`
- `CSP_IMG_SRC_EXTRA`
- `CSP_FONT_SRC_EXTRA`
- `CSP_CONNECT_SRC_EXTRA`
- `CSP_MEDIA_SRC_EXTRA`
- `CSP_FRAME_SRC_EXTRA`
- `CSP_WORKER_SRC_EXTRA`
- `CSP_FORM_ACTION_EXTRA`

Daftar sumber dapat dipisahkan dengan koma atau spasi. Daftar tersebut akan menambahkan, bukan menggantikan, nilai default LibreChat. `CSP_FRAME_ANCESTORS` adalah pengecualian karena secara sengaja menggantikan nilai `'self'` default.

Kebijakan skrip default menggunakan `'strict-dynamic'`. Mengatur `CSP_SCRIPT_SRC_EXTRA` akan menghapus `'strict-dynamic'` sehingga host skrip yang tercantum dapat berlaku. Cantumkan hanya origin yang Anda percayai untuk mengeksekusi kode di LibreChat.

Jika origin lain harus membingkai LibreChat, terapkan `frame-ancestors` sebelum menghapus `X-Frame-Options`:

```bash filename=".env"
CSP_ENABLED=true
CSP_REPORT_ONLY=false
X_FRAME_OPTIONS=off
CSP_FRAME_ANCESTORS="'self' https://portal.example.com"
```

Jangan atur `X_FRAME_OPTIONS=off` saat CSP dinonaktifkan atau dalam mode report-only. Kebijakan report-only mencatat pelanggaran tetapi tidak membatasi framing, sehingga menghapus `X-Frame-Options` terlebih dahulu akan memungkinkan origin mana pun untuk melakukan framing pada deployment Anda. Browser yang tidak mendukung `frame-ancestors` tidak akan menerapkan pembatasan framing dalam pengaturan lintas-origin ini.

Lihat [referensi variabel lingkungan](/docs/configuration/dotenv#security-headers-and-content-security-policy) untuk mengetahui di mana pengaturan ini berada di dalam `.env`.
