LibreChat sendet bei jeder Antwort, einschließlich der Health-Endpoints, einen grundlegenden Satz von HTTP-Sicherheitsheadern. Eine auf Nonces basierende Content Security Policy (CSP) ist separat verfügbar und standardmäßig deaktiviert, damit bestehende Integrationen vor der Aktivierung überprüft werden können.

## Basis-Header [#baseline-headers]

Baseline-Header sind aktiviert, sofern nicht `SECURITY_HEADERS=false` gesetzt ist. Diese Variable ist der globale Kill-Switch: Sie deaktiviert sowohl die Baseline-Header als auch CSP.

| Variable | Default | Behavior |
| --- | --- | --- |
| `SECURITY_HEADERS` | `true` | Aktiviert alle Basis-Header. `false` deaktiviert auch CSP. |
| `HSTS_ENABLED` | `true` | Sendet `Strict-Transport-Security`. Browser berücksichtigen dies nur über HTTPS. |
| `HSTS_MAX_AGE` | `31536000` | HSTS-Lebensdauer in Sekunden. Muss eine nicht-negative Ganzzahl sein. |
| `HSTS_INCLUDE_SUBDOMAINS` | `false` | Wendet HSTS auf jede Subdomain an. Nur aktivieren, wenn alle Subdomains HTTPS verwenden. |
| `HSTS_PRELOAD` | `false` | Fügt das HSTS `preload`-Token hinzu. |
| `X_FRAME_OPTIONS` | `SAMEORIGIN` | Akzeptiert `SAMEORIGIN`, `DENY` oder `off`. |
| `REFERRER_POLICY` | `no-referrer` | Legt `Referrer-Policy` fest; verwenden Sie `off`, um es wegzulassen. |
| `CROSS_ORIGIN_OPENER_POLICY` | `same-origin` | Legt `Cross-Origin-Opener-Policy` fest; verwenden Sie `off`, um es wegzulassen. |
| `CROSS_ORIGIN_RESOURCE_POLICY` | `same-origin` | Legt `Cross-Origin-Resource-Policy` fest; verwenden Sie `off`, um es wegzulassen. |

Helmet sendet außerdem `X-Content-Type-Options: nosniff`. Ungültige Werte werden protokolliert und auf die dokumentierten Standardwerte zurückgesetzt.

Akzeptierte Opener-Richtlinien sind `same-origin`, `same-origin-allow-popups`, `noopener-allow-popups` und `unsafe-none`. Akzeptierte Ressourcen-Richtlinien sind `same-origin`, `same-site` und `cross-origin`. Akzeptierte Referrer-Richtlinien sind `no-referrer`, `no-referrer-when-downgrade`, `same-origin`, `origin`, `strict-origin`, `origin-when-cross-origin`, `strict-origin-when-cross-origin` und `unsafe-url`.

```bash filename=".env"
SECURITY_HEADERS=true
HSTS_ENABLED=true
HSTS_MAX_AGE=31536000
HSTS_INCLUDE_SUBDOMAINS=false
HSTS_PRELOAD=false
X_FRAME_OPTIONS=SAMEORIGIN
REFERRER_POLICY=no-referrer
CROSS_ORIGIN_OPENER_POLICY=same-origin
CROSS_ORIGIN_RESOURCE_POLICY=same-origin
```

Wenn ein Upstream-Proxy diese Header ebenfalls schreibt, behalten Sie eine maßgebliche Richtlinie bei und überprüfen Sie die endgültige Antwort, die vom Browser empfangen wird.

## Content Security Policy [#content-security-policy]

CSP ist optional (opt-in). LibreChat erstellt für jede SPA-Antwort eine neue Nonce und wendet diese auf ausführbare Skripte und module-preload-Links in der Shell an.

<Callout type="warning" title="Im Nur-Bericht-Modus starten">
  Aktivieren Sie CSP mit `CSP_REPORT_ONLY=true`, sammeln Sie Verstöße aus Ihrer tatsächlichen Bereitstellung, fügen Sie nur die erforderlichen Quellen hinzu und erzwingen Sie die Richtlinie erst, nachdem die Abläufe für App, Authentifizierung, Speicher, Telemetrie und eingebettete Inhalte bereinigt sind.
</Callout>

```bash filename=".env"
CSP_ENABLED=true
CSP_REPORT_ONLY=true
CSP_REPORT_URI=https://reports.example.com/csp

# Examples for deployment-specific services
CSP_CONNECT_SRC_EXTRA="https://telemetry.example.com wss://stream.example.com"
CSP_FRAME_SRC_EXTRA=https://tenant.sharepoint.com
CSP_IMG_SRC_EXTRA=https://cdn.example.com
```

`CSP_REPORT_ONLY` ist standardmäßig auf `true` gesetzt. Nur ein erkannter Wert für „false“ schaltet auf Durchsetzung um; ein nicht erkannter Wert wird protokolliert und bleibt im „Report-Only“-Modus. Während CSP aktiviert ist, erzwingt LibreChat für die SPA-Shell `Cache-Control: no-store` und ignoriert `INDEX_CACHE_CONTROL`, `INDEX_PRAGMA` sowie `INDEX_EXPIRES` für diese Antwort, damit ein Nonce nicht aus dem Cache wiederverwendet werden kann.

### CSP-Variablen [#csp-variables]

| Variable | Default | Behavior |
| --- | --- | --- |
| `CSP_ENABLED` | `false` | Aktiviert nonce-basiertes CSP für die SPA-Shell. |
| `CSP_REPORT_ONLY` | `true` | Sendet `Content-Security-Policy-Report-Only`; auf `false` setzen, um es zu erzwingen. |
| `CSP_REPORT_URI` | leer | Fügt die veraltete `report-uri`-Direktive hinzu. |
| `CSP_ALLOW_WASM` | `true` | Erlaubt WebAssembly-Kompilierung, die für die HEIC-Konvertierung verwendet wird. |
| `CSP_ALLOW_DATA_WORKERS` | `true` | Erlaubt `data:`-Worker, die vom Monaco-Loader verwendet werden. |
| `CSP_FRAME_ANCESTORS` | `'self'` | Ersetzt die vollständige `frame-ancestors`-Quellliste. |
| `CSP_ADDITIONAL_DIRECTIVES` | leer | Fügt durch Semikolons getrennte Roh-Direktiven hinzu. |

Diese Variablen fügen Quellen zu der entsprechenden integrierten Direktive hinzu:

- `CSP_DEFAULT_SRC_EXTRA`
- `CSP_SCRIPT_SRC_EXTRA`
- `CSP_STYLE_SRC_EXTRA`
- `CSP_IMG_SRC_EXTRA`
- `CSP_FONT_SRC_EXTRA`
- `CSP_CONNECT_SRC_EXTRA`
- `CSP_MEDIA_SRC_EXTRA`
- `CSP_FRAME_SRC_EXTRA`
- `CSP_WORKER_SRC_EXTRA`
- `CSP_FORM_ACTION_EXTRA`

Quellenlisten können durch Kommas oder Leerzeichen getrennt werden. Sie ergänzen die Standardwerte von LibreChat, anstatt sie zu ersetzen. `CSP_FRAME_ANCESTORS` ist die Ausnahme, da dieser Wert den Standardwert `'self'` absichtlich ersetzt.

Die Standard-Skriptrichtlinie verwendet `'strict-dynamic'`. Das Festlegen von `CSP_SCRIPT_SRC_EXTRA` entfernt `'strict-dynamic'`, sodass die aufgelisteten Skript-Hosts wirksam werden können. Listen Sie nur Ursprünge auf, denen Sie vertrauen, um Code in LibreChat auszuführen.

Falls ein anderer Ursprung LibreChat einbetten muss, erzwingen Sie `frame-ancestors`, bevor Sie `X-Frame-Options` entfernen:

```bash filename=".env"
CSP_ENABLED=true
CSP_REPORT_ONLY=false
X_FRAME_OPTIONS=off
CSP_FRAME_ANCESTORS="'self' https://portal.example.com"
```

Setzen Sie `X_FRAME_OPTIONS=off` nicht, während CSP deaktiviert ist oder sich im Report-Only-Modus befindet. Eine Report-Only-Richtlinie protokolliert Verstöße, schränkt das Framing jedoch nicht ein. Das vorherige Entfernen von `X-Frame-Options` würde es daher jedem Ursprung ermöglichen, die Bereitstellung zu framen. Browser ohne Unterstützung für `frame-ancestors` werden in diesem Cross-Origin-Setup keine Framing-Beschränkung erzwingen.

Siehe die [Referenz der Umgebungsvariablen](/docs/configuration/dotenv#security-headers-and-content-security-policy), um zu erfahren, wo sich diese Einstellungen in der `.env` befinden.
