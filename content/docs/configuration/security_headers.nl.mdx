LibreChat verstuurt een basisset aan HTTP-beveiligingsheaders bij elk antwoord, inclusief health-endpoints. Een op nonce gebaseerd Content Security Policy (CSP) is afzonderlijk beschikbaar en is standaard uitgeschakeld, zodat bestaande integraties kunnen worden gecontroleerd voordat ze worden afgedwongen.

## Basis-headers [#baseline-headers]

Baseline headers zijn ingeschakeld tenzij `SECURITY_HEADERS=false`. Die variabele is de globale kill switch: deze schakelt zowel de baseline headers als CSP uit.

| Variabele | Standaard | Gedrag |
| --- | --- | --- |
| `SECURITY_HEADERS` | `true` | Schakelt alle basisheaders in. `false` schakelt ook CSP uit. |
| `HSTS_ENABLED` | `true` | Verstuurt `Strict-Transport-Security`. Browsers honoreren dit alleen via HTTPS. |
| `HSTS_MAX_AGE` | `31536000` | HSTS-levensduur in seconden. Moet een niet-negatief geheel getal zijn. |
| `HSTS_INCLUDE_SUBDOMAINS` | `false` | Past HSTS toe op elk subdomein. Schakel alleen in wanneer alle subdomeinen HTTPS gebruiken. |
| `HSTS_PRELOAD` | `false` | Voegt het HSTS `preload`-token toe. |
| `X_FRAME_OPTIONS` | `SAMEORIGIN` | Accepteert `SAMEORIGIN`, `DENY`, of `off`. |
| `REFERRER_POLICY` | `no-referrer` | Stelt `Referrer-Policy` in; gebruik `off` om deze weg te laten. |
| `CROSS_ORIGIN_OPENER_POLICY` | `same-origin` | Stelt `Cross-Origin-Opener-Policy` in; gebruik `off` om deze weg te laten. |
| `CROSS_ORIGIN_RESOURCE_POLICY` | `same-origin` | Stelt `Cross-Origin-Resource-Policy` in; gebruik `off` om deze weg te laten. |

Helmet verstuurt ook `X-Content-Type-Options: nosniff`. Ongeldige waarden worden gelogd en er wordt teruggevallen op de gedocumenteerde standaardwaarden.

Geaccepteerd opener-beleid is `same-origin`, `same-origin-allow-popups`, `noopener-allow-popups` en `unsafe-none`. Geaccepteerd resource-beleid is `same-origin`, `same-site` en `cross-origin`. Geaccepteerd referrer-beleid is `no-referrer`, `no-referrer-when-downgrade`, `same-origin`, `origin`, `strict-origin`, `origin-when-cross-origin`, `strict-origin-when-cross-origin` en `unsafe-url`.

```bash filename=".env"
SECURITY_HEADERS=true
HSTS_ENABLED=true
HSTS_MAX_AGE=31536000
HSTS_INCLUDE_SUBDOMAINS=false
HSTS_PRELOAD=false
X_FRAME_OPTIONS=SAMEORIGIN
REFERRER_POLICY=no-referrer
CROSS_ORIGIN_OPENER_POLICY=same-origin
CROSS_ORIGIN_RESOURCE_POLICY=same-origin
```

Als een upstream proxy deze headers ook schrijft, hanteer dan één autoritatief beleid en verifieer het uiteindelijke antwoord dat door de browser wordt gezien.

## Content Security Policy [#content-security-policy]

CSP is opt-in. LibreChat maakt een nieuwe nonce aan voor elke SPA-respons en past deze toe op uitvoerbare scripts en module-preload-links in de shell.

<Callout type="warning" title="Start in report-only modus">
  Schakel CSP in met `CSP_REPORT_ONLY=true`, verzamel schendingen van je daadwerkelijke implementatie, voeg alleen de vereiste bronnen toe en dwing het pas af nadat de app-, authenticatie-, opslag-, telemetrie- en embedded-content-stromen schoon zijn.
</Callout>

```bash filename=".env"
CSP_ENABLED=true
CSP_REPORT_ONLY=true
CSP_REPORT_URI=https://reports.example.com/csp

# Examples for deployment-specific services
CSP_CONNECT_SRC_EXTRA="https://telemetry.example.com wss://stream.example.com"
CSP_FRAME_SRC_EXTRA=https://tenant.sharepoint.com
CSP_IMG_SRC_EXTRA=https://cdn.example.com
```

`CSP_REPORT_ONLY` staat standaard op `true`. Alleen een herkende false-waarde schakelt over naar handhaving; een niet-herkende waarde wordt gelogd en blijft in de rapportage-modus. Terwijl CSP is ingeschakeld, dwingt LibreChat de SPA-shell naar `Cache-Control: no-store` en negeert `INDEX_CACHE_CONTROL`, `INDEX_PRAGMA` en `INDEX_EXPIRES` voor dat antwoord, zodat een nonce niet opnieuw kan worden gebruikt vanuit de cache.

### CSP-variabelen [#csp-variables]

| Variabele | Standaard | Gedrag |
| --- | --- | --- |
| `CSP_ENABLED` | `false` | Schakelt nonce-gebaseerde CSP in voor de SPA-shell. |
| `CSP_REPORT_ONLY` | `true` | Verstuurt `Content-Security-Policy-Report-Only`; zet op `false` om af te dwingen. |
| `CSP_REPORT_URI` | leeg | Voegt de verouderde `report-uri` richtlijn toe. |
| `CSP_ALLOW_WASM` | `true` | Staat WebAssembly-compilatie toe die wordt gebruikt door HEIC-conversie. |
| `CSP_ALLOW_DATA_WORKERS` | `true` | Staat `data:` workers toe die worden gebruikt door Monaco's loader. |
| `CSP_FRAME_ANCESTORS` | `'self'` | Vervangt de volledige `frame-ancestors` bronlijst. |
| `CSP_ADDITIONAL_DIRECTIVES` | leeg | Voegt door puntkomma's gescheiden onbewerkte richtlijnen toe. |

Deze variabelen voegen bronnen toe aan de overeenkomstige ingebouwde richtlijn:

- `CSP_DEFAULT_SRC_EXTRA`
- `CSP_SCRIPT_SRC_EXTRA`
- `CSP_STYLE_SRC_EXTRA`
- `CSP_IMG_SRC_EXTRA`
- `CSP_FONT_SRC_EXTRA`
- `CSP_CONNECT_SRC_EXTRA`
- `CSP_MEDIA_SRC_EXTRA`
- `CSP_FRAME_SRC_EXTRA`
- `CSP_WORKER_SRC_EXTRA`
- `CSP_FORM_ACTION_EXTRA`

Bronlijsten kunnen worden gescheiden door komma's of spaties. Ze voegen toe aan de standaardwaarden van LibreChat in plaats van deze te vervangen. `CSP_FRAME_ANCESTORS` is de uitzondering omdat deze opzettelijk de standaardwaarde `'self'` vervangt.

Het standaard scriptbeleid gebruikt `'strict-dynamic'`. Het instellen van `CSP_SCRIPT_SRC_EXTRA` verwijdert `'strict-dynamic'`, zodat de vermelde script-hosts van kracht kunnen worden. Vermeld alleen origins die je vertrouwt om code uit te voeren in LibreChat.

Als een andere oorsprong LibreChat moet framen, dwing dan `frame-ancestors` af voordat `X-Frame-Options` wordt verwijderd:

```bash filename=".env"
CSP_ENABLED=true
CSP_REPORT_ONLY=false
X_FRAME_OPTIONS=off
CSP_FRAME_ANCESTORS="'self' https://portal.example.com"
```

Stel `X_FRAME_OPTIONS=off` niet in terwijl CSP is uitgeschakeld of in de report-only modus staat. Een report-only beleid registreert schendingen, maar beperkt het framen niet, dus het eerst verwijderen van `X-Frame-Options` zou elke oorsprong toestaan om de implementatie te framen. Browsers zonder ondersteuning voor `frame-ancestors` zullen in deze cross-origin configuratie geen framing-beperking afdwingen.

Zie de [referentie voor omgevingsvariabelen](/docs/configuration/dotenv#security-headers-and-content-security-policy) voor waar deze instellingen zich bevinden in `.env`.
