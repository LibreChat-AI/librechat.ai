LibreChat 会在每次响应（包括健康检查 endpoint）时发送一组基准 HTTP 安全标头。此外，还提供了一个基于 nonce 的 Content Security Policy (CSP)，该策略默认处于禁用状态，以便在强制执行前对现有集成进行审计。

## 基准标头 [#baseline-headers]

除非 `SECURITY_HEADERS=false`，否则默认启用基准标头。该变量是全局终止开关：它会同时禁用基准标头和 CSP。

| 变量 | 默认值 | 行为 |
| --- | --- | --- |
| `SECURITY_HEADERS` | `true` | 启用所有基准标头。设置为 `false` 也会禁用 CSP。 |
| `HSTS_ENABLED` | `true` | 发送 `Strict-Transport-Security`。浏览器仅在 HTTPS 下遵循此设置。 |
| `HSTS_MAX_AGE` | `31536000` | HSTS 有效期（以秒为单位）。必须是非负整数。 |
| `HSTS_INCLUDE_SUBDOMAINS` | `false` | 将 HSTS 应用于所有子域名。仅在所有子域名均使用 HTTPS 时启用。 |
| `HSTS_PRELOAD` | `false` | 添加 HSTS `preload` 令牌。 |
| `X_FRAME_OPTIONS` | `SAMEORIGIN` | 接受 `SAMEORIGIN`、`DENY` 或 `off`。 |
| `REFERRER_POLICY` | `no-referrer` | 设置 `Referrer-Policy`；使用 `off` 可省略此项。 |
| `CROSS_ORIGIN_OPENER_POLICY` | `same-origin` | 设置 `Cross-Origin-Opener-Policy`；使用 `off` 可省略此项。 |
| `CROSS_ORIGIN_RESOURCE_POLICY` | `same-origin` | 设置 `Cross-Origin-Resource-Policy`；使用 `off` 可省略此项。 |

Helmet 还会发送 `X-Content-Type-Options: nosniff`。无效的值会被记录并回退到文档中记载的默认值。

接受的 opener 策略为 `same-origin`、`same-origin-allow-popups`、`noopener-allow-popups` 和 `unsafe-none`。接受的资源策略为 `same-origin`、`same-site` 和 `cross-origin`。接受的 referrer 策略为 `no-referrer`、`no-referrer-when-downgrade`、`same-origin`、`origin`、`strict-origin`、`origin-when-cross-origin`、`strict-origin-when-cross-origin` 和 `unsafe-url`。

```bash filename=".env"
SECURITY_HEADERS=true
HSTS_ENABLED=true
HSTS_MAX_AGE=31536000
HSTS_INCLUDE_SUBDOMAINS=false
HSTS_PRELOAD=false
X_FRAME_OPTIONS=SAMEORIGIN
REFERRER_POLICY=no-referrer
CROSS_ORIGIN_OPENER_POLICY=same-origin
CROSS_ORIGIN_RESOURCE_POLICY=same-origin
```

如果上游代理也写入了这些标头，请保留一项权威策略，并验证浏览器最终接收到的响应。

## 内容安全策略 (Content Security Policy) [#content-security-policy]

CSP 是可选功能。LibreChat 会为每个 SPA 响应创建一个新的 nonce，并将其应用于 shell 中的可执行脚本和 module-preload 链接。

<Callout type="warning" title="以仅报告模式启动">
  通过 `CSP_REPORT_ONLY=true` 启用 CSP，从您的实际部署中收集违规报告，仅添加所需的源，并确保在应用程序、身份验证、存储、遥测和嵌入内容流程均无误后，再进行强制执行。
</Callout>

```bash filename=".env"
CSP_ENABLED=true
CSP_REPORT_ONLY=true
CSP_REPORT_URI=https://reports.example.com/csp

# Examples for deployment-specific services
CSP_CONNECT_SRC_EXTRA="https://telemetry.example.com wss://stream.example.com"
CSP_FRAME_SRC_EXTRA=https://tenant.sharepoint.com
CSP_IMG_SRC_EXTRA=https://cdn.example.com
```

`CSP_REPORT_ONLY` 默认为 `true`。只有识别为 false 的值才会切换到强制执行模式；无法识别的值会被记录日志并保持为仅报告模式。当启用 CSP 时，LibreChat 会强制将 SPA shell 设置为 `Cache-Control: no-store`，并忽略该响应的 `INDEX_CACHE_CONTROL`、`INDEX_PRAGMA` 和 `INDEX_EXPIRES`，以确保 nonce 不会从缓存中重复使用。

### CSP 变量 [#csp-variables]

| 变量 | 默认值 | 行为 |
| --- | --- | --- |
| `CSP_ENABLED` | `false` | 为 SPA shell 启用基于 nonce 的 CSP。 |
| `CSP_REPORT_ONLY` | `true` | 发送 `Content-Security-Policy-Report-Only`；设置为 `false` 以强制执行。 |
| `CSP_REPORT_URI` | 空 | 添加旧版 `report-uri` 指令。 |
| `CSP_ALLOW_WASM` | `true` | 允许 HEIC 转换所使用的 WebAssembly 编译。 |
| `CSP_ALLOW_DATA_WORKERS` | `true` | 允许 Monaco 加载器所使用的 `data:` worker。 |
| `CSP_FRAME_ANCESTORS` | `'self'` | 替换完整的 `frame-ancestors` 源列表。 |
| `CSP_ADDITIONAL_DIRECTIVES` | 空 | 添加以分号分隔的原始指令。 |

这些变量会将来源附加到匹配的内置指令中：

- `CSP_DEFAULT_SRC_EXTRA`
- `CSP_SCRIPT_SRC_EXTRA`
- `CSP_STYLE_SRC_EXTRA`
- `CSP_IMG_SRC_EXTRA`
- `CSP_FONT_SRC_EXTRA`
- `CSP_CONNECT_SRC_EXTRA`
- `CSP_MEDIA_SRC_EXTRA`
- `CSP_FRAME_SRC_EXTRA`
- `CSP_WORKER_SRC_EXTRA`
- `CSP_FORM_ACTION_EXTRA`

源列表可以使用逗号或空格分隔。它们是追加到 LibreChat 的默认值之后，而不是替换它们。`CSP_FRAME_ANCESTORS` 是个例外，因为它有意替换了默认的 `'self'` 值。

默认的脚本策略使用 `'strict-dynamic'`。设置 `CSP_SCRIPT_SRC_EXTRA` 会移除 `'strict-dynamic'`，从而使列出的脚本主机生效。请仅列出您信任可以在 LibreChat 中执行代码的来源。

如果必须由其他源来嵌入 LibreChat，请在移除 `X-Frame-Options` 之前强制执行 `frame-ancestors`：

```bash filename=".env"
CSP_ENABLED=true
CSP_REPORT_ONLY=false
X_FRAME_OPTIONS=off
CSP_FRAME_ANCESTORS="'self' https://portal.example.com"
```

在 CSP 被禁用或处于仅报告模式（report-only）时，请勿设置 `X_FRAME_OPTIONS=off`。仅报告策略仅记录违规行为，而不限制框架嵌入，因此先移除 `X-Frame-Options` 会允许任何源嵌入该部署。在不支持 `frame-ancestors` 的浏览器中，这种跨源设置将不会强制执行框架限制。

请参阅 [环境变量参考](/docs/configuration/dotenv#security-headers-and-content-security-policy)，了解这些设置在 `.env` 中的位置。
