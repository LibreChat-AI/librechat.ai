O LibreChat envia um conjunto básico de cabeçalhos de segurança HTTP em todas as respostas, incluindo endpoints de integridade. Uma Content Security Policy (CSP) baseada em nonce está disponível separadamente e está desativada por padrão, para que as integrações existentes possam ser auditadas antes da aplicação.

## Cabeçalhos de Referência [#baseline-headers]

Os cabeçalhos de linha de base (baseline headers) estão habilitados, a menos que `SECURITY_HEADERS=false`. Essa variável é o interruptor global: ela desativa tanto os cabeçalhos de linha de base quanto o CSP.

| Variável | Padrão | Comportamento |
| --- | --- | --- |
| `SECURITY_HEADERS` | `true` | Habilita todos os cabeçalhos básicos. `false` também desabilita o CSP. |
| `HSTS_ENABLED` | `true` | Envia `Strict-Transport-Security`. Navegadores respeitam isso apenas via HTTPS. |
| `HSTS_MAX_AGE` | `31536000` | Tempo de vida do HSTS em segundos. Deve ser um número inteiro não negativo. |
| `HSTS_INCLUDE_SUBDOMAINS` | `false` | Aplica HSTS a todos os subdomínios. Habilite apenas quando todos os subdomínios usarem HTTPS. |
| `HSTS_PRELOAD` | `false` | Adiciona o token `preload` ao HSTS. |
| `X_FRAME_OPTIONS` | `SAMEORIGIN` | Aceita `SAMEORIGIN`, `DENY` ou `off`. |
| `REFERRER_POLICY` | `no-referrer` | Define a `Referrer-Policy`; use `off` para omiti-la. |
| `CROSS_ORIGIN_OPENER_POLICY` | `same-origin` | Define a `Cross-Origin-Opener-Policy`; use `off` para omiti-la. |
| `CROSS_ORIGIN_RESOURCE_POLICY` | `same-origin` | Define a `Cross-Origin-Resource-Policy`; use `off` para omiti-la. |

O Helmet também envia `X-Content-Type-Options: nosniff`. Valores inválidos são registrados em log e retornam aos padrões documentados.

As políticas de opener aceitas são `same-origin`, `same-origin-allow-popups`, `noopener-allow-popups` e `unsafe-none`. As políticas de recurso aceitas são `same-origin`, `same-site` e `cross-origin`. As políticas de referrer aceitas são `no-referrer`, `no-referrer-when-downgrade`, `same-origin`, `origin`, `strict-origin`, `origin-when-cross-origin`, `strict-origin-when-cross-origin` e `unsafe-url`.

```bash filename=".env"
SECURITY_HEADERS=true
HSTS_ENABLED=true
HSTS_MAX_AGE=31536000
HSTS_INCLUDE_SUBDOMAINS=false
HSTS_PRELOAD=false
X_FRAME_OPTIONS=SAMEORIGIN
REFERRER_POLICY=no-referrer
CROSS_ORIGIN_OPENER_POLICY=same-origin
CROSS_ORIGIN_RESOURCE_POLICY=same-origin
```

Se um proxy upstream também gravar esses cabeçalhos, mantenha uma política autoritativa e verifique a resposta final vista pelo navegador.

## Content Security Policy [#content-security-policy]

CSP é opcional (opt-in). O LibreChat cria um nonce novo para cada resposta SPA e o aplica a scripts executáveis e links de pré-carregamento de módulos (module-preload) no shell.

<Callout type="warning" title="Iniciar no modo somente relatório">
  Habilite o CSP com `CSP_REPORT_ONLY=true`, colete violações da sua implantação real, adicione apenas as fontes necessárias e aplique a restrição somente após os fluxos de aplicativo, autenticação, armazenamento, telemetria e conteúdo incorporado estarem limpos.
</Callout>

```bash filename=".env"
CSP_ENABLED=true
CSP_REPORT_ONLY=true
CSP_REPORT_URI=https://reports.example.com/csp

# Examples for deployment-specific services
CSP_CONNECT_SRC_EXTRA="https://telemetry.example.com wss://stream.example.com"
CSP_FRAME_SRC_EXTRA=https://tenant.sharepoint.com
CSP_IMG_SRC_EXTRA=https://cdn.example.com
```

`CSP_REPORT_ONLY` tem como padrão `true`. Apenas um valor reconhecido como falso alterna para a aplicação (enforcement); um valor não reconhecido é registrado e permanece apenas em modo de relatório (report-only). Enquanto o CSP está ativado, o LibreChat força o shell da SPA para `Cache-Control: no-store` e ignora `INDEX_CACHE_CONTROL`, `INDEX_PRAGMA` e `INDEX_EXPIRES` para essa resposta, de modo que um nonce não possa ser reutilizado a partir do cache.

### Variáveis CSP [#csp-variables]

| Variável | Padrão | Comportamento |
| --- | --- | --- |
| `CSP_ENABLED` | `false` | Habilita CSP baseado em nonce para o shell da SPA. |
| `CSP_REPORT_ONLY` | `true` | Envia `Content-Security-Policy-Report-Only`; defina como `false` para aplicar. |
| `CSP_REPORT_URI` | vazio | Adiciona a diretiva legada `report-uri`. |
| `CSP_ALLOW_WASM` | `true` | Permite a compilação de WebAssembly usada pela conversão HEIC. |
| `CSP_ALLOW_DATA_WORKERS` | `true` | Permite workers `data:` usados pelo carregador do Monaco. |
| `CSP_FRAME_ANCESTORS` | `'self'` | Substitui a lista de fontes `frame-ancestors` completa. |
| `CSP_ADDITIONAL_DIRECTIVES` | vazio | Adiciona diretivas brutas separadas por ponto e vírgula. |

Estas variáveis adicionam fontes à diretiva integrada correspondente:

- `CSP_DEFAULT_SRC_EXTRA`
- `CSP_SCRIPT_SRC_EXTRA`
- `CSP_STYLE_SRC_EXTRA`
- `CSP_IMG_SRC_EXTRA`
- `CSP_FONT_SRC_EXTRA`
- `CSP_CONNECT_SRC_EXTRA`
- `CSP_MEDIA_SRC_EXTRA`
- `CSP_FRAME_SRC_EXTRA`
- `CSP_WORKER_SRC_EXTRA`
- `CSP_FORM_ACTION_EXTRA`

As listas de origem podem ser separadas por vírgulas ou espaços. Elas são adicionadas aos padrões do LibreChat em vez de substituí-los. `CSP_FRAME_ANCESTORS` é a exceção, pois substitui intencionalmente o valor padrão `'self'`.

A política de script padrão usa `'strict-dynamic'`. Definir `CSP_SCRIPT_SRC_EXTRA` remove `'strict-dynamic'` para que os hosts de script listados possam entrar em vigor. Liste apenas origens em que você confia para executar código no LibreChat.

Se outra origem precisar incorporar o LibreChat, aplique `frame-ancestors` antes de remover `X-Frame-Options`:

```bash filename=".env"
CSP_ENABLED=true
CSP_REPORT_ONLY=false
X_FRAME_OPTIONS=off
CSP_FRAME_ANCESTORS="'self' https://portal.example.com"
```

Não defina `X_FRAME_OPTIONS=off` enquanto o CSP estiver desativado ou em modo apenas de relatório (report-only). Uma política de apenas relatório registra violações, mas não restringe o framing; portanto, remover o `X-Frame-Options` primeiro permitiria que qualquer origem fizesse o framing da implantação. Navegadores sem suporte a `frame-ancestors` não aplicarão uma restrição de framing nesta configuração de origem cruzada (cross-origin).

Consulte a [referência de variáveis de ambiente](/docs/configuration/dotenv#security-headers-and-content-security-policy) para saber onde essas configurações residem no arquivo `.env`.
